# 话题标注（离线评测工具）

用内网本地大模型把全部未删除的制程问题单读一遍，判断每张单与说法清单 14 个话题的关系，再与说法清单按词找的结果对照。替代探测 T4 的逐张人工判定：人只抽查两边不一致的单。

- **不是模块代码**：`src/` 不引用它，不随 wheel 发布。
- **产出用于**：
  - 话题级应命中集；
  - G2 检索评测集；
  - 说法清单（`docs/2_landed/topic_terms.md`）修订建议。

## 红线

- **只允许连内网本地模型服务**（OpenAI 兼容接口），禁止填外部模型 API。脚本会把单上文字发给 `FI_LLM_BASE_URL`，不加 `--confirm-local` 不会发。
- **凭据只放本机 `.env`**：API key、数据库口令都放在仓库根目录的 `.env`（已在 `.gitignore`），不要贴进对话、不要写进任何入库文件。
- **只在能连正式镜像库与本地模型的内网机器上运行**，由开发者或业务方自己运行。编程助手不运行它，也不接收原始输出。
- 输出写在 `runtime/topic_labeling/<日期>-<提示词版本>/`（`runtime/` 不入库）。哪些文件能发回，见下文「输出」。

## 准备

在仓库根目录 `.env` 里加（已有同名变量时以环境变量为准）：

```dotenv
# 正式镜像库（PostgreSQL，库 ai-info，schema public），只读账号即可
FI_PG_DSN=postgresql://<用户>:<口令>@<主机>:5432/ai-info
# 内网本地模型服务（OpenAI 兼容，地址到 /v1 为止）
FI_LLM_BASE_URL=http://<主机>:<端口>/v1
FI_LLM_API_KEY=<key>
FI_LLM_MODEL=<模型名，如服务上 Qwen 的名称>
# 可选
FI_LLM_CONCURRENCY=4          # 并发数，按服务能力调
FI_LLM_DISABLE_THINKING=1     # Qwen3 关闭思考模式；服务不认 chat_template_kwargs 而报错时改为 0
FI_LLM_TIMEOUT=120
FI_LLM_MAX_TOKENS=800
FI_LLM_RETRIES=5              # 每张单最多试几次；服务报 5xx 时按 2、4、8、16、32 秒退避
```

## 运行

三步走，每步都在仓库根目录执行：

```powershell
# 1. 不调模型：只做按词匹配，核对与探测 T4 的计数是否一致（几分钟）
uv run --with "psycopg[binary]>=3.2,<4" python scripts/topic_labeling/label_topics.py --dry-run

# 2. 试跑 30 张：看提示词.txt、汇总.md，确认模型回得出 JSON、判断大体合理、速度可接受
uv run --with "psycopg[binary]>=3.2,<4" python scripts/topic_labeling/label_topics.py --confirm-local --limit 30

# 3. 全量（约 2,700 张，一张一次调用；按试跑的速度估算耗时，可放一晚）
uv run --with "psycopg[binary]>=3.2,<4" python scripts/topic_labeling/label_topics.py --confirm-local `
    --t4 docs/1_user_input/probe_answers/T4探测.md
```

- **第 1 步**：看 `汇总.md` 第一节「与探测 T4 的计数对照」，5 行应全部「一致」。不一致说明脚本的按词匹配与 SQL 有出入，先停下来发回这一节。
- **中断了可以续跑**：同一天、同一输出目录再运行一次，已标注成功的单跳过，失败的重试。换一天运行要用 `--out` 指回原目录。提示词版本或模型换了，旧结果自动作废、重新标注。
- **提示词 v2**：把每张单文字里出现过说法的话题列给模型，要求逐个给出「问题本身 / 顺带提到 / 无关」，其余话题照常可补。v1 让模型从 14 个话题里自由挑，次要话题常被整个漏掉。
- **`--t4`**：把探测 T4 已判的单当标尺，算模型与人工判定的一致率；已判的单不再进抽查清单。
- **其他参数**：`--domain 国内` 只跑一个域；`--per-col`、`--total` 调每张单交给模型的字数上限（默认每栏 1,000 字、每张 6,000 字）；`--sample-cap` 调抽查张数。

## 改清单之前先估算（--what-if）

拿一份说法清单草稿（格式同 `topic_terms.md`，至少要有「清单」一节；可复制 `topic_terms.md` 再改）与现行清单对比。2026-10-26 那次修订就是这样做的，见决策 2026-10-26「说法清单按全量标注修订」。脚本只连镜像库取文字，复用之前几次运行的模型标签，不调模型，几分钟跑完：

```powershell
uv run --with "psycopg[binary]>=3.2,<4" python scripts/topic_labeling/label_topics.py `
    --what-if runtime/topic_labeling/<草稿>.md `
    --labels-dir runtime/topic_labeling/20261025 --labels-dir runtime/topic_labeling/20261025-v2
```

输出 `runtime/topic_labeling/<日期>-whatif/清单对比-<草稿名>.md`，只有计数，可以发回。每个改了的话题列出：
- 每条改动命中多少张，其中模型判为问题本身的比例，每个标签集各给一个；
- 改前、改后各组的张数；
- 换了组的单有多少，其中模型判为问题本身的比例。

再加 `--judged <填过的抽查清单.csv>`（可给多次）和 `--t4 <T4 判定文件>`，会多出一节：人工判定过的单在现行清单和草稿里各落在哪一组，并列出草稿仍然分错的单（判「是」却没找到，或判「不是」仍在前两组）。抽查清单用 Excel 另存过也能读：GBK 或 UTF-8 编码、逗号或制表符分隔都行。

## 输出

| 文件 | 内容 | 能否发回 |
|---|---|---|
| `汇总.md` | 运行信息、T4 计数对照、每个话题「说法清单分组 × 模型判断」、与 T4 人工判定的一致率、可能太宽的说法、说法清单没找到的张数、说法候选 | 可以；「说法候选」一节的短语摘自原文，外传前过目 |
| `说法精度.csv` | 每个说法命中多少张、其中模型判为问题本身多少张 | 可以（只有计数） |
| `说法候选.csv` | 模型依据里不含现有说法、在 2 张及以上单上出现的短语 | 过目后可以 |
| `应命中集草稿.csv` | 每个话题：说法清单前两组的单与模型判为问题本身的单（单号、建单日期、分组、模型判断，没有文字） | 单号要进仓库，业务方同意后发回 |
| `抽查清单.csv` | 每个话题四类各抽几张，带命中位置与模型依据，留两列给人工填 | 在内网填；发回前删掉「模型依据」列 |
| `T4对照.csv` | T4 已判的单逐张对照 | 删掉「模型依据」列后可以 |
| `提示词.txt` | 本次交给模型的系统提示词（由 `topic_terms.md` 生成，不含单上数据） | 可以 |
| `labels.jsonl` | 每张单的模型原始结果，含原文短语 | 只留本地 |

## 抽查怎么做

`抽查清单.csv` 的四类：

| 类 | 是什么 | 人看了能定什么 |
|---|---|---|
| A | 说法清单命中（前两组），模型说不是问题本身 | 说法是否太宽；模型是否漏判 |
| B | 说法清单没找到，模型说是问题本身 | 说法清单漏了哪些写法；第三组的正样本 |
| C | 待判断（只在问题描述、现象、原因里出现有歧义的说法） | 线上助手判断第三组时的标准答案 |
| D | 两边一致，随机抽 | 估计模型标签的准确率 |

到管理页面打开单，「人工判定」填是 / 不是 / 拿不准。判定标准与探测 T4 相同：**这张单坏的正是这个话题的功能或部件**才算「是」；它只作为另一个问题的原因出现，或只是检验、处理时提到，都算「不是」。不要把单上文字抄进备注。建议先做非接、音频。

## 注意

- **模型标签不是标准答案**：线上助手用的是同一个模型，直接拿它的标签当 golden 会把模型的偏差一起放过。进 golden 的只有人工判定过的单；其余标签用于找分歧、估准确率、修说法清单。
- **提示词与 T4 标尺不完全独立**：提示词里「只作为另一个问题的原因出现算顺带提到」这条，来自 T4 的人工判定，所以 T4 里对应那几张单的一致率会偏高。
- **口径来源**：说法清单与补充说明直接读 `docs/2_landed/topic_terms.md`，清单改了重跑即可，不用改脚本。
- **按词匹配要与线上一致**：文字的取法、剥图、分组栏目、匹配规则，都与探测 T4 的 SQL 及总述「涉及某个话题怎么找」一致。改了口径要同步改 `TEXT_SQL` 与 `TopicMatcher`。
