## High-level view

提示部分照设计做。system 在导入时按两种占位写法各渲染一份、之后固定，和 r2 实测时的文本逐字相同。user 的参考内容由调用方传入，P3 期间传空：`five_why_answer` 这时提示里没有「这一答对应的问」，与 §8.2「恒不为空」不符。P4 接上之前不要发版，这一点任务单写了。

第 ⑥ 步与 §4 的代码段一致，超时、模型出错、`ctx.llm` 为 None 都直接 `POLISH_FAILED`、不重试。两层 `aclosing` 都有必要，让停止时的取消在 `aclose()` 里同步发出，不依赖事件循环的异步生成器收尾钩子。临时实验数了从 `aclose()` 返回到模型调用收到取消要几拍：两层都在 1 拍，少任一层 3 拍，两层都少 5 拍；单测等 3 拍，所以只能发现两层都少。设计 §3 说里层「要等垃圾回收」，并不准确：CPython 下是引用释放后由收尾钩子排队关闭，时机不保证。

日志有两处与 §14 对不上：`output_chars` 记的是拼回后 HTML 的长度；停止或取消时整轮没有结束日志。

3. **停止或取消时没有结束日志** — §14 要求「每次润色结束记一条」，代码只在正常返回的各分支调 `finish`。补一个 `outcome="stopped"`（在 `GeneratorExit`/`CancelledError` 时记），或在 §14 写明停止不记。
4. **output_chars 口径** — 代码记的是 `len(verdict.output)`，即拼回后的 HTML（含标签与图片地址，base64 图会很大），`input_chars` 却是去掉占位与空白后的字数，两者没法对比。改用与 `input_chars` 相同的口径，或在 §14 写明是 HTML 长度。
5. **完成时异常可能没人取回**（possible）— 外层取消恰好在模型任务结束的那一拍到达，或者 `chat` 在被取消时换成别的异常抛出，`finally` 里只在任务未完成时 `cancel()`，任务的异常就没人取回，asyncio 会记一条 "Task exception was never retrieved"。可以在 `finally` 里加 `task.add_done_callback(lambda t: t.cancelled() or t.exception())`。
6. **文档小处** — 设计 §3 的「要等垃圾回收」改成「要等事件循环的异步生成器收尾钩子，时机不保证」；任务单 P2 行状态为「完成（`70fe325`）」，备注却仍写「未提交」，P1 行仍写「待整理提交」，与「P0–P2 已提交」不一致；`ctx.llm` 为 None 时 `call_failed` 记 `attempt=1`，结束日志却是 `attempts=0`，两处统一一下。

### 停止与取消的路径

```
平台 aclose(handle) ──GeneratorExit──▶ handle: aclosing(run)
                                          └─▶ run: aclosing(call_with_heartbeat)
                                                 └─▶ finally: task.cancel()
外层 task.cancel() ──CancelledError 落在 asyncio.wait 上──▶ finally: task.cancel()
超时 ──box.error="timeout"; return──▶ finally: task.cancel()
```

外层取消不经过 `aclosing`：CancelledError 直接落在最里层的 `await asyncio.wait` 上，所以外层取消的单测检查的是 `finally` 本身。

停止路径用临时实验把 `module.aclosing`、`steps.aclosing` 分别换成不关闭的上下文管理器，数从 `aclose()` 返回到 `SlowLLM` 收到取消的拍数：两层都在 1 拍，去掉 module 层 3 拍，去掉 steps 层 3 拍，两层都去掉 5 拍（关掉 `gc` 结果一样，说明靠的是引用计数触发的收尾钩子，而非循环垃圾回收）。现有单测等 3 拍，所以只能发现两层都去掉。如果有别的引用拿住里层生成器（比如异常 traceback 被日志或监控留着），收尾钩子会推迟到那份引用释放，这正是两层 `aclosing` 要防的情况，单测应当把它锁住。

`task.result()` 只接 `Exception`。如果 `ctx.llm` 自己把任务取消了，CancelledError 会从生成器冒出去，看起来像整轮被取消；`ctx.llm` 正常不会这样做，这里只记下这个行为。

### 日志与测试缺口

结束日志在正常返回的每个分支都记，停止和外层取消两种情况不记，所以这类轮次在日志里看不到。`ctx.llm` 为 None 时 `attempts` 是 0，同一轮的 `call_failed` 却记 `attempt=1`。修一次后通过时，`failed_checks` 留着第一次的编号，与 §14 新写的「最后一次不过的」一致，但这一条没有单测锁住。

没测到：停止时只等 1 拍就已取消（见 Issues 1）；修一次后通过的日志；润色 guardrails 场景的最终结果（见 Issues 2）；心跳测试只数个数、不核对间隔。
