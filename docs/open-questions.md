# 待澄清清单（open questions）

> G1 强制产物：业务逻辑/数据口径的歧义、缺口、冲突。逐条向业务方确认，
> 确认结论落 `docs/2_landed/` 或 `docs/decisions/` 后勾选划除。
> 格式约定：未决项写作 `- [ ] 问题描述`，确认后改为 `- [x] 问题描述 → 结论（日期）`。
> **存在未决项 `- [ ]`（且无 `docs/.g1-cleared` 放行标记）时，guard hook 会阻止编写 src/ 代码。**
> 素材路径：未决项可以写「请把答复/执行结果放到 `docs/1_user_input/<子目录>/`」；**关闭时不留指向
> `1_user_input` 具体文件的路径**——结论写进 `2_landed`，来源用文字描述（如「业务方 2026-10-10 书面答复」）。
> `1_user_input` 是临时投递区，梳理完成后素材随时可能被清理。

**答复方式**：每条未决项都附了「建议」。同意建议回一句「Gx/Dx… 同意」即可；不同意请写明正确口径。
书面答复与执行结果请放到 `docs/1_user_input/answers/2026-10-16/`。

- [x] **G2 数据量** → 28 张表行数与三个主表按年分布已落盘到 `business_description.md`「数据量声明」（业务方 2026-10-16 内网统计）。巴西涉及存货子表未统计，随 B7 一并处理

- [x] **G3 默认时间范围** → 清单类不限时间、按建单时间倒序给最近的单；汇总类追问时间范围（业务方 2026-10-16 答复）
- [x] **G4 时间列（海外；巴西统计日期）** → 三域一致，默认按建单时间，说到「现场发现 / 发现日期」才按发现日期；巴西统计日期只在用户明说「统计日期」时使用（同上）
- [x] **G5 只说人名或部门** → 人名按问题跟进人，部门按问题跟进部门；国内说「责任部门 / 定责」才查责任归属部门（同上）

- [x] **G7 海外处理步骤的「最新」** → 与国内一致，按 ID 最大（同上）
- [x] **G8 附件选取** → 国内步骤附件 ID 按可能逗号多值处理；海外有效附件只要求业务记录 ID = 海外主表 ID 且未删除，不加业务名称条件（同上）

- [x] **G9 跨域汇总的归并** → 问题类型、问题等级同名合并，不按含义归并，该域没有的显示「—」；状态跨域只分已结案 / 未结案，巴西另列待提交、已终止；各环节分布按域分别给（业务方 2026-10-16 答复）
- [x] **G10 类似问题按什么文本比对** → 国内比对问题描述、原因分析、改善措施；巴西比对问题现象、问题描述、处理过程的原因分析与改善措施；海外比对已选问题现象、问题描述、问题原因。命中后带回原因、改善措施、预防对策。另分两种问法：关键词搜索返回全部命中的单；类似问题默认最多 10 张、按相近程度排序，并说明不保证完整（业务方 2026-10-16 答复）。比对方法留 G2 决策
- [x] **G11 链接站点地址** → 分三项配置（国内 / 海外制程单、巴西制程单、附件预览），当前都填同一个 INFO 正式站点地址（同上）
- [x] **G12 跨域汇总的呈现** → 先给各域小计再给合计；无权限的域明说「无权限，未计入」，不说成「没有数据」（同上）

- [x] **G13 一单多值时怎么计数** → 在每个所属分组下各计一次；统计口径说明写明各组之和可能大于问题单总数（业务方 2026-10-16 答复）

- [x] **G14 「机型 X」「PN X」在各域查哪一列，跨域按机型汇总怎么合并** → 说「机型」时国内查机型、巴西 / 海外查大机型（不按 PN）；说「PN」时国内查生产订单 PN，巴西 / 海外按 PN 名称或编码任一命中；跨域按机型汇总同名合并，规则同问题类型（业务方 2026-10-16 答复，同意建议）
