# 待澄清清单（open questions）

> G1 强制产物：业务逻辑/数据口径的歧义、缺口、冲突。逐条向业务方确认，结论落 `docs/2_landed/`（需留痕的写 `docs/decisions/`）。
> 格式约定：未决项写作 `- [ ] 问题描述`，附「建议」。确认后**移入本组「已关闭」索引表**，只留编号、主题、一句结论与落盘位置；完整口径以 `2_landed` 为准，讨论过程与推翻理由见 `docs/decisions/`。编号不复用，其他文档按编号引用。
> **存在未决项 `- [ ]`（且无 `docs/.g1-cleared` 放行标记）时，guard hook 会阻止编写 src/ 代码。**
> 素材路径：未决项可以写「请把答复/执行结果放到 `docs/1_user_input/<子目录>/`」；关闭时不留指向 `1_user_input` 具体文件的路径，来源用文字描述（如「业务方 2026-10-10 书面答复」）。

**答复方式**：同意建议回一句「Px/Dx… 同意」即可；不同意请写明正确口径。书面答复与执行结果请放到 `docs/1_user_input/answers/<答复日期>/`（只要配置、取值清单与计数，不要业务数据行）。

## 通用（G）

未决：

- [ ] **G22 按文字找单时，新建或修改的单多久后能找到**：关键词搜索与类似问题要先把三域叙述文字剥净图片和格式、再算出用于「按意思比对」的向量，这一步定时批量做，计划每 30 分钟一次。所以最近约半小时内新建的单可能按文字找不到，刚改过文字的单可能还按旧文字匹配。单上的状态、当前责任人、处理步骤等事实不受影响，每次都实时查。
  **建议**：
  - 接受约半小时的延迟。需要更快可缩到 10 分钟，代价是更频繁地读源库。
  - 不在每次回答里提这件事，只在统计口径「文字查找」一项加一句：「最近约半小时内新建或修改的单可能尚未纳入」。

- [ ] **G23 点名某个字段的「类似问题」怎么找**：现落盘（G15）规定，用户点名某个叙述字段时（「预防对策里提到换料的单」「处理步骤意见里写了返工的单」），只在该字段里找，关键词搜索与类似问题都如此。G2 设计把比对范围内的字段（问题描述、现象、原因分析、改善建议、改善措施、预防对策、处理步骤分析类环节，巴西另有 SQE 跟进结果，见 G29）按字段分段算向量，这几个字段可以只在该字段里按意思找；其余叙述字段（如效果确认、备注、原因分类说明、重启方案，以及不纳入的处理步骤环节）没有单独的向量。
  **建议**：
  - 没点名字段时，类似问题照常在比对范围里按意思找。
  - 点名的是比对范围内的字段：在该字段里按意思找，同时按词找，两者合并（同 G24）。处理步骤在比对范围里是整理后的一段；点名其中某一列（「处理步骤意见里写了返工」）时，按词在该列里找（同样只看每个环节最新一条），与下一条相同。
  - 点名的是其他字段：在该字段里按词找。用户说的做法先对到同义词表（见 G24）；表里没有时，助手提出几个近义说法（如「换料」→ 换料、更换物料、替换物料），回答里列出用了哪些说法，给出该字段里命中任一说法的全部单。结果是完整的，「只是提到」的同样标注、不删除，统计口径按「关键词搜索」写。
  - 理由：点名字段的问法多是「写了 / 提到」某个做法，按词找更准，也能给全。若某个其他字段确实需要按意思找，请举一两个典型问法，再评估把它加进分段范围。

- [ ] **G24 「有没有涉及 X」「X 相关问题」返回什么**：现落盘把「最近一年有没有涉及音频（喇叭、蜂鸣器）的问题」归为「类似问题」，只给最相近的 10 张、不保证完整。但这类问法（含巴西示例「请提供 26 年出现的非接相关问题」）用户期望的多半是完整清单。只按意思比对有两个弱点：行业简称（「非接」）模型未必认得出它指非接触、NFC；X 只是单里一句话时容易被漏掉。只按词找也有噪音：同义说法有歧义（「射频」也可能指 4G 模块），还有大量「只是提到」的写法（「NFC、打印测试均正常」「排除非接问题」）。
  **建议**：
  - **一张清单，三类单**：
    - 文字中明确提到 X 的单（按业务方维护的强词找，结果完整、计数确定），每行带一段上下文；
    - 其中「可能只是提到」的（如写着「测试正常」「排除」）照常计入、标注出来、排到后面，不删除；
    - 说法不同或说法有歧义、经助手判断与 X 相关的单，作为补充列出，注明不保证完整。
  - **表头写清几个数**：明确提到的 N 张、其中可能只是提到的 K 张、补充的 S 张；判断为不相关的、来不及逐张判断的单只计数，可以展开查看。
  - 「有没有出现过开机花屏，当时怎么处理的」这类描述具体现象、想找先例的问法，仍按「类似问题」给最相近的若干张。用户自己点名要搜某几个词（「描述里有『打印』和『USB』的单」）时，只按用户给的词找，不套同义词。
  - **请按概念整理一份同义说法清单**，放到 `docs/1_user_input/answers/<答复日期>/`。上线后由管理员在平台上维护，不必改版本。每个概念给：
    - 一句话说明（如「非接：非接触式读卡相关的问题」）；
    - 强词：一出现就算涉及，如 NFC、非接触；
    - 弱词：有歧义、出现后要再判断，如射频、RF、感应；
    - 排除词：出现了也不算，如纸张感应、RFID。

    再给一份表示「只是提到」的说法，如「正常」「OK」「无异常」「排除」「未发现」。以下只是示意，请改正、补全：「非接」强词 NFC、非接触、非接卡，弱词射频、RF、感应、刷卡；「音频」强词喇叭、蜂鸣器、扬声器、音频，弱词无声、杂音；「安全」（G41 已定，涉及安全的问题按这一概念找）强词起火、冒烟、爆炸、漏电、触电，弱词发热、烫、异味。三域文字经核实都是中文，只要中文说法与常见英文缩写。
