# 待澄清清单（open questions）

> G1 强制产物：业务逻辑/数据口径的歧义、缺口、冲突。逐条向业务方确认，
> 确认结论落 `docs/2_landed/` 或 `docs/decisions/` 后勾选划除。
> 格式约定：未决项写作 `- [ ] 问题描述`，确认后改为 `- [x] 问题描述 → 结论（日期）`。
> **存在未决项 `- [ ]`（且无 `docs/.g1-cleared` 放行标记）时，guard hook 会阻止编写 src/ 代码。**
> 素材路径：未决项可以写「请把答复/执行结果放到 `docs/1_user_input/<子目录>/`」；**关闭时不留指向
> `1_user_input` 具体文件的路径**——结论写进 `2_landed`，来源用文字描述（如「业务方 2026-10-10 书面答复」）。
> `1_user_input` 是临时投递区，梳理完成后素材随时可能被清理。
