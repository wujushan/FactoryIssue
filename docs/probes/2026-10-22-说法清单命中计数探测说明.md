# 2026-10-22 说法清单命中计数探测说明

G24 定了「涉及某个话题」按说法写在哪一栏分三组（决策 2026-10-22「涉及某个话题的找法与呈现」）。G45 的说法清单初稿要靠数据检查：每个说法各找到多少张单、落在哪一组；再到管理页面抽几张，看分组是否合理。

## 执行须知

- 在正式镜像库 `ai-info` 上执行，默认 schema 为 `public`，SQL 里只写表名；表名、列名保留源表大小写，删除标记一律 `::int` 后比较。
- 全部是只读 `SELECT`。
- **L1–L2 只输出计数**，以及本仓起草的话题与说法（不是业务数据），可以发回。
- **L3 输出问题编号**，只在内网对照管理页面用，不要发回，也不要放进 `docs/1_user_input/`。只回告页面上看到的结论，见 L3「结果怎么用」。
- 只看未删除的单（国内是否删除不为 1；巴西状态不为 -1；海外是否删除为 0）。
- 文字处理与比对时一致：
  - 剥净内嵌图片、HTML 标签与实体，连续空白压成一个空格；全角字母数字转半角，转小写。
  - 剥净后不超过 10 个字的内容不比对；问题现象除外。
  - 处理步骤只取分析类环节，每个环节只取最新一条：国内按环节编码 3、4、6、10、11、13、14、35；海外按环节名称。取意见、措施，工厂制程分析另取结论。巴西只取最新一条处理过程。
- 匹配：
  - 中文说法（含夹带英文的，如「IC卡」）忽略空格按包含匹配。
  - 纯英文缩写（如 NFC、4G）要求前后不是英文字母或数字。
  - 「不算的说法」先从文字里屏蔽掉，再找「算的说法」。
- 问题现象从 JSON 里取 `Value`、`parentType`、`otherVal` 三个键的文字，比展示时的展平规则略宽（标准现象的 `parentType` 也算进去），只影响少量计数。
- 巴西问题描述里有单值约 4,800 万字的内嵌图片，剥净会慢一些，属正常。
- 结果放到 `docs/1_user_input/probe_answers/`，按段号命名（如 `L1-L2.csv`），也可以直接贴在对话里。

## 总览

| 段 | 看什么 | 用于 |
|---|---|---|
| L1 | 每个说法在三域各找到多少张单：在第一组栏目里命中的、只在第二组栏目里命中的 | 太宽、太窄或没用的说法；不算的说法屏蔽了多少 |
| L2 | 每个话题三组各多少张 | 分组比例是否合理 |
| L3 | 国内非接、音频、打印三个话题，每组挑最近 5 张（只在内网用） | 到管理页面核对分组 |

两组栏目：

| 域 | 第一组（问题本身涉及） | 第二组（处理中提到） |
|---|---|---|
| 国内 | 问题描述、问题现象、原因分析 | 改善建议、改善措施、预防对策、处理步骤 |
| 巴西 | 问题现象、问题描述、最新一条处理过程的原因分析 | 最新一条处理过程的改善措施、预防对策、SQE 跟进结果 |
| 海外 | 已选问题现象、问题描述、问题原因 | 改善建议、改善措施、预防对策、处理步骤 |

## L1–L2 每个说法、每个话题的命中单数（镜像库，可发回）

一段查询同时输出两种行：
- 「L1 每个说法」：一个说法一行。
- 「L2 每个话题合计」：一个话题一行，说法列写「（合计）」。

各列含义：

| 列 | L1 行 | L2 行 |

| 只在第二组栏目命中单数 | 只在第二组栏目里出现的单数 | 第二组的单数：算的说法只在第二组栏目里命中 |
| 待判断单数 | — | 不在前两组、带 ＊ 的说法在第一组栏目里命中的单数（这些交给助手判断） |

```sql
        bool_or("类别" = '算＊' AND g1) AS s1,
        bool_or("类别" = '算＊' AND g2) AS s2

SELECT 'L1 每个说法' AS "段", t."话题", t."说法", t."类别", t."域",
    count(*) FILTER (WHERE t.g1)              AS "第一组栏目命中单数",
    count(*) FILTER (WHERE t.g2 AND NOT t.g1) AS "只在第二组栏目命中单数",
    NULL::bigint                              AS "待判断单数",
    NULL::bigint                              AS "只有带＊说法在第二组栏目命中的单数",
    max(tot.n)                                AS "本域未删除单数"
FROM per_term t
JOIN tot ON tot."域" = t."域"
GROUP BY t."话题", t."说法", t."类别", t."域"
UNION ALL
SELECT 'L2 每个话题合计', p."话题", '（合计）', '—', p."域",
    count(*) FILTER (WHERE p.a1),
    count(*) FILTER (WHERE p.a2 AND NOT p.a1),
    count(*) FILTER (WHERE NOT p.a1 AND NOT p.a2 AND p.s1),
    count(*) FILTER (WHERE NOT p.a1 AND NOT p.a2 AND NOT p.s1 AND p.s2),
    max(tot.n)
FROM per_topic p
JOIN tot ON tot."域" = p."域"
GROUP BY p."话题", p."域"
ORDER BY 2, 1, 4, 3, 5;
```

**核对**：「本域未删除单数」应为国内 2,474、巴西 203、海外 12（与落盘一致）。某个说法在三域都没有命中时不出现在结果里。

**结果怎么用**（本仓据此改初稿，再交业务方过目）：
- 算的说法命中单数很多（如超过本域一成）且大多只在第二组栏目里：可能太宽，改加 ＊ 或换成更具体的说法。
- 带 ＊ 的说法在第一组栏目里命中很多：交给助手判断的单会很多，考虑拆成更具体的说法。
- 说法一张都没命中：保留与否由业务方定（以后的单可能会用到）。
- 不算的说法出现很多：确认它确实不该算。
- L2 第一组与第二组的比例：第二组远多于第一组的话题，到 L3 重点看第二组。

## L3 国内三个话题每组挑最近 5 张（镜像库，只在内网用）

> **本段输出问题编号，结果只在内网对照管理页面用，不要发回，也不要放进 `docs/1_user_input/`。** 只需按下方「结果怎么用」回告页面上的结论。

前面的 `WITH` 部分（从 `w` 到 `per_topic`）与 L1–L2 完全相同。做法：把 L1–L2 查询从第一行 `WITH w(...)` 起，复制到 `per_topic AS (...)` 的右括号为止，在右括号后面加一个逗号，再接上下面这段（`tot` 与最后的 `SELECT` 不要）：

```sql
-- （此处粘贴 L1–L2 查询从 WITH w(...) 到 per_topic AS (...) 的全部内容，per_topic 之后加一个逗号）
pick AS (
    SELECT p."话题", p.pid,
        CASE WHEN p.a1 THEN '1 问题本身涉及'
             WHEN p.a2 THEN '2 处理中提到'
             ELSE '3 待判断' END AS "组别"
    FROM per_topic p
    WHERE p."域" = '国内'
      AND p."话题" IN ('非接', '音频', '打印')
      AND (p.a1 OR p.a2 OR p.s1)
),
ranked AS (
    SELECT k."话题", k."组别", m."Numbers"::text AS "问题编号", m."AddDate"::date AS "建单日期",
        (SELECT string_agg(DISTINCT t."说法", '、')
         FROM per_term t
         WHERE t."域" = '国内' AND t."话题" = k."话题" AND t.pid = k.pid AND t."类别" <> '不算') AS "命中的说法",
        row_number() OVER (PARTITION BY k."话题", k."组别" ORDER BY m."AddDate" DESC) AS rk
    FROM pick k
    JOIN "ZCTracking_ProblemList" m ON m."ID"::text = k.pid
)
SELECT "话题", "组别", "问题编号", "建单日期", "命中的说法"
FROM ranked
WHERE rk <= 5
ORDER BY 1, 2, 4 DESC;
```

**结果怎么用**：在管理页面逐张打开，看这张单的问题是不是这个话题（例如非接：问题出在非接读卡上，而不是只在检验时顺带测了一下非接）。按「话题 × 组别」回告「5 张里有几张是」，不必附单号。例：非接第一组 5/5、第二组 1/5、待判断 2/5。

- 第一组大多「是」、第二组大多「不是」：分组按设计工作。
- 第二组也有不少「是」：说明原因或现象常写在处理步骤里，本仓再看是否把某些环节（如 SQE跟进）的意见归入第一组。
- 第一组有不少「不是」：看命中的说法，多半是某个说法太宽，回到 L1 调整。
