## M1 物料问题的责任部门（D31）

管理页面详情对物料问题不显示「责任部门」，原因分类照常显示。本段看物料问题里有多少张填了责任部门。

```sql
SELECT m."ProblemType"::int                                                         AS "问题类型码",
       count(*)                                                                     AS "单数",
       count(*) FILTER (WHERE btrim(COALESCE(m."AllReDepartment"::text, '')) <> '') AS "责任归属部门有值",
       count(*) FILTER (WHERE btrim(COALESCE(m."AllReDepartment"::text, '')) <> ''
                          AND m."Status"::int = 32)                                 AS "其中已完成",
       count(*) FILTER (WHERE btrim(COALESCE(m."ReasonClass"::text, '')) <> '')     AS "原因分类有值"
FROM "ZCTracking_ProblemList" m
WHERE COALESCE(m."IsDelete"::int, 0) <> 1
GROUP BY 1
ORDER BY 1;
```

**结果怎么用**：
- 问题类型 3（物料问题）的「责任归属部门有值」为 0 时，D31 只是兜底，照建议落盘。
- 不为 0 时，这就是按页面改了之后按责任部门查单、统计会少掉的单数，写进 D31 供业务方决定。

## M2 其他在线订单在哪些单上（D32）

管理页面详情只在物料问题的两块里显示其他在线订单：
- 「IQC意见」：有环节编码 14、状态码不是 11，且 IQC 意见为继续使用（3）；
- 「IQC确认」：有环节编码 7 或 8，且状态码 ≥ 6。

单上有风险订单时，这个位置改显示风险订单表。风险订单表不在本模块的表里，本段不扣除这部分，结果略偏大。

```sql
WITH m AS (
    SELECT m."ID",
           m."ProblemType"::int AS pt,
           m."Status"::int      AS st,
           m."IQCOpinion"::int  AS iqc_op
    FROM "ZCTracking_ProblemList" m
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1
),
o AS (
    SELECT o."ProblemId", count(*) AS n
    FROM "ZCTracking_OtherOrder" o
    GROUP BY 1
),
s AS (
    SELECT st."ProblemId",
           bool_or(st."Step"::int = 14)      AS has14,
           bool_or(st."Step"::int IN (7, 8)) AS has78
    FROM "ZCTracking_ProblemSteplog" st
    GROUP BY 1
)
SELECT m.pt                                               AS "问题类型码",
       count(*)                                           AS "有其他在线订单的单数",
       sum(o.n)                                           AS "其他在线订单行数",
       count(*) FILTER (
           WHERE m.pt = 3
             AND (   (COALESCE(s.has14, false) AND m.st <> 11 AND m.iqc_op = 3)
                  OR (COALESCE(s.has78, false) AND m.st >= 6)))  AS "按页面条件能看到的单数"
FROM m
JOIN o ON o."ProblemId" = m."ID"
LEFT JOIN s ON s."ProblemId" = m."ID"
GROUP BY 1
ORDER BY 1;
```

**结果怎么用**：
- 非物料问题的「有其他在线订单的单数」，就是按页面改了之后不再展示其他在线订单的单数。
- 物料问题里「按页面条件能看到的单数」与「有其他在线订单的单数」的差，是物料问题里同样看不到的单数。
- 两个数一起写进 D32，供业务方在三个选项里定。

## M3 国内影响数量的来历（D35）

落盘写影响数量 =「受影响的关联生产订单的订单数量之和」。页面代码里，建单时影响数量取填单页面提交的值，之后追加生产订单时累加的是新订单的在线数量。本段看现有的单按哪种算法对得上。

```sql
WITH m AS (
    SELECT m."ID", m."ImpactQty"::int AS impact, m."AddDate"
    FROM "ZCTracking_ProblemList" m
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1
      AND btrim(COALESCE(m."MHead"::text, '')) = ''
),
o AS (
    SELECT o."ProblemId",
           sum(COALESCE(o."OrderQty"::int, 0))  AS order_sum,
           sum(COALESCE(o."OnlineQty"::int, 0)) AS online_sum
    FROM "ZCTracking_ProblemOrders" o
    GROUP BY 1
)
SELECT CASE
           WHEN m.impact IS NULL                                  THEN '1 影响数量为空'
           WHEN o."ProblemId" IS NULL                             THEN '2 没有生产订单'
           WHEN m.impact = o.order_sum AND m.impact = o.online_sum THEN '3 两种和都相等'
           WHEN m.impact = o.order_sum                            THEN '4 只等于订单数量之和'
           WHEN m.impact = o.online_sum                           THEN '5 只等于在线数量之和'
           WHEN m.impact < LEAST(o.order_sum, o.online_sum)       THEN '6 都不相等，比两种和都小'
           ELSE                                                        '7 都不相等，其他'
       END                                AS "类别",
       count(*)                           AS "整机单数",
       min(m."AddDate")::date             AS "最早建单",
       max(m."AddDate")::date             AS "最晚建单"
FROM m
LEFT JOIN o ON o."ProblemId" = m."ID"
GROUP BY 1
ORDER BY 1;
```

**结果怎么用**：
- 4 类占绝大多数时，落盘的定义成立，D35 关闭不改。
- 5 类占绝大多数时，定义改为「受影响的关联生产订单的在线数量之和」。
- 6、7 类多时，影响数量是填单人手填的，定义改为「填单时填写的受影响数量，之后追加订单时累加新订单的在线数量」，不再说它等于哪一种和；「最早 / 最晚建单」用来看是不是只在某段时期才这样。

## M4 海外大机型能否对上产品主数据（O17）

巴西已核实大机型全部能对上（B13）；海外没有核过。

```sql
WITH m AS (
    SELECT "Id", COALESCE("ProductType"::text, '') AS pt
    FROM "OverseasProblemDetail"
    WHERE COALESCE("IsDelete"::int, 0) = 0
),
seg AS (
    SELECT m."Id",
           btrim(x.v) AS v,
           EXISTS (SELECT 1 FROM "ProductName" p WHERE p."ID"::text = btrim(x.v)) AS ok
    FROM m
    CROSS JOIN LATERAL regexp_split_to_table(m.pt, '[,，]') AS x(v)
    WHERE btrim(x.v) <> ''
),
per AS (
    SELECT "Id", count(*) AS n, count(*) FILTER (WHERE ok) AS n_ok
    FROM seg
    GROUP BY 1
)
SELECT '未删除单数' AS "项", count(*) AS "数" FROM m
UNION ALL SELECT '大机型为空的单',       count(*) FROM m WHERE btrim(m.pt) = ''
UNION ALL SELECT '非空段数',             count(*) FROM seg
UNION ALL SELECT '对不上产品主数据的段', count(*) FROM seg WHERE NOT ok
UNION ALL SELECT '有段对不上的单',       count(*) FROM per WHERE n_ok < n
UNION ALL SELECT '全部段都对不上的单',   count(*) FROM per WHERE n_ok = 0;
```

**结果怎么用**：「有段对不上的单」为 0 时，O17 的规则只是兜底，照建议落盘。不为 0 时，把张数写进 O17。

## M5 文档示例里的问题编号是否存在（示例问题）

总述与各域业务描述的示例问题用了 5 个问题编号。这些示例以后会写进助手的场景说明与引导按钮，编号在正式数据里不存在的话，用户照着问会查空。海外最近一张单建于 2026-02，HW2609001 预计不存在。

```sql
WITH s(no) AS (
    VALUES ('ZC2109001'), ('ZC2509012'), ('BR2404001'), ('BR2601009'), ('HW2609001')
)
SELECT s.no AS "示例问题编号",
       CASE
           WHEN EXISTS (SELECT 1 FROM "ZCTracking_ProblemList" m
                        WHERE upper(btrim(m."Numbers"::text)) = s.no AND COALESCE(m."IsDelete"::int, 0) <> 1)
             OR EXISTS (SELECT 1 FROM "BrazilProblemList" b
                        WHERE upper(btrim(b."OrderNumber"::text)) = s.no AND b."Status"::int <> -1)
             OR EXISTS (SELECT 1 FROM "OverseasProblemDetail" d
                        WHERE upper(btrim(d."Numbers"::text)) = s.no AND COALESCE(d."IsDelete"::int, 0) = 0)
               THEN '有，未删除'
           WHEN EXISTS (SELECT 1 FROM "ZCTracking_ProblemList" m WHERE upper(btrim(m."Numbers"::text)) = s.no)
             OR EXISTS (SELECT 1 FROM "BrazilProblemList" b WHERE upper(btrim(b."OrderNumber"::text)) = s.no)
             OR EXISTS (SELECT 1 FROM "OverseasProblemDetail" d WHERE upper(btrim(d."Numbers"::text)) = s.no)
               THEN '有，已删除'
           ELSE '没有'
       END AS "正式数据里"
FROM s
ORDER BY 1;
```

**结果怎么用**：
- 示例里的编号只示意格式，不换成真实单号（`2_landed` 不复制业务数据）。
- 不存在或已删除的编号，在示例旁注明「编号仅示意」；G4b 写场景说明与引导按钮时，按单号查的场景用不带具体编号的说法（如「某张单现在到哪一步了」），G3 的测试用例另从正式数据取单号。

## M6 产品在制属性的显示文字（D34）

管理页面详情的文字取自后端一张字典，交付的代码里没有这张字典；前端留着一份已注释掉的旧写法，8、9、197 与落盘不同，另有一个落盘没有的 194。本段先数各取值的单数，再给 8、9、194、197 各挑一张最近的单，到页面上看显示文字。

**M6a**（只出计数，可以发回）：

```sql
SELECT COALESCE(m."OutPutStatus"::text, '空')                                    AS "产品在制属性码",
       count(*)                                                                 AS "单数",
       count(*) FILTER (WHERE btrim(COALESCE(m."MHead"::text, '')) <> '')        AS "其中物料单"
FROM "ZCTracking_ProblemList" m
WHERE COALESCE(m."IsDelete"::int, 0) <> 1
GROUP BY 1
ORDER BY 1;
```

**M6b**（输出问题编号，只在内网用，不要发回）：

```sql
SELECT DISTINCT ON (m."OutPutStatus"::int)
       m."OutPutStatus"::int AS "产品在制属性码",
       m."Numbers"::text     AS "问题编号"
FROM "ZCTracking_ProblemList" m
WHERE COALESCE(m."IsDelete"::int, 0) <> 1
  AND m."OutPutStatus"::int IN (8, 9, 194, 197)
ORDER BY m."OutPutStatus"::int, m."AddDate" DESC;
```

**结果怎么用**：
- 在管理页面打开 M6b 的每张单，回告「产品在制属性」一栏显示的文字，按「码 → 文字」回告即可，不必附单号。
- M6a 里出现落盘没有的取值（如 194）时，同样回告它的显示文字。
- 本仓照页面改主表字段说明与术语表「产品在制属性」。
