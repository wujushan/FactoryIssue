# 制程问题查询助手 G2 数据画像探测说明（2026-10-20）

> 给谁：能连到正式环境镜像库（PostgreSQL，库名 `ai-info`）的业务方；F6、F7 两段另需 INFO SQL Server 开发库或 DBA。
> 做什么：G2 要确认叙述文字的形态（富文本、内嵌图片、语言）与数量，以及两张大表的索引。本说明给出只读查询，结果用于 `docs/decisions/2026-10-20-G2数据源与治理决策.md` 里「待定项与判定规则」一节。

## 执行环境

业务方已把正式环境的各表镜像同步到 PostgreSQL 库 `ai-info`（表在 `public` 下，如 `ai-info.public.ZCTracking_ProblemList`）。镜像里是正式数据、没有测试数据，所以叙述文字的形态与数量改在镜像库上查。索引、执行方式和数据库版本是 SQL Server 自身的属性，镜像库代表不了，这几项仍在 SQL Server 上查。

| 段 | 在哪执行 | 能说明什么 | 说明不了什么 |
|---|---|---|---|
| P0 | 镜像库 | 镜像是否完整、列名大小写与类型、镜像的数据时点 | — |
| F1、F2、F3、F5 | 镜像库 | 正式数据的富文本、内嵌图片、空比对文字、语言，以及确切的行数与字符数 | 镜像同步时点之后的变化 |
| F4 | —— | 已删除：同步方式不依赖修改时间与修改频率，见决策「同步策略」 | —— |
| F6 | SQL Server 开发库 | 两张大表的索引；两种参数写法的耗时差距（反映能否走索引，不随数据量变） | 正式库上的绝对耗时 |
| F7 | SQL Server 开发库；正式库由 DBA 告知 | SQL Server 版本与兼容级别 | — |

F1 已在开发库上跑过一次（结果见「执行记录」）。镜像库上再跑一次 F1，以镜像库的结果为准；两次的「总字节数」不能直接比较，见 F1 说明。

## 执行须知

- 全部是只读 `SELECT`，只输出计数、字符数与表结构元数据，不输出业务数据行。F6a 输出两张表的索引名与列名，外传前请人工过目；其余各段只有计数。
- **镜像库**：连到 `ai-info` 库执行，默认 schema 为 `public`。PostgreSQL 不支持跨库的三段名，所以 SQL 里只写表名。需要 PostgreSQL 12 及以上，库编码为 UTF8（P0c 会显示）。
- **列名大小写**：下面的 SQL 假定镜像保留了源表的大小写（表名、列名带双引号，如 `"ZCTracking_ProblemList"."ProblemDesc"`）。先跑 P0a：如果显示的表名、列名全是小写，**先别跑后面各段**，把 P0 结果发回，业务仓改好再发一版。
- **SQL Server 段（F6、F7）**：写法同之前，需要 SQL Server 2016 及以上（用到 `STRING_SPLIT`）；查询里没有 `SET` 语句。待办任务表约 420 万行、文档清单约 193 万行，建议低峰执行。
- **交付**：每段结果另存为 CSV，按小节编号命名（如 `P0a.csv`、`F1.csv`），放到 `docs/1_user_input/answers/<执行日期>/`。F6b 另需记录耗时，见该节。某段报错时，把报错信息原样存成同名文本，其余照常执行。
- **请在交付目录的 `README.txt` 里写明镜像的情况**（一两句即可）：用什么方式同步、最近一次同步的时间、是全量复制还是增量同步、源端删除的行会不会在镜像里删掉。

## P0 镜像库自检（镜像库）

**P0a 表与列**：列出本说明用到的 7 张表的全部列名与类型。按小写比较表名，所以镜像改了大小写也能查到，输出里显示的是镜像里的真实写法。

```sql
SELECT table_name AS "表", ordinal_position AS "序号", column_name AS "列", data_type AS "类型"
FROM information_schema.columns
WHERE table_schema = 'public'
  AND lower(table_name) IN (
      'zctracking_problemlist', 'zctracking_problemsteplog',
      'brazilproblemlist', 'brazilproblemprocess', 'brazilproblemcost',
      'overseasproblemdetail', 'overseasproblem_steplog')
ORDER BY lower(table_name), ordinal_position;
```

7 张表都应出现。缺哪张、或表名列名是全小写，先停下，把结果发回。

**P0b 行数与删除标记**：与已落盘的行数对照（落盘数取自开发库，可能略有出入），看镜像是否完整。

```sql
SELECT '国内主表' AS "表", count(*) AS "行数",

FROM "ZCTracking_ProblemList"
UNION ALL
SELECT '国内处理步骤', count(*), NULL, max("AddDate") FROM "ZCTracking_ProblemSteplog"
UNION ALL
SELECT '巴西主表', count(*), count(*) FILTER (WHERE "Status"::int = -1), max("AddDate")
FROM "BrazilProblemList"
UNION ALL
SELECT '巴西处理过程', count(*), NULL, NULL FROM "BrazilProblemProcess"
UNION ALL
SELECT '巴西费用明细', count(*), NULL, NULL FROM "BrazilProblemCost"
UNION ALL
SELECT '海外主表', count(*), count(*) FILTER (WHERE COALESCE("IsDelete"::int, 0) <> 0), max("AddDate")
FROM "OverseasProblemDetail"
UNION ALL
SELECT '海外处理步骤', count(*), NULL, max("AddDate") FROM "OverseasProblem_StepLog";
```

落盘行数（开发库，2026-10-16 统计）供对照：国内主表 2,758（已删除 311）、国内处理步骤 14,834、巴西主表 199（已删除 8）、巴西处理过程 193、巴西费用明细 998、海外主表 17（已删除 4）、海外处理步骤 87。「最近建单时间」大致就是镜像的数据时点。

## F1 叙述列的体量与富文本特征（镜像库）

三个域全部叙述列，含已删除的单（同步时会一起读）。「未删除有值行数」只算未删除的单。

- 「总字节数」是 PostgreSQL 的 UTF-8 字节数（中文 3 字节），开发库那次是 SQL Server 的 UTF-16 字节数（中文 2 字节），两次不能直接比较；字符数可以比较。
- 是否删除写成 `::int` 再比较，镜像把删除标记存成整数、布尔都能用。

```sql
WITH v AS (
    SELECT '国内' AS "域", c."列", COALESCE(m."IsDelete"::int, 0) = 1 AS del, c.x
    FROM "ZCTracking_ProblemList" m
    CROSS JOIN LATERAL (VALUES
        ('主表.问题描述',     m."ProblemDesc"::text),
        ('主表.原因分析',     m."Reason"::text),
        ('主表.改善建议',     m."Improve"::text),
        ('主表.改善措施',     m."Measures"::text),
        ('主表.预防对策',     m."Prevention"::text),
        ('主表.效果确认',     m."Confirmation"::text),
        ('主表.生产确认备注', m."ProduceConfirmRemark"::text),
        ('主表.备注',         m."Remark"::text),
        ('主表.原因分类说明', m."ReasonClassRemark"::text),
        ('主表.重启方案',     m."ReStartScheme"::text)
    ) AS c("列", x)
    UNION ALL
    SELECT '国内', c."列", COALESCE(m."IsDelete"::int, 0) = 1, c.x
    FROM "ZCTracking_ProblemSteplog" s
    JOIN "ZCTracking_ProblemList" m ON m."ID" = s."ProblemId"
    CROSS JOIN LATERAL (VALUES
        ('处理步骤.结论', s."Result"::text),
        ('处理步骤.意见', s."Opinon"::text),
        ('处理步骤.措施', s."Measures"::text)
    ) AS c("列", x)
    UNION ALL
    SELECT '巴西', c."列", b."Status"::int = -1, c.x
    FROM "BrazilProblemList" b
    CROSS JOIN LATERAL (VALUES
        ('主表.问题现象', b."ProblemPhenomenon"::text),
        ('主表.问题描述', b."ProblemDesc"::text),
        ('主表.补料备注', b."SupplementMemo"::text),
        ('主表.备注',     b."Memo"::text)
    ) AS c("列", x)
    UNION ALL
    SELECT '巴西', c."列", b."Status"::int = -1, c.x
    FROM "BrazilProblemProcess" p
    JOIN "BrazilProblemList" b ON b."ID" = p."ProblemID"
    CROSS JOIN LATERAL (VALUES
        ('处理过程.SQE跟进结果',    p."DisposeResult"::text),
        ('处理过程.原因分析',       p."ReasonAnalysis"::text),
        ('处理过程.改善措施',       p."ImprovementMeasure"::text),
        ('处理过程.改善批次',       p."ImprovementBatch"::text),
        ('处理过程.预防对策',       p."PrecautionPolicy"::text),
        ('处理过程.退货确认备注',   p."StockPrecessMemo"::text),
        ('处理过程.未转嫁原因',     p."UnCostShiftReason"::text),
        ('处理过程.设计更改备注',   p."DesignMemo"::text),
        ('处理过程.SQE确认备注',    p."SQEMemo"::text),
        ('处理过程.责任人确认备注', p."ProcessMemo"::text),
        ('处理过程.效果确认备注',   p."ConfirmMemo"::text),
        ('处理过程.结案备注',       p."FinishMemo"::text)
    ) AS c("列", x)
    UNION ALL
    SELECT '巴西', '费用.费用备注', b."Status"::int = -1, f."CostMemo"::text
    FROM "BrazilProblemCost" f
    JOIN "BrazilProblemList" b ON b."ID" = f."ProblemID"
    UNION ALL
    SELECT '海外', c."列", COALESCE(o."IsDelete"::int, 0) <> 0, c.x
    FROM "OverseasProblemDetail" o
    CROSS JOIN LATERAL (VALUES
        ('主表.已选问题现象', o."hasCheckedPhenomenon"::text),
        ('主表.问题描述',     o."ProblemDesc"::text),
        ('主表.改善建议',     o."Improve"::text),
        ('主表.问题原因',     o."Reason"::text),
        ('主表.改善措施',     o."Measures"::text),
        ('主表.预防对策',     o."Prevention"::text),
        ('主表.备注',         o."Remark"::text),
        ('主表.效果确认',     o."Confirmation"::text),
        ('主表.其他问题说明', o."ProblemRemark"::text)
    ) AS c("列", x)
    UNION ALL
    SELECT '海外', c."列", COALESCE(o."IsDelete"::int, 0) <> 0, c.x
    FROM "OverseasProblem_StepLog" s
    JOIN "OverseasProblemDetail" o ON o."Id" = s."ProblemId"
    CROSS JOIN LATERAL (VALUES
        ('处理步骤.结论',     s."Result"::text),
        ('处理步骤.意见',     s."Opinon"::text),
        ('处理步骤.预防措施', s."Measures"::text)
    ) AS c("列", x)
), f AS (
    SELECT "域", "列", del,
        CASE WHEN NULLIF(btrim(x), '') IS NULL THEN 0 ELSE 1 END AS has_val,
        CASE WHEN x ~* '<[a-z/!]' THEN 1 ELSE 0 END AS has_tag,
        CASE WHEN x ILIKE '%<img%' THEN 1 ELSE 0 END AS has_img,
        CASE WHEN x ILIKE '%data:image%base64,%' THEN 1 ELSE 0 END AS has_b64,
        CASE WHEN x ILIKE ANY (ARRAY['%&nbsp;%', '%&amp;%', '%&lt;%', '%&gt;%', '%&quot;%', '%&#%'])
             THEN 1 ELSE 0 END AS has_ent,
        COALESCE(char_length(x), 0)::bigint AS n_chars,
        COALESCE(octet_length(x), 0)::bigint AS n_bytes
    FROM v
)
SELECT "域", "列",
    count(*)                                                        AS "总行数",
    sum(has_val)                                                    AS "有值行数",
    sum(CASE WHEN NOT del THEN has_val ELSE 0 END)                  AS "未删除有值行数",
    sum(has_tag)                                                    AS "含HTML标签行数",
    sum(has_img)                                                    AS "含图片标签行数",
    sum(has_b64)                                                    AS "含内嵌图片行数",
    sum(has_ent)                                                    AS "含HTML实体行数",
    sum(n_chars)                                                    AS "总字符数",
    sum(n_bytes)                                                    AS "总字节数_UTF8",
    sum(CASE WHEN has_b64 = 1 THEN n_chars ELSE 0 END)              AS "含内嵌图片行的字符数",
    max(n_chars)                                                    AS "最长字符数",
    sum(CASE WHEN has_val = 1 AND n_chars <= 200 THEN 1 ELSE 0 END)                  AS "1至200字",
    sum(CASE WHEN has_val = 1 AND n_chars BETWEEN 201 AND 1000 THEN 1 ELSE 0 END)    AS "201至1000字",
    sum(CASE WHEN has_val = 1 AND n_chars BETWEEN 1001 AND 4000 THEN 1 ELSE 0 END)   AS "1001至4000字",
    sum(CASE WHEN has_val = 1 AND n_chars BETWEEN 4001 AND 32000 THEN 1 ELSE 0 END)  AS "4001至32000字",
    sum(CASE WHEN has_val = 1 AND n_chars > 32000 THEN 1 ELSE 0 END)                 AS "32000字以上"
FROM f
GROUP BY "域", "列"
ORDER BY "域", "列";
```

## F3 比对文字全为空的单（镜像库）

只看未删除的单。比对范围按总述「关键词搜索与类似问题 · 比对范围」：国内为问题描述、原因分析、改善措施；巴西为问题现象、问题描述、最新一条处理过程的原因分析与改善措施；海外为已选问题现象、问题描述、问题原因。问题现象为空串、空数组或不是数组时算空。

```sql
WITH d AS (
    SELECT '国内' AS "域",
        CASE WHEN NULLIF(btrim(m."ProblemDesc"::text), '') IS NULL
              AND NULLIF(btrim(m."Reason"::text), '') IS NULL
              AND NULLIF(btrim(m."Measures"::text), '') IS NULL
             THEN 1 ELSE 0 END AS all_empty,
        CASE WHEN m."ProblemDesc"::text ILIKE '%data:image%base64,%'
               OR m."Reason"::text ILIKE '%data:image%base64,%'
               OR m."Measures"::text ILIKE '%data:image%base64,%'
             THEN 1 ELSE 0 END AS any_b64
    FROM "ZCTracking_ProblemList" m
    WHERE COALESCE(m."IsDelete"::int, 0) = 0
    UNION ALL
    SELECT '巴西',
        CASE WHEN (ph.p0 IS NULL OR left(ph.p0, 1) <> '['
                   OR regexp_replace(ph.p0, '\s', '', 'g') = '[]')
              AND NULLIF(btrim(b."ProblemDesc"::text), '') IS NULL
              AND NULLIF(btrim(lp."ReasonAnalysis"::text), '') IS NULL
              AND NULLIF(btrim(lp."ImprovementMeasure"::text), '') IS NULL
             THEN 1 ELSE 0 END,
        CASE WHEN b."ProblemDesc"::text ILIKE '%data:image%base64,%'
               OR lp."ReasonAnalysis"::text ILIKE '%data:image%base64,%'
               OR lp."ImprovementMeasure"::text ILIKE '%data:image%base64,%'
             THEN 1 ELSE 0 END
    FROM "BrazilProblemList" b
    CROSS JOIN LATERAL (SELECT NULLIF(btrim(b."ProblemPhenomenon"::text), '') AS p0) ph
    LEFT JOIN LATERAL (SELECT p."ReasonAnalysis", p."ImprovementMeasure"
                       FROM "BrazilProblemProcess" p
                       WHERE p."ProblemID" = b."ID"
                       ORDER BY p."ID" DESC
                       LIMIT 1) lp ON true
    WHERE b."Status"::int <> -1
    UNION ALL
    SELECT '海外',
        CASE WHEN (ph.p0 IS NULL OR left(ph.p0, 1) <> '['
                   OR regexp_replace(ph.p0, '\s', '', 'g') = '[]')
              AND NULLIF(btrim(o."ProblemDesc"::text), '') IS NULL
              AND NULLIF(btrim(o."Reason"::text), '') IS NULL
             THEN 1 ELSE 0 END,
        CASE WHEN o."ProblemDesc"::text ILIKE '%data:image%base64,%'
               OR o."Reason"::text ILIKE '%data:image%base64,%'
             THEN 1 ELSE 0 END
    FROM "OverseasProblemDetail" o
    CROSS JOIN LATERAL (SELECT NULLIF(btrim(o."hasCheckedPhenomenon"::text), '') AS p0) ph
    WHERE COALESCE(o."IsDelete"::int, 0) = 0
)
SELECT "域",
    count(*)       AS "未删除单数",
    sum(all_empty) AS "比对文字全为空的单数",
    sum(any_b64)   AS "比对文字含内嵌图片的单数"
FROM d
GROUP BY "域"
ORDER BY "域";
```

## F5 比对文字的语言（镜像库）

只看未删除单的比对文字（巴西处理过程取全部记录）。「含中文」按 CJK 统一汉字（U+4E00–U+9FFF）判断；「含葡语字母」按 ã õ ç á é í ó ú â ê ô à 及其大写、以及对应的 HTML 实体判断。「有值但不含中文」里也包括只有图片或标签的值。库编码须为 UTF8（P0c）。

```sql
WITH v AS (
    SELECT '国内' AS "域", c."列", c.x
    FROM "ZCTracking_ProblemList" m
    CROSS JOIN LATERAL (VALUES
        ('主表.问题描述', m."ProblemDesc"::text),
        ('主表.原因分析', m."Reason"::text),
        ('主表.改善措施', m."Measures"::text)
    ) AS c("列", x)
    WHERE COALESCE(m."IsDelete"::int, 0) = 0
    UNION ALL
    SELECT '巴西', c."列", c.x
    FROM "BrazilProblemList" b
    CROSS JOIN LATERAL (VALUES
        ('主表.问题现象', b."ProblemPhenomenon"::text),
        ('主表.问题描述', b."ProblemDesc"::text)
    ) AS c("列", x)
    WHERE b."Status"::int <> -1
    UNION ALL
    SELECT '巴西', c."列", c.x
    FROM "BrazilProblemProcess" p
    JOIN "BrazilProblemList" b ON b."ID" = p."ProblemID" AND b."Status"::int <> -1
    CROSS JOIN LATERAL (VALUES
        ('处理过程.原因分析', p."ReasonAnalysis"::text),
        ('处理过程.改善措施', p."ImprovementMeasure"::text)
    ) AS c("列", x)
    UNION ALL
    SELECT '海外', c."列", c.x
    FROM "OverseasProblemDetail" o
    CROSS JOIN LATERAL (VALUES
        ('主表.已选问题现象', o."hasCheckedPhenomenon"::text),
        ('主表.问题描述',     o."ProblemDesc"::text),
        ('主表.问题原因',     o."Reason"::text)
    ) AS c("列", x)
    WHERE COALESCE(o."IsDelete"::int, 0) = 0
), f AS (
    SELECT "域", "列",
        CASE WHEN NULLIF(btrim(x), '') IS NULL THEN 0 ELSE 1 END AS has_val,
        CASE WHEN x ~ '[\u4e00-\u9fff]' THEN 1 ELSE 0 END AS has_cjk,
        CASE WHEN x ~ '[ãõçáéíóúâêôàÃÕÇÁÉÍÓÚÂÊÔÀ]'
                  OR x ILIKE ANY (ARRAY['%&ccedil;%', '%&atilde;%', '%&otilde;%'])
             THEN 1 ELSE 0 END AS has_pt
    FROM v
)
SELECT "域", "列",
    sum(has_val)                                                 AS "有值行数",
    sum(has_cjk)                                                 AS "含中文行数",
    sum(has_pt)                                                  AS "含葡语字母行数",
    sum(CASE WHEN has_val = 1 AND has_cjk = 0 THEN 1 ELSE 0 END) AS "有值但不含中文行数"
FROM f
GROUP BY "域", "列"
ORDER BY "域", "列";
```

## F6 两张大表能否直连（SQL Server 开发库）

**本段在 SQL Server 开发库上执行，不在镜像库上执行**：要看的是 SQL Server 上的索引与执行方式，镜像库的索引和执行方式与它无关。

本助手只按问题单去这两张表里取很少几行：待办任务表按「业务记录 ID + 业务表名以 ZCTracking 开头 + 已接受」取国内并行阶段的任务；文档清单按文档 ID 取附件、按「业务名称 + 业务记录 ID」取巴西 8D。要确认这几种取法有索引可用。开发库上的绝对耗时不代表正式环境，这里只看有没有索引、两种写法差多少。

**F6a 两张表的索引**（输出索引名与列名，外传前请过目）

```sql
SELECT t.name AS [表], i.name AS [索引名], i.type_desc AS [类型],
       i.is_primary_key AS [主键], i.is_unique AS [唯一],
       ic.key_ordinal AS [键序], ic.is_included_column AS [包含列], c.name AS [列]
FROM info.sys.tables t
JOIN info.sys.schemas sc       ON sc.schema_id = t.schema_id AND sc.name = N'dbo'
JOIN info.sys.indexes i        ON i.object_id = t.object_id
JOIN info.sys.index_columns ic ON ic.object_id = i.object_id AND ic.index_id = i.index_id
JOIN info.sys.columns c        ON c.object_id = ic.object_id AND c.column_id = ic.column_id
WHERE t.name IN (N'tbTask', N'DocumentList')
ORDER BY t.name, i.name, ic.is_included_column, ic.key_ordinal;
```

**F6b 典型取法的耗时**

逐条执行，每条记下返回的计数和执行耗时（查询窗口状态栏显示的时间），整理成 `F6b.txt`，每行一条：「编号 计数 耗时」。①② 的条件相同，只差业务记录 ID 是否带 `N` 前缀——平台取数时传入的文字参数可能按带 `N` 的写法发送。两者都是一张单的查询，差距只取决于能否走索引，不取决于库里有多少数据，所以开发库上测得出来；② 比 ① 慢一个数量级以上，说明需要另想办法。③④⑤ 的耗时只作参考。

## F8 不同当前库下的可用写法（SQL Server 开发库，F7 后补）

F7 显示服务器是 SQL Server 2019，但 `info` 库的兼容级别是 100（SQL Server 2008），`CoreINFO` 是 150。SQL Server 有些写法是否可用，看的是**会话的当前库**的兼容级别，而不是被查的表在哪个库：F6b ⑤ 在 `info` 下用不了 `STRING_SPLIT`、`TRY_CONVERT` 就是这个原因。本助手的取数平台会生成分页写法（`OFFSET ... FETCH NEXT`），治理任务打算用 `HASHBYTES` 给长文本算指纹，要确认这几样在两个当前库下都能用。

**分别执行两次**：一次在查询窗口的「可用数据库」下拉框里选 `info`，一次选 `CoreINFO`（不用 `USE` 语句，执行环境可能不允许）。下面 4 条逐条执行，某条报错就把报错原文记下，接着执行下一条。结果整理成 `F8.txt`：「当前库 编号 结果或报错」。

```sql
-- ① 当前库与兼容级别
SELECT DB_NAME() AS [当前库],
       (SELECT compatibility_level FROM sys.databases WHERE name = DB_NAME()) AS [兼容级别];

-- ② 长文本哈希：对 2 万字节的文本算 SHA2_256，正常应返回 32
SELECT DATALENGTH(HASHBYTES('SHA2_256', REPLICATE(CAST(N'a' AS nvarchar(max)), 10000))) AS [哈希字节数];

-- ③ 分页写法：正常应返回 1
SELECT COUNT(*) AS [行数]
FROM (SELECT m.ID FROM CoreINFO.dbo.ZCTracking_ProblemList m
      ORDER BY m.ID OFFSET 0 ROWS FETCH NEXT 1 ROWS ONLY) t;

-- ④ 拆分与容错转换：正常应返回 3
SELECT COUNT(TRY_CONVERT(int, x.value)) AS [段数]
FROM STRING_SPLIT('1,2,3', ',') x;
```
