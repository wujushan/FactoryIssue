## H1 「停线中」的单按结案情况分布

按现落盘的「停线中」口径取单，再按单是否结案分开计数。

```sql
SELECT '国内' AS "域",
       CASE WHEN m."Status"::int = 32 THEN '已完成' ELSE '未结案' END AS "结案情况",
       CASE m."StopStatus"::int WHEN 1 THEN '停线中' WHEN 4 THEN '重启审核'
                                WHEN 5 THEN '审核通过' WHEN 6 THEN '填写重启方案' END AS "停线状态",
       CASE WHEN m."ReStartDate" IS NULL THEN '无' ELSE '有' END AS "有无停线重启时间",
       count(*) AS "单数"
FROM "ZCTracking_ProblemList" m
WHERE COALESCE(m."IsDelete"::int, 0) <> 1
  AND m."StopStatus"::int IN (1, 4, 5, 6)
GROUP BY 1, 2, 3, 4
UNION ALL
SELECT '巴西',
       CASE b."Status"::int WHEN 50 THEN '已结案' WHEN 0 THEN '待提交' WHEN -2 THEN '已终止'
                            ELSE '未结案' END,
       COALESCE(NULLIF(btrim(b."StopStatus"::text), ''), '（空）'),
       '—',
       count(*)
FROM "BrazilProblemList" b
WHERE b."Status"::int <> -1
  AND btrim(b."IsStopLine"::text) = '是'
  AND COALESCE(btrim(b."StopStatus"::text), '') <> '停线重启'
GROUP BY 1, 2, 3, 4
UNION ALL
SELECT '海外',
       CASE WHEN o."Status"::int = 32 THEN '已完成' ELSE '未结案' END,
       '停线中',
       CASE WHEN o."ReStartDate" IS NULL THEN '无' ELSE '有' END,
       count(*)
FROM "OverseasProblemDetail" o
WHERE o."IsDelete"::int = 0
  AND o."StopState"::int = 1
GROUP BY 1, 2, 3, 4
ORDER BY 1, 2, 3, 4;
```

**结果怎么用**：「已完成」「已结案」「已终止」的行就是按现口径会被当成「停线中」的已结案单。张数为 0 或极少时，G34 的建议只是兜底；张数多时，G34 必须先定。国内、海外已结案的单「有停线重启时间」，说明重启过、只是停线状态没改回。

**H1b 巴西、海外停线两列的取值分布**（2026-10-21 补充）：H1 的结果里巴西、海外没有行。海外未删除只有 12 张单，没有停线中的单说得通；巴西按现口径要求「是否停线」恰好写作「是」，写法对不上（如存成 1、Y）也会得到 0 行。本段把两列的取值全列出来。输出巴西停线状态的写法，外传前请过目。

```sql
SELECT '巴西' AS "域",
       COALESCE(NULLIF(btrim(b."IsStopLine"::text), ''), '（空）') AS "是否停线",
       COALESCE(NULLIF(btrim(b."StopStatus"::text), ''), '（空）') AS "停线状态",
       CASE b."Status"::int WHEN 50 THEN '已结案' WHEN 0 THEN '待提交' WHEN -2 THEN '已终止'
                            ELSE '未结案' END AS "结案情况",
       count(*) AS "单数"
FROM "BrazilProblemList" b
WHERE b."Status"::int <> -1
GROUP BY 1, 2, 3, 4
UNION ALL
SELECT '海外',
       COALESCE(o."IsStop"::text, '（空）'),
       COALESCE(o."StopState"::text, '（空）'),
       CASE WHEN o."Status"::int = 32 THEN '已完成' ELSE '未结案' END,
       count(*)
FROM "OverseasProblemDetail" o
WHERE o."IsDelete"::int = 0
GROUP BY 1, 2, 3, 4
ORDER BY 1, 2, 3, 4;
```

**结果怎么用**：巴西「是否停线」只有「是」「否」两种写法、「是」的单停线状态都是「停线重启」时，H1 的 0 行成立，现口径不用动。出现其他写法时，按实际写法修订巴西停线口径。海外「是否停线」为 1 的单，停线状态应为 2（已经重启）。

**H1c 是哪几张单**（2026-10-21 补充）：列出 H1 里「已完成」、停线状态却仍是停线中一类（停线中、重启审核、审核通过、填写重启方案）的国内单，供业务方到管理页面逐张核对。H1 显示目前有 2 张。

> **本段输出问题编号，与其他各段不同。结果只在内网对照管理页面用，不要发回，也不要放进 `docs/1_user_input/`。** 只需回告页面上的结论（见下方「结果怎么用」）。

```sql
SELECT m."Numbers"                                   AS "问题编号",
       CASE m."StopStatus"::int WHEN 1 THEN '停线中'   WHEN 4 THEN '重启审核'
                                WHEN 5 THEN '审核通过' WHEN 6 THEN '填写重启方案' END AS "停线状态",
       CASE m."IsStop"::int WHEN 1 THEN '是' WHEN 0 THEN '否' ELSE '（空）' END   AS "是否停线",
       m."StopDate"::date                            AS "停线日期",
       m."AddDate"::date                             AS "建单时间",
       (SELECT btrim(s."StepStr"::text) || ' ' || to_char(s."AddDate", 'YYYY-MM-DD')
          FROM "ZCTracking_ProblemSteplog" s
         WHERE s."ProblemId" = m."ID" AND s."StepStr"::text LIKE '%重启%'
         ORDER BY s."ID" DESC
         LIMIT 1)                                    AS "最后一条重启相关步骤",
       (SELECT btrim(s."StepStr"::text) || ' ' || to_char(s."AddDate", 'YYYY-MM-DD')
          FROM "ZCTracking_ProblemSteplog" s
         WHERE s."ProblemId" = m."ID"
         ORDER BY s."ID" DESC
         LIMIT 1)                                    AS "最后一条处理步骤"
FROM "ZCTracking_ProblemList" m
WHERE COALESCE(m."IsDelete"::int, 0) <> 1
  AND m."Status"::int = 32
  AND m."StopStatus"::int IN (1, 4, 5, 6)
ORDER BY m."AddDate";
```

「最后一条重启相关步骤」取环节名称里带「重启」的最新一条（停线重启、停线重启审核、停线重启发起、责任人填写重启方案），用来看这张单是重启了、只是停线状态没改，还是重启流程走到一半就结案了。

**结果怎么用**：在管理页面逐张打开这几张单，回告三点即可，不必附单号：

1. 页面上这张单的停线状态显示什么；
2. 在管理页面按停线状态筛「停线中」（或页面上对应的筛选项）时，这张单在不在结果里；
3. 按业务理解，这张单现在还算不算停线中。

三点都是「不算」时，G34 按建议定（「停线中」只算未结案的单）；页面把它们算进停线中时，按页面来。

## H2 已结案的单能不能定出结案时间

国内、海外看已完成的单最后一条处理步骤是什么环节、有没有「结案确认」这一步；巴西看最新一条处理过程上的结案日期有没有填。

```sql
WITH dom AS (
    SELECT
        (SELECT btrim(s."StepStr"::text) FROM "ZCTracking_ProblemSteplog" s
          WHERE s."ProblemId" = m."ID" ORDER BY s."ID" DESC LIMIT 1) AS last_step,
        EXISTS (SELECT 1 FROM "ZCTracking_ProblemSteplog" s
                 WHERE s."ProblemId" = m."ID" AND btrim(s."StepStr"::text) = '结案确认') AS has_close
    FROM "ZCTracking_ProblemList" m
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1 AND m."Status"::int = 32
), ovs AS (
    SELECT
        (SELECT btrim(s."StepStr"::text) FROM "OverseasProblem_StepLog" s
          WHERE s."ProblemId" = o."Id" ORDER BY s."Id" DESC LIMIT 1) AS last_step,
        EXISTS (SELECT 1 FROM "OverseasProblem_StepLog" s
                 WHERE s."ProblemId" = o."Id" AND btrim(s."StepStr"::text) = '结案确认') AS has_close
    FROM "OverseasProblemDetail" o
    WHERE o."IsDelete"::int = 0 AND o."Status"::int = 32
)
SELECT '国内' AS "域", COALESCE(last_step, '（没有处理步骤）') AS "最后一条处理步骤的环节",
       CASE WHEN has_close THEN '有' ELSE '无' END AS "有无结案确认步骤", count(*) AS "单数"
FROM dom GROUP BY 1, 2, 3
UNION ALL
SELECT '海外', COALESCE(last_step, '（没有处理步骤）'),
       CASE WHEN has_close THEN '有' ELSE '无' END, count(*)
FROM ovs GROUP BY 1, 2, 3
UNION ALL
SELECT '巴西', '（最新一条处理过程）',
       CASE WHEN lp."FinishDate" IS NULL THEN '结案日期为空' ELSE '结案日期有值' END, count(*)
FROM "BrazilProblemList" b
LEFT JOIN LATERAL (SELECT p."FinishDate" FROM "BrazilProblemProcess" p
                   WHERE p."ProblemID" = b."ID" ORDER BY p."ID" DESC LIMIT 1) lp ON true
WHERE b."Status"::int = 50
GROUP BY 1, 2, 3
ORDER BY 1, 4 DESC;
```

**结果怎么用**：G35 已定结案时间取最后一条「结案确认」的发生时间（巴西取最新一条处理过程的结案日期）。「无结案确认步骤」的单数与巴西「结案日期为空」的单数，就是按结案时间统计时要写明「未计入」的张数。这类单很多时，另提待确认，看要不要换取法。最后一条处理步骤是不是「结案确认」不影响取法，只作参考。

## H3 机型名称互相包含

「被其他名称包含」= 用这个名称做包含匹配，会把别的机型也查进来（如 A920 包含于 A920Pro）。不分大小写，去首尾空格。

**H3a 计数**

```sql
WITH dn AS (
    SELECT DISTINCT upper(btrim(p."ProductName"::text)) AS name
    FROM "ZCTracking_ProductNames" p
    JOIN "ZCTracking_ProblemList" m ON m."ID" = p."ProblemId"
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1
      AND NULLIF(btrim(p."ProductName"::text), '') IS NOT NULL
), pn AS (
    SELECT DISTINCT upper(btrim(x."ProductName"::text)) AS name
    FROM "ProductName" x
    WHERE NULLIF(btrim(x."ProductName"::text), '') IS NOT NULL
)
SELECT '国内单上用到的机型' AS "范围",
       (SELECT count(*) FROM dn) AS "不同名称数",
       (SELECT count(*) FROM dn a
         WHERE EXISTS (SELECT 1 FROM dn b WHERE b.name <> a.name AND strpos(b.name, a.name) > 0))
           AS "被其他名称包含的名称数"
UNION ALL
SELECT '产品主数据的大机型（巴西、海外）',
       (SELECT count(*) FROM pn),
       (SELECT count(*) FROM pn a
         WHERE EXISTS (SELECT 1 FROM pn b WHERE b.name <> a.name AND strpos(b.name, a.name) > 0));
```

**H3b 受影响的国内单**：机型名称里含有另一个机型名称的单（按包含匹配查那个较短的名称时，这些单会被一起查进来）。

```sql
WITH dn AS (
    SELECT DISTINCT upper(btrim(p."ProductName"::text)) AS name
    FROM "ZCTracking_ProductNames" p
    JOIN "ZCTracking_ProblemList" m ON m."ID" = p."ProblemId"
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1
      AND NULLIF(btrim(p."ProductName"::text), '') IS NOT NULL
), longer AS (
    SELECT DISTINCT b.name FROM dn a JOIN dn b ON b.name <> a.name AND strpos(b.name, a.name) > 0
)
SELECT count(DISTINCT p."ProblemId") AS "单数"
FROM "ZCTracking_ProductNames" p
JOIN "ZCTracking_ProblemList" m ON m."ID" = p."ProblemId"
WHERE COALESCE(m."IsDelete"::int, 0) <> 1
  AND upper(btrim(p."ProductName"::text)) IN (SELECT name FROM longer);
```

**H3c 示例**（输出机型名称，外传前请过目）：取国内单上用量最多的 20 个「较短名称」，列出包含它的名称。

```sql
WITH used AS (
    SELECT upper(btrim(p."ProductName"::text)) AS name, count(DISTINCT p."ProblemId") AS n
    FROM "ZCTracking_ProductNames" p
    JOIN "ZCTracking_ProblemList" m ON m."ID" = p."ProblemId"
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1
      AND NULLIF(btrim(p."ProductName"::text), '') IS NOT NULL
    GROUP BY 1
)
SELECT a.name AS "较短的机型名称", a.n AS "该名称的单数",
       string_agg(b.name, '、' ORDER BY b.name) AS "名称里包含它的机型",
       sum(b.n) AS "这些机型的单数合计"
FROM used a
JOIN used b ON b.name <> a.name AND strpos(b.name, a.name) > 0
GROUP BY a.name, a.n
ORDER BY a.n DESC
LIMIT 20;
```

**结果怎么用**：被包含的名称很少时，G31 的建议只是兜底；不少时，按 G31 先完整匹配再包含匹配。H3c 里若有「较短名称」本来就是一族机型的统称，请在 G31 的答复里说明。

## H4 部门名称互相包含

输出部门名称，外传前请过目。部门表约 50 行。

```sql
WITH d AS (
    SELECT DISTINCT btrim(x."Name"::text) AS name
    FROM "Department" x
    WHERE NULLIF(btrim(x."Name"::text), '') IS NOT NULL
)
SELECT a.name AS "较短的部门名称",
       string_agg(b.name, '、' ORDER BY b.name) AS "名称里包含它的部门"
FROM d a
JOIN d b ON b.name <> a.name AND strpos(b.name, a.name) > 0
GROUP BY a.name
ORDER BY a.name;
```

**结果怎么用**：每一行都是 G32 里「按包含匹配会一次命中多个部门」的情形，答复 G32 时可对照这张表说明哪些应合起来算、哪些应分开。

## H5 国内不良率与不良数量、生产数量是否一致

落盘里单张单展示单上存的不良率，多张单合计时用「合计不良数量 ÷ 合计生产数量」。两者对不上时，一张单单独看与按机型汇总（只有这一张）看到的数会不同。

```sql
SELECT
    CASE
        WHEN m."Rate" IS NULL THEN '1 不良率为空'
        WHEN COALESCE(m."ProdQty"::int, 0) = 0 THEN '2 生产数量为 0 或空、不良率有值'
        WHEN abs(m."Rate"::numeric - COALESCE(m."BadQty"::int, 0) * 100.0 / m."ProdQty"::int) <= 0.01
            THEN '3 与不良数量 ÷ 生产数量一致'
        WHEN abs(m."Rate"::numeric - COALESCE(m."BadQty"::int, 0) * 100.0 / m."ProdQty"::int) <= 1
            THEN '4 相差 0.01–1'
        ELSE '5 相差超过 1'
    END AS "与生产数量比",
    CASE
        WHEN m."Rate" IS NULL OR COALESCE(m."ImpactQty"::int, 0) = 0 THEN '—'
        WHEN abs(m."Rate"::numeric - COALESCE(m."BadQty"::int, 0) * 100.0 / m."ImpactQty"::int) <= 0.01
            THEN '与不良数量 ÷ 影响数量一致'
        ELSE '不一致'
    END AS "与影响数量比",
    count(*) AS "单数"
FROM "ZCTracking_ProblemList" m
WHERE COALESCE(m."IsDelete"::int, 0) <> 1
GROUP BY 1, 2
ORDER BY 1, 2;
```

**结果怎么用**：绝大多数落在「3」时口径成立，不用动。「4」「5」多时，看第二列：若多与影响数量一致，说明源系统的分母不是生产数量，要另提待确认；都不一致时，另提「单张单展示哪个数」。

## H6 巴西影响数量为空、为 0 的单

```sql
SELECT
    CASE WHEN b."ImpactQty" IS NULL THEN '1 影响数量为空'
         WHEN b."ImpactQty"::int = 0 THEN '2 影响数量为 0'
         WHEN b."ImpactQty"::int < 0 THEN '3 影响数量小于 0'
         ELSE '4 影响数量大于 0' END AS "影响数量",
    CASE WHEN b."BadQty" IS NULL THEN '不良数量为空'
         WHEN b."BadQty"::int = 0 THEN '不良数量为 0'
         ELSE '不良数量有值' END AS "不良数量",
    count(*) AS "单数"
FROM "BrazilProblemList" b
WHERE b."Status"::int <> -1
GROUP BY 1, 2
ORDER BY 1, 2;
```

**结果怎么用**：「1」的张数就是 B16 影响到的单；为 0 时 B16 只是兜底。

## H7 CAR 编号的前三个字母

O1 只看了写法形态（字母统一换成 A），没核实前三个字母是不是都是 CAR。落盘按「CAR 加 9 位数字」识别 CAR 编号（G26）。含已删除的单。

```sql
SELECT upper(left(btrim(m."CAR"::text), 3)) AS "前三个字符",
       CASE WHEN btrim(m."CAR"::text) ~* '^[a-z]{3}[0-9]{9}$' THEN '3 个字母 + 9 位数字'
            ELSE '其他形态' END AS "形态",
       count(*) AS "单数"
FROM "ZCTracking_ProblemList" m
WHERE NULLIF(btrim(m."CAR"::text), '') IS NOT NULL
GROUP BY 1, 2
ORDER BY 3 DESC;
```

**结果怎么用**：只有「CAR」一行时，识别规则成立。出现其他前缀时，把国内业务描述「按 CAR 编号查单」的识别规则放宽为「3 个字母 + 9 位数字」，并核对管理页面上这些编号怎么显示。

```sql
    WHERE btrim(st."StepStr"::text) = '停线重启'
```

```sql
       count(*) FILTER (WHERE restart_at < stop_at)                    AS "重启时间早于停线日期",
       count(*) FILTER (WHERE EXISTS (SELECT 1 FROM "ZCTracking_ProblemSteplog" s
                                      WHERE s."ProblemId" = m.id AND btrim(s."StepStr"::text) = '停线重启'))
                                                                       AS "有停线重启步骤",
       count(*) FILTER (WHERE EXISTS (SELECT 1 FROM "ZCTracking_ProblemSteplog" s
                                      WHERE s."ProblemId" = m.id AND btrim(s."StepStr"::text) = '停线重启审核'
                                        AND btrim(regexp_replace(COALESCE(s."Result"::text, ''), '<[^>]+>|&nbsp;', '', 'g')) = '1'))
                                                                       AS "有重启审核通过的步骤",
       min(restart_at)::date                                           AS "最早停线重启时间",
       max(restart_at)::date                                           AS "最晚停线重启时间"
FROM m
GROUP BY 1, 2
ORDER BY 1, 2;
```

**H12b 国内：主表停线重启时间是什么时候写入的**

对有停线重启时间的单，看它与几个步骤的发生时间是不是同一天：最新一条重启审核通过的步骤、最新一条停线重启步骤、最新一条停线重启发起步骤；以及与停线重启这一步登记的日期是否同一天。

```sql
WITH m AS (
    SELECT m."ID" AS id, m."ReStartDate"::date AS rd
    FROM "ZCTracking_ProblemList" m
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1 AND m."ReStartDate" IS NOT NULL
),
x AS (
    SELECT m.id, m.rd,
        (SELECT max(s."AddDate")::date FROM "ZCTracking_ProblemSteplog" s
          WHERE s."ProblemId" = m.id AND btrim(s."StepStr"::text) = '停线重启审核'
            AND btrim(regexp_replace(COALESCE(s."Result"::text, ''), '<[^>]+>|&nbsp;', '', 'g')) = '1') AS pass_d,
        (SELECT max(s."AddDate")::date FROM "ZCTracking_ProblemSteplog" s
          WHERE s."ProblemId" = m.id AND btrim(s."StepStr"::text) = '停线重启') AS rs_d,
        (SELECT max(s."AddDate")::date FROM "ZCTracking_ProblemSteplog" s
          WHERE s."ProblemId" = m.id AND btrim(s."StepStr"::text) = '停线重启发起') AS launch_d,
        (SELECT left(btrim(regexp_replace(COALESCE(s."Result"::text, ''), '<[^>]+>|&nbsp;', '', 'g')), 10)
           FROM "ZCTracking_ProblemSteplog" s
          WHERE s."ProblemId" = m.id AND btrim(s."StepStr"::text) = '停线重启'
          ORDER BY s."ID" DESC LIMIT 1) AS rs_v
    FROM m
)
SELECT '与最新重启审核通过步骤' AS "比对",
       CASE WHEN pass_d IS NULL THEN '没有这一步' WHEN rd = pass_d THEN '同一天'
            WHEN rd < pass_d THEN '早于这一步' ELSE '晚于这一步' END AS "情况",
       count(*) AS "单数"
FROM x GROUP BY 1, 2
UNION ALL
SELECT '与最新停线重启步骤',
       CASE WHEN rs_d IS NULL THEN '没有这一步' WHEN rd = rs_d THEN '同一天'
            WHEN rd < rs_d THEN '早于这一步' ELSE '晚于这一步' END,
       count(*)
FROM x GROUP BY 1, 2
UNION ALL
SELECT '与最新停线重启发起步骤',
       CASE WHEN launch_d IS NULL THEN '没有这一步' WHEN rd = launch_d THEN '同一天'
            WHEN rd < launch_d THEN '早于这一步' ELSE '晚于这一步' END,
       count(*)
FROM x GROUP BY 1, 2
UNION ALL
SELECT '与停线重启步骤登记的日期',
       CASE WHEN rs_v IS NULL OR rs_v !~ '^[0-9]{4}-[0-9]{2}-[0-9]{2}$' THEN '没有这个日期'
            WHEN rd = rs_v::date THEN '同一天'
            WHEN rd < rs_v::date THEN '早于登记的日期' ELSE '晚于登记的日期' END,
       count(*)
FROM x GROUP BY 1, 2
ORDER BY 1, 2;
```

**H12c 国内：停了多久（停线日期到停线重启时间）**

```sql
SELECT CASE WHEN d < 0 THEN '1 负数（重启早于停线）'
            WHEN d = 0 THEN '2 当天'
            WHEN d <= 7 THEN '3 1–7 天'
            WHEN d <= 30 THEN '4 8–30 天'
            WHEN d <= 180 THEN '5 31–180 天'
            ELSE '6 180 天以上' END AS "停线天数",
       count(*) AS "单数"
FROM (
    SELECT m."ReStartDate"::date - m."StopDate"::date AS d
    FROM "ZCTracking_ProblemList" m
    WHERE COALESCE(m."IsDelete"::int, 0) <> 1
      AND m."StopDate" IS NOT NULL AND m."ReStartDate" IS NOT NULL
) t
GROUP BY 1
ORDER BY 1;
```

**H12d 海外：停线两列与两个日期**

```sql
SELECT COALESCE(o."IsStop"::text, '空')    AS "是否停线",
       COALESCE(o."StopState"::text, '空') AS "停线状态",
       count(*)                                                            AS "单数",
       count(*) FILTER (WHERE NULLIF(btrim(o."StopDate"::text), '') IS NOT NULL) AS "有停线日期",
       count(o."ReStartDate")                                               AS "有停线重启时间",
       count(*) FILTER (WHERE o."ReStartDate"::time <> '00:00:00')          AS "停线重启时间带时分",
       count(*) FILTER (WHERE EXISTS (SELECT 1 FROM "OverseasProblem_StepLog" s
                                      WHERE s."ProblemId" = o."Id" AND s."StepStr"::text LIKE '%重启%'))
                                                                            AS "有带「重启」的处理步骤"
FROM "OverseasProblemDetail" o
WHERE COALESCE(o."IsDelete"::int, 0) = 0
GROUP BY 1, 2
ORDER BY 1, 2;
```

**结果怎么用**：

- **「X 时间重启的单」**：已经重启（国内停线状态 2、海外 2）的单大多有停线重启时间时，可以按它筛，没填的写明未计入。H12b 若显示它与重启审核通过那一步同一天，说明它是审核通过时写入的「重启时间」，按它筛的含义是「重启获批的时间」，回答里照这个说法写。
- **「停了多久才重启」**：H12c 负数很少、分布合理时可以算，按天计，只算两个日期都有的已重启单；负数多时不提供。
- **「重启审核通过的单」**：国内停线状态 5 就是「重启审核通过」，按状态查，不依赖日期。
- 停线重启时间在停线状态为停线中、重启审核等尚未重启的单上也有值时，说明它会被重复写入或预填，另提待确认。
