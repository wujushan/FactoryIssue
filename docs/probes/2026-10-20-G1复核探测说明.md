## 执行须知

- 全部是只读 `SELECT`，连 INFO 实例的只读热备副本执行。CoreINFO、info 两个库在同一实例；不涉及 ERP。
- 只输出计数、取值分类和表结构元数据，不输出业务数据行。C1b 输出的是日期写法的「形状」（数字统一替换成 9），C6 输出文档的业务名称，C8 输出业务表名，外传前请人工过目。
- 需要 SQL Server 2012 及以上（用到 `TRY_CONVERT`）。拆分逗号分隔的列用 INFO 库现有的 `info.dbo.f_split`（输出列名 `col`），源系统的巴西列表查询也在用它；如果当前账号调用不了，可换成 `STRING_SPLIT(列, ',')`（SQL Server 2016 及以上，输出列名 `value`），同时把 `x.col` 改成 `x.value`。执行 C6 时已确认当前账号调用不了 `f_split`，C9 请直接用 `STRING_SPLIT`。
- 执行环境不允许 `SET` 语句时，去掉各段开头的 `SET NOCOUNT ON;`，不影响结果。
- 待办任务表约 420 万行、文档清单约 193 万行，C6、C8 可能要跑一会，建议在业务低峰执行。
- 交付：每段查询的结果网格另存为 CSV，按小节编号命名（如 `C1a.csv`），放到 `docs/1_user_input/answers/<执行日期>/`。某段报错时，把报错信息原样存成同名文本，其余照常执行。

## C1 巴西文本日期的写法

已删除的单（状态 -1）不计入。

**C1a 按写法分类计数**

```sql
SET NOCOUNT ON;
WITH v AS (
    SELECT N'主表.停线日期' AS [列], LTRIM(RTRIM(m.StopDate)) AS x
    FROM CoreINFO.dbo.BrazilProblemList m WHERE m.Status <> -1
    UNION ALL
    SELECT N'主表.现场发现日期', LTRIM(RTRIM(m.ProblemDiscoveryDate))
    FROM CoreINFO.dbo.BrazilProblemList m WHERE m.Status <> -1
    UNION ALL
    SELECT N'主表.统计日期', LTRIM(RTRIM(m.StatisticsDate))
    FROM CoreINFO.dbo.BrazilProblemList m WHERE m.Status <> -1
    UNION ALL
    SELECT N'处理过程.计划完成日期', LTRIM(RTRIM(p.PlanCompleteDate))
    FROM CoreINFO.dbo.BrazilProblemProcess p
    JOIN CoreINFO.dbo.BrazilProblemList m ON m.ID = p.ProblemID AND m.Status <> -1
    UNION ALL
    SELECT N'处理过程.设计更改评估时间', LTRIM(RTRIM(p.DesignEstimateDate))
    FROM CoreINFO.dbo.BrazilProblemProcess p
    JOIN CoreINFO.dbo.BrazilProblemList m ON m.ID = p.ProblemID AND m.Status <> -1
), c AS (
    SELECT [列],
        CASE
            WHEN x IS NULL OR x = '' THEN N'1 空'
            WHEN x LIKE '[12][0-9][0-9][0-9]-[01][0-9]-[0-3][0-9]'
                 AND TRY_CONVERT(date, x, 23) IS NOT NULL THEN N'2 YYYY-MM-DD'
            WHEN x LIKE '[12][0-9][0-9][0-9]-[01][0-9]-[0-3][0-9]' THEN N'3 YYYY-MM-DD 形式但不是有效日期'
            WHEN x LIKE '[12][0-9][0-9][0-9]-[01][0-9]-[0-3][0-9][ T]%' THEN N'4 日期后带时间'
            WHEN x LIKE '%/%' THEN N'5 含斜杠'
            ELSE N'6 其他'
        END AS [写法]
    FROM v
)
SELECT [列], [写法], COUNT(*) AS [行数]
FROM c
GROUP BY [列], [写法]
ORDER BY [列], [写法];
```

        REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(x,
            '0', '9'), '1', '9'), '2', '9'), '3', '9'), '4', '9'), '5', '9'), '6', '9'), '7', '9'), '8', '9') AS [形状]

## C2 国内 IQC 状态与并行阶段

已删除的单不计入。

**C2a 主状态 × IQC 状态 × 有无 IQC 成员**

```sql
SET NOCOUNT ON;
SELECT [主状态], [IQC状态], [IQC成员], COUNT(*) AS [单数]
FROM (
    SELECT
        ISNULL(CAST(m.Status AS varchar(10)), 'NULL') AS [主状态],
        ISNULL(CAST(m.IQCStatus AS varchar(10)), 'NULL') AS [IQC状态],
        CASE WHEN NULLIF(LTRIM(RTRIM(m.IQCMemberList)), '') IS NULL THEN N'无' ELSE N'有' END AS [IQC成员]
    FROM CoreINFO.dbo.ZCTracking_ProblemList m
    WHERE ISNULL(m.IsDelete, 0) = 0
) t
GROUP BY [主状态], [IQC状态], [IQC成员]
ORDER BY TRY_CONVERT(int, [主状态]), [IQC状态], [IQC成员];
```

**C2b 有进行中退货 / 退库记录的单，按主状态分**

```sql
SET NOCOUNT ON;
SELECT m.Status AS [主状态], COUNT(*) AS [有进行中退货退库的单数]
FROM CoreINFO.dbo.ZCTracking_ProblemList m
WHERE ISNULL(m.IsDelete, 0) = 0
  AND EXISTS (SELECT 1 FROM CoreINFO.dbo.ZCTracking_RiskStream r
              WHERE r.ProblemId = m.ID AND r.Status = 1)

ORDER BY m.Status;
```

**执行状态**：已于 2026-10-20 执行。IQC 状态只有空与 6，6 只在主状态 8 的 2 张单上；结案确认、已完成等后段环节全为空，D13 的前提成立。进行中的退货 / 退库只在主状态 8（2 张）与 37（1 张）；状态 37 那张单转为 open-questions D21，经管理页面核对后已关闭（并行阶段追加进行中的退货 / 退库）。

**结果怎么用**：主状态码 30、36、37 为并行阶段，31 为结案确认，32 为已完成。
- IQC 状态出现 6、7 以外的值（含 0）时，要定这些值显示什么文案、算不算「有值」。
- 结案确认等后段环节仍大量挂着 IQC 状态 6、7 时，说明 IQC 走完后状态不一定清空，D13 的前提不成立。
- 并行阶段的单有 IQC 状态或进行中的退货 / 退库时，按 D14 这些进度不会出现在当前状态里，请业务方确认能否接受。

## C3 国内 CAR 编号与 CAR 报告 ID

```sql
SET NOCOUNT ON;
SELECT [CAR编号], [CAR报告ID], [问题类型], [报告表能否对上], COUNT(*) AS [单数]
FROM (
    SELECT
        CASE WHEN NULLIF(LTRIM(RTRIM(m.CAR)), '') IS NULL THEN N'空' ELSE N'有值' END AS [CAR编号],
        CASE WHEN m.CARID IS NULL THEN N'NULL' WHEN m.CARID = 0 THEN N'0' ELSE N'大于0' END AS [CAR报告ID],
        CASE WHEN m.ProblemType = 3 THEN N'物料问题' ELSE N'其他类型' END AS [问题类型],
        CASE WHEN ISNULL(m.CARID, 0) = 0 THEN N'-'
             WHEN EXISTS (SELECT 1 FROM info.dbo.tbIQCreportOut r WHERE r.fid = m.CARID) THEN N'能对上'
             ELSE N'对不上' END AS [报告表能否对上]
    FROM CoreINFO.dbo.ZCTracking_ProblemList m
    WHERE ISNULL(m.IsDelete, 0) = 0
) t
GROUP BY [CAR编号], [CAR报告ID], [问题类型], [报告表能否对上]
ORDER BY [CAR编号], [CAR报告ID], [问题类型], [报告表能否对上];
```

**执行状态**：已于 2026-10-20 执行。CAR 编号与报告 ID 总是同时有值或同时为空（G20 ② 判据成立）；关联了 CAR 的 1,348 张单中，物料问题 1,331 张、其他类型 17 张；3 张单的报告 ID 在报告表里查不到（物料问题中 1 张）。业务方确认源系统只在物料问题上展示 CAR，其他类型的 17 张不展示、不计入；结果已落盘。

**结果怎么用**：
- 「CAR 编号有值、CAR 报告 ID 为空或 0」的单数大于 0 时，G20 ② 以报告 ID 为准的判据要重新定。
- 「对不上」的单数大于 0 时，这些单生成的 CAR 链接打不开。
- 非物料问题也有 CAR 时，「只有物料问题可关联 CAR」要修正。

## C4 国内三个文本型人员列

```sql
SET NOCOUNT ON;
SELECT [列], [取值情况], COUNT(*) AS [单数]
FROM (
    SELECT u.[列],
        CASE WHEN NULLIF(u.v, '') IS NULL THEN N'1 空'
             WHEN u.v LIKE '%,%' THEN N'2 含逗号（多值）'
             WHEN TRY_CONVERT(int, u.v) IS NULL THEN N'3 不是整数'
             WHEN NOT EXISTS (SELECT 1 FROM info.dbo.Employee e WHERE e.ID = TRY_CONVERT(int, u.v)) THEN N'4 整数但人员表查不到'
             ELSE N'5 单个有效员工' END AS [取值情况]
    FROM CoreINFO.dbo.ZCTracking_ProblemList m
    CROSS APPLY (VALUES
        (N'问题跟进人', LTRIM(RTRIM(m.RUser))),
        (N'重启方案制定人', LTRIM(RTRIM(m.ReStartSchemeUser))),
        (N'重启审核人', LTRIM(RTRIM(m.ReStartExamineUser)))
    ) u([列], v)
    WHERE ISNULL(m.IsDelete, 0) = 0
) t
GROUP BY [列], [取值情况]
ORDER BY [列], [取值情况];
```

**执行状态**：已于 2026-10-20 执行。三列只有「空」与「单个有效员工」两类，没有多值、非整数或对不上人员表的值；单值前提成立，结果已落盘。

**结果怎么用**：
- 出现「含逗号」时单值前提不成立（问题跟进人涉及 D3），这一列要改成按段关联，否则多出来的人会被静默丢掉。
- 「不是整数」「查不到」的单数，就是回答里会显示「未填」的单数。

## C6 海外附件的业务记录 ID

**C6a 单上登记的附件，在文档清单里的业务记录 ID 指向哪里**

```sql
SET NOCOUNT ON;
SELECT [附件来源], [业务记录ID情况], [删除标志], [业务名称], COUNT(*) AS [附件数]
FROM (
    SELECT a.[附件来源],
        CASE WHEN d.ID IS NULL THEN N'文档清单查不到'
             WHEN d.frecid = a.ProblemId THEN N'等于主表 Id'
             WHEN a.StepId IS NOT NULL AND d.frecid = a.StepId THEN N'等于处理步骤 Id'
             ELSE N'其他值' END AS [业务记录ID情况],
        ISNULL(CAST(d.EffectFlag AS varchar(5)), '-') AS [删除标志],
        ISNULL(d.BusinessType, N'-') AS [业务名称]
    FROM (
        SELECT N'填单附件' AS [附件来源], m.Id AS ProblemId, CAST(NULL AS int) AS StepId, m.DocId AS Ids
        FROM CoreINFO.dbo.OverseasProblemDetail m
        WHERE m.IsDelete = 0 AND NULLIF(LTRIM(RTRIM(m.DocId)), '') IS NOT NULL
        UNION ALL
        SELECT N'步骤附件', s.ProblemId, s.Id, s.DocID
        FROM CoreINFO.dbo.OverseasProblem_StepLog s
        JOIN CoreINFO.dbo.OverseasProblemDetail m ON m.Id = s.ProblemId AND m.IsDelete = 0
        WHERE NULLIF(LTRIM(RTRIM(s.DocID)), '') IS NOT NULL
    ) a
    CROSS APPLY info.dbo.f_split(a.Ids, ',') x
    LEFT JOIN info.dbo.DocumentList d ON d.ID = TRY_CONVERT(int, LTRIM(RTRIM(x.col)))
    WHERE NULLIF(LTRIM(RTRIM(x.col)), '') IS NOT NULL
) t
GROUP BY [附件来源], [业务记录ID情况], [删除标志], [业务名称]
ORDER BY [附件来源], [业务记录ID情况], [删除标志], [业务名称];
```

**C6b 业务记录 ID 指向海外单、但单上没有登记的文档**

```sql
SET NOCOUNT ON;
SELECT [业务名称], [删除标志], [引用情况], COUNT(*) AS [文档数]
FROM (
    SELECT ISNULL(d.BusinessType, N'-') AS [业务名称],
        d.EffectFlag AS [删除标志],
        CASE WHEN EXISTS (SELECT 1 FROM CoreINFO.dbo.OverseasProblemDetail m2
                          WHERE ',' + REPLACE(ISNULL(m2.DocId, ''), ' ', '') + ','
                                LIKE '%,' + CAST(d.ID AS varchar(20)) + ',%')
               OR EXISTS (SELECT 1 FROM CoreINFO.dbo.OverseasProblem_StepLog s2
                          WHERE ',' + REPLACE(ISNULL(s2.DocID, ''), ' ', '') + ','
                                LIKE '%,' + CAST(d.ID AS varchar(20)) + ',%')
             THEN N'单上有登记' ELSE N'单上没有登记' END AS [引用情况]
    FROM info.dbo.DocumentList d
    JOIN CoreINFO.dbo.OverseasProblemDetail m ON m.Id = d.frecid AND m.IsDelete = 0
) t
GROUP BY [业务名称], [删除标志], [引用情况]
ORDER BY [业务名称], [删除标志], [引用情况];
```

**执行状态**：已于 2026-10-20 执行（`f_split` 无权限，改用 `STRING_SPLIT`）。单上登记的 41 个附件，业务记录 ID 全部等于主表 Id、全部未删除，业务名称共 3 种，都是海外制程问题类。C6b 中「单上没有登记」的 1 万多个文档来自 200 多种其他业务，是业务记录 ID 撞号，不是漏掉的附件。现取法成立，结果已落盘。

**结果怎么用**：
- 现口径是附件按单上登记的文档 ID 取，并要求文档的业务记录 ID 等于海外主表 Id、未删除（G8）。
- C6a 中步骤附件多为「等于处理步骤 Id」或「其他值」时，这条有效性条件会把步骤附件全部滤掉，要改。
- C6b 中业务名称为海外制程问题、且「单上没有登记」的文档，是现取法会漏掉的附件。
- C6b 的其他业务名称，说明只按业务记录 ID 取会混入别的业务的文档。

## C7 海外已完成的单的当前责任人

## C8 待办任务表里的国内业务表名

```sql
SET NOCOUNT ON;
SELECT t.ftable AS [业务表名], COUNT(*) AS [任务数],
       SUM(CASE WHEN t.fstat = N'已接受' THEN 1 ELSE 0 END) AS [已接受的任务数]
FROM info.dbo.tbTask t
WHERE t.ftable LIKE 'ZCTracking%'
GROUP BY t.ftable
ORDER BY t.ftable;
```

**结果怎么用**：权限协议 v1.3 的行规则没有前缀匹配，只有等于、不等于、大于、小于、属于（IN）和集合包含几种操作符。「只放行以 ZCTracking 开头的任务」要写进权限，只能写成「业务表名属于这份清单」；清单就是本查询的结果。清单很短，就请权限平台按 IN 配置；不配的话，由助手取数时自带条件。

## C9 巴西费用判据与大机型编号

已删除的单不计入。

**C9a 是否涉及费用 × 费用明细合计 × 最新处理过程扣款**

```sql
SET NOCOUNT ON;
WITH c AS (
    SELECT ProblemID, SUM(ISNULL(CostMoney, 0)) AS usd, SUM(ISNULL(CostBrlMoney, 0)) AS brl
    FROM CoreINFO.dbo.BrazilProblemCost
    GROUP BY ProblemID
)
SELECT [是否涉及费用], [费用明细], [最新处理过程扣款], COUNT(*) AS [单数]
FROM (
    SELECT
        CASE m.IsCost WHEN 1 THEN N'1 是' WHEN 2 THEN N'2 否' WHEN 0 THEN N'0 测试值' ELSE N'空或其他' END AS [是否涉及费用],
        CASE WHEN c.ProblemID IS NULL THEN N'没有费用明细'
             WHEN c.usd > 0 THEN N'美元合计大于 0'
             WHEN c.brl > 0 THEN N'只有雷亚尔合计大于 0'
             ELSE N'合计都为 0' END AS [费用明细],
        CASE WHEN ISNULL(lp.DebitMoney, 0) > 0 THEN N'大于 0' ELSE N'0 或空' END AS [最新处理过程扣款]
    FROM CoreINFO.dbo.BrazilProblemList m
    LEFT JOIN c ON c.ProblemID = m.ID
    OUTER APPLY (SELECT TOP 1 p.DebitMoney FROM CoreINFO.dbo.BrazilProblemProcess p
                 WHERE p.ProblemID = m.ID ORDER BY p.ID DESC) lp
    WHERE m.Status <> -1
) t
GROUP BY [是否涉及费用], [费用明细], [最新处理过程扣款]
ORDER BY [是否涉及费用], [费用明细], [最新处理过程扣款];
```

**C9b 大机型各段能否对上产品主数据**

```sql
SET NOCOUNT ON;
SELECT [段情况], COUNT(*) AS [段数], COUNT(DISTINCT t.ID) AS [涉及单数]
FROM (
    SELECT m.ID,
        CASE WHEN NULLIF(LTRIM(RTRIM(x.col)), '') IS NULL THEN N'1 空段'
             WHEN TRY_CONVERT(int, LTRIM(RTRIM(x.col))) IS NULL THEN N'2 不是数字'
             WHEN p.ID IS NULL THEN N'3 数字但产品表查不到'
             ELSE N'4 能对上' END AS [段情况]
    FROM CoreINFO.dbo.BrazilProblemList m
    CROSS APPLY info.dbo.f_split(m.ProductIDAll, ',') x
    LEFT JOIN info.dbo.ProductName p ON p.ID = TRY_CONVERT(int, LTRIM(RTRIM(x.col)))
    WHERE m.Status <> -1 AND NULLIF(LTRIM(RTRIM(m.ProductIDAll)), '') IS NOT NULL
) t
GROUP BY [段情况]
ORDER BY [段情况];
```

**C9c 每张单的大机型整体能否对上**

```sql
SET NOCOUNT ON;
SELECT [情况], COUNT(*) AS [单数]
FROM (
    SELECT m.ID,
        CASE WHEN SUM(CASE WHEN p.ID IS NOT NULL THEN 1 ELSE 0 END) = 0 THEN N'一段都对不上'
             WHEN SUM(CASE WHEN p.ID IS NULL THEN 1 ELSE 0 END) > 0 THEN N'部分对不上'
             ELSE N'全部能对上' END AS [情况]
    FROM CoreINFO.dbo.BrazilProblemList m
    CROSS APPLY info.dbo.f_split(m.ProductIDAll, ',') x
    LEFT JOIN info.dbo.ProductName p ON p.ID = TRY_CONVERT(int, LTRIM(RTRIM(x.col)))
    WHERE m.Status <> -1
      AND NULLIF(LTRIM(RTRIM(m.ProductIDAll)), '') IS NOT NULL
      AND NULLIF(LTRIM(RTRIM(x.col)), '') IS NOT NULL
    GROUP BY m.ID
) t
GROUP BY [情况]
ORDER BY [情况];
```

**执行状态**：C9 已于 2026-10-20 全部执行。C9a：两种判据都是 172 张，有 2 张单归属不同，另有 1 张只有雷亚尔；B14 已据此关闭。C9b、C9c（改用 `STRING_SPLIT`）：有大机型的 190 张单共 203 段，全部能对上产品主数据，B13 已关闭。

**结果怎么用**：
- C9a：「是否涉及费用为是」与「费用明细合计大于 0」对不上的单数，决定 B14 选哪个判据；「只有雷亚尔大于 0」的单数，决定判据要不要把雷亚尔算进去；扣款大于 0 的单数，决定扣款要不要单独说明。
- C9b、C9c：对不上的段数与单数，就是 B13 改口径会影响的范围。
