# 2026-10-26 删除标记取值探测说明

三个域都只查未删除的单（决策 2026-10-22「按编号查单」），落盘的判断写法各不相同：国内是否删除为 0 或空；巴西状态不为 -1；海外是否删除为 0。G2 独立评审（2026-10-26）指出 G2 草案把国内写成了「不为 1」，草案已改回落盘写法。

这几种写法只在出现空值、或 0 和 1 以外的值时才有区别，而这些情形可能存在：

- 国内主表的是否删除按 information_schema 可为空（见国内主表字段说明）；巴西主表的状态、海外主表的是否删除没有核对过可空性，按可空处理。
- 国内管理页面源码的清单查询条件是是否删除 = 0，不含空。落盘的「0 或空」含空。
- 以往探测各段的写法也不完全一致：国内多按「空按 0、不为 1」，海外多按「空按 0、为 0」，巴西按「状态不为 -1」（空不计入）。落盘的未删除张数等计数就是这样数出来的。

本说明先数清三域删除标记实际有哪些取值。如果没有空值，国内也只有 0 和 1，几种写法结果相同，口径和计数都不用动；有的话，再挑几张单到管理页面上看页面怎么处理。结果只影响查询与治理任务的筛选条件，不改 mart 的表结构。

## U1 三域删除标记的取值（镜像库，可发回）

国内、海外按删除标记的原值分组，空值单列；巴西只分「空」「-1（已删除）」「其余状态」三类，其余状态各是多少不在本段看。

```sql
SELECT '国内' AS "域",
       CASE WHEN m."IsDelete" IS NULL THEN '空' ELSE m."IsDelete"::int::text END AS "删除标记",
       count(*)                AS "单数",
       min(m."AddDate")::date  AS "最早建单",
       max(m."AddDate")::date  AS "最晚建单"
FROM "ZCTracking_ProblemList" m
GROUP BY 2
UNION ALL
SELECT '巴西',
       CASE WHEN b."Status" IS NULL THEN '空'
            WHEN b."Status"::int = -1 THEN '-1（已删除）'
            ELSE '其余状态' END,
       count(*), min(b."AddDate")::date, max(b."AddDate")::date
FROM "BrazilProblemList" b
GROUP BY 2
UNION ALL
SELECT '海外',
       CASE WHEN o."IsDelete" IS NULL THEN '空' ELSE o."IsDelete"::int::text END,
       count(*), min(o."AddDate")::date, max(o."AddDate")::date
FROM "OverseasProblemDetail" o
GROUP BY 2
ORDER BY 1, 2;
```

各域单数合计应等于主表行数：国内 2,791、巴西 212、海外 16（业务方 2026-10-22 正式镜像计数）。镜像同步过的话会略多，照实发回即可。

## U2 挑几张空值或其他取值的单（镜像库，输出问题编号，只在内网用）

U1 里出现以下任一行时才执行：国内「空」或 0、1 以外的值，巴西「空」，海外「空」。每域每种取值挑最近建的 3 张。

```sql
WITH t AS (
    SELECT '国内' AS "域",
           CASE WHEN m."IsDelete" IS NULL THEN '空' ELSE m."IsDelete"::int::text END AS "删除标记",
           m."Numbers"::text AS "问题编号",
           m."Status"::int   AS "状态码",
           m."AddDate"       AS add_date
    FROM "ZCTracking_ProblemList" m
    WHERE m."IsDelete" IS NULL OR m."IsDelete"::int NOT IN (0, 1)
    UNION ALL
    SELECT '巴西', '空', b."OrderNumber"::text, NULL::int, b."AddDate"
    FROM "BrazilProblemList" b
    WHERE b."Status" IS NULL
    UNION ALL
    SELECT '海外', '空', o."Numbers"::text, o."Status"::int, o."AddDate"
    FROM "OverseasProblemDetail" o
    WHERE o."IsDelete" IS NULL
),
r AS (
    SELECT t.*, row_number() OVER (PARTITION BY "域", "删除标记" ORDER BY add_date DESC) AS rn
    FROM t
)
SELECT "域", "删除标记", "问题编号", "状态码", add_date::date AS "建单日期"
FROM r
WHERE rn <= 3
ORDER BY 1, 2, 5 DESC;
```

到管理页面的问题清单里按问题编号搜这几张单，每种取值只回告两点，不回告单号：

- 清单里能不能搜到；
- 搜到的话，页面上显示的状态是什么。

## 结果怎么用

| U1 结果 | 怎么处理 |
|---|---|
| 三域都没有「空」，国内只有 0 和 1 | 落盘写法、管理页面、以往计数三者结果相同，口径与计数都不用动 |
| 国内有「空」 | 按落盘「0 或空」这些单算未删除、能查到，以往计数也算进去了；页面清单条件不含空。按 U2 到页面核对：页面搜不到时，国内改为「是否删除为 0」，并另出探测按同一时点重算落盘里按未删除数的国内计数；页面搜得到时，口径不变 |
| 国内有 0、1 以外的值 | 落盘写法与页面都不把它们当未删除，以往探测按「不为 1」把它们算进了未删除，落盘计数要按同一时点重算。按 U2 到页面看这些单显示成什么，请业务方说明这些值的含义 |
| 巴西有「空」 | 落盘「状态不为 -1」把空排除，以往计数同样排除。按 U2 到页面核对：页面搜得到时，口径改为「状态不为 -1，含空」并重算计数，并回告页面显示的状态；搜不到时口径不变，在巴西主表字段说明里写明 |
| 海外有「空」 | 落盘「为 0」不含空，以往计数按「空按 0」算进去了。按 U2 到页面核对：搜得到时，口径改为「为 0 或空」；搜不到时口径不变，海外计数按同一时点重算 |

口径有变时，本仓同步改各域业务描述「查询范围」、主表字段说明与 G2 决策草案的筛选条件，并在 `docs/decisions/` 记一条。
