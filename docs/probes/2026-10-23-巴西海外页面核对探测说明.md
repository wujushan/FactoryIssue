## N1 巴西投诉单附件的业务名称（B20）

巴西详情页「填单信息」里有「投诉单（附件）」。本仓只取了 8D 报告（业务名称「巴西制程问题单8D报告」，业务记录 ID 是处理过程的 ID）。本段列出名称里带「巴西」「投诉」或 Brazil 的业务名称，看它们的业务记录 ID 是巴西主表 ID 还是处理过程 ID。

```sql
WITH m AS (
    SELECT "ID" FROM "BrazilProblemList" WHERE "Status"::int <> -1
),
p AS (
    SELECT pr."ID" FROM "BrazilProblemProcess" pr JOIN m ON m."ID" = pr."ProblemID"
)
SELECT btrim(d."BusinessType"::text)                                        AS "业务名称",
       count(*)                                                            AS "有效文档数",
       count(*) FILTER (WHERE d."frecid" IN (SELECT "ID" FROM m))          AS "业务记录ID是巴西主表ID",
       count(*) FILTER (WHERE d."frecid" IN (SELECT "ID" FROM p))          AS "业务记录ID是巴西处理过程ID",
       min(d."AddDate")::date                                              AS "最早上传",
       max(d."AddDate")::date                                              AS "最晚上传"
FROM "DocumentList" d
WHERE COALESCE(d."EffectFlag"::int, 0) = 0
  AND (d."BusinessType"::text LIKE '%巴西%'
       OR d."BusinessType"::text LIKE '%投诉%'
       OR d."BusinessType"::text ILIKE '%brazil%')
GROUP BY 1
ORDER BY 2 DESC;
```

**结果怎么用**：
- 找到投诉单附件对应的业务名称，以及它挂在主表 ID 还是处理过程 ID 上，写进 B20 的取法。
- 业务记录 ID 是全公司共用的编号，只按它反查会撞上别的业务（见文档清单字段说明），取附件时必须同时限定业务名称。

## N2 挑几张单到管理页面核对（G46 第二轮）

每类最多挑 2 张最近建的单。

```sql
WITH lp AS (
    SELECT DISTINCT ON (pr."ProblemID") pr.*
    FROM "BrazilProblemProcess" pr
    ORDER BY pr."ProblemID", pr."ID" DESC
),
bm AS (
    SELECT b."ID", b."OrderNumber"::text AS no, b."AddDate",
           btrim(COALESCE(b."IsStopLine"::text, '')) = '是' AS stopped,
           COALESCE(b."IsSupplement"::int, 0) = 1            AS supp
    FROM "BrazilProblemList" b
    WHERE b."Status"::int <> -1
),
bc AS (
    SELECT bm.no, bm."AddDate", bm.stopped, bm.supp,
           btrim(regexp_replace(COALESCE(lp."PrecautionPolicy"::text, ''), '<[^>]+>|&nbsp;', '', 'g')) <> ''  AS has_prev,
           btrim(COALESCE(lp."PlanCompleteDate"::text, '')) <> ''                                            AS has_plan,
           btrim(regexp_replace(COALESCE(lp."UnCostShiftReason"::text, ''), '<[^>]+>|&nbsp;', '', 'g')) <> '' AS has_uncost,
           btrim(COALESCE(lp."SQEResult"::text, '')) <> ''                                                   AS has_sqe,
           (SELECT count(*) FROM "BrazilProblemProcess" x WHERE x."ProblemID" = bm."ID") > 1                AS multi
    FROM bm
    LEFT JOIN lp ON lp."ProblemID" = bm."ID"
),
hm AS (
    SELECT d."Numbers"::text AS no, d."AddDate", d."ProblemType"::int AS pt,
           COALESCE(d."IsStop"::int, 0) = 1                     AS stopped,
           btrim(COALESCE(d."InvInfo"::text, '')) LIKE '[%'      AS has_inv
    FROM "OverseasProblemDetail" d
    WHERE COALESCE(d."IsDelete"::int, 0) = 0
)
(SELECT 'B1 巴西：最新一条处理过程填了预防对策' AS "类别", no AS "问题编号" FROM bc WHERE has_prev   ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT 'B2 巴西：填了计划完成日期',           no FROM bc WHERE has_plan   ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT 'B3 巴西：填了未转嫁原因',             no FROM bc WHERE has_uncost ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT 'B4 巴西：有 SQE 确认结果',            no FROM bc WHERE has_sqe    ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT 'B5 巴西：停过线',                     no FROM bc WHERE stopped    ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT 'B6 巴西：需要补料',                   no FROM bc WHERE supp       ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT 'B7 巴西：处理过程不止一条',           no FROM bc WHERE multi      ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT DISTINCT ON (pt) 'H' || COALESCE(pt::text, '空') || ' 海外：问题类型码 ' || COALESCE(pt::text, '空'), no
 FROM hm ORDER BY pt, "AddDate" DESC)
UNION ALL
(SELECT 'H8 海外：停过线',                     no FROM hm WHERE stopped    ORDER BY "AddDate" DESC LIMIT 2)
UNION ALL
(SELECT 'H9 海外：填了物料',                   no FROM hm WHERE has_inv    ORDER BY "AddDate" DESC LIMIT 2)
ORDER BY 1, 2;
```

**结果怎么用**：在管理页面打开每张单的详情，按类别回告下面几点，不必附单号；某类没有挑出单时写「无」。

| B2 | 有没有「计划完成日期」一栏，在哪一块 |

## N3 巴西附件与 8D 挂在主表 ID 还是处理过程 ID 上（2026-10-23 补充，B20）

N1 的两列分不出来：巴西主表 ID 与处理过程 ID 互相重叠。本段用上传时间判断：文档不可能在它所挂的单建单之前上传。

- 「上传早于同号主表建单 1 天以上」不为 0 → 至少这些文档不是挂在主表 ID 上的。
- 「上传早于同号处理过程所属单建单 1 天以上」不为 0 → 至少这些文档不是挂在处理过程 ID 上的。

8D 报告已知挂在处理过程 ID 上，作对照。只输出计数，可以发回。

```sql
WITH d AS (
    SELECT d."frecid", d."AddDate", btrim(d."BusinessType"::text) AS bt
    FROM "DocumentList" d
    WHERE COALESCE(d."EffectFlag"::int, 0) = 0
      AND btrim(d."BusinessType"::text) IN ('巴西制程问题单附件', '巴西制程问题单8D报告', '巴西制程问题单设计更改')
)
SELECT d.bt                                                                                  AS "业务名称",
       count(*)                                                                              AS "文档数",
       count(b."ID")                                                                         AS "有同号巴西主表",
       count(*) FILTER (WHERE b."ID" IS NOT NULL AND d."AddDate" < b."AddDate" - interval '1 day')  AS "上传早于同号主表建单1天以上",
       count(*) FILTER (WHERE b."ID" IS NOT NULL
                          AND d."AddDate" BETWEEN b."AddDate" - interval '1 day' AND b."AddDate" + interval '1 day') AS "上传在同号主表建单前后1天内",
       count(pr."ID")                                                                        AS "有同号处理过程",
       count(*) FILTER (WHERE pr."ID" IS NOT NULL AND d."AddDate" < pb."AddDate" - interval '1 day') AS "上传早于同号处理过程所属单建单1天以上"
FROM d
LEFT JOIN "BrazilProblemList" b     ON b."ID"  = d."frecid"
LEFT JOIN "BrazilProblemProcess" pr ON pr."ID" = d."frecid"
LEFT JOIN "BrazilProblemList" pb    ON pb."ID" = pr."ProblemID"
GROUP BY 1
ORDER BY 1;
```

**结果怎么用**：8D 报告一行应是「早于同号处理过程所属单」为 0。附件一行：「早于同号主表」为 0、「早于同号处理过程所属单」不为 0 时，附件挂在主表 ID 上；反过来则挂在处理过程 ID 上；两个都为 0 时，看「上传在同号主表建单前后 1 天内」占多少，并到管理页面看一张单核对。

## N4 巴西停线级别；海外效果确认、结案结论取哪一列（2026-10-23 补充，B21 与海外单张单详情）

**N4a** 巴西「停线级别」：页面上停过线的单不显示停线级别。本段看这一列在停线、没停线的单上各填了多少，对应到问题分类表里的哪些分类。会输出问题分类表的分类类型与分类名称（配置值，不是业务记录），外传前请过目。

```sql
SELECT btrim(COALESCE(b."IsStopLine"::text, ''))                                         AS "是否停线",
       CASE WHEN btrim(COALESCE(b."ProblemClass"::text, '')) IN ('', '0') THEN '空或0' ELSE '有值' END AS "停线级别列",
       COALESCE(btrim(c."TypeName"::text), '—')                                          AS "分类类型",
       COALESCE(btrim(c."ClassName"::text), '—')                                         AS "分类名称",
       count(*)                                                                          AS "单数"
FROM "BrazilProblemList" b
LEFT JOIN "AfterSaleIssueClass" c ON c."ID"::text = btrim(COALESCE(b."ProblemClass"::text, ''))
WHERE b."Status"::int <> -1
GROUP BY 1, 2, 3, 4
ORDER BY 1, 2, 5 DESC;
```

**N4b** 海外：页面「效果确认结果」「结案结论」取的是主表效果确认，还是处理步骤里对应环节的意见。只输出计数，可以发回。

```sql
WITH m AS (
    SELECT "Id",
           btrim(regexp_replace(COALESCE("Confirmation"::text, ''), '<[^>]+>|&nbsp;', '', 'g')) AS conf
    FROM "OverseasProblemDetail"
    WHERE COALESCE("IsDelete"::int, 0) = 0
),
s AS (
    SELECT DISTINCT ON (st."ProblemId", btrim(st."StepStr"::text))
           st."ProblemId",
           btrim(st."StepStr"::text)                                                            AS step,
           btrim(regexp_replace(COALESCE(st."Opinon"::text, ''), '<[^>]+>|&nbsp;', '', 'g'))    AS op,
           btrim(regexp_replace(COALESCE(st."Result"::text, ''), '<[^>]+>|&nbsp;', '', 'g'))    AS res,
           btrim(regexp_replace(COALESCE(st."Measures"::text, ''), '<[^>]+>|&nbsp;', '', 'g'))  AS mea
    FROM "OverseasProblem_StepLog" st
    ORDER BY st."ProblemId", btrim(st."StepStr"::text), st."Id" DESC
),
e AS (SELECT s.*, m.conf FROM s JOIN m ON m."Id" = s."ProblemId")
SELECT '有效果确认步骤的单' AS "项", count(*) AS "数" FROM e WHERE step = '效果确认'
UNION ALL SELECT '  其中步骤意见与主表效果确认相同',   count(*) FROM e WHERE step = '效果确认' AND op = conf
UNION ALL SELECT '  其中步骤意见为空、主表有值',       count(*) FROM e WHERE step = '效果确认' AND op = '' AND conf <> ''
UNION ALL SELECT '  其中步骤意见有值、主表为空',       count(*) FROM e WHERE step = '效果确认' AND op <> '' AND conf = ''
UNION ALL SELECT '  其中两者都有值但不同',             count(*) FROM e WHERE step = '效果确认' AND op <> '' AND conf <> '' AND op <> conf
UNION ALL SELECT '有结案确认步骤的单',                 count(*) FROM e WHERE step = '结案确认'
UNION ALL SELECT '  其中意见有值',                     count(*) FROM e WHERE step = '结案确认' AND op <> ''
UNION ALL SELECT '  其中结论有值',                     count(*) FROM e WHERE step = '结案确认' AND res <> ''
UNION ALL SELECT '  其中预防措施有值',                 count(*) FROM e WHERE step = '结案确认' AND mea <> '';
```

**结果怎么用**：
- N4a：停线级别只在停过线的单上有值、且对得上「停线级别」一类分类时，它确实是停线级别，B21 只是要不要展示；没停线的单上也大量有值、或对应的是别的分类时，这一列不是停线级别，B21 改为这一列不展示、不再叫停线级别。
- N4b：效果确认步骤的意见与主表效果确认全部相同时，两者都行，取主表；不同时取步骤意见（与国内详情页一致）。结案结论取结案确认步骤里有值的那一列。
