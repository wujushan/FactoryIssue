# 平台反馈：带按钮的追问在多轮上下文里整条消失

| 项 | 内容 |
|---|---|
| 提出方 | 制程问题查询助手（模块编码 `FACTORY_ISSUE`）业务仓 |
| 日期 | 2026-11-02 |
| 类型 | SDK 与平台落库格式不一致（缺陷）。不阻塞上线，影响所有用 `conversation_messages` 拼多轮上下文、又发过带按钮的追问或答后建议的模块 |
| 涉及版本 | `paxsz-forge-core` 0.3.7、`paxsz-forge-platform` 0.3.7 |
| 涉及代码 | `forge_core/conversation.py` 的 `strip_projections`、`conversation_messages`、`_CLARIFY_BLOCK`；`forge_platform/gateway/pipeline.py` 的 `render_clarify_answer`、`render_suggestions_answer` |
| 验证方式 | 测试环境手动多轮对话里看到的现象；本地脚本复现（不连库、不调模型，脚本与输出见文末） |
| 期望答复 | 是否按下文方案 1 改 `strip_projections`，预计哪个 SDK 版本发布 |

## 一句话

平台把带按钮的追问落库时，问句只放进 `<intent_routing_clarify>` 数据块里、块外不留文字；SDK 拼多轮上下文时把这个数据块整块删掉，剩下空串，这一轮的助手消息于是整条被丢掉，模型下一轮看不到自己问过什么、给过哪些选项。

## 业务场景

本助手按用户说的地区找工厂。用户问「今年上半年国内惠州的三个工厂一共出了多少问题？」，「惠州」对上三家工厂，本助手发一个带按钮的追问（`Event.clarify`）：「『惠州的三个工厂』对上了这几家工厂：柯洱斯、亮亮、惠州百富。按哪几家查？」，按钮是「柯洱斯、亮亮、惠州百富」「柯洱斯」「亮亮」「惠州百富」。用户点了「惠州百富」，本助手答了张数。用户接着问「那另外两个工厂呢？」。

第三轮本助手用 `conversation_messages(ctx, request, turns=3)` 取最近几轮交给本地模型理解问题。测试环境里看到交给模型的是：

```text
用户：今年上半年国内惠州的三个工厂一共出了多少问题？
用户：惠州百富
助手：国内……
```

第一轮的追问整条不在，三家工厂的名字也不在。模型只能看到用户先问三个工厂、紧接着说了一句「惠州百富」，中间问了什么不知道，也就答不出「另外两个」是哪两家。

## 当前行为

- `render_clarify_answer`（`forge_platform/gateway/pipeline.py`）的文档串写明：有结构化推荐时只输出数据块，「guide_text 只进块内，块前不再重复一份裸文本（2026-09-10）」，为的是 INFO 前端不把同一句显示两遍。落库正文就是：

  ```text
  <intent_routing_clarify>
  {"guide_text": "…按哪几家查？", "recommendations": [{"label": "惠州百富", "query": "惠州百富", …}, …]}
  </intent_routing_clarify>
  ```

  `render_suggestions_answer` 复用同一个函数，答后建议的引导语同样只在块内。
- `strip_projections`（`forge_core/conversation.py`）的文档串写的是「`<intent_routing_clarify>` 数据块 → 删除（块外的引导话术保留）」，模块级注释也写「喂给模型时整块剥掉，块外的引导话术保留（那是对话内容）」。代码是 `_CLARIFY_BLOCK.sub("", text)`。平台改成只在块内放引导语之后，「块外的引导话术」已经不存在，剥完是空串。
- `conversation_messages` 对每条消息先 `strip_projections`，再 `if content:` 才收进结果，所以追问那一轮的助手消息被整条丢掉；答后建议那一轮只剩块外的正文，引导语与按钮文字丢掉（这一种影响小）。

两处各自都说得通，合在一起就把对话内容丢了：落库为了前端只放块内，剥离为了模型删掉整块。

## 期望

**方案 1（倾向）**：`strip_projections` 不再整块删除，而是把数据块换成一行给模型看的文字：`guide_text`，后面接各按钮的 `label`，例如

```text
「惠州的三个工厂」对上了这几家工厂：柯洱斯、亮亮、惠州百富。按哪几家查？（选项：柯洱斯、亮亮、惠州百富 / 柯洱斯 / 亮亮 / 惠州百富）
```

数据块是平台自己生成的 JSON，结构固定，解析得出来；解析失败时退回现在的删除。`query`、`id`、`name` 不进上下文（与 `label` 重复或对模型没有信息）。落库格式不用动，INFO 前端也不受影响。答后建议的块可以同样处理，或只保留 `guide_text`，由平台定。

**方案 2**：`render_clarify_answer` 在块外再留一份引导语。这会让 INFO 前端把同一句显示两遍，正是 2026-09-10 那次改动要去掉的，不建议。

方案 1 发布后请告知版本号，我们升级 SDK 后复测这个多轮场景。

## 影响范围

- 所有用 `conversation_messages` 拼多轮上下文、发过带按钮的 `clarify` 的模块：追问那一轮在下一轮的上下文里整条消失。用户点按钮回答追问（「惠州百富」「是」「近 30 天」）时，模型看到的是一句没头没尾的话。
- 平台自己的路由澄清（多个助手都可能答时的追问）落库后同样只有数据块，被路由到的模块下一轮也看不到它。
- 发过答后建议（`suggestions`）的轮次：引导语与按钮文字丢掉，正文保留。

## 业务仓的临时做法

- 本助手不在业务仓里绕开 SDK 去重新解析落库正文。
- 「另外两个工厂」这一类改由本助手在会话工作区里记下「地区说法对上的几家、用户选了哪几家」，下一轮由代码按「候选减去选定的」查，不依赖模型从上下文里看出来。这只补上这一个场景；其他追问（取值对不上、认不出的号、缺时间）点了按钮之后，模型仍看不到追问本身，要等方案 1。

## 复现

不连库、不调模型：照平台的 `render_clarify_answer` / `render_suggestions_answer` 生成落库正文，放进一个内存里的假会话，交给 `conversation_messages`。导入 `forge_platform` 需要 `greenlet`，用 `uv run --with greenlet python repro_clarify_history.py` 执行。

```python
"""复现：带按钮的追问落库后，conversation_messages 拼出来的多轮上下文里这一轮的助手消息整条消失。
不连库、不调模型：照平台的 render_clarify_answer 生成落库正文，交给一个内存里的假会话。"""

import asyncio
import importlib.metadata as md
from types import SimpleNamespace

from forge_core.conversation import conversation_messages, strip_projections
from forge_core.events import Event
from forge_platform.gateway.pipeline import render_clarify_answer, render_suggestions_answer

for pkg in ("paxsz-forge-core", "paxsz-forge-platform"):
    print(f"{pkg}=={md.version(pkg)}")

# 第 1 轮：模块按地区说法对上三家工厂，发带按钮的追问
ask = Event.clarify("「惠州的三个工厂」对上了这几家工厂：柯洱斯、亮亮、惠州百富。按哪几家查？",
                    ["柯洱斯、亮亮、惠州百富", "柯洱斯", "亮亮", "惠州百富"],
                    recommendations=[{"id": str(i), "name": "多工厂", "label": o, "query": o}
                                     for i, o in enumerate(["柯洱斯、亮亮、惠州百富", "柯洱斯", "亮亮", "惠州百富"], 1)])
stored_ask = render_clarify_answer(ask.data)
# 第 2 轮：点了「惠州百富」，模块答了张数并给答后按钮
tips = Event.suggestions([{"id": "1", "name": "接着问", "label": "按问题类型统计", "query": "按问题类型统计这些单"}],
                         guide_text="您还可以继续问：")
stored_answer = "国内今年上半年惠州百富共 3 张。\n\n" + render_suggestions_answer(tips.data)

print("\n== 第 1 轮落库的助手正文（render_clarify_answer）")
print(stored_ask)
print("\n== strip_projections 之后")
print(repr(strip_projections(stored_ask)))


class FakeSession:
    def __init__(self, rows):
        self.rows = rows

    async def history(self, conversation_id, limit=10):
        return self.rows[-limit:]


rows = [
    {"role": "user", "content": "今年上半年国内惠州的三个工厂一共出了多少问题？", "message_id": "m1"},
    {"role": "assistant", "content": stored_ask, "message_id": "m1"},
    {"role": "user", "content": "惠州百富", "message_id": "m2"},
    {"role": "assistant", "content": stored_answer, "message_id": "m2"},
    {"role": "user", "content": "那另外两个工厂呢", "message_id": "m3"},  # 当前轮，平台在分发前已落库
]
ctx = SimpleNamespace(session=FakeSession(rows))
request = SimpleNamespace(conversation_id="c1", message_id="m3")
messages = asyncio.run(conversation_messages(ctx, request, turns=3))
print("\n== conversation_messages(turns=3) 给模块的多轮上下文")
for m in messages:
    print(f"{m['role']}: {m['content']}")
```
