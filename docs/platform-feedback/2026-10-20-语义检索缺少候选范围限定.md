## 一句话

`ctx.retrieval.search()` 只能在整张向量表里找最相近的 `top_k` 条；模块没有办法先说「只在这几张单里找」。用户的问题同时带了时间、机型、工厂等条件时，模块只能召回后再按编号求交，条件越窄，求交后剩下的越少，经常是 0 条，而且不报错。

## 业务场景

- 制程问题查询助手管国内、巴西、海外三个域的制程问题单，约 3,000 张（国内约 2,750、巴西约 200、海外约 17），每年新增几百张。
- 「类似问题」：用户描述一个缺陷现象，助手按意思找出历史上最相近的若干张单（默认 10 张）及其处理方式。计划每个域建一张向量表，一单一行，向量化文字是该单的问题描述、原因分析、改善措施等。
- 业务方明确要求：用户同时给了时间、机型、加工厂等条件时，**先按条件缩小范围，再在范围内找最相近的**。典型问法：
  - 「L1400 的制程问题中是否有与音频相关的？」——国内 L1400 的单约百张，音频相关的散在全部约 2,750 张里。
  - 「最近一年有没有涉及喇叭、蜂鸣器的问题？」
  - 「惠州某工厂今年有没有出现过开机花屏？」
- 这些条件要关联机型子表、工厂表等多张原始表（SQL Server），由模块经 `ctx.data.fetch()` 取出符合条件的单号，权限照常生效。向量表里不放这些条件列，也放不全（机型一单多值、工厂按名称近似匹配、时间口径随问法变）。

## SDK 当前行为

模块看到的契约（`forge_core.module.RetrievalPort`）：

```python
async def search(self, query: str, *, source: str, table: str,
                 top_k: int = 50, top_n: int = 10) -> list[Any]
```

平台实现（`forge_data.retrieval.scoped.ScopedRetrieval.search`）多出的参数只有表布局（`dim`、`id_col`、`text_col`、`embedding_col`、`metadata_col`），没有任何限定范围的参数。检索 SQL 的 `WHERE` 只有行级权限片段（`row_scope_sql()` 的产物）：

```sql
SELECT id AS id, content AS content, metadata AS metadata,
       1 - (embedding <=> %(q_emb)s::vector) AS score
FROM domestic_issue_vec
WHERE (1 = 1)                      -- 只有行级权限片段
ORDER BY embedding <=> %(q_emb)s::vector
LIMIT %(k)s
```

`retrieve()` 的顺序是：向量近邻取 `top_k` → 本地 rerank → 截到 `top_n`。模块拿到手时已经截过两次。

## 缺口

1. **模块能做的只有召回后求交**：在整表召回 `top_k`，再与 `ctx.data` 取到的候选单号求交。候选集窄（如某机型约百张、全表约 2,750 张）时，候选里真正相关的那几张未必排进全表的前 `top_k`，求交后常为 0，回答就成了「没有找到」，而事实上有。
2. **加大 `top_k` 代价高，也治不了根**：rerank 作用于全部 `top_k` 条再截到 `top_n`。想让求交前的候选够多，就得把 `top_n` 也设成 `top_k`，等于每次 rerank 上百条与本问题条件无关的文本；且 rerank 排的是全表相关性，不是候选内的相关性。
3. **行级权限片段不能借用**：`row_scope_sql()` 的 WHERE 由权限平台下发决定，模块不能往里加业务条件（也不该）。

## 期望

**方案 1（倾向）：`search()` 增加候选编号限定参数**

```python
hits = await ctx.retrieval.search(
    "音频 喇叭 蜂鸣器 无声 杂音",
    source="forge_mart_factory_issue", table="domestic_issue_vec",
    restrict_ids=["2811", "2824", ...],   # 新增：只在这些 id 里找；None 表示不限定
    top_k=50, top_n=10,
)
```

- 编译成 `WHERE (<行级权限片段>) AND id = ANY(%(restrict_ids)s)`，与行级权限是 AND 关系，**不放宽任何权限**。
- 候选编号由模块经 `ctx.data.fetch()` 取得，取的过程已受权限约束；限定只会让结果更少，不会更多。
- `id` 是向量表主键（平台建表时已有索引），候选集小的时候规划器可以直接走主键取行再精确排序，不依赖 HNSW，召回是完整的。
- `restrict_ids` 为空列表时直接返回空、不发 SQL；审计记录候选个数即可，不必记录全部编号。
- 编号个数建议设上限（如 5,000），超限报错，由模块改用不限定的检索。

**方案 2：向量表带上可过滤列，`search()` 接受结构化过滤条件**

`VectorizeSpec` 增加 `filter_columns`（从治理后表照抄到向量表的真实列），`search()` 接受与 `QuerySpec.filter` 同形的条件，按同一套列白名单编译。更通用，但要改建表 DDL 与回填、要处理列级权限；本模块的条件（一单多机型、工厂名称近似匹配）也很难全部落成向量表上的列，仍要先在原始表上算出候选，最后还是回到「按编号限定」。

## 影响范围

- 任何「语义检索 + 结构化条件」的模块都会遇到：条件越窄，静默少召回越严重，表现为「没有找到」，测试时用宽条件测不出来。
- 与平台已知的「HNSW + 行级权限后过滤的召回塌陷」同一类问题，但发生在模块侧求交这一步，平台的 `hnsw.iterative_scan` 续扫救不了。

## 业务仓的临时做法（平台实现前）

- 每个域一张向量表。没有附加条件时直接检索。
- 有附加条件时：`top_k` 与 `top_n` 都设成该域表的行数与 100 中较小的一个（巴西、海外表很小，等于全表；国内取 100），召回并 rerank 后与候选单号求交，取前 10 张。
- 求交后为 0 或很少时，回答说明「在符合条件的单里没有找到很相近的，结果不保证完整」，不说成「没有」。
- 平台发布方案 1 后，升级 `paxsz-forge-core` / `paxsz-forge-data` 改用 `restrict_ids`。

## 复现

不连数据库。在装有 `paxsz-forge-core` 0.3.4、`paxsz-forge-data` 0.3.0 的环境执行：

```python
"""复现：ctx.retrieval.search 没有业务条件预过滤的入口（不连数据库）。"""

import inspect
from importlib.metadata import version

from forge_core.module import RetrievalPort
from forge_data.retrieval.index import PgVectorIndex
from forge_data.retrieval.scoped import ScopedRetrieval

for pkg in ("paxsz-forge-core", "paxsz-forge-data"):
    print(f"{pkg} {version(pkg)}")

print("\n[1] RetrievalPort.search 签名（模块看到的契约）")
print("   ", inspect.signature(RetrievalPort.search))

print("\n[2] ScopedRetrieval.search 签名（平台实现）")
print("   ", inspect.signature(ScopedRetrieval.search))

print("\n[3] 检索 SQL：WHERE 里只有行级权限片段（这里用无行规则时的 1 = 1）")
idx = PgVectorIndex(dsn="postgresql://unused", table="domestic_issue_vec")
sql, params = idx.build_search_sql(scope_where="1 = 1")
print("   ", sql)

print("\n[4] 模块能做的只有「召回后按编号求交」：候选集窄时命中会被挤出 top_k")
recalled = [f"id{i}" for i in range(50)]          # 全表最相近的 50 张（top_k=50）
candidates = {"id3", "id120", "id480", "id900"}   # 按机型等条件取到的候选（假设 4 张）
kept = [h for h in recalled if h in candidates]
print(f"    召回 {len(recalled)} 张，条件候选 {len(candidates)} 张，求交后剩 {len(kept)} 张: {kept}")
```
