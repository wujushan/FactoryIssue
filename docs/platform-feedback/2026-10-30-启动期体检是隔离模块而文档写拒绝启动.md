## 一句话

平台 0.3.7 启动时，模块声明了未登记的数据源别名、或声明的向量表不存在，结果是**这个模块被隔离下线、平台和其他模块照常启动**；开发者文档几处仍写「平台拒绝启动」「平台起不来」。

## 业务场景

- 本助手要接一个产物库别名 `forge_mart_factory_issue`（文字查找用），并在 `manifest.vectorize` 声明三张向量表。按平台文档，产物库要先由运维建好、登记别名、建出向量表，含这些声明的版本才能装配到同一个环境。
- 业务仓据文档估计「装早了」的后果：文档说平台拒绝启动，那同一测试环境上的其他模块也会一起起不来，所以我们把「含产物库声明的版本什么时候发」当成会影响别人的事来排。
- 写代码前在本机核对时发现，代码里的处置是隔离本模块。后果的范围小得多（只有本助手下线，包括它不依赖产物库的结构化查询），但仍要避免。我们需要一个准确的说法来跟测试环境的协调方沟通。

## 当前行为（代码）

`forge_platform/main.py` 的 `lifespan`：

```python
# 启动期逐模块体检（决策 2026-08-09-模块装载失败隔离）。判据一字未改——依赖成环、
# 数据源/知识库别名未注册、向量表或声明表缺权限承载列，仍然一条都不放过；变的是
# **不合格时谁下线**：是那个模块，不是整个平台。
failures = registry.enforce_startup(data_sources=data_sources, knowledge_bases=knowledge_bases)
```

`registry.enforce_startup` 把每个不合格的模块 `quarantine(...)`，记一条 `module_quarantined`（`reason=data_source_missing` / `vector_scope_missing` 等），平台带着其余模块启动，另记 `platform_started_degraded`。

另一种情形同样值得写进文档：别名登记了但连不上时，`_scan_vector_scope` 只记 `vector_scope_probe_failed` 告警、整个别名的向量表校验跳过，模块照常装载。这一点 `docs/dev/11` 排查表已写，与代码一致。

## 文档写法（与代码不一致的几处）

- `04`「启动即校验」：「缺一个就**拒绝启动**（`DATA_SOURCE_NOT_REGISTERED`）」。代码的处置是隔离该模块，`reason` 为 `data_source_missing`。
- `04` 语义检索一节：向量表缺权限承载列「**缺列即拒绝启动**（`VECTOR_SCOPE_COLUMNS_MISSING`）」。
- `08` mart 前置表：漏了建库登记、漏了建向量表，「平台**拒绝启动**」。
- `11` 阶段 6「没登记就**拒绝启动**」；§5 表「拒绝启动」四行；§6 排查表「平台起不来，`VECTOR_SCOPE_COLUMNS_MISSING`」「平台起不来，别名未登记」。
- `07` `semantic-retrieval`「缺列即拒绝启动」「声明了的向量表不存在也拒绝启动」。

## 期望

**方案 1（倾向）**：以代码为准改这几处文档：写成「该模块被隔离下线（`module_quarantined`，`reason=…`），平台与其他模块照常启动；被隔离的模块一行数据取不到、一次路由不到」，并说明在哪里看（Admin Console 模块页、`GET /healthz` 的 `failed_modules`）。排查表的症状改为「模块不在服务 / 模块页显示隔离」。

**方案 2**：如果某些情形本意仍是拒绝整个平台启动，请在文档里分开写哪几种隔离、哪几种拒绝。

## 影响范围

- 所有要接产物库或声明向量化的模块：上线前排期与风险说明都依据这几处文档。
- 运维排查：文档让人按「平台起不来」去找，实际症状是平台正常、某个模块不在服务。

## 业务仓的做法

- 本仓设计稿按代码行为写：含产物库声明的版本在测试环境建库、登记别名、建出向量表之前不发，理由是本助手整个会被隔离下线，不再写「其他模块一起起不来」。

## 复现

`uv run --with greenlet python repro_startup_quarantine.py`（导入 `forge_platform` 要 `greenlet`，见另一份反馈「本机起平台缺少 greenlet」）：

```python
"""复现：模块声明了未登记的数据源别名、或 mart 别名连不上时，平台启动期体检怎么处置。不连任何库。"""

import json
import os
import tempfile
from collections.abc import AsyncIterator
from pathlib import Path

from forge_core.events import Event
from forge_core.module import (
    DataSourceRef, ForgeModule, ModuleContext, ModuleManifest, ModuleRequest, VectorizeSpec,
)
from forge_platform.config import Settings
from forge_platform.datasources import build_data_source_registry
from forge_platform.registry import ModuleRegistry

MART = "forge_mart_demo"


class Demo(ForgeModule):
    manifest = ModuleManifest(
        code="DEMO", name="demo", profiles=["structured-query", "semantic-retrieval"],
        data_sources=[
            DataSourceRef(alias="info", kind="sqlserver", tables=["CoreINFO.dbo.T"]),
            DataSourceRef(alias=MART, kind="postgres", tables=["t_vec"]),
        ],
        vectorize=[VectorizeSpec(source=MART, vector_table="t_vec", origin_table="t_seg",
                                 id_column="seg_id", text_columns=["seg_text"],
                                 default_cron="10,40 * * * *", metadata_columns=["rid"])],
    )

    async def handle(self, request: ModuleRequest, ctx: ModuleContext) -> AsyncIterator[Event]:
        yield Event.delta("ok")


SQLSERVER = {"type": "sqlserver", "driver": "ODBC Driver 18 for SQL Server", "host": "127.0.0.1",
             "port": 1, "user": "u", "password_env": "REPRO_PW"}
PG = {"type": "postgres", "host": "127.0.0.1", "port": 1, "database": MART, "user": "u",
      "password_env": "REPRO_PW", "connect_timeout": 2}
os.environ.setdefault("REPRO_PW", "x")

for label, cfg in (("A mart 别名未登记", {"info": SQLSERVER}),
                   ("B mart 别名已登记、连不上", {"info": SQLSERVER, MART: PG})):
    path = Path(tempfile.mkdtemp()) / "data_sources.json"
    path.write_text(json.dumps(cfg), encoding="utf-8")
    ds = build_data_source_registry(Settings(data_sources_path=str(path)))
    reg = ModuleRegistry()
    reg.try_register(Demo(), source="repro")
    failures = reg.enforce_startup(data_sources=ds)  # forge_platform/main.py create_app 启动时调的就是它
    print(f"== {label}")
    print("  仍装载的模块:", sorted(reg.all()))
    print("  隔离:", [(f.code, f.reason, f.detail) for f in failures] or "无")
```

实际输出（2026-10-30，日志行略去时间戳）：

```text
[error    ] module_quarantined   code=DEMO detail='数据源别名未在平台注册: forge_mart_demo' reason=data_source_missing source=repro
== A mart 别名未登记
  仍装载的模块: []
  隔离: [('DEMO', 'data_source_missing', '数据源别名未在平台注册: forge_mart_demo')]
[warning  ] vector_scope_probe_failed   alias=forge_mart_demo declared=1 error='ConnectionTimeout: connection timeout expired' impact='本别名的向量表校验整体跳过（存在性 + 权限承载列都未验）' module=DEMO
== B mart 别名已登记、连不上
  仍装载的模块: ['DEMO']
  隔离: 无
```

声明的向量表在一个连得上的库里不存在时，`_scan_vector_scope` 断言①给出「向量表不存在（manifest.vectorize 声明了它）」，`_collect_startup_issues` 同样按 `reason=vector_scope_missing` 隔离该模块（读代码得出，本机没有 PG，未实跑）。

## 状态（2026-11-06）：文档已改，关闭

平台已按方案 1 改开发者文档。本次同步进本仓的 `docs/dev` 里，`04`「启动即校验」与语义检索一节、`06` 给已有向量表补 `metadata_columns`、`07` 各 profile 的平台前置、`08` mart 前置表、`11` 阶段 6 / §5 / §6，以及 `02` 里 ETL 漏权限列那一句，都写成「隔离该模块」。平台与其他模块照常启动，`/healthz` 报 `degraded`，失败模块在 `failed_modules` 与 Console 模块页。

本仓对照已装的 platform 0.3.9（`forge_platform/registry.py` 的 `enforce_startup`）：`/healthz` 的 `failed_modules[].reason` 与日志 `module_quarantined` 仍是 `data_source_missing`、`vector_scope_missing`。文档排查表用 `DATA_SOURCE_NOT_REGISTERED`、`VECTOR_SCOPE_COLUMNS_MISSING` 称呼同一类缺口。设计与 G2 继续用健康检查上的 `reason`。

`11` 阶段 1「权限承载列那行为空就是没配对」不在本稿范围，仍见 `2026-10-26-无权限管控时向量化自检说法冲突.md`。
