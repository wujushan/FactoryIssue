## 一句话

`11` 说「`forge vectorize ddl` 的『权限承载列』那行是空的，就说明 `field_mappings` 没配对」，`07` 和 `04` 却说「无需权限管控的向量库别填 `field_mappings`」。按后者配置的模块，那一行必然是空的，照 `11` 的自检就会被判成配错；而 SDK 的实际行为与 `04` 一致：不填映射时启动期校验整段跳过，不会拒绝启动。

## 业务场景

- 本助手管国内、巴西、海外三个域的制程问题单。权限只有表级：每个域的主表允许或拒绝，域内没有按人变化的行级、列级规则。
- 按文字找单要用语义检索。治理任务把叙述文字落进本模块的 mart 库（每域一张文字表、一张分段表、一张向量化来源表），平台按 `manifest.vectorize` 生成每域一张向量表。域权限靠「每域一套表、权限平台逐表允许或拒绝」落地，所以这些表上没有任何权限承载列。
- 按 `07`、`04`，这种「无需管控的向量库」不给 mart 别名填 `field_mappings`。
- 业务开发者照 `11` 阶段 1 做本机自检时，会看到「权限承载列：（无）」，再读到「空的说明 `field_mappings` 没配对」。最容易出的错是为了让这一行不为空，随手填一条映射（例如把某个协议字段指到一个并不存在、也不需要的列）。那样一来，平台启动期会要求每张向量表和每张声明的治理后表都带这一列，缺列即 `VECTOR_SCOPE_COLUMNS_MISSING` / `TABLE_SCOPE_COLUMNS_MISSING` 拒绝启动；为了过校验再去建一列空的权限列，口径就被搞脏了。

## 文档与 SDK 当前行为

**`11-vectorization-and-governance.md`「阶段 1 · manifest 声明」末段原文：**

> 此刻在你机器上能做的自检只有一条：`uv run forge vectorize ddl` 打得出 DDL，且「权限承载列」那行不是空的（空的说明 `field_mappings` 没配对，检索期就没有行级过滤可编译）。

**`07-capability-profiles.md`，`semantic-retrieval` 小节「平台 / 运维前置」原文：**

> 故同一 mart 别名下的向量表**权限口径须一致**；无需管控的向量库别填 `field_mappings`。

**`04-permissions-and-data-access.md`，语义检索小节「推论」原文：**

> 确实无需权限管控的向量库，就别给它填 `field_mappings`（该别名整体跳过校验）；与受管控向量表混在同一别名下是建模错误。

**SDK 实际行为（输出见文末 ①）：**

- `forge vectorize ddl` 用 `scope_columns_for(spec, field_mappings)` 算权限承载列，不填映射时为空列表，打印成「（无）」。
- `_scan_vector_scope` 里「扫到的向量表必须带齐权限承载列」这条断言有 `if not scoped: continue`，`scoped` 由 `mapped_columns(...)` 判断；不填映射即跳过。「声明的向量表必须存在」「`metadata_columns` 必须在表上」两条断言照常执行，不受影响。
- `_scan_table_scope` 开头 `if not mapped_columns(manifest.field_mappings, ref.alias): continue`，不填映射即整个别名跳过。

所以 `04` 的说法与代码一致，`11` 的那句只对「该别名有权限管控」的模块成立。

**那一行为空确实有一种是配错**（输出见文末 ③）：别名下只写了表级映射（`{"<别名>": {"<某张治理后表>": {...}}}`），漏了向量表。这时 `mapped_columns` 非空、别名算作受管控，但 `resolve_field_mapping` 对向量表解析出空映射，DDL 同样打印「（无）」，向量表启动期校验也不报缺列（它按表解析，向量表的要求列本来就是空集）；要到检索期权限平台对这张向量表下发行规则时才 fail-closed。`11` 的自检想抓的应该是这种情况，但现在的写法区分不了它和「本来就不管控」。

## 期望

**方案 1（倾向，只改文档）：把 `11` 阶段 1 的自检改成有条件的**，例如：

> 该 mart 别名在 `field_mappings` 里有映射时，`uv run forge vectorize ddl` 每张向量表的「权限承载列」那行都应列出它要承载的物理列；为空说明映射没覆盖到这张向量表（常见于只写了表级映射、漏了向量表）。无需权限管控的向量库不填 `field_mappings`，那行为「（无）」是预期，不要为了让它不为空去补映射。

**方案 2（在方案 1 之外，可选）：`forge vectorize ddl` 把两种「无」分开打印**

- 别名在 `field_mappings` 里没有任何映射：打印「（无：该别名未配 `field_mappings`，按无行级权限管控处理）」。
- 别名有映射（`mapped_columns` 非空），但对这张向量表解析为空：打印告警，例如「（无）⚠ 该别名有权限映射，但没有覆盖这张向量表」。

这样本机自检就能直接抓住「表级映射漏了向量表」，不用靠读文档判断。

## 影响范围

- 所有「无需权限管控的 mart / 向量库」模块（只有表级权限，或完全不管控）照 `11` 自检都会得出错误结论。
- 方案 1 只改文档；方案 2 只改 CLI 打印，不改 DDL、回填 SQL 与启动期校验。

## 业务仓的临时做法（平台改文档前）

- 按 `04` 与上面核对的实际行为办：mart 别名不填 `field_mappings`；`forge vectorize ddl` 的「权限承载列」那行为「（无）」视为预期，不为通过 `11` 那条自检去填映射。
- 本模块的数据源与治理决策里写明了这一点，评审与后续开发照它执行。

## 复现

不连任何服务。在装有 `paxsz-forge-core` 0.3.7、`paxsz-forge-data` 0.3.2、`paxsz-forge-platform` 0.3.7 的环境执行。数据源用假连接器，只返回 `information_schema.columns` 形状的列清单：向量表按平台生成的 DDL 建好，带 `metadata_columns` 两列，没有任何权限列。

> 本机项目环境里没有 `greenlet`，`_scan_vector_scope` 会导入 `forge_platform.bus` → `sqlalchemy.ext.asyncio`，缺它时报 ImportError，所以用 `uv run --with greenlet python repro.py` 执行。

```python
"""复现：mart 别名不配 field_mappings 时，`forge vectorize ddl` 的「权限承载列」行为空，
而启动期两道校验都不拒绝启动。不连库：数据源用假连接器，只返回 information_schema 形状的列清单。"""

import importlib.metadata as md
from types import SimpleNamespace

import pandas as pd

from forge_core.module import DataSourceRef, ModuleManifest, VectorizeSpec
from forge_platform.cli import _vectorize_plan
from forge_platform.registry import ModuleRegistry

for pkg in ("paxsz-forge-core", "paxsz-forge-data", "paxsz-forge-platform"):
    print(f"{pkg}=={md.version(pkg)}")

ALIAS = "forge_mart_demo"
spec = VectorizeSpec(
    source=ALIAS, vector_table="issue_seg_vec", origin_table="issue_seg_src",
    id_column="seg_id", text_columns=["seg_text"], metadata_columns=["issue_id", "field"],
)


def make_registry(field_mappings):
    manifest = ModuleManifest(
        code="DEMO", name="demo", profiles=["semantic-retrieval", "governance-etl"],
        data_sources=[DataSourceRef(alias=ALIAS, tables=["issue_text", "issue_seg", "issue_seg_vec"])],
        field_mappings=field_mappings, vectorize=[spec],
    )
    return SimpleNamespace(all=lambda: {"DEMO": SimpleNamespace(manifest=manifest)})


# 假连接器：向量表按平台生成的 DDL 建好（id/content/embedding/metadata + 两列 metadata + content_hash），
# 治理后表各有自己的列。两条 information_schema 查询按 SQL 里有没有 udt_name 区分。
VEC_COLS = ["id", "content", "embedding", "metadata", "issue_id", "field", "content_hash"]
OTHER = {"issue_text": ["issue_id", "issue_no", "desc_norm"],
         "issue_seg": ["seg_id", "issue_id", "field", "seq", "seg_text", "seg_norm"]}


class FakeConnector:
    vector_index = object()  # 非 None = 当作 PG 别名

    def query(self, sql, params=None):
        rows = [("public", "issue_seg_vec", c) for c in VEC_COLS]
        if "udt_name" not in sql:
            rows += [("public", t, c) for t, cols in OTHER.items() for c in cols]
        return pd.DataFrame(rows, columns=["table_schema", "table_name", "column_name"])


data_sources = SimpleNamespace(get=lambda alias: FakeConnector())

for label, fm in (("① 不配 field_mappings（无行级管控）", {}),
                  ("② 对照：配了 departmentId -> dept_id", {ALIAS: {"departmentId": "dept_id"}}),
                  ("③ 对照：只给 issue_text 写了表级映射，漏了向量表", {ALIAS: {"issue_text": {"departmentId": "dept_id"}}})):
    reg = make_registry(fm)
    print(f"\n== {label}")
    for item in _vectorize_plan(reg):
        s, cols = item["spec"], item["scope_columns"]
        # 与 forge vectorize ddl 打印的那一行逐字相同（见 forge_platform/cli.py::_cmd_vectorize_ddl）
        print(f"-- 权限承载列（由 field_mappings[{s.source}] 自动算出）: {cols or '（无）'}")
        print(f"-- 建表语句: {item['statements'][0]}")
    print("向量表启动期校验 _scan_vector_scope:", ModuleRegistry._scan_vector_scope(reg, data_sources) or "无问题，不拒绝启动")
    print("治理后表启动期校验 _scan_table_scope:", ModuleRegistry._scan_table_scope(reg, data_sources) or "无问题，不拒绝启动")
```

读法：

- ①：「权限承载列」那行为「（无）」，两道启动期校验都不报问题。这是本模块的配置，按 `04` 是对的，按 `11` 会被判成「没配对」。
