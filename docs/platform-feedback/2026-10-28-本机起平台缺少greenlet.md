# 平台反馈：业务仓 `uv sync` 之后 `uv run forge dev serve` 起不来（缺 greenlet）

| 项 | 内容 |
|---|---|
| 提出方 | 制程问题查询助手（模块编码 `FACTORY_ISSUE`）业务仓 |
| 日期 | 2026-10-28 |
| 类型 | SDK 依赖声明缺陷（打包问题）。不阻塞业务开发，有临时做法 |
| 涉及版本 | `paxsz-forge-platform` 0.3.7；解析到的 `sqlalchemy` 为 2.1.6 |
| 涉及代码 | `paxsz-forge-platform` 的依赖声明 `sqlalchemy>=2.0.36`；`forge_platform/cli.py` 的 `_cmd_dev_serve` 导入 `forge_platform.main`，后者经 `forge_platform/admin_auth.py` 导入 `sqlalchemy.ext.asyncio` |
| 验证方式 | 本机执行（不连任何服务），脚本与输出见文末 |
| 期望答复 | 是否按下文方案 1 修依赖声明，以及预计版本 |

## 一句话

平台声明的是 `sqlalchemy>=2.0.36`，没有带 `asyncio` 附加项；SQLAlchemy 2.1 起 `greenlet` 只随 `sqlalchemy[asyncio]` 安装，于是按模板建好的业务仓 `uv sync` 之后没有 `greenlet`，`uv run forge dev serve` 在导入平台时就报 ImportError。

## 业务场景

- 业务仓开发指引（模板生成的 `AGENTS.md` / `README.md`「常用命令」）让开发者用 `uv run forge dev serve` 在本机起迷你平台，验证模块能装配、寒暄与权限前置答得对。
- 本仓按模板的 `pyproject.toml` 把 `paxsz-forge-platform>=0.3.7` 放在 dev 依赖里，`uv sync` 时解析到了当前最新的 `sqlalchemy` 2.1.6。
- 执行 `uv run forge dev serve` 立即报错退出，模块一行都没有加载。

## 当前行为

- `paxsz-forge-platform` 0.3.7 的 `Requires-Dist` 里与 SQLAlchemy 有关的只有 `sqlalchemy>=2.0.36`。
- `sqlalchemy` 2.1.6 的 `Requires-Dist` 里，`greenlet` 只出现在 `extra == "asyncio"` 下。
- 平台在 `admin_auth.py` 顶层导入 `sqlalchemy.ext.asyncio`，SQLAlchemy 导入这个子模块时要求 `greenlet`，没装就抛：

  > ImportError: The SQLAlchemy asyncio module requires that the Python 'greenlet' library is installed.  In order to ensure this dependency is available, use the 'sqlalchemy[asyncio]' install target:  'pip install sqlalchemy[asyncio]'

- 同样的原因，业务仓里凡是导入 `forge_platform.bus`、`forge_platform.main` 的本地脚本都会失败。

## 期望

**方案 1（倾向）**：平台把依赖改成 `sqlalchemy[asyncio]>=2.0.36`。平台本来就用异步引擎，这是它实际需要的安装目标；改后业务仓重新 `uv sync` 即可，无需改业务仓配置。

**方案 2**：平台直接声明 `greenlet>=1`。效果相同，但与 SQLAlchemy 自己给出的安装目标不一致，以后 SQLAlchemy 再调整附加项时还要跟着改。

两种都需要发一个平台补丁版本；发布后请告知版本号，业务仓抬 `paxsz-forge-platform` 下界并执行 `uv sync`。

## 影响范围

- 所有业务仓在本机 `uv run forge dev serve`，以及任何导入平台网关模块的本地脚本、单测。
- 平台正式部署环境若同样按 `sqlalchemy>=2.0.36` 解析到 2.1，也会在启动时失败；若部署环境锁在 2.0.x（2.0 在常见平台上默认带 `greenlet`），则暂时不受影响，但下次升级依赖时会出现同样的问题。

## 业务仓的临时做法（平台修依赖前）

- 本机起平台用 `uv run --with greenlet forge dev serve`，导入平台网关模块的脚本用 `uv run --with greenlet python <脚本>`。不改 `pyproject.toml`，免得平台修好后留下多余的直接依赖。

## 复现

在按模板建好、执行过 `uv sync` 的业务仓里执行 `uv run python repro_greenlet.py`：

```python
"""复现：业务仓按模板 `uv sync` 之后，`forge dev serve` 导入平台即因缺 greenlet 失败。不连任何服务。"""

import importlib.metadata as md
import importlib.util

for pkg in ("paxsz-forge-platform", "sqlalchemy"):
    print(f"{pkg}=={md.version(pkg)}")
print("platform 声明的 sqlalchemy 依赖:", [r for r in md.requires("paxsz-forge-platform") if r.lower().startswith("sqlalchemy")])
print("sqlalchemy 声明里含 greenlet 的行:", [r for r in md.requires("sqlalchemy") if "greenlet" in r])
print("greenlet 已安装:", importlib.util.find_spec("greenlet") is not None)
try:
    import forge_platform.main  # noqa: F401  —— `forge dev serve` 的 _cmd_dev_serve 第一步就导入它
    print("import forge_platform.main: OK")
except ImportError as exc:
    print("import forge_platform.main:", type(exc).__name__, str(exc)[:160])
```
