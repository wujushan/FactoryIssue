# 平台反馈：声明了 `require_privileges=True` 的模块，在 Admin 调试对话与 `forge dev serve` 里取不到数

| 项 | 内容 |
|---|---|
| 提出方 | 制程问题查询助手（模块编码 `FACTORY_ISSUE`）业务仓 |
| 日期 | 2026-10-28 |
| 类型 | 平台行为与文档不一致（缺口）。不阻塞上线，影响调试 |
| 涉及版本 | `paxsz-forge-core` 0.3.7、`paxsz-forge-data` 0.3.2、`paxsz-forge-platform` 0.3.7 |
| 涉及代码 | `forge_platform/auth.py`：`build_full_access_tree`（`"privileges": {}`）与 `build_test_access_tree`（`"privileges": {"defaultEffect": "ALLOW", "dataScope": []}`）；`forge_platform/cli.py`：`_cmd_dev_serve` → `DevAuthProvider`；`forge_platform/gateway/admin_api.py`：调试对话用 `build_full_access_tree`；`forge_platform/gateway/pipeline.py`：只有 `auth_source == AUTH_SOURCE_INFO` 且配了按需拉取时才按需解析权限；`forge_data/access/scoped.py`：`_resolve_table_scope` |
| 验证方式 | 读源码 + 本地脚本实测（不连库，脚本与输出见文末）；`forge dev serve` 端到端实测 |
| 期望答复 | 是否按下文方案 1 让两条旁路授权树也给「全放开」权限，以及预计版本 |

## 一句话

测试通道的授权树给的是合法的「全放开」权限，所以 `require_privileges=True` 的模块能测；Admin 调试对话与 `forge dev serve` 默认授权树给的却是空权限 `{}`，解析成 `privileges=None`，这类模块的 `ctx.data.describe()` 与一切取数都抛 `PrivilegesRequiredError`，在这两处没法调试。

## 业务场景

- 本助手管国内、巴西、海外三个域的制程问题单，三个域分别授权，默认拒绝。为了防止权限平台漏发权限时静默放开，模块声明了 `manifest.require_privileges=True`（`docs/dev/04`「高敏模块的 opt-in fail-closed」）。
- 每轮开头调一次 `ctx.data.describe()` 判断本轮可查的域（`docs/dev/04`「`describe()`」：零 DB 往返、与取数共用表级判定），再决定查哪些域。拿不到权限判断时，按业务口径答「暂时无法确认您的查看权限，请稍后再试」，三个域都不出数。
- 开发与运维要在 Admin 调试对话里问几句看模块答得对不对，开发者要在本机 `forge dev serve` 里验寒暄、权限前置。这两处现在都只能拿到上面那句「暂时无法确认」，看不到任何取数路径。

## 当前行为

- `auth.build_test_access_tree` 的说明写得很清楚：

  > 与 build_full_access_tree 只差一处，但那一处是关键：privileges 给的是 `{"defaultEffect": "ALLOW", "dataScope": []}` 而**不是** `{}`。
  >
  > 协议里 `{}`/缺失 = 「未声明约束」，解析成 `privileges=None` → 对声明了 `manifest.require_privileges=True` 的高敏模块，取数层会 fail-closed 抛 PrivilegesRequiredError

- `auth.build_full_access_tree`（Admin 调试对话、`DevAuthProvider` 都用它）给的正是 `"privileges": {}`。
- 这两条入口都不按需解析权限：调试对话的 `auth_source` 是 `admin_bypass`；`forge dev serve` 的 `/v2/chat` 虽是 `info`，但本机没配按需拉取（启动日志 `privileges_on_demand` 为 disabled）。于是取数层拿到的是授权树里的 `privileges=None`、`privileges_resolved=False`，`_resolve_table_scope` 在 `require_privileges=True` 时抛 `PrivilegesRequiredError`。
- `describe()` 同样走 `_resolve_table_scope`，所以连「判断可查的域」这一步都过不去。
- 文档侧：`docs/dev/04` 只说 `require_privileges=True` 时「privileges 缺失/空时 `ctx.data` 取数直接抛」，没提这两条调试入口会落进这个分支；`docs/dev/01`、`06` 介绍 `forge dev serve` 时也没提要配 `--tree`。

## 期望

**方案 1（倾向）**：`build_full_access_tree` 与测试通道同样给 `{"defaultEffect": "ALLOW", "dataScope": []}`。理由与 `build_test_access_tree` 的说明相同：这两条入口本来就是「已在入口完成鉴权、全模块放行」的旁路，给一份合法且全放开的权限，红线代码一行不改，`require_privileges=True` 的模块也能调试。

**方案 2**：维持现状，但在 `docs/dev/04`「高敏模块的 opt-in fail-closed」与 `docs/dev/01`「本地跑起来」写明：声明了 `require_privileges=True` 的模块，Admin 调试对话取不到数；`forge dev serve` 要用 `--tree <授权树文件>` 给一份带权限的授权树。

方案 1 改后，方案 2 的文档说明仍建议保留 `--tree` 的用法：要在本机验「部分域有权」「三域都无权」这类分支，本来就要自己给权限。

## 影响范围

- 所有声明 `require_privileges=True` 的模块：Admin 调试对话里所有要取数的问题都失败；本机 `forge dev serve` 不带 `--tree` 时同样失败。
- 测试通道 `/test/*` 不受影响（已给全放开权限）。正式链路不受影响（按需从权限平台拉取）。

## 业务仓的临时做法（平台答复前）

- 模块照常保持 `require_privileges=True`；拿不到权限判断时答「暂时无法确认您的查看权限，请稍后再试」，不出数。这正是没拉到权限时的业务口径。
- 本机 `forge dev serve` 用 `--tree` 指一份授权树文件，权限按本模块的权限写法构造（只申请国内、三域都无权等几种）；数据源用一份只登记别名、指向不可达地址的 `data_sources.json`（`describe()` 不连库）。
- 在平台答复前，不在 Admin 调试对话里验本模块的取数。

## 复现

不连库：数据源用不执行 SQL 的假连接器，只调 `describe()`。导入 `forge_platform.auth` 需要 `greenlet`（见同日另一份反馈「业务仓 `uv sync` 之后 `uv run forge dev serve` 起不来」），所以用 `uv run --with greenlet python repro_debug_tree.py` 执行。

```python
"""复现：`require_privileges=True` 的模块在 Admin 调试对话与 `forge dev serve` 的授权树下取不到数，
测试通道却可以。不连库：数据源用不执行 SQL 的假连接器，只调 `describe()`（零 DB 往返）。"""

import importlib.metadata as md
from types import SimpleNamespace

from forge_core.module import DataSourceRef, ModuleManifest
from forge_data import DataSourceRegistry, Dialect, ScopedDataAccess
from forge_data.datasources.base import ParamStyle
from forge_platform.auth import build_full_access_tree, build_test_access_tree

for pkg in ("paxsz-forge-core", "paxsz-forge-data", "paxsz-forge-platform"):
    print(f"{pkg}=={md.version(pkg)}")

manifest = ModuleManifest(
    code="DEMO", name="demo", require_privileges=True,
    data_sources=[DataSourceRef(alias="info", kind="sqlserver", tables=["CoreINFO.dbo.Issue"])],
)
module = SimpleNamespace(manifest=manifest)
registry = SimpleNamespace(all=lambda: {"DEMO": module}, has=lambda c: c == "DEMO",
                           get=lambda c: module)


class NoDb:
    name, dialect, param_style = "info", Dialect.SQLSERVER, ParamStyle.QMARK

    def query(self, sql, params=None):
        raise AssertionError("不该连库")


sources = DataSourceRegistry()
sources.register(NoDb())


def try_describe(label, tree):
    node = tree[0]
    print(f"\n== {label}")
    print("privileges:", None if node.privileges is None else node.privileges.model_dump(exclude_none=True))
    # 与 forge_platform.bus.ModuleBus._build_scoped_data 同样的构造；旁路授权树不按需解析，privileges_resolved=False
    data = ScopedDataAccess(
        registry=sources, agent_node=node, field_mappings={}, allowed_sources={"info"},
        require_privileges=manifest.require_privileges, data_sources=manifest.data_sources,
        privileges_resolved=False,
    )
    try:
        print("describe():", [t.table for c in data.describe() for t in c.tables])
    except Exception as exc:  # noqa: BLE001
        print("describe():", type(exc).__name__, "-", str(exc)[:80])


try_describe("Admin 调试对话 / forge dev serve（build_full_access_tree）", build_full_access_tree(registry))
try_describe("测试通道 /test/*（build_test_access_tree）", build_test_access_tree(registry))
```

端到端：本机 `uv run --with greenlet forge dev serve`（不带 `--tree`，数据源登记了 `info`、`erp`）向本模块发「你好」，模块按上面的临时做法答「暂时无法确认您的查看权限，请稍后再试」；换成 `--tree` 指一份带权限的授权树后，权限前置按树里的权限判域，答复正常。
