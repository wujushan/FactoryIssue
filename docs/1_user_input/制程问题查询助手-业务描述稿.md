# 制程问题查询助手业务描述稿

> 只写业务定位、范围、可查对象与常用口径。不含技术选型与实现方案。
> 各域已落盘口径以 `docs/2_landed/<域>/business_description.md` 为准。海外尚未落盘的口径在文末标明，不写成已确认规则。

## 业务定位

制程问题查询助手面向公司内部参与制程质量问题的人员，只读查询国内、巴西、海外三个域的制程问题。它回答「有哪些、到哪一步、怎么处理的、停了没有、结案没有」，不代替源系统填单、审批、上传或改状态。

三个域的单据各自独立。单号前缀国内是 `ZC`，巴西是 `BR`，海外是 `HW`。用户点明某一域时只查该域；只说「制程问题」而没有点明域时，三个域分别查询再汇总。某一域没有权限时，该域不出数，有权限的域照常计入。

## 范围

助手覆盖制程问题从发现、分类、跟进与处理，到停线、改善和结案的查询。可以按时间、加工厂、机型、物料、问题类型、状态、跟进部门或单号筛清单，也可以看一张单的处理过程，或按机型、工厂、问题类型、时间段做汇总。用户用缺陷现象描述时，按现象查找类似问题。

各域边界：

| 域 | 管什么 | 不管什么 |
| --- | --- | --- |
| 国内 | 国内工厂制程问题。整机看关联生产订单；物料标识为「物料」时另看小板订单和其他在线订单 | 不把退货、订单版本修订当作专项场景；问到时按已有内容回答 |
| 巴西 | 巴西工厂产线上的制程问题，含费用、补料、8D | 不含海外工厂单据。没有国内那种结案后的责任归属部门 |
| 海外 | 海外工厂制程问题。加工厂是海外工厂名称；另有国内工厂。含已选现象、可能原因、物料、PN、发货单和附件 | 停线口语、问题类型空值、默认时间范围等尚未落盘，见文末 |

默认不查已删除单据。国内已删除需用户明确要求才列出。巴西状态为「已删除」的单据排除，草稿和已终止仍在查询范围内。

## 可查对象与常用口径

### 三域共用的说法

| 用户说法 | 口径 |
| --- | --- |
| 制程问题、制程相关问题、制程单 | 该次查询范围内的全部问题单，不按「问题类型」再筛一刀 |
| 工厂制程、制程优化、硬件问题、物料问题等 | 点名了具体类型时，才按问题类型筛选 |
| 制程、制程类 | 没有这个类型，不能当成某一类问题 |
| 单号（`ZC` / `BR` / `HW` 开头） | 定位这一张单 |
| 某部门跟进的、某人跟进的 | 问题跟进部门、问题跟进人 |
| 当前谁在处理 | 当前处理人，随最新处理节点变化 |
| 未结案、进行中、没完成 | 还没有到达该域的结案完成状态 |

国内结案完成是「已完成」；「结案确认」仍算未结案。巴西结案完成是「已结案」。

### 国内

问题类型为：硬件问题、软件问题、物料问题、资料问题、工厂制程、结构问题、制程优化。

| 用户说法 | 口径 |
| --- | --- |
| 停线中、目前停线、正在停线 | 停线中、重启审核、审核通过、填写重启方案。不含已经重启、没有停线 |
| 停线、曾经停线、发生过停线 | 曾经停过线，已经重启的仍算 |
| 给出时间、没说现场发现 | 按建单时间筛 |
| 现场发现、发现日期 | 按现场发现日期筛 |
| 责任部门、定责、责任归属 | 结案后的责任归属部门，不是问题跟进部门 |
| 问题责任人 | 没有与问题跟进人同义的个人定责。问当前谁在处理，看当前处理人 |

物料问题可以看 CAR（纠正预防措施报告）。问题等级为 A、B、C。

### 巴西

问题类型为：设计问题、结构问题、生产问题、制程优化、硬件问题、物料问题、其他。写成「其他」加备注时，类型仍是「其他」，备注单独展示。

| 用户说法 | 口径 |
| --- | --- |
| 停线、是否停线 | 曾经发生过停线。重启后不改回「否」 |
| 停线状态、是否已重启 | 是否已经标记停线重启 |
| 停线级别 | 用级别名称，不用内部编号 |
| 某部门的问题、责任部门 | 没有定责部门。按问题跟进部门理解 |
| 问题跟进部门、问题跟进人 | 取该单最新一条处理过程上的人员及其部门 |
| 需要 8D、8D 报告 | 「是否需要回复 8D」和已经上传的 8D 文件是两件事。文件以文档名称打开预览 |
| 已删除 | 排除。待提交、已终止仍可查 |

工厂按巴西工厂名称筛选，一个单可以写多个工厂名称。大机型按产品名称。PN 经发货侧申请单解析为机型名称。不良率由不良数量和生产数量得出。

### 海外（已落盘）

| 对象 | 口径 |
| --- | --- |
| 已选问题现象 | 一单可有多条，标准现象和手填现象混在一起，用中文分号连成一段文字 |
| 可能问题原因 | 标准现象下可供选择的原因清单，不是单上已经写下的原因分析 |
| 物料 | 看料号、描述、供应商编号、供应商名称。料号与 PN 不是同一套编号 |
| PN | 主表 PN 对应机型名称；发货单上的 PN 用发货单自己的编号 |
| 系列 | 展示单上已有文字 |
| 问题等级 | A+、A、B、C；空为未填写 |
| 问题跟进部门、问题跟进人 | 先有部门，再有该部门下的一个或多个跟进人 |
| 当前处理人 | 问题单流转到最新节点时的处理人 |
| 状态 | 从指定责任人、责任人确认、IQC、工厂制程分析、SQE、设计更改、效果确认、结案确认，到已完成 |
| 不良率 | 按单上原文展示，保留百分号或千分号 |
| IQC 意见 | 退回仓库，或继续使用 |
| 涉及发货单 | 可有多行，看 PO、发货单号、日期、PN、版本、订单数量和备注 |
| 附件 | 未删除的文档。预览地址三域相同：对应到文档清单的一行后，用文档名称打开 |
| 问题编号 | `HW` 加年月加 3 位序号，如 HW2609001 |
| 问题类型 | 硬件问题、软件问题、物料问题、其他、工厂制程、结构问题、制程优化 |
| 加工厂、国内工厂 | 加工厂是海外工厂名称。国内工厂是另一列，存工厂码 |
| 建单时间、发现日期 | 建单时间、发现日期是两列。发现日期也叫现场发现日期 |
| 停线字段 | 是否停线在重启后仍为「是」。停线状态为停线中、已经重启、没有停线 |
| 处理步骤 | 同一环节名称只留最新一条 |

### 海外尚未落盘

下列说法还不能写成固定口径：「停线中」和「曾经停线」各看哪一列；用户给了时间但没说现场发现时，用建单时间还是发现日期；没给时间时是否默认一段时间；只说人名或部门、没有「跟进」时默认查哪一列；问题类型的空值和枚举以外的值怎么展示；已选问题现象要不要带上现象分类名称。
