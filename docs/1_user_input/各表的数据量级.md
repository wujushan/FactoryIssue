## 关键结论

1. **数据量级很小**：三个问题主表合计不到 3,000 行，属于典型 OLTP 小表，任何 JOIN / 全表扫描都毫无压力，无需特别优化索引。
2. **国内是绝对主力**：占三表 92%（2,758/2,974），2022 年是峰值（764 条），之后稳定在 400~600/年。
3. **巴西次之且稳定**：199 条，年均 60~80 条，2024 年才开始有数据。
4. **海外几乎可忽略**：仅 17 条，2024 年起零星出现，基本可以视为低频业务。
5. **明细/步骤表量级**：`ZCTracking_ProblemSteplog`（14,834）和 `ZCTracking_OtherOrder`（18,179）比主表大 5~6 倍，属于 1:N 明细，JOIN 时注意基数。
6. **真正的大表是 DocumentList（193 万）和 Inventory / NewProduct（9 万级）**——如果后续要联表查附件或物料，注意这些表的性能。
