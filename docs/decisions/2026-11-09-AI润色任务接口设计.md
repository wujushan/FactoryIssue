## 0. 已澄清

开发者 2026-11-09 定，两项都按默认做法：

| 编号 | 问题 | 结论 |
|---|---|---|
| Q1 | INFO 页面能不能按 HTML 收发富文本栏 | 能：页面把编辑器里的 HTML 原样放进 `query`（TinyMCE `getContent()`），收到结果后原样放回编辑器（`setContent()`）；图片是已上传的链接 `<img src="…">`。`2_landed`「图片、表格和格式」据此成立 |
| Q2 | 页面要不要边生成边显示 | 不要：本助手生成完、检查通过后再发出结果，页面先收到「正在润色」，几秒到几十秒后一次拿到结果 |

## 1. 范围

只做一件事：润色一栏的原文，返回润色后的内容。各栏按同一套通用规则润色（`2_landed`「通用润色」）。

不在本接口里：写回问题单；按钮放在哪、谁能点、结果怎么显示（业务方与 INFO 前端定）；对话框里润色（不做，见 §10）；参考其他单的处理经验；点评原文缺什么、给补充提示（`2_landed`「返回什么」）；多个版本、语气或长短选项。

## 2. 协议给的约束

依据：INFO 对接 v2 协议 §2.1、§3.1.1、§3.2、§3.3、§3.6、§3.8、§4；平台适配通知「业务页面助手调用从对话调用中分离」；已装的 paxsz-forge-core 0.3.9、paxsz-forge-platform 0.3.9 源码（`gateway/api_v2.py` 的 `tasks` 与 `_start_turn`、`ext_param.py`、`gateway/pipeline.py`、`forge_core/module.py` 的 `TaskSpec`）。

| 协议与实现 | 对本接口的约束 |
|---|---|
| 页面调用走 `POST /v2/tasks`；`target`、`ext_param.task` 必填，任务码要在 `manifest.tasks` 声明，否则 `400 UNKNOWN_TASK` | 声明一个 `TaskSpec`；页面把 `target`、`task` 写成常量 |
| 身份用触发润色的人本人的 token 与工号，`user_id` 与 token 不符 `401 USER_TOKEN_MISMATCH` | 不另设身份参数 |
| 被加工的正文放 `query`，`query` 进会话历史与审计；平台不校验它非空 | `query` 只放这一栏的原文；原文为空由本助手报错 |
| 其余参数放 `ext_param`：除 `task` 外的键平台不解析、不校验、原样交给模块；不入库、不进历史，只进平台归档；序列化后 ≤ 64KB、嵌套 ≤ 6 层，超了开流前 `400 invalid_param` | 栏目种类、字数上限、问题编号、同单参考内容都放这里；同单参考内容传纯文字 |
| `ext_param` 不参与权限判断 | 问题编号只用来找单，取数照常按调用人的权限 |
| 模块收到的请求与 `/v2/chat` 逐字一致，平台要求模块不区分入口 | `handle()` 只按 `ext_param.task` 分派；`/v2/chat` 带同样的 `ext_param` 也会得到润色 |
| `TaskSpec` 有 `code`、`name`、`description`、`query`、`ext_param_schema`、`data_scope`；任务码写在 manifest 里，加任务码要发版 | 只声明一个任务码，栏目种类做成参数，「加栏目改配置即可」（`2_landed`「栏目种类」）才成立 |
| 统计按「模块 × 任务码」细分 | 统计分不出栏目，本助手在日志里记栏目种类 |
| 事件类型只有 delta、tool_call、tool_result_meta、table、chart、citation、progress、clarify、suggestions、error、end；协议说 `delta` 按序拼接即答案正文；平台把 `delta` 原样转发，把 `table` 原样转发并投影成 Markdown 表格落库 | 只返回润色结果这一块，走 `delta`；不用 `table` |
| 任务会话不进会话列表、最近使用，也不生成标题 | 每次润色不额外占用模型 |
| 同一会话同时只能有一轮（`409 CONVERSATION_BUSY`）；同一用户同时进行中的最多 3 轮，与对话共用（`429 TOO_MANY_RUNNING_TURNS`，部署可调） | 每次润色不带 `conversation_id`；页面在一栏润色进行中时禁用这一栏的按钮 |
| 断开连接不停止生成；停止要调 `POST /v2/chat/{request_id}/stop` | 用户关掉弹窗时页面可以调停止，不调也不影响结果 |
| `/v2/modules` 每个助手带 `tasks`（`code`、`name`、`description`、`query`、`ext_param_schema`） | 页面据「有这个任务码」决定显不显示按钮 |
| `require_privileges=True` 在 `fetch` / `query` / `raw` / `describe` 时检查（`forge_data` 的 `ScopedDataAccess`；2026-11-10 按评审更正，原写「只在取数时」），不取数也不调 `describe()` 的分支不受影响 | 润色本身不受权限拉取影响；按编号取数时拿不到权限按「查不到」处理 |
| 平台适配通知：业务仓升级到 core ≥ 0.3.9（本地 dev serve 用 platform ≥ 0.3.9）；`/test/chat` 不检查任务是否声明，要另写单元测试用 `manifest.find_task` 核对 | 见 §8 |

## 3. 任务声明

```python
TaskSpec(
    code="domestic_polish",
    name="国内制程问题填单润色",
    description="INFO 管理页面国内制程问题单的【AI润色】：润色一栏的填写内容",
    query="这一栏当前的内容：富文本栏放编辑器里的 HTML，5Why 的问或答放纯文字",
    ext_param_schema={...},  # §4.2 的 JSON Schema，只作文档与 Console 展示，平台不据它校验
)                            # data_scope 用默认的 "user"
```

## 4. 请求

### 4.1 请求体

```json
POST /v2/tasks
Authorization: Bearer <触发润色的人本人的 INFO token>

{
  "query": "<这一栏当前的内容>",
  "user_id": "<触发润色的人的工号>",
  "target": "FACTORY_ISSUE",
  "ext_param": {
    "task": "domestic_polish",
    "field": "measures",
    "max_length": 2000,
    "issue_no": "ZC2026110001",
    "context": { "reason": "<同一表单里刚写的原因分析，纯文字>" }
  }
}
```

不传 `conversation_id`、`file_ids`、`attributes`。

### 4.2 `ext_param` 的键

| 键 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `task` | ✅ | string | 固定 `"domestic_polish"` |
| `field` | ✅ | string | 栏目种类，见 §4.3 |
| `max_length` | ✕ | 正整数 | 这一栏最多能存多少字符，润色结果不超过它。按返回内容原样数字符，富文本栏连 HTML 标记一起数，与库里的列宽同一口径。页面应当传；没传时用配置里这一栏的默认值 |
| `issue_no` | ✕ | string | 问题编号（`ZC` 开头）。传了就按编号查这张单已保存的内容作参考；建单页还没有编号时不传 |
| `context` | ✕ | object | 页面发来的同单其他栏内容，见 §4.4；和按编号查到的同名项冲突时以它为准 |

其余的键忽略。

### 4.3 `field` 的取值

| 取值 | 栏目 | 原文与结果的格式 | 默认字数上限 |
|---|---|---|---|
| `problem_desc` | 问题描述 | HTML | 不限 |
| `reason` | 原因分析 | HTML | 不限 |
| `five_why_question` | 5Why 的问 | 纯文字 | 不限 |
| `five_why_answer` | 5Why 的答 | 纯文字 | 不限 |
| `measures` | 改善措施 | HTML | 2000 |
| `prevention` | 预防对策 | HTML | 900 |

这是润色规则配置的初始版本，格式与默认上限随栏目在配置里定义。管理员加了新栏目，页面传新的 `field` 即可。默认上限取自国内主表这两列的列宽。

### 4.4 `context` 的键

都可选，只传页面上有的；正在润色的这一栏不用传。内容传纯文字（TinyMCE `getContent({format: "text"})`），参考用不到图片，带 HTML 容易超过 64KB；传了 HTML，本助手去掉标签再用。

| 键 | 类型 | 说明 |
|---|---|---|
| `problem_type` | string | 问题类型，如「硬件问题」 |
| `model` | string | 机型；「物料」单不传 |
| `material` | string | 物料名称或料号 |
| `problem_desc`、`reason`、`measures`、`prevention` | string | 同单这几栏的当前内容 |
| `five_why` | array | 已有的 5Why，按先后排列，每项 `{"question": "…", "answer": "…"}`，待答复的 `answer` 为空串；不含正在润色的这一条 |
| `current_question` | string | 润色 5Why 的答时，这一答对应的问。`field` 为 `five_why_answer` 时**必传**：一单可能有几条待答复的问，按编号认不出是哪一条 |

嵌套最深是 `ext_param → context → five_why → 一项 → 字符串`，5 层。

### 4.5 典型调用

| 场景 | `field` | 要带的 |
|---|---|---|
| 建单页润色问题描述 | `problem_desc` | 没有 `issue_no`；`context` 带问题类型、机型或物料 |
| 责任人确认表单里润色改善措施 | `measures` | `max_length`；同一表单里刚写、还没提交的原因分析放进 `context.reason`（按编号查不到它）；`issue_no` 用来补问题描述等已保存的内容 |
| 答复一条 5Why | `five_why_answer` | `context.current_question`；前面的问答放 `context.five_why`，或只带 `issue_no` 由本助手去查 |

## 5. 本助手怎么处理

1. 校验 `ext_param`：`field` 在配置里、`max_length` 是正整数、润色 5Why 的答带了 `current_question`。不通过发 `POLISH_BAD_PARAM`。
2. 原文为空，或去掉图片、表格后没有文字：发 `POLISH_EMPTY`；去掉图片、表格后的文字超过配置里的原文长度上限（初始 3,000 字）：发 `POLISH_TOO_LONG`。两种都不调用模型。
3. 取同单参考内容：先用 `context`，再按 `issue_no` 补没给的项（主表的问题类型、料号、问题描述、原因分析、改善措施、预防对策，机型子表的机型，5Why 表的问答）。按编号查不到、没有权限或取数出错时跳过，不报错。
4. 富文本栏把图片和表格换成占位标记，只把文字交给模型；提示按「固定规则 + 这一栏是什么 + 配置里的额外要求（初始为空）+ 同单参考内容 + 原文」组成，各栏是同一套通用规则，不按栏目设写法要点（`2_landed`「通用润色」「润色规则的配置」）；原文与参考内容放进明确的数据区，其中像指令的话不执行。
5. 检查结果：不超过字数上限；占位标记一个不少、顺序不变；没有多出原文与参考内容里没有的数字、料号、日期（分条的序号除外）。不通过重试一次，仍不通过发 `POLISH_FAILED`。
6. 通过后把图片、表格放回原位，发出结果。

## 6. 响应

### 6.1 事件

| 顺序 | 事件 | 内容 | 页面怎么用 |
|---|---|---|---|
| 1 | `progress` | `stage` 为「正在润色」 | 可显示等待状态，也可忽略 |
| 2 | `delta`（一条或几条） | 润色结果，格式见 §4.3。**按序拼起来就是完整结果** | 拼起来放进输入框或预览；不要按 Markdown 渲染 |
| — | `error`（出错时代替 2） | `code`、`message`，见 §6.3 | 显示 `message`，不动原文 |
| 末 | `end` | `status` 等 | 本次结束 |

页面只在收到 `end`、`end.status` 为 `completed`、并且没有 `error` 时才用结果替换原文。`stopped`（调了停止）或 `interrupted`（超时、平台重启）时结果可能不完整，不要用。

### 6.2 结果格式

- HTML 栏：每段一个 `<p>…</p>`；原文里的 `<img>`、`<table>` 原样放回原位置，表格里的文字不改；加粗、颜色、字号不保留。
- 纯文字栏：段落之间用换行。
- 原文不需要修改时，原样返回。

### 6.3 错误

平台在开流前返回的错误（`400 invalid_param`、`400 UNKNOWN_TASK`、`401`、`403 NOT_AUTHORIZED_FOR_MODULE`、`404 MODULE_NOT_REGISTERED`、`409`、`429`、`503`）见协议 §2.2、§3.2、§3.8，页面照协议处理。

本助手在开流后以 `error` 事件返回（`fatal: true`，随后仍有 `end`）：

| code | 场景 | message |
|---|---|---|
| `POLISH_EMPTY` | 原文为空，或去掉图片、表格后没有文字 | 请先填写内容再润色 |
| `POLISH_TOO_LONG` | 去掉图片、表格后的文字超过原文长度上限（初始 3,000 字，配置可改；定稿后按 D52 补） | 内容较长，请分段润色 |
| `POLISH_BAD_PARAM` | `field` 不认识、`max_length` 不是正整数、润色 5Why 的答没给 `current_question` | 润色参数有误，请联系系统管理员 |
| `POLISH_FAILED` | 模型出错，或结果重试后仍没通过检查 | 这次没有润色成功，请稍后重试或手动修改 |

`message` 可以直接显示给用户，不含字段名和内部细节。

## 7. 会话与并发

- 每次润色不带 `conversation_id`，平台每次新开一个任务会话；它不在用户的会话列表里，`query`（原文）进这个会话的历史，`ext_param` 不进。
- 共用一个会话号时，同一会话一次只能有一轮，再点会得到 `409`，所以不要共用。
- 同一用户同时进行中的最多 3 轮，与对话共用。页面在一栏润色进行中时禁用这一栏的按钮，收到 `429` 时提示稍后再试。

## 9. 取舍

1. **一个任务码 + `field` 参数**：加栏目不用发版。代价是平台统计页分不出各栏调用量，由本助手日志补。
2. **不设格式参数**：格式随栏目在配置里定。同一种栏目在不同页面格式不同时，在配置里加一种栏目。
3. **用问题编号，不用内部 ID**：本助手已有按编号查单的写法。
4. **生成完、检查通过后再发出**（Q2 的默认）：页面不会遇到显示了一半又作废的结果。
5. **检查不通过时报错，不返回原文**：原样返回会让用户以为已经润色过了。

## 10. 留给 G4a 的（已在决策 2026-11-09「AI 润色技术设计」§2、§10、§13 定）

- 对话框里不做润色（`2_landed`「边界」）。查询规划把润色请求归为「超出范围」时，现行回答（`turn/errors.py` 的 `OUT_OF_SCOPE`）末尾是「其他问题请换用对应的助手」，对润色请求有误导，改为补一句「润色请在国内制程问题单页面点该栏旁的【AI润色】」。
- 本助手简介（`declarations.py` 的 `DESCRIPTION`）要不要提润色：简介进路由素材，提了会把更多对话里的润色请求引到本助手，结合路由一起定。
- 润色规则配置文件的格式与校验；`ext_param_schema` 的全文。
