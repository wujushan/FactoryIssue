# 2026-11-11 深入分析与研发改进建议

## 背景

测试反馈：明确要求「深入分析 + 研发改进建议」时，回答仍只有统计结果。现行统计结论的限制是有意的：只用确定性程序结果，不自行归纳记录中的因果，也不默认给建议。本次不是放宽默认回答，而是为用户明确提出的深度分析 / 研发建议增加一条有证据边界的可选路径。

## 决定（G106）

- **仅在本轮用户明确要求深入分析或研发改进建议时启用**。普通清单、统计、单据查询继续现有回答，不自动附加研发建议。
- **先给本轮准确统计与明细**；其后把可核对的记录事实、基于记录的分析判断、研发改进建议分开呈现。
- 深度分析只使用本轮实际查到、当前用户有权查看的结果及用户本轮意图。每条分析判断与建议都必须引用支持它的问题编号和记录原文片段；不能引用本轮结果之外的单据。
- 明确区分记录事实与推断。不得把相关性说成已证实因果，不得把推断写成根因结论。证据不足、记录内容不可用或建议缺乏记录依据时，明确说明证据不足，不输出无依据的判断或建议。
- 分析 / 建议模型不得计算或编造数字、百分比、排名、日期、门槛或目标值；数值事实仍以确定性统计结果和原始记录为准。
- 研发建议作为需要验证的候选方向，不作为已确认的根因或已验证有效的措施。
