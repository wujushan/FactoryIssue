# 2026-11-06 问完整信息时给整张详情

## 背景

开发者 2026-11-06 手动测试「国内单ZC2607022的完整信息，包括生产订单、料号、供应商、问题现象、可能问题原因、可能问题物料、CAR、IQC意见、库存和在线、SQE跟进、5Why等所有字段」。回答在最后一块（是否设计变更）之后接了一串说明：

- 处理过程里没有驳回记录；国内单上没有发货单、费用、8D、补料、库存处理；
- 制程问题单上没有『其他在线订单』『生产订单』『库存和在线』『可能问题物料』这项信息。

说明直接接在上一块最后一项（「处理结果：未填」）下面，在 Markdown 里被并进那一项，排版乱。

从说明的顺序看，模型把整份 ASPECTS 都抄进了 `aspects`，再加上「其他:生产订单」「其他:库存和在线」「其他:可能问题物料」等几项（模型原文没有拿到，是按回答推的）。原因有四处：

- 用户没点到的项（发货单、费用、8D、补料、库存处理、驳回）照「本域没有」逐条说明。
- 「其他在线订单」以「其他」开头，被当成「其他:X」去对显示名，对不上就说没有这项信息。
- 「其他:X」只对「一单一行」的显示名与各块里的栏名，不对块名、环节名：生产订单是一张表、可能的问题物料的栏名是「可能的问题物料」，都对不上。
- 国内 IQC 部分的库存、在线三栏是「不在查询范围、请到管理页面查看」（国内「查询范围」），代码没有接上，说成了没有这项信息。

## 结论

开发者 2026-11-06 提出问题，按以下处理：

1. 问「完整信息」「所有字段」「全部内容」时给该域整张详情，再补上问句里点到、整张详情里没有的项（CAR 报告内容、点到的栏）；用户没点到的项不给、也不逐条说明本域有没有。判断「点到」看问句原话，不看模型抄的列表；「可能问题原因」不算点到「原因」，「可能问题物料」不算点到「物料」，「其他在线订单」不算点到「订单」。
2. 「其他:X」说到块名（生产订单、小板订单、可能问题物料、可能问题原因）或环节名（SQE跟进、IQC确认等）也算对上：这张单有这一块就给，没有就说这张单没有。
3. 本域不在查询范围的项照各域原有说法说明：国内 IQC 部分的库存、在线、CKD 机型三栏与风险订单信息「不在查询范围，请到管理页面查看」，海外的其他在线订单、库存、在线 / 在库退货单号「不在查询范围」。
4. 说明另起一段；几句时列成要点。块内的说明前面是列表项时同样空一行。
5. 问完整信息时，点到的栏（料号、供应商等）放在整张详情之后，各块里已经给过的不再给。

规划提示不变，不用重跑对照集。
