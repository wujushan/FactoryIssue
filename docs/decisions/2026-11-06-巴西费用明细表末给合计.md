# 2026-11-06 巴西费用明细表末给合计

## 背景

开发者 2026-11-06 测试「BR2510001的详情」。费用这一段的写法是：

- 加粗标题「费用明细与合计」，下面是费用美元合计、费用雷亚尔合计、扣款费用（美元）0.00 三行，再加一句「扣款单独列出，未计入费用」；
- 接着是一张表，表名也叫「巴西 BR2510001 费用明细与合计」，表里只有逐条费用，没有合计行。

问题：

- 表名写着「合计」，表里却没有合计行；同一段有两个标题。
- 合计写在表格上方的正文里，离它所合计的两列很远，读的人要自己把「费用美元合计」对到「费用金额（美元）」那一列。
- 这张单没有转嫁，扣款费用是 0.00，那一行和那句说明对用户都没有用。整张详情里，「责任人确认」也会给扣款，和费用转嫁、扣款单号放在一起；之前费用段先给了一次，责任人确认里那一行就因为重复被去掉，只剩扣款单号。
- 金额为 0 的占位行上汇率写成「0」，这是没填的占位值，不是汇率。

## 结论

开发者 2026-11-06 要求「梳理最佳的呈现方式」，按下面几条改：

1. **费用明细与合计是一张表**，与管理页面「涉案金额」相同：全部明细行（含 0 金额行）之后，表末一行「合计」给美元、雷亚尔各自的合计，汇率、备注两格写「—」。合计由沙箱算。表格上方不再另起合计几行，也不另加加粗标题，表名就是标题。
2. **汇率为 0 或空的写「未填」**。
3. **扣款不进费用表**。整张详情里扣款只在责任人确认里给，和费用转嫁、扣款单号放在一起。只问费用、没给责任人确认时，若费用转嫁为是或扣款大于 0，在费用表下面另给一行扣款费用（美元），注明「扣款单独列出，未计入上表的费用合计」；没有转嫁时不提扣款。统计口径里「扣款单独列出、未计入费用」也只在有扣款这一行时写。

4. **列名与列序同管理页面**（开发者 2026-11-06 同日补充）：项目名称、金额（单位：雷亚尔）、汇率（美元兑雷亚尔）、金额（单位：美元），最后是费用备注。原先是费用类型、费用金额（美元）、费用金额（雷亚尔）、汇率、费用备注。备注一列页面叫「备注说明」，这里仍叫费用备注：按文字找单点名字段时用的是这个名字，改了同一栏会有两种叫法。

没有改：0 金额的占位行照旧全部列出（巴西业务描述「看明细时」）。
