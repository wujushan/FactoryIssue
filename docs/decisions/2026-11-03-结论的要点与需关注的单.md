# 2026-11-03 结论的要点与需关注的单

## 背景

开发者 2026-11-03 手动测试「26 年，关于非接的制程问题」。回答的结论是一大段话：各域张数、未结案张数、问题类型分布，再点名三张未结案单，说它们「均涉及天线装配或来料不良」。开发者指出三点：没有重点；所有内容糅在一段里，用户抓不住重点；列了 13 张单，却没有有深度的分析或数据洞察。要求一切围绕数据，不做推测和联想。这不是「非接」一个词的问题，而是所有清单、统计类回答的结论都这样写。

查实的原因：
- **一段话是口径定的**：总述「先给结论」写的是「3 到 6 句的一段话，不用标题和列表」。核数删句后，程序把剩下的句子直接拼接，模型写了换行也会被拼成一段。
- **程序给的数太少**：写结论的提示拼了 11 个初步分析维度，要模型按维度分析，但清单交给它的只有张数、问题类型、机型前五、未结案、停线中几项。积压在哪个环节、未结案拖了多久、等级、按月分布、结案周期都没算；模型又不许自己算，能写的就只剩复述张数和分布。
- **「最需要关注」是最新的几张**：按文字找单交给模型看的是各域按建单时间排在最前的 5 张，模型从里面挑。「均涉及天线装配或来料不良」是模型对这几张单的文字做的归纳；核数只核数字和名称，核不到这种归纳。
- 事实里给了各域张数，提示虽然说不要逐域报，模型照样报了。

## 结论（开发者 2026-11-03 同意 G81–G85 的建议）

1. **结论分三部分**（G81）：加粗的一句结论；至多 4 条要点；「需关注」1 到 3 张单。适用于清单、按文字找单（类似问题除外）、汇总统计、临时统计。结果只有一两张时照旧用一句话；类似问题照旧；单张单详情、按编号查单照旧不写结论。
2. **要点只从程序算出的发现里来**（G82）：程序按集中、积压、严重、重复、时间、时效六项逐项判断，成立的才交给模型，数字、占比、单号都由程序算好。模型只照着写，不从几张单的文字里归纳共同点，不写程序没给的发现。门槛管理员可改。不与同期全部单比。
3. **需关注由程序排**（G83）：停线中 → A+、A 级且未结案 → 未结案里建单最久的 → 不良率最高的（海外不参与），取前 3 张。每张带一个来自数据的理由，再附这张单的问题描述摘要。一张都排不出来时不写。
4. **多取数据**（G84）：积压要看国内处理环节（待办任务），时效要看结案时间（国内、海外处理步骤）。清单、按文字找单、汇总统计都改为取这两样。开发时实测耗时，明显变慢时再定要不要限制。
5. **清单不配图**（G85）：要看分布时用答后的可点选项改问统计。

口径原文落在总述「先给结论」第 2 条、「结论里的要点与需关注的单」（新节）与「什么时候配图」。

## 实现时定的几处

| 事项 | 怎么定 | 理由 |
|---|---|---|
| 谁写哪一部分 | 结论句与要点由模型照着程序给的写；「需关注」整段由程序写（编号带链接、理由来自沙箱、摘要同清单那一列） | 需关注的每一项都是数据，没有要模型措辞的地方；交模型写只多一个出错的机会 |
| 核数 | 结论句逐句核，不合格时带着错处重写一次，仍不合格用原先的模板句（加粗）；要点逐条核，模型写的条数与程序给的项数相同时一条对一条，不合格的那一条换成程序的模板句，条数对不上时全部用模板句 | 一条要点出错不拖累整段；模板句保证每个成立的发现都会出现 |
| 结论句的句数 | 原先剩不到 2 句要重写，现在结论句一句即可 | 新的结构里结论句本来就是一句 |
| 写结论的提示 | 新的一份固定 system（`narrative.POINTS_SYSTEM`），不再拼 `analysis_section` | 分析什么由程序判断；拼上 11 个维度，模型会照着自由发挥。`manifest.analysis_dimensions` 照旧声明（统计的配图与总述那张表） |
| 一问里几段统计 | 要点与需关注只在第一段结论里给一次 | 一样信息只在一处说 |
| 按文字找单看哪些单 | 直接找到的单（关键词搜索的全部、话题的前两组），「可能相关」一组不算 | 那一组不保证找全，也可能不相关 |
| 时间一项 | 建单最多的月份并列超过 3 个时不写 | 说不出哪个月最多 |
| 积压停在哪个环节 | 某域最多的环节不到 2 张、或并列超过 2 个时不写这一域（总述那张表已写明） | 用假数据生成样例时，「停在『IQC确认』『SQE跟进』『责任人确认』『预防对策确认』的最多（各 1 张）」只是罗列，说不出积压在哪 |
| 各域张数 | 三域清单交模型的事实里不再给「各域张数」，每域自己的张数仍在各域的事实里 | 减少逐域报张数的诱因 |
| 门槛的配置 | `answer_params.toml` 新增 `points_max`（4，0–6）、`focus_max`（3，0–5）、`concentrate_share`（40，1–100）、`repeat_min`（3，≥2）、`trend_months`（3，≥2）、`close_min`（5，≥1）；写 0 即不给要点或需关注 | 总述写明这几项管理员可改 |

## 没验证到的

- 本地 Qwen 能不能稳定地按「第一行加粗、每条一行」的格式写，条数对不对得上；对不上时全用模板句，读起来会比较生硬。发包后用「26 年，关于非接的制程问题」与三域清单、按问题类型统计各问一次，看日志 `factory_issue_points_count_mismatch`、`factory_issue_points_templated` 出现得多不多。
- 多取待办任务与处理步骤后清单慢了多少（G84）。发包后对比同一问句改前改后的耗时。
- spike 的写分析一项要按新提示重跑。
