# 2026-10-19 国内「当前状态」：状态文案修订，并行阶段取待办任务

## 背景

业务方《制程问题单状态和当前处理人的展示逻辑》给出国内「当前状态」= 环节 + 处理人、可多行的展示方式：状态 30、36、37（效果确认与预防对策确认并行）从流程待办任务取环节与处理人，其余状态由主状态、IQC 状态、风险订单步骤三段拼成。其中状态文案与现有落盘有 4 处不同（open-questions D11），并行阶段的取法有待确认（D12）。

## 结论

**D11 状态文案**（业务方 2026-10-19 答复）：

| 值 | 改为 |
|---|---|
| 8 | SQE跟进（业务方确认原「SQC跟进」为笔误） |
| 10 | SQE确认 |
| 36 | 效果确认 |
| 37 | 预防对策确认 |

当时另定按环节统计时 36、37 加括注与 30 区分；该条随 D16 取消，见文末。

**D12 并行阶段取待办任务**（业务方 2026-10-19 答复）：

- 业务表名以 `ZCTracking` 开头的任务，业务记录 ID 即国内问题单主表 ID，按前缀匹配。
- 任务标题固定为「国内制程问题单【单号】待××」，环节取「】待」之后的文字。
- 任务人员是单个员工 ID，多人时每人一条记录（源数据字典已补充）。
- 同一环节多人合并一行，先效果确认后预防对策确认；查不到已接受的任务时用状态文案 + 当前处理人兜底（同意建议）。

## 补充：「当前责任人」口径（D15，业务方 2026-10-19 同意建议）

业务方更新说明把当前状态里的人称为「当前责任人」。原口径是国内、海外「当前处理人」= 主表当前处理人姓名列，「当前责任人」只是别称；新说明下国内当前状态里的人有四个来源，并行阶段主表当前处理人也不可靠，原口径会答错或答不全。

结论：

- 当前责任人 = 当前状态各行出现的全部人员，按行给出环节 + 人。国内来源：主状态处理人（主表当前处理人姓名列）、IQC 成员、进行中的风险订单责任人；并行阶段只取待办任务人员。「已完成」的单没有当前责任人。
- 对用户统一叫「当前责任人」，「当前处理人」「当前谁在处理」作别称；海外同名（即主表姓名列）；巴西仍不提供（B6）。国内主表姓名列的显示名改为「主状态处理人」，不单列展示。
- 只说「责任人」时同时给当前责任人与问题跟进人，写明角色；「指定责任人」「责任人确认」环节、「责任人处理结果」「计划完成时间」里的责任人指问题跟进人。（2026-10-22 经 D25 修订国内部分：国内只说「责任人」时给管理页面导出口径的责任人，即按问题类型取对应环节最新一步的操作人，另附当前责任人；见决策 2026-10-22「国内管理页面代码对齐」补记「D25 结论」。巴西、海外不变。）
- 按人查单 / 统计：任一行命中即算，同一单只计一次，一单多人各计一次（多值归属）；「已完成」不计入；同名同姓追问部门。
- 只说人名仍按问题跟进人（G5）；带「手上 / 待处理 / 卡在」的说法按当前责任人。

## 补充：按处理环节筛选与统计看当前状态各行（D16，业务方 2026-10-19 答复）

原建议是筛选、环节统计只看主表状态，一单只落一个环节。业务方否决：源系统管理页面上分别按「SQE跟进」「IQC确认」筛选能命中同一单，本助手要与之一致。

结论：

- 按处理环节筛选：当前状态任一行的环节命中即算。
- 环节统计：一单在当前状态出现的每个环节下各计一次（多值归属），统计口径写明。
- 结案判断不变，只看主表状态。
- 当前状态没有显示的环节不命中（「已完成」只有一行；并行阶段只看待办任务），「看得到才筛得到」。这两种边界情形与管理页面是否一致待核（D19）。
- 取消 D11 中「按环节统计时 36、37 加括注」：改按当前状态各行后，30 在效果确认、预防对策确认下各计一次，36、37 各落一个环节，不再需要括注区分。
