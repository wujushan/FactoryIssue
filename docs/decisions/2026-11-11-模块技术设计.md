# 2026-11-11 模块技术设计：显式请求的深入分析与研发建议

> 本设计是 `docs/decisions/2026-10-27-模块技术设计.md` 的 G106 增补，沿用其计划、权限、取数、统计与呈现边界；业务口径见 `docs/2_landed/business_description.md`「用户明确要求深入分析或研发改进建议」。本变更不改变默认回答或统计结果。

## 1. 触发与覆盖范围

- 只看本轮用户实际发来的问句，用确定性的中文短语白名单识别「深入分析 / 深度分析 / 进一步分析」和「研发改进建议 / 改进建议 / 改善建议 / 优化建议 / 研发改进方案 / 怎么改进」；不让规划模型推断用户想要建议。明确否定按类别关闭（如「深入分析，但不要建议」只启用分析；「不要深度分析」不启用分析）。普通统计、按维度分析、单据「原因与措施」字段、以及「改善措施」作为记录字段都不触发。
- 有明确深入分析请求时生成记录依据与分析判断；有明确研发建议请求时生成记录依据与待验证建议。用户只请求其中一类时不额外呈现另一类。
- 整轮只针对最后一个实际执行的可分析步骤追加一次：`list_issues`、`aggregate`、`text_search`、`custom_stats`、`lookup_numbers`、`issue_detail`。这样多步查询只分析最终范围，不把中间较宽范围误当成最终结果。空结果给证据不足说明；步骤失败、追问、介绍、权限拒绝、重放、换图不启用。
- 单据来源必须是本轮最后一步已经过权限与条件限制的结果 ID。禁止为了找更多证据放宽条件、跨域或借用上轮暂存结果。文字查找的「可能相关」组不纳入；类似问题仅使用本轮展示的相近问题。

## 2. 证据选择与读取

- 统计结果、表格与图表仍由现有确定性流程产出；本功能不改统计脚本、不让模型重算、不改变原统计口径。
- 为控制额外取数与提示大小，整轮最多选 9 张、每域最多 3 张。先按沙箱 `insights.focus` 的确定性顺序选，再按最后一步结果 ID 的稳定顺序补齐；比较结果没有 `focus` 时也按此稳定顺序。单张详情直接按本轮输入顺序。此选择是定性分析用的确定性子集，不是随机样本，不能据此推断总体比例或根因。
- 仅对选中的单据读取证据：清单 / 汇总 / 临时统计 / 按号 / 文字查找结果用既有 `issue_detail` 详情读取路径取本轮原文；其中按文字找单只选直接结果，不选「可能相关」，类似问题只选本轮展示的相近问题。单张详情直接使用本轮已经取到的字段。只纳入问题描述、现象、原因与措施等用户可见文字字段；某字段为空、不可用或无权时不补写、不猜测。
- 每条证据保存所属域、问题编号、字段名及实际交给模型的原文片段；单字段限长，展示与核验都使用同一片段。JSON 只回传证据代号与原文引句，问题编号 / 域 / 字段由代码查证据代号后生成，模型不自报引用身份。

## 3. 模型契约与核验

- 使用新增的独立提示，不修改默认统计结论的 `POINTS_SYSTEM`（其中禁止推断与建议仍然有效）。整轮最多一次额外调用；仅一个 `system` 消息，temperature 0，`max_tokens` 与 `response_format={"type":"json_object"}` 按 SDK 约定传入；调用超时沿用客户端配置，不重试。
- `user` 输入包含本轮问句、最后一步的技能与确定性统计事实、选定证据。禁止引用外部资料或范围外单据；分析只能描述记录范围内的模式、差异或证据缺口；建议是结合记录的候选研发方向，并给出如何核实的办法，不得声称已验证有效。
- 输出固定为 JSON：

```json
{
  "analysis": [
    {"text": "一条基于记录的分析判断", "citations": [
      {"evidence_id": "E1", "quote": "记录中的原文片段"}
    ]}
  ],
  "recommendations": [
    {"proposal": "一条待验证的改进方向", "validation": "如何用后续检查验证", "citations": [
      {"evidence_id": "E2", "quote": "记录中的原文片段"}
    ]}
  ]
}
```

- 代码逐条核验：形状与条数上限；每条至少一个引用；证据代号属于本轮提供项；引用片段去空白后必须是该原文的连续子串，并由代码还原为实际原文。任何无效条目整体丢弃。
- 对模型生成的分析与建议调用现有 `present.narrative.check` 做数字、日期和业务名称核验；另行拒绝模型 prose 中的数字、数量、比例与排名，避免模型复述或改写任何统计值。核验输入仅限本轮问句、确定性统计产物及该条实际引用的原始记录。
- 未作不确定限定的因果 / 根因断言不通过。建议必须在正文中引用原文、明确标成待验证候选方向，并给出包含检查、复测、记录、比对等动作的核实方法；分析由呈现模板明确标为推断，建议标为待验证。
- 事实部分由代码根据同一组证据原样生成；不让模型改写事实或引用。输出不合格、超时、模型缺失或没有足够原文时，不展示未核验的模型内容，改为说明证据不足 / 本轮分析暂未生成。

## 4. 事件顺序与降级

- 所有正常步骤的统计 / 清单 / 图表、统计口径与导出信息照常发完；再针对最后一个实际执行的可分析步骤发独立的分析段，最后仍发既有答后选项。
- 记录事实逐条显示问题编号与字段原文；分析判断与建议各自附代码生成的域、问题编号、字段和原文引句。所选记录不足以代表总体时，明确只作定性举证，不推断总体比例或因果。证据不足时说明，不凑条目。只请求深入分析时不显示建议标题；只请求建议时不显示分析标题；两类都明确请求时分别显示。
- 普通请求与当前事件顺序完全不变，不额外取记录、不额外调用此分析模型、不默认输出建议。

## 5. 验收测试

- 触发白名单、逐类别明确否定、普通统计与按维度分析不触发；只请求深度分析 / 只请求研发建议时的段落差异。
- 集成覆盖清单 / 汇总统计、文字查找、按号 / 单张详情：只引用当前最后一步所选记录，精确显示问题编号与原文；分析段位于统计口径与导出之后；普通问句不新增详情查询或模型调用。
- 检查无结果、没有可引原文、跨域权限不全、使用暂存旧结果、证据代号错误、引文不匹配、模型数字越界、未限定因果断言、模型超时均安全降级；统计表、图与数值仍与原有回归一致。
