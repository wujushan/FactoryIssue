## 结论

**先改再收口。** 两处口径管道的形状对不上，都在单测覆盖之外（单测只用「建单」依据、也没断言「没有结案时间」那一行），
所以测试全绿盖不住：一处会在真实问句上**抛异常让整轮失败**，一处让一条该出的口径**静默不出**。其余实现（红线、

## 必须改

### M1　非「建单」依据的临时统计会抛 `ValueError`、整轮失败

`stats/tasks/custom_frame.py` 把「未计入」拼成三元组 `[dom, basis, n]`：

```python
missing += [[dom, b, n] for b, n in miss]
...
"caliber": {"未计入": missing, ...}
```

但消费方 `skills/custom_stats.py::_add_caliber` 原样丢给 `cal.time_range`，而 `time_range` 只解两元组：

```python
# custom_stats._add_caliber
C.time(cal.time_range(time_text, aggregate.basis_of(run.step), [tuple(x) for x in raw.get("未计入") or []]))
# caliber.time_range
extra = [f"{domain}{BASIS_TEXT.get(b, b)}没填的 {n} 张未计入" for b, n in missing if n]  # ← for b, n 解两元组
```

实测（`runtime/probes/review_s7_caliber.py`）：传三元组 → `ValueError: too many values to unpack (expected 2)`。
`aggregate` 一侧的沙箱给的是两元组 `[basis, n]`、域名另走 `named` 参数，所以统计从不撞上；临时统计多塞了 `dom`。

- **触发条件**：`custom_stats` 一步的时间依据是结案 / 停线 / 现场发现 / 统计日期，且本步范围内有单缺该日期（`vw_time`
  产出非空 `miss`）。例「今年结案的单按结案日是星期几看看」。`basis=建单` 时 `miss` 为空，撞不上——这正是单测与
  spike 都没覆盖到的原因。
- **后果**：`_add_caliber` 无 try/except 保护，异常冒泡到 `execute.run` → 编排 → 整轮失败（比「没算出来」更糟，脚本其实
  已经跑对了，栽在拼口径这一步）。质疑重查、换图走 `replay` 时同样经 `_add_caliber`，一并受影响。
- **建议**：要么 `custom_frame` 照 `aggregate` 只产两元组、把域名单独带出（设计 §8.4 的 `named` 已是这套）；要么
  `_add_caliber` 解三元组、把 `dom` 当 `time_range` 的 `named` 用。后者还能顺带把「巴西结案时间没填的 1 张未计入」
  按域写清，和统计一致。

### M2　「已完成但没有结案确认记录的 N 张未计入」在临时统计里永远不出

`custom_frame.py` 把「没有结案时间」按域拼成 **dict**：

```python
no_close[dom] = int(done["_close"].apply(fi_blank).sum()) if len(done) else 0
...
"caliber": {..., "没有结案时间": no_close}   # {"国内": 2, "海外": 1}
```

消费方 `_caliber_items` 却按 **int** 判断：

```python
n = raw.get("没有结案时间")
if isinstance(n, int) and n:          # dict → isinstance 为假，永远跳过
    out.append(cal.no_close_time(n))
```

实测（`review_s7_checks.py` 与 `review_s7_caliber.py`）：`_caliber_items` 对 `{"国内":2,"海外":1}` 只产出「结案时间：…」
一行，**没有**「已完成但没有结案确认记录的 N 张未计入」。`aggregate` 一侧 `ag_metric_facts` 产的是 `int(len(done) - n)`
（单个整数），所以统计那边照常出；临时统计这边形状不同、被 `isinstance` 吃掉。

- **后果**：脚本用到结案时间 / 结案周期、又有已结案却无结案时间的单时，这些单被排除却不告诉用户——正是设计 §19
  「没有结案时间的张数在沙箱 ① 里按域相加」要给的那句口径，静默丢了。不是数字错，是**该披露的口径缺失**，与临时
  统计「口径照统计那一套」的目标相违。
- **单测盲区**：`test_caliber_follows_the_derived_columns_the_script_uses` 只断言 `"结案时间：" in text`，没断言这一行；
  假数据里也未必有「已结案却无结案时间」的单。
- **建议**：`custom_frame` 直接产 `int(sum)`，或 `_caliber_items` 改成 `cal.no_close_time(sum(n.values()))`（dict）/
  `_num` 式兜底。顺手补一条断言这一行的单测。

> M1、M2 同源：`custom_frame` 的 `caliber` 形状与 `aggregate` 不一致，而两条消费路径各写各的。收口时建议让临时统计
> 的 `caliber` 复用统计那一套形状（设计本就说「口径照统计那一套」），一处对齐两个 bug 一起消。

## 可以考虑（不挡收口）

- **A1 沙箱 AST 检查不是安全边界，别当成边界**。实测（`review_s7_sandbox_reach.py`）脚本能经 `pd.io.common.os` 够到
  `os`、用 `np.loadtxt` 读本进程可见的文件——`os` 不以 `__` 开头，AST 检查放行。这**不是 S7 的缺陷**：真正的硬边界是
  平台沙箱子进程（无凭据、无网络、超时强杀，`forge_sandbox/harness.py` 自己也写明「已知残余面」），模块正确地用了
  `ctx.stats`、没有自造。只是设计 §5.5 把 AST 检查描述成「不许 `getattr`、`__` 属性……防反射」，读起来像是靠它兜安全；
  建议在 §5.5 加半句「AST 检查只为提前报可改的错，隔离靠平台沙箱子进程」，免得日后有人以为这层拦得住逃逸。

- **A2 `handle()` 一侧的数字红线——干净**（任务单点名要查的一处）。`skills/custom_stats.py` 的 `len` 只用于「几个域有
  来源」「要不要写分析（>2 行）」「图有几组」；`stats/custom.py` 的 `len`/`sorted` 只用于检查信息与错误串；`present/charts.py`
  的 `len` 只定样式。没有 `max`/`min`/`sorted`/`sum` 产出给用户的数，没有 pandas 直算。表与图的每个数都来自两次沙箱。✓

- **A3 `docs/dev/09` 自检**：英文/代码列名在形状检查运行期拦下（护栏 `S7_SCENARIOS` 有「英文列名修一次」）；显示名
  取 `glossary_note` 走术语表唯一信源；输入帧排除 `_id`、权限承载列、`_` 开头辅助列与 blind 列（`test_frame_columns_*`
  已覆盖）；>2 行才追加分析段。都符合。一处小提醒：模型返回的单元格 `None` 经 `cs_cell` 仍是 `None`、平台表格投影成
  空格，而非「未填」；临时统计由模型控列，提示也要求空值单列写「未填」，可接受，留意即可。
