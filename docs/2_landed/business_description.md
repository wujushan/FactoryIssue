# 制程问题查询助手 业务描述（总述）

> 本文件写三域共用的定位、范围、跨域规则、常用场景与数据量。各域口径分别见同目录
> `domestic/business_description.md`（国内）、`brazil/business_description.md`（巴西）、
> `overseas/business_description.md`（海外）；链接生成见 `link_rules.md`；字段以 `db_description/` 为准。
> 所有统计类回答都要附「统计口径」说明，规则见下文「统计口径说明」。

## 业务定位

面向公司内部参与制程质量问题的人员，只读查询国内、巴西、海外三个域的制程问题。回答「有哪些、到哪一步、怎么处理的、停了没有、结案没有」，不代替源系统填单、审批、上传或改状态。

**使用者**：处理生产问题的部门人员（生产工程部、质量管理部等）、质量 / SQE 角色、上级领导。领导多看时段统计、工厂 / 类型 / 等级分布与停线、费用态势；处理人员多看待跟进清单、单号详情、改善措施。

**本助手管不着的问题、看不懂的输入**（决策 2026-10-27「G4a 设计时补的口径」补记）：

- 范围以外的问题（天气、写邮件、算术，或本助手没有的数据，如员工入职、销售额、身份证号）：回答「这个问题不在本助手的范围。本助手只查国内、巴西、海外的制程问题，其他问题请换用对应的助手。」并给 3 个常用问法的可点选项（同「你能做什么」，见 `privileges.md`「寒暄与『你能做什么』」）。不编答案，不点名别的助手。
- 问句里点了本助手没有的数据项（「把今年的单列出来，带上跟进人的手机号」）：回答里说明「本助手没有『手机号』这一项」，其余照常作答；整句只问这一项时按上一条答。不拿相近的项顶替。有没有这一项以各表的「用户可见显示名」与术语表为准，同义叫法照常对上（「负责人」即责任人）。
- 只有标点或空白：回答「没能理解这个问题，可以换个说法」，并给同样 3 个选项。乱码或意思不明的输入，请用户说明想查什么，并给几个可点的问法；不猜实体，不按全部单去查。
- 「嗯」「测试」「讲个笑话」这类招呼与闲聊，按「你能做什么」介绍本助手，不讲笑话、不闲聊。

**一行一单**：清单与汇总里一张问题单只占一行。单下的一对多内容先收敛成一行再挂到单上，计数以问题单张数为准。一对多内容既有子表（机型、处理步骤 / 处理过程、订单、发货单、费用、关联申请单、问题现象、风险订单流程等），也有单内的逗号多值或 JSON 列（巴西、海外大机型，海外 PN、物料与已选问题现象，巴西问题现象），还有附件。

## 三个域

三域单据各自独立，表结构、枚举与流程互不相同。

| 域 | 单号前缀 | 管什么 | 不管什么 |
|---|---|---|---|
| 国内 | `ZC` | 国内工厂的制程问题，含 CAR、责任归属部门、生产订单与小板订单 | 退货、订单版本修订不做专项口径，问到时按单上原值答 |
| 巴西 | `BR` | 巴西工厂产线的制程问题，含费用、补料、8D | 没有国内那种结案后的责任归属部门，也没有当前责任人、停线重启时间 |
| 海外 | `HW` | 海外工厂的制程问题，含已选问题现象、可能问题原因、物料、PN、发货单和附件；另记一列国内工厂 | 没有费用、8D、CAR，也没有国内那种结案后的责任归属部门；单上的其他在线订单、库存、在线 / 在库退货单号不在查询范围 |

单号格式统一为「前缀 + 年 2 位 + 月 2 位 + 当月 3 位序号」，如 ZC2109001、BR2404001、HW2609001。

## 跨域规则

- **选域**：用户点明某一域（国内 / 巴西 / 海外），或给出带前缀的单号（按前缀定域）时，只查该域。没有点明域时（如只说「制程问题」），三个域分别查询再汇总。
- **权限**：三域各自授权。某一域没有权限时，该域不出数，有权限的域照常计入。国内 CAR 报告另行授权，见 `privileges.md`「CAR 报告」。
- **汇总呈现**：三域一起查时，各域单据各自查询再合并，不把三域的表合成一张。先给各域小计，再给合计。三域枚举不同，按下文「跨域归并」对齐。无权限的域明说「无权限，未计入」，不说成「没有数据」。
- **清单呈现**：三域一起列清单时按域分开列，每域一张表（三域口径不同，用户点名的列某域可能没有），域内按建单时间倒序；开头给各域张数与合计。列见下文「清单默认列」。某域结果多（上百条）时，表格只列前若干条，全量导出成一个文件，每域一页（条数见下文「回答怎么组织」）。按文字找到的单（关键词搜索、涉及某个话题、类似问题）同样按域分组。
- **已删除**：三域都不查，与管理页面一致（管理页面上已删除的单查不到）。清单、统计、按编号查单、按文字找单都不含已删除的单，也不提示有几张已删除的单；用户要看已删除的单时，说明本助手与管理页面一样查不到。巴西草稿「待提交」和「已终止」不是删除，仍在范围内。

### 跨域归并

**问题类型：同名合并，不按含义归并。** 三域合起来共 10 个类型：

| 问题类型 | 国内 | 巴西 | 海外 |
|---|---|---|---|
| 硬件问题 | ✓ | ✓ | ✓ |
| 物料问题 | ✓ | ✓ | ✓ |
| 结构问题 | ✓ | ✓ | ✓ |
| 制程优化 | ✓ | ✓ | ✓ |
| 软件问题 | ✓ | — | ✓ |
| 工厂制程 | ✓ | — | ✓ |
| 其他 | — | ✓ | ✓ |
| 资料问题 | ✓ | — | — |
| 设计问题 | — | ✓ | — |
| 生产问题 | — | ✓ | — |

- 名称相同才合并（三域的「硬件问题」相加）；名称不同各占一行，不推断彼此等同。
- 汇总表里「该域没有这个类型」显示「—」，「有这个类型但为 0」显示 0。
- 问题类型的「未填」（巴西草稿、海外空值）与海外的「其他（未识别）」也各占一行。
- 用户点名某个类型跨域筛选时，没有该类型的域不计入，统计口径里写明（如「巴西无『工厂制程』类型，未计入」）。
- 问题等级三域相同，都是 A+、A、B、C（与管理页面一致），按等级同名合并；某域某级没有单时显示 0。等级的「未填」单独一行。
- 机型同理：三域一起按机型汇总时，国内的机型与巴西、海外的大机型按名称同名合并，名称不同各占一行。名称按写法统一后再比（见下文「机型与系列怎么对」）。
- 加工厂、问题跟进部门同样按名称同名合并。三域用同一张部门表，同一个部门自然合在一起；三域的加工厂取值各不相同，名称相同才合并。

**状态：跨域只分「已结案 / 未结案」两档。** 三域流程环节不同，不按环节对齐。

| 档 | 国内 | 巴西 | 海外 |
|---|---|---|---|
| 已结案 | 已完成 | 已结案 | 已完成 |
| 未结案 | 除「已完成」外的全部（含结案确认） | 待修改类别、待跟进、待设计更改、待SQE确认、待效果确认、待结案 | 除「已完成」外的全部（含结案确认） |
| 另列 | — | 待提交、已终止 | — |

- 巴西「已结案 + 未结案」少于巴西总单数，差额是另列的待提交、已终止，统计口径里写明另列了几张。
- 用户要看各环节积压时，按域分别给该域自己的环节分布，不合成跨域的环节表。国内按当前状态各行的环节计，一单可落多个环节（见国内业务描述「按处理环节筛选与统计」）。

### 汇总不良率

多张单合起来算不良率（按机型、阶段、月份等）时：

- 不良率 = 合计不良数量 ÷ 合计分母 × 100，保留 2 位小数。国内分母为生产数量，巴西为影响数量。不取各单不良率的平均。
- 不良数量为空，或分母为 0、为空的单不参与这次计算，统计口径里写明有几张不参与。不良数量为空不按 0 计，免得把「没填」当成「没有不良」。
- 海外不良率是单上原文，% 与 ‰ 混用，不汇总，只逐单列出原文；三域一起统计时写明海外未汇总。
- 国内、巴西的分母不同，三域一起统计时分域给出不良率，不合成一个跨域不良率。

### 清单默认列

按条件查清单（按时间、机型、加工厂、物料、问题类型、状态、跟进部门等筛出一批单，如「某机型近期的制程单」「某时段的制程单」），用户没说要哪些列时，每域表格给下面 6 列（决策 2026-10-23「清单默认列」）：

| 列 | 取什么 |
|---|---|
| 问题编号 | 可跳转，见 `link_rules.md` |
| 机型 | 国内取机型，一单多个时去重后用「、」连接；「物料」单写「物料」，与管理页面详情一致。巴西、海外取大机型，规则同各域单张单详情。三域列名都写「机型」 |
| 问题类型 | 各域单上当前的问题类型，显示规则见各域「问题类型」 |
| 不良率 | 各域单张单的不良率：国内取单上已存的值，巴西现算，海外照单上原文 |
| 不良数量 | 单上的不良数量 |
| 问题描述 | 摘要，不给全文：先按 `dirty_data.md`「富文本」剥净图片与格式，再由助手浓缩成一两句话，保留核心内容。摘要里的数字只照抄原文，不做计算 |

- 某列没有值时写「未填」。
- 问题描述摘要取自按文字找单用的整理后文字，这份文字约每半小时整理一次（见「命中后带回什么与时效」）。还没整理进去的单（多是最近约半小时内新建的）问题描述写「新建不久，稍后可见」，不写「未填」，也不去单上现取原文；刚改过描述的单，摘要可能仍是改之前的，不另提示。某域的文字查找表无权时（见 `privileges.md`「域闸门」），该域表格的问题描述一列写「暂不可用」，回答开头说明一次，其他列照常（决策 2026-10-27「G4a 设计时补的口径」及其补记）。
- 结果多、全量导出成文件时，导出文件的列与表格相同，问题描述给剥净图片与格式后的全文，不给摘要；还没整理进去的单同样写「新建不久，稍后可见」。
- 用户点名了要哪些列时按用户说的给（如「列出单号、处理人、问题类型、机型、不良数量、不良率」）；只说「再加上 X」时，在默认列后面加。点名的项本助手没有时，见上文「业务定位」。
- 按文字找单（带回命中处的文字）、按编号查单与单张单详情另有规定，见各自一节。

## 三域共用的说法

| 用户说法 | 口径 |
|---|---|
| 制程问题、制程相关问题、制程单 | 该次查询范围内的全部问题单，不按「问题类型」再筛 |
| 工厂制程、制程优化、硬件问题、物料问题等 | 点名了具体类型时，才按问题类型筛选。类型名称省掉末尾的「问题」、或带「类」时照样认（「软件、硬件、结构三类」即软件问题、硬件问题、结构问题），统计口径的筛选条件写全称。「物料不良」（「高展光电物料不良的单」）等同物料问题，按问题类型筛，与供应商、机型、时间等条件照常组合；明说「物料是 X」「X 物料」时仍按物料名称查（见下文「明说物料」一行） |
| 制程、制程类 | 不是问题类型，不能当成某一类问题 |
| 安全问题、涉及安全的问题（「有没有安全问题」「电池起火的问题」） | 不是问题类型，不按问题类型筛。两路都查、分开列：问题等级为 A+ 的单；文字里涉及安全的单（按下文「涉及某个话题怎么找」找，「安全」是说法清单里的一个话题，如起火、冒烟、爆炸、触电，见 `topic_terms.md`）。按 A+ 查不到单时，回答写明「目前没有登记为 A+ 的单」，再给按文字找到的单。明说「A+ 的单」「A+ 等级」时只按等级查。见下文「问题等级」 |
| 单号（`ZC` / `BR` / `HW` 开头） | 定位这一张单。写法统一、查不到时怎么答，见下文「按编号查单」 |
| 某 CAR 编号（「CAR 编号 XXX 对应哪张单」，或给出 `CAR` + 9 位数字形态的号） | 国内物料问题单上的 CAR 编号精确匹配，一号一单；不需要 CAR 报告权限。详见国内业务描述 |
| 某订单号（「订单 XXXXXX 的问题」，或只给一个 6 位数字） | 国内按生产订单号、小板订单号精确匹配；其他在线订单号、退货单号不用于查单。海外按发货单号（多为 7 位数字）、PO 精确匹配。巴西不支持按订单号查单。详见国内、海外业务描述；各种号怎么认、对不上时怎么答，见下文「按编号查单」 |
| 某机型（「L1400 的问题」） | 国内按机型；巴西、海外按大机型，不按 PN；匹配规则见下文「机型与系列怎么对」 |
| 某系列（「A 系列」） | 国内看机型的系列，巴西看大机型的系列；海外系列不作查询条件，不计入，统计口径里写明；规则见下文「机型与系列怎么对」 |
| 某 PN | 三域同一套 PN。用户给 PN 编码（15 位数字）或 PN 名称（带连字符的型号码，如 `A35-000-RD6-00E0`）都能命中：编码按段精确匹配，名称包含匹配。国内看生产订单上的 PN 编码与 PN 名称；巴西看关联申请单解析出的 PN（PN 编码为 0 的是占位值，不算）；海外看主表 PN（发货单上的 PN 都等于主表 PN，不另外匹配）。三域统一展示为「PN」一项（与管理页面一致），内容为「PN 名称 PN 编码」，一单多个时去重、用「、」连接，找不到名称的只给编码，分开说时叫「PN 名称」「PN 编码」（决策 2026-10-20「PN 统一展示名称与编码」） |
| 某料号（「物料编号」「物料编码」同义） | 国内、巴西按主表料号；海外按物料清单里任一条的料号。国内不匹配小板订单上的料号。「物料编号」指单上料号这个位置，不指 PN 那个位置 |
| 只给一串 15 位数字、没说是料号还是 PN | 料号与 PN 编码是同一套 15 位物料编码，号码本身分不出是哪种。单上料号的位置与 PN 的位置都查，结果分开列出并写明命中在哪（「单上料号为该号的 N 张」「订单 / PN 为该号的 M 张」）；只有一处命中时直接给结果并说明在哪查到；不替用户判断这是料号还是 PN |
| 明说物料（「物料是喇叭的单」「喇叭物料出的问题」「物料名称含电池」） | 只按物料名称查：国内、巴西按存货档案的物料名称包含匹配；海外按物料清单里的描述包含匹配 |
| 问涉及、相关（「有没有涉及喇叭的问题」「喇叭相关问题」「出现过电池鼓包吗」） | 按文字找，分问题本身涉及、处理中提到、可能相关三组。说的是话题本身（「音频问题」）时按整个话题的说法找；说的比话题小（「喇叭」「电池鼓包」「电池卡扣」）时只按意思相同的几个说法找，不展开成整个话题。见下文「涉及某个话题怎么找」 |
| 其他、其它、剩下的、还有别的吗（「其他类型的问题呢」「其他工厂呢」） | 看语境，见下文「『其他』『剩下的』指什么」 |
| 只说「X 的问题」（「喇叭的问题有哪些」「电池问题」） | 物料名称与文字两种都查，分开列出：「单上物料为 X 的 N 张」「文字提到 X 的 M 张」（文字一边按「涉及某个话题怎么找」分组），两边都有的单标出来；只有一边有结果时直接给，并说明是怎么找到的（做法同只给 15 位数字时料号、PN 都查）。X 是机型、系列、加工厂、部门、问题类型等已有的说法时，按那一条查，不套用本条 |
| 某加工厂 | 各域按自己的加工厂查：国内按国内工厂名称包含或相近匹配，命中多个工厂时列出请用户选，地区说法（「惠州的工厂」）与同名的工厂码见国内业务描述「加工厂」；巴西按段匹配巴西工厂名称；海外按海外工厂名称包含或相近匹配，命中多个工厂时同样列出请用户选。只说「工厂」「加工厂」时，海外单上的「国内工厂」不参与 |
| 明说「国内工厂为 X」的海外单 | 按海外单上的国内工厂列筛，名称匹配方式同国内加工厂 |

### 「其他」「剩下的」指什么

「其他」意思随语境变。问题类型里有一个叫「其他」的类型（巴西、海外有，国内没有），但「物料问题和硬件问题各有多少？其他类型的问题呢？」里的「其他」指的是上文没点到的类型。按下面三种情形理解：

- **明说问题类型「其他」**（「问题类型是其他」「其他类的问题」「归为其他的单」）：按问题类型「其他」查。国内没有这个类型，写明未计入（同「跨域归并」）。巴西「其他|备注」的写法同样命中。
- **上文点过某一维的具体取值，再问「其他的呢」「剩下的呢」「还有别的吗」**：指同一维里除已点到之外的其余取值。适用于问题类型、加工厂、机型、部门、问题等级等各维，例如上文问过物料问题、硬件问题，「其他类型呢」指其余类型（含问题类型「其他」）；上文问过惠州百富，「其他工厂呢」指其余工厂。
  - 「上文」指本轮或前几轮里点到的取值；时间、域、其他筛选条件沿用上文。
  - 其余取值只在该域本次范围内有单的取值里取，不列没有单的；三域一起查时各域按自己的取值取其余部分。
  - 回答开头写明「按以下类型统计：软件问题、结构问题……」，用户可以再改。
  - 这一维「未填」的单不算在其余取值里，有的话单独写明张数。
- **没有上文、也没说是哪一维**（只问「有哪些其他问题」）：追问是指问题类型为「其他」的单，还是除某些类型（或工厂、机型）以外的单，给可点的选项，不猜。

系列里的「其它」是没归进具体系列的兜底取值，用户说「其他」「其它」时不当作系列名匹配；明说「其它系列」时按系列查（见下文「机型与系列怎么对」）。

### 机型与系列怎么对

**机型**：按完整名称匹配。

- 不分大小写，忽略空格、连字符、下划线（「A920 Pro」即 A920PRO），不做包含匹配。
- A920MAX、A920PRO 是与 A920 不同的机型。问 A920 时不并入，回答里也不另行提示。
- 用户明说「A920 各型号」「A920 各款」「A920 及衍生型号」时，才一起查 A920 与名称为「A920 + 字母」的机型，分机型给数。A800 这类后接数字的、IM30 这类名称里夹着 M30 的都是别的机型，不算。
- 名称对不上任何机型时，回答没有找到这个机型，请用户核对名称。不改用包含匹配，也不猜相近的名称。

**系列**：国内看机型的系列，巴西看大机型在产品主数据上的系列。海外系列不作查询条件，不计入，统计口径里写明。

- 系列不是「机型名称 + 系列」：A920 属于 A 系列，没有「A920 系列」。
- 按完整名称匹配，写法统一同机型。比较时两边都不看末尾的「系列」二字。
- 对不上任何系列时，列出可选系列请用户选。用户给的是机型名称（如「A920 系列」）时，同时说明这个机型属于哪个系列。

**系列名称不带「系列」二字时**：系列多写作「X系列」，另有「底座」「其它」两个不带「系列」二字的取值（正式镜像计数：底座系列 19 个机型，如 L920、L920PRO、T3510、B99、B910，国内 89 张单；巴西没有）。

- **用户说的词与某个系列名称完全相同**（「底座的问题」「底座类的单」）：主结果按系列查（按物料或文字找会漏掉大部分这类单），各域查法同上。
- **主结果之后另给一句计数**：「另有 N 张其他机型的单在文字或物料里提到底座（多为底座部件），需要可以列出」。计数按上文「只说『X 的问题』」的物料名称与文字两种找法得出，不并进主结果，用户要看再列。
- **明说是部件**（「底座部件」「底座这个零件」「带底座的」）：反过来按物料名称与文字两种查，不按系列查。
- **「其它」除外**：只在明说「其它系列」时按系列查，见上文「『其他』『剩下的』指什么」。
- 以后新增的系列名称不带「系列」二字时同样处理。

### 时间说法怎么换算

- 没写年份的月份、季度指今年的；今年这个月或季度还没到时指去年的（如 3 月里问「11 月」，指去年 11 月）。
- 「26 年」= 2026 年；「Q3」「第三季度」= 7–9 月。
- 两个完整自然年对比（「24 年和 25 年的软件问题增减」）按年度对比给两年数量、增减量、变化率，统计口径写明「2025 年全年与 2024 年全年对比」。用户这时说「环比」照常作答，不纠正措辞；给的是相邻的月份或季度时才按环比理解。
- 「今年」「本月」「本季度」「本周」从期初到今天；「上个月」「去年」「上周」是完整的自然月、自然年、自然周。一周从周一算起，「上周」= 上周一至上周日，「上上周」= 再往前一周的周一至周日。
- 「最近 N 天」「近一年」含今天往前倒推：今天是 10 月 21 日时，「最近 14 天」= 10 月 8 日至 10 月 21 日。「最近 / 近 N 周」按 7N 天、「最近 / 近 N 个月」按 30N 天、「近 N 年」按 365N 天同样倒推：「最近一周」= 近 7 天，「近三个月」= 近 90 天，「近一年」= 近 365 天（今天是 10 月 21 日时为去年 10 月 22 日至今天），「近半年」= 近 180 天，「近半个月」= 近 15 天；回答写明起止日期。「本周」「上周」是自然周，见上一条（决策 2026-10-27「G4a 设计时补的口径」补记）。
- 起止说法：「25 年到现在」「2024 年以来」= 那一段的期初到今天；「截止 2026 年 6 月」= 不限起点、到 2026 年 6 月 30 日；「2026 年 1 到 6 月」= 1 月 1 日至 6 月 30 日；「今年截止 6 月」= 今年 1 月 1 日至 6 月 30 日。「24 年和 25 年」作为一段时间时 = 两年合起来；中间隔开的（「24 年和 26 年」）不合成一段，请用户给出起止日期。「6 月之前」「6 月以后」含不含 6 月说不准，同样请用户给出起止日期（决策 2026-10-27「G4a 设计时补的口径」补记）。
- 「最近」不带数字（「A920 最近咋样」「最近有什么问题」）按近 30 天，含今天往前倒推；回答开头写明「按近 30 天」，并给可点的选项「近 90 天」「今年」（决策 2026-10-26「回答组织方式默认值」）。
- 「这个月比上个月」「本月比上月」：本月按月初到今天、上个月按完整自然月对比，不自动换成同期；回答写明「本月截至今天」，并给可点的选项「按上月同期比」（上月 1 日到上月的今天这一天；上月没有这一天时到上月最后一天）。今天的日子已到或超过上月的天数时（如 10 月 30 日、31 日对 9 月），上月同期就是上月整月，与原来的比法一样，不给这个选项，回答写明「今天已到上月月底这一天，上月同期就是上月整月」。
- 还没结束的期间，回答里写明「截至今天」；统计口径的时间范围一律写出起止日期。上一条的起止说法期末还没到时同样止于今天：3 月问「今年截止 6 月」= 今年 1 月 1 日至今天，写明「截至今天」。
- 写明了年份、整段都还没到的时间（10 月问「2026 年 12 月」「2027 年」）照原样按那一段查，查不到单时说明这段时间还没到，不请用户重给起止日期。没写年份的照上文指去年的（10 月问「12 月」即去年 12 月）（决策 2026-10-27「G4a 设计时补的口径」补记）。
- 节日、农历和口语里上面换算不了的说法（「国庆以来」「春节前后」「年中」）不换算、不估日期，请用户给出起止日期，见下文「必要澄清项」（决策 2026-10-27「G4a 设计时补的口径」补记）。

### 结案时间与结案周期

- **结案时间**只对已结案的单定（国内、海外「已完成」，巴西「已结案」）：
  - 国内、海外：处理步骤里最新一条「结案确认」的发生时间（国内按环节编码 31 认）；
  - 巴西：最新一条处理过程上的结案日期；
  - 已结案却定不出结案时间的单，按结案时间筛选、统计时不计入，写明张数。
- 单张单详情里同样展示，显示名「结案时间」。
- **结案周期** = 结案时间的日期 − 建单时间的日期，按天计，只算有结案时间的已结案单。汇总时给平均、中位数与分档（30 天及以内、31–90 天、91 天及以上）。
- 几个域一起统计结案周期时，各域给各自的平均与中位数。国内、海外的结案时间取法相同，只有这两域时可以合起来算合计；含巴西时不合成一个跨域的结案周期：按域统计的「合计」行写「—」，按问题类型等维度统计时不合成一张表，按域分别给，统计口径里写明。

### 问题等级

三域相同，由高到低为 A+、A、B、C，与管理页面一致。各级定义（管理页面「问题等级」介绍原文）：

- **A+ 类产品质量问题**：「安全问题」类别全部定义为 A+ 等级。
- **A 类产品质量问题**：
  1. 所有涉及安全的事故，例如电池起火爆、充电器/适配器/线材等漏电；
  2. 涉及关键电子器件，如主CPU、存储芯片、卡处理芯片、安全保护器件功能不良问题；
  3. 关键装配物料，如显示屏（LCD+TP）、通讯模块或芯片、打印机严重不良；
  4. 高比例开箱不良，严重客诉问题等，如：软件重大Bug、大面积触发/掉密钥等。
- **B 类产品质量问题**：
  1. A类问题之外的其他功能性问题；
  2. 生产过程中发生，并且已经影响产品交付的，属于B类问题。
- **C 类产品质量问题**：
  1. 非功能性问题，均属于C类问题；
  2. 其余不属于A类、B类的产品质量问题也属于C类质量问题。

- **以单上登记的为准**：用户问「这张单为什么是 A 级」时，给出单上的等级与该级定义；不按定义给单重新定级，也不评判定级对不对。
- **怎么筛**：按显示文字精确匹配，「A 级」只指 A，不含 A+。「A 级及以上」「A 级以上」= A+、A；「B 级及以上」「B 级以上」= A+、A、B。
- **「安全问题」**：定义里的「安全问题」类别不是问题类型，三域的问题类型里都没有它。用户问「安全问题」时按 A+ 等级与文字两路查，见上文「三域共用的说法」。
- **现有数据**（业务方 2026-10-22 正式镜像计数）：三域目前都没有 A+ 的单，按 A+ 查时如实回答目前没有。国内 2024-04-17 起才登记等级，此前建的单都没有等级（1,207 张）；巴西 14 张没填；海外都已填。没有等级的单显示「未填」，按等级统计时「未填」单独一行，统计口径写明原因。

## 按编号查单

用户常拿着一个号来问：待办或邮件里的问题编号、IQC 给的 CAR 编号、计划给的订单号、物流给的发货单号或 PO。用户说了是什么号时按说的查，不按样子猜；只说「订单」「订单号」时国内订单与海外发货单、PO 都查（见上文「三域共用的说法」）。没说时按样子认，下表自上而下认，先命中的为准：

| 号的样子 | 认作 | 查哪 | 规则见 |
|---|---|---|---|
| `ZC` / `BR` / `HW` + 7 位数字 | 问题编号 | 按前缀定域 | 本节 |
| `CAR` + 9 位数字 | CAR 编号 | 国内 | 国内「按 CAR 编号查单」 |
| 6 位数字 | 国内生产订单号、小板订单号 | 国内 | 国内「按订单号查单」 |
| 纯数字带连字符（如「6 位数字-序号」） | 国内生产订单号（少量手填） | 国内 | 国内「按订单号查单」 |
| 7 位数字 | 海外发货单号；前四位是 2021 年以来的年月（月份 01–12）时，也当作省了前缀的问题编号 | 海外；问题编号查三域 | 本节 |
| 15 位数字 | 料号或 PN 编码 | 三域 | 上文「三域共用的说法」 |
| 带连字符、含字母的串 | PN 名称或海外 PO | PN 查三域，PO 查海外 | 本节 |
| `CLAIM` 开头 | 巴西投诉单号 | 巴西，不分大小写、去掉空格后精确匹配 | 巴西「投诉单号」 |
| `ZC` / `BR` / `HW` 以外的 2 个字母 + 7 位数字 | 国内其他在线订单号 | 不用于查单 | 国内「按订单号查单」 |
| 以上都不是（如 12 位数字、带汉字或斜杠） | 认不出 | — | 本节 |

巴西处理过程上的扣款单号、入库单号只在用户明说是哪种号时查，见巴西「查询范围」。

- **写法统一**：问题编号、CAR 编号不分大小写，全角转半角，忽略中间的空格、连字符（`zc2509012`、`ZC 2509012`、`ZC-2509-012` 都是 ZC2509012），统一后照常查，不提示。
- **权限**：只查有权的域。号只可能在一个域（问题编号、CAR 编号、国内订单号）而用户对该域无权时，只答「您没有该域的查看权限」，不说有没有这个号（见 `privileges.md`「域闸门」）；号可能在几个域（7 位数字、15 位数字、带连字符的串）时只查有权的域，写明无权的域未查。
- **已删除的单查不到**：号只对应或只挂在已删除的单上时答法与查不到相同；号同时挂在未删除与已删除的单上时只列未删除的，不提已删除的（见上文「跨域规则」）。

对不上时怎么答：

| 情形 | 怎么答 |
|---|---|
| 问题编号、CAR 编号位数不对或年月不合理（`ZC25090`、`ZC2513001`、`CAR12345`） | 「单号应为前缀 + 年 2 位 + 月 2 位 + 3 位序号，请核对」（CAR 编号提示「CAR + 9 位数字」），不猜 |
| 问题编号格式对，但查不到（含已删除的单） | 「没有找到单号为 X 的问题单（已删除的单查不到），请核对单号」。括号里那句是固定提示，不论这张单是否真被删除都带上；不猜相近的单号，不说这张单已删除 |
| CAR 编号查不到（含只登记在已删除的单、其他类型的单上） | 「没有找到这个 CAR 编号对应的物料问题单（已删除的单查不到），请核对编号」 |
| 订单号、发货单号、PO 查不到（含只挂在已删除的单上） | 「没有找到挂着这个号的单（已删除的单查不到），请核对」。6 位数字另说明本助手不按其他在线订单号、退货单号查单；国内手填带连字符的订单号照国内规则列出请用户选 |
| 单号前缀与用户说的域不一致（「巴西的 ZC2509012」） | 按前缀定域，回答里点出这是国内的单 |
| 巴西待提交（草稿）、已终止的单 | 照常展示，写明状态 |
| 只给 7 位数字 | 按海外发货单号查；前四位像年月时，同时按三域问题编号（补上 ZC、BR、HW）查。命中的分开列出，写明按哪种号找到；都没有时说明按哪几种号查过 |
| 带连字符、含字母的串，没说是什么号 | PN 名称（三域）与海外 PO 都查，命中的分开列出、写明在哪找到；只一处命中时直接给（做法同只给 15 位数字时料号、PN 都查） |
| 一次给多个号（「ZC2509012、BR2601009 现在到哪了」） | 逐个查，合成一张表，一号一行。这是「跨域规则」清单呈现按域分表的例外：列用上文「清单默认列」，另加所属域与当前状态。无权、查不到的在该行注明，不影响其他号。超过约 20 个时按清单呈现，全量导出 |
| 认不出是什么号 | 「认不出这是什么号」，列出能用来查单的号（问题编号、CAR 编号、国内生产订单号与小板订单号、海外发货单号与 PO、料号与 PN、巴西投诉单号），请用户说明；不拿它去全库模糊搜 |

## 通用筛选规则

上文「三域共用的说法」、各域口径与 `dirty_data.md` 只写需要特别说明的维度。没有单独写的筛选条件（如「问题等级为 A」「影响数量超过 100」「IQC 意见为退回仓库」）按本节查；单独写了的，以那里为准。

- **哪些列能当条件**：`db_description/` 里有用户可见显示名、不是内部字段的列。内部字段（自增 ID、软删标记、审计列等）不作条件，也不向用户提起。
- **怎么匹配**：

  | 列的类别 | 匹配方式 |
  |---|---|
  | 编号（问题编号、料号、PN 编码、订单号、CAR 编号、发货单号等） | 去掉首尾空格后精确匹配 |
  | 名称、描述（物料名称、PN 名称等） | 包含匹配 |
  | 加工厂 | 各域不同，见各域业务描述「加工厂」 |
  | 机型、大机型、系列 | 完整名称匹配，不做包含匹配（见上文「机型与系列怎么对」） |
  | 部门 | 依次按完整名称、部门简称、包含匹配（见上文「部门名称怎么对」） |
  | 枚举 | 按显示文字匹配，用户的说法对到对应取值；对不上任何取值时，列出可选值请用户选 |
  | 数值 | 等于、大于、小于、区间 |
  | 日期 | 按区间；文本存的日期先解析（见 `dirty_data.md`「文本存日期」） |
  | 是 / 否 | 按是否 |
  | 逗号分隔的多值 | 逐段精确匹配（见 `dirty_data.md`「逗号分隔的多值列」） |

- **叙述文字**不作筛选条件，按下文「关键词搜索与类似问题」找。
- **默认范围**同其他查询：已删除的单不查；没点明域时三域都查；某个条件在某域没有对应的列时，该域不计入，统计口径里写明（同「跨域归并」）。

## 关键词搜索与类似问题

按文字找单有三种问法，结果预期不同：

| 问法 | 典型说法 | 返回什么 |
|---|---|---|
| 关键词搜索 | 「搜索描述中有『打印』和『USB』的问题」「含 USB 或打印的问题」 | 文字里确实出现这些词的**全部**单。「和」= 都出现，「或」= 出现任一。只按用户给的词找，不按意思补充。说「描述里」「描述中」时只在问题描述里找；没说栏目时在下文比对范围里找；回答写明在哪些文字里找。结果多时按「跨域规则」清单呈现给 |
| 涉及某个话题 | 「最近一年有没有涉及音频（喇叭、蜂鸣器）的问题」「请提供 26 年出现的非接相关问题」「出现过电池鼓包吗」 | 一张清单分三组：问题本身涉及的、处理中提到的（这两组全部列出），以及说法不同、可能相关的（最多 10 张，不保证找全）。见下文「涉及某个话题怎么找」 |
| 类似问题 | 「有没有出现过开机花屏，当时怎么处理的」「以前有没有类似的情况」 | 描述一个具体现象想找先例：按意思最相近的单，默认最多 10 张，按相近程度排序。回答说明这是「按现象描述找到的相近问题，不保证完整」，不当作精确计数 |

没点名栏目时，三种问法比对的文字范围相同，见下。关键词搜索说「描述里」「描述中」时只在问题描述里找（见上表）；其他点名栏目的问法见下文「点名字段时怎么找」。

### 比对范围

用户没点名字段时，三域各比对下列文字（比对前按 `dirty_data.md`「富文本」剥净图片与 HTML，只留文字；剥净后不超过 10 个字的内容，如「OK」「同意」「结案」「无」，不参与按意思找，即类似问题与「可能相关」那一组；按词找时照常比对，即关键词搜索、涉及某个话题的前两组、点名字段按词找）：

| 域 | 比对哪些文字 |
|---|---|
| 国内 | 问题现象（建单时选的，按现象去重后连成一段）、问题描述、原因分析、改善建议、改善措施、预防对策、处理步骤（分析类环节） |
| 巴西 | 问题现象（展平后）、问题描述；最新一条处理过程的原因分析、改善措施、预防对策、SQE 跟进结果 |
| 海外 | 已选问题现象（展平后）、问题描述、原因分析、改善建议、改善措施、预防对策、处理步骤（分析类环节） |

**预设的问题现象只按词找**（决策 2026-10-26「预设问题现象不参与按意思找」）：建单时从现象清单里选的现象是分类标签，不是填单人自己写的现象，不参与按意思找（类似问题与「可能相关」那一组），只按词找（关键词搜索、涉及某个话题的前两组、点名字段按词找）。包括国内的全部问题现象，以及巴西、海外现象里的标准现象。国内建单时手填的「其他」现象也写进现象主数据，与选的现象一样关联到单上，本助手不区分，同样只按词找。巴西、海外手填的现象（现象数组里编号小于 0 的元素，含补充说明）是填单人自己写的，与其他叙述文字一样参与按意思找，也同样受上面 10 个字的限制。

国内物料问题的原因与处理几乎只写在处理步骤里（主表原因分析、改善措施基本为空），所以处理步骤要进比对范围；但处理步骤里还有大量人名、流程登记与确认套话，只比对分析类环节：

- **怎么认环节**：国内按环节编码认，名称只用于展示。一个编码有两个名称的算同一个环节，名称是别的环节、编码是驳回的记录算驳回（见国内处理步骤表「环节编码与名称」；决策 2026-10-22「国内管理页面代码对齐」）。海外按环节名称认。
- **每个环节只取最新一条**：同一张单同一环节有多条时（驳回后重填），只取最新的一条，与「某一环节最新一次的结果」取法相同。
- **国内纳入的环节**（按编码）：
  - 3 责任人确认
  - 4 工程确认（含「确认版本信息」）
  - 6 工厂制程分析
  - 10 SQE跟进
  - 11 设计变更
  - 13 设计变更后SQE确认
  - 14 IQC意见 / IQC填写意见
  - 35 预防对策确认

  其余编码都不纳入，包括驳回（28，含名称写作「预防对策确认」的驳回记录）。
- **海外纳入的环节**（按名称）：SQE跟进、IQC意见、IQC填写意见、工厂制程分析、责任人确认、工程确认、设计变更、设计变更后SQE确认、预防对策确认。不纳入：效果确认、结案确认、停线重启、停线重启审核、停线重启发起、责任人填写重启方案、驳回、指定责任人、任务转移、确认版本信息、确认退货单号、工厂填写在线、IQC确认、PMC确认、生产角色确认、删除问题、填写问题、修改问题。
- 取意见与内容（处理步骤的措施列，管理页面「操作记录」里叫「内容」）；工厂制程分析另取结论。主表的效果确认内容、重启方案同样不在比对范围。
- 环节清单由管理员维护，国内维护的是编码清单，海外是名称清单。出现清单里没有的新编码或新名称时先不纳入，由管理员决定。
- 每条带上环节名称（如「SQE跟进：…」）；同一张单里完全相同的内容只比对一次。
- 这份环节清单只决定按文字找单时比对哪些处理步骤，不受单张单详情显示条件限制：国内、海外命中的内容所在环节当前不显示（已退回重新处理）时，命中处照给那段文字、不另注明；看这张单的详情时，该环节写「该环节已退回重新处理」（决策 2026-10-31「文字查找的选项与分组叫法」）。看完整处理过程按各域处理步骤的规则给。

关键词搜索与类似问题里，命中处理步骤与命中主表字段同等对待，不另列、不排到后面；涉及某个话题按说法写在哪一栏分组，见下文「涉及某个话题怎么找」。

**按问法分工**：问现象（「有没有涉及非接」「有没有出现过开机花屏」）时比对上表全部文字；问做法（「有没有用换料解决过」「这类问题一般怎么改善」）时只比对改善建议、改善措施、预防对策、处理步骤与巴西 SQE 跟进结果，免得问题描述里顺带提到该做法的单排到前面。

### 点名字段时怎么找

用户点名了某个叙述字段时（如「预防对策里提到换料的单」「效果确认里写了返工的单」），只在该字段里找，不受上表限制；各域有哪些叙述字段，见各域业务描述「叙述文字」。按点的是哪个字段分两种找法：

| 点名的字段 | 怎么找 |
|---|---|
| 比对范围内的字段（问题描述 / 问题现象、原因分析、改善建议、改善措施、预防对策，巴西 SQE 跟进结果；只说「处理步骤里」、没点具体某一列时，指比对范围里的处理步骤；只说栏目名的一部分（「原因里」「描述里」「改善里」）时先对这些字段，「原因」是原因分析而不是原因分类说明，「改善」是改善建议与改善措施两栏，这里对不上才对其他叙述字段） | 在该字段里按意思找，同时按词找，两边合并成一张清单：按词找到的单全部列出，标为「直接提到」；只按意思找到的单列在后面、标为「可能相关」，注明不保证完整。点名问题现象时，预设的现象只按词找，只有巴西、海外手填的现象也按意思找（见上文「比对范围」） |
| 其他叙述字段（如效果确认内容、备注、原因分类说明、重启方案），以及处理步骤里的某一列（「处理步骤意见里写了返工」） | 只在该字段里按词找。处理步骤同样只看每个环节最新一条，不限于分析类环节 |

按词找时：

- 用户说的做法或现象先对到说法清单：是某个话题本身时用这个话题的说法，比话题小时只用意思相同的几个说法（同下文「涉及某个话题怎么找」的「按哪些说法找」）；清单里没有时，助手提出几个近义说法（如「换料」→ 换料、更换物料、替换物料）。回答里列出用了哪些说法。匹配规则见 `topic_terms.md`「怎么读」。
- 说法清单里带 ＊ 的说法有歧义：点名的是问题描述、问题现象或原因分析时，带 ＊ 的命中交助手看上下文判断，相关的同样标为「可能相关」列出；点名的是其他字段（包括改善措施等比对范围内的字段）时不用带 ＊ 的说法。
- 结果是该字段里命中任一说法的全部单，完整、计数确定，照常列出，不另作标注。
- 统计口径按「关键词搜索」写：按哪些说法、在哪个字段里找。
- 用户自己给定了几个词（「效果确认里有『返工』的单」）时只按用户给的词找，不套说法清单。

点名字段的问法多是「写了 / 提到」某个做法，按词找更准，也能给全。某个其他字段确实需要按意思找时，由业务方给出典型问法，再评估是否加进比对范围。

### 涉及某个话题怎么找

用户问某个话题有哪些单、有没有（「有没有涉及音频的问题」「非接相关问题」「出现过电池鼓包吗」）时，要的是一份找全的清单。先定按哪些说法找，再按说法写在哪一栏分三组（决策 2026-10-22「涉及某个话题的找法与呈现」）。

**按哪些说法找**（决策 2026-10-24「测试案例梳理补充口径」）：

| 用户说的 | 例子 | 按哪些说法找 |
|---|---|---|
| 话题本身，或话题加例子 | 「通信问题」「涉及非接」「音频（喇叭、蜂鸣器）」 | 说法清单里这个话题的全部说法 |
| 比话题小：清单里的某个说法 | 「跟 ESIM 有关」「喇叭相关」「电池鼓包」 | 只用意思相同的几个说法（如喇叭 → 喇叭、扬声器、SPK），不展开成整个话题 |
| 比话题小：清单外、跨话题的组合说法 | 「电池卡扣」 | 按词组找（电池卡扣、电池盖卡扣），不展开成哪个话题，也不拆成「电池」「卡扣」两个词分别找 |

- 比话题小的两种，说法由助手挑；挑到的说法在清单里时沿用清单的标记，有歧义的照样交助手判断，不算的照样屏蔽。
- 照常分下表三组，第三组按意思补写法不同的单。
- 回答列出本次用了哪些说法，并提示要增减时直接说「再加上『某个说法』」「去掉『某个说法』」重新找（不做成选项：选项不知道该加、减哪个说法）；用的是清单里某个话题的几个说法时，另给可点的选项「按整个话题找」（决策 2026-10-31「文字查找的选项与分组叫法」）。
- 是话题本身还是比话题小，由助手按用户的说法判断；判断错了，用户从回答列出的说法能看出来，改选项即可。

分三组：

| 分组 | 怎么认 | 给什么 |
|---|---|---|
| 问题本身涉及 X | 说法出现在问题描述、问题现象或原因里（各域的栏目见下表） | 全部列出，张数确定。算的说法也会出现在部件名、贴标作业这类写法里（如「打印机支架」，见 `topic_terms.md`「说明」），这一组同样请用户看每行命中的文字 |
| 处理中提到 X | 说法只出现在比对范围内的其余文字里：改善建议、改善措施、预防对策、处理步骤，巴西另有 SQE 跟进结果 | 全部列出，张数确定，排在第一组之后。这一组多是处理或检验时顺带提到，回答里注明，请用户看每行命中的文字 |
| 说法不同、可能相关 | 没出现清单里的说法、按意思找到的单；或问题描述等第一组栏目里只出现有歧义说法（如「杂音」）的单。经助手看内容判断与 X 相关才列入 | 最多 10 张，按相近程度排序，注明不保证找全。候选太多、来不及逐张看完时，建议用户加时间、机型等条件再查 |

| 域 | 第一组看的栏目 |
|---|---|
| 国内 | 问题描述、问题现象、原因分析 |
| 巴西 | 问题现象、问题描述、最新一条处理过程的原因分析 |
| 海外 | 已选问题现象、问题描述、原因分析 |

- 一张单只要在第一组的栏目里命中就归第一组，不再重复列进第二组。分组只决定排在哪一组，不剔除单；前两组合起来就是写到这些说法的全部单。
- 前两组按建单时间倒序，与其他清单一致。三域都查时按域分开列，结果多时按上文「跨域规则」清单呈现给。
- 回答开头给三组各几张（三域都查时分域给，再给合计），并列出本次按哪些说法找。例：「26 年国内找到 35 张与非接有关的单：问题本身是非接的 28 张；处理过程中提到非接的 7 张，多是顺带提到，请看每行命中的文字；另有 3 张说法不同、可能相关，仅供参考，不保证找全。本次按这些说法找：NFC、PICC、非接、非接触、RF、挥卡、闪付」。数字一律来自本次查询结果。
- **说法清单**：按话题列「算的说法」与「不算的说法」，有歧义的说法加标记，初始版本见 `topic_terms.md`。清单由管理员维护，改了不必发版。算的说法、有歧义的说法、不算的说法各怎么用，以及怎么匹配，见 `topic_terms.md`「怎么读」。
- **清单里没有的话题**：助手提几个说法当作算的说法用，回答里写明用了哪些，同样提示可以增减说法；问题本身涉及、处理中提到两组都有单时，另给可点的选项「只看问题本身涉及的」，点了只在第一组的栏目里找（决策 2026-10-31「文字查找的选项与分组叫法」）。常用的临时说法由管理员补进清单。跨话题的组合说法照上文「按哪些说法找」按词组找。
- **问做法**（「有没有用换料解决过」）时不分前两组：按上文「按问法分工」只看措施类文字，命中的单全部列出，再附按意思找到、可能相关的单（最多 10 张，不保证找全）。
  - 问做法时还说了现象（「以前有没有用换料解决过外壳开裂的问题」）：做法、现象各找一遍，两边都命中的单才列入（决策 2026-10-27「G4a 设计时补的口径」）。做法同上，只在措施类文字里找，说法按上文「点名字段时怎么找」的按词找取；现象在比对范围全部文字里找，说法按上文「按哪些说法找」取。
  - 做法、现象都按词命中的单全部列出，张数确定，每行带两处命中的文字；再附做法按词命中、现象可能相关（按意思找到）的单，最多 10 张，注明不保证找全。
  - 两边都命中的为 0 张时照实说，并给「只看用换料处理过的」「只看外壳开裂的」这样两个选项，各带张数。
- 描述一个具体现象想找先例（「有没有出现过开机花屏，当时怎么处理的」）时按「类似问题」给最相近的若干张；用户自己给定要搜的词时按「关键词搜索」，只用用户给的词，不套说法清单；点名字段时按上文「点名字段时怎么找」。

### 命中后带回什么与时效

命中后每张单带回：问题编号（可跳转）、所属域、问题现象或问题描述摘要、命中处前后的一段文字（让用户看到为什么找到它），以及原因与措施（按下文「原因与措施怎么给」），让用户看到「当时怎么处理的」。没点明域时三域都找，结果按域分组（见上文「跨域规则」清单呈现）；用户同时给了时间、机型、加工厂等条件时，先按条件缩小范围再找。

**时效**：按文字找单（关键词搜索、涉及某个话题、类似问题）用的是定时整理过的文字，约每半小时更新一次。最近约半小时内新建的单可能按文字找不到，刚改过文字的单可能仍按改之前的文字匹配。找到之后单上的状态、当前责任人、处理步骤等内容都是实时查的，不受影响。不在正文里提这件事，只在统计口径「文字查找」一项写一句；按文字找单的回答（含类似问题）都附这一项。

## 原因与措施怎么给

问一张单「原因是什么、怎么改善的、当时怎么处理的」，以及按文字找到的单带回原因与措施时，按下表给：

| 域 | 给什么 |
|---|---|
| 国内 | 主表的原因分析、改善措施、预防对策，加上处理步骤分析类环节每个环节最新一条的意见、内容（工厂制程分析另含结论）；只给单张单详情里当前显示的环节，结论、意见按管理页面的标签给（标签见国内处理步骤表「单张单详情里的结论」），有 5Why 时附在后面（见国内业务描述「单张单详情各环节怎么显示」「问题现象、可能问题原因、可能的问题物料、5Why」） |
| 海外 | 主表的原因分析、改善措施、预防对策；处理步骤里分析类环节每个环节最新一条的意见、内容（工厂制程分析另含结论） |
| 巴西 | 最新一条处理过程的原因分析、改善措施、预防对策、SQE 跟进结果 |

- 各项有内容就显示；没有内容（空值、空白，或剔除内嵌图片后只剩空的格式标记）就不显示，不写「未填」。
- 处理步骤分析类环节直接给，不看主表写没写。环节清单与上文「比对范围」相同；每条前带环节名称（如「SQE跟进：…」），按发生先后排列。
- 国内、海外某环节因驳回退回而当前不显示时，不给它的旧内容，回答「该环节已退回重新处理」，并说明之前填写的内容可在处理过程里看到。
- 上表各项都没有内容、而用户直接问原因或措施时，回答这张单上和处理过程里都没有写。
- 国内物料问题关联了 CAR 时：有 CAR 报告权限的用户再附 CAR 报告的根本原因、永久纠正措施；没有权限的不展示报告内容，回答「该单关联了 CAR 报告，您没有查看权限，可点链接到报告页面查看」并附链接（见 `privileges.md`「CAR 报告」）。
- 看「完整处理过程」时按各域处理步骤的规则给（国内、海外照管理页面「操作记录」列出全部记录，巴西只给最新一条处理过程），不受本节影响。

## 统计口径说明（所有统计类回答必带）

凡回答里给出数字结论的——汇总统计，以及清单附带的总数、分布、Top N——都要在结尾附一段「统计口径」，让用户知道这个数是怎么算出来的。只写与本次统计相关的项，用业务语言，不出现表名、字段名。

| 项 | 什么时候写 | 写什么 | 示例 |
|---|---|---|---|
| 时间范围 | 总是 | 起止日期，以及按哪个日期筛；问当前状态、没给时间，或用户明说不限时间时写「不限建单时间」；按停线日期、结案时间等筛时，该日期没填的单有几张未计入 | 2026-01-01 至 2026-03-31，按建单时间 |

| 筛选条件 | 用户给了条件时 | 回显本次用到的条件 | 问题类型：硬件问题；加工厂：惠州百富 |

## 回答怎么组织

以下是用户看得到的默认做法（决策 2026-10-26「回答组织方式默认值」）。标「管理员可改」的数值放在模块配置里，改了不必发版。

### 一问多段

- 按提问的顺序分段作答，每段一个小标题，写明这段答的是什么（如「国内 A920PRO 的软件问题（2026-09）」），下面是这段的表格与结论。
- 几段共用的条件（时间等）在第一段写明，后面各段沿用，并写进各自的小标题。
- 统计口径合并成一段放在最后，各段不同的项分条写，不每段重复一遍。
- 同一范围的「多少 + 按 X 分」（「A8900 今年出了多少问题？按类型分一下」）算一段：先给总数，再给分组表。问题类型一单一个，分组之和等于总数；按机型、加工厂这类一单可多值的维度分时，统计口径写明各组之和可能大于总数。
- 同一范围按两个维度分组（「按类型统计，再按工厂统计」）分两张表，各带标题；共用的时间范围只在统计口径里写一次。
- 先算条件再决定答什么（「如果这个月比上个月多，就告诉我是哪类多了；没多就不用列」）：先给两个数；条件成立时按问题类型列出各类的增减，不成立时写明两个数、说「没有增加」，不列分类。
- 一步接一步的问法（「问题最多的机型是哪个？把它的单列出来，不良率最高那张的原因是什么」）：每步给出结果，并写明承接上一步的什么；某一步没有结果时写明，停在这一步。
- 某一段查不出或无权时，其他段照常给。那一段在原位置用一句话说明原因：无权按 `privileges.md` 的说法；查不到按各自「查不到」的说法；系统出错写「这一部分暂时没查到，请稍后再试」，不带内部报错。整轮都没有结果时才整轮报错。

### 接着上一轮问

- 「那上个月呢」只换时间，域、机型、类型等其他条件沿用上一轮；回答写明沿用了哪些、换了哪些。
- 「不是 A920，是 A920PRO」只换被纠正的条件重答，不并列作答。
- 「再看看里面停过线的」在上一轮的**全部**结果里找，不只在表格列出的前若干条里找；上一轮的结果已经过期时，按上一轮的条件重查，不让用户重问。
- 换了域（上一轮问巴西，本轮问「那国内呢」）同样沿用：只换域，时间、机型、类型等其余条件沿用上一轮，回答写明沿用了哪些。沿用的条件在新的域里对不上时（如上一轮的巴西工厂名），按该条件平常对不上时的说法回答（见上文「机型与系列怎么对」「部门名称怎么对」、各域「加工厂」）；点名的类型新的域没有时，同「跨域归并」写明。
- 隔了很多轮时不沿用。这时本轮问句自己说全了条件，就按本轮问句作答；说不全（只说「那上个月呢」）时追问，不猜。没有上文时同样追问。
- 上一轮没有结果（上一轮是追问、整轮出错，或查出 0 张）时，「其中」「这些」「里面」「刚才那些」这类要在上一轮结果里找的说法，不接更早的轮次：回答「上一轮没有查到结果，没有可以接着统计的范围」，并把更早那一轮的条件写成一个可点的完整问句（如「今年 A920 的问题按状态统计」）；没有更早的轮次就请用户重新给条件。只换条件的「那上个月呢」不受影响，照上面沿用上一轮的条件（决策 2026-10-27「G4a 设计时补的口径」补记）。
- 用户质疑上一轮的回答（「你确定吗」「好像不对吧」）：按上一轮同样的条件重新查一遍。结果相同时，说明当时按什么理解、按什么口径算的，并给其他理解的可点选项；结果不同时，说明哪里变了（多半是这期间数据有更新）。不因为用户质疑就改口（决策 2026-10-27「G4a 设计时补的口径」）。

### 结果为空时

- 不自动放宽条件，照实说没有。再给至多 2 个放宽的可点选项，只放宽默认读法（如「最近」按近 30 天，选项为「看近 90 天」），按钮上带预先查好的张数；用户明说的条件不放宽（决策 2026-10-27「G4a 设计时补的口径」）。
- 各问法自己规定了「查不到」怎么答的（如按编号查单），照那里的说法答。

### 排名、长清单与导出

- 问「哪个最多」：先一句点名第一（并列第一时全部点名），再给前 10 名的表；第 10 名有并列时，并列的都列出并写明。用户说了「前 N」按用户的 N。10 为默认值，管理员可改。
- 某域结果超过 100 张时，表格给最近 20 张，全量导出成一个文件（每域一页），正文写明「完整 N 张见附件（24 小时内有效）」。用户明说「导出」「全部给我」时不论多少都导出，表格同样给前 20 张。100 与 20 管理员可改。

### 表格列名

- 统计表的计数列叫「单数」（按问题单张数计）；订单、发货单、费用明细这类明细的计数叫「条数」；正文里说「N 张」。
- 金额列带币种：「费用（美元）」「费用（雷亚尔）」；比例列带单位：「占比（%）」，多张单合计的不良率叫「不良率（%）」，按域统计时各域的未结案比例叫「未结案占比（%）」；天数列带单位：「结案周期平均（天）」「结案周期中位数（天）」「停线时长平均（天）」「停线时长中位数（天）」。比较两个时段时，两段各一列（列名为这段时间，如「2024 年全年」），另加「增减量」「变化率」。
- 三域一起按问题类型、问题等级、机型、加工厂、跟进部门、时间等维度统计时，同名合并成一张表：每域一列（列名为域名，如「国内」，列里是该域的单数），最后一列「单数」是三域合计；某域没有这一项时写「—」（见上文「跨域归并」）。按域统计（「三个域各多少」）时一域一行，最后一行「合计」。处理环节、状态这类各域取值不同的维度不合并，按域分别给。回答开头写「合计 N 张（国内 a 张、巴西 b 张、海外 c 张）」。
- 清单不加「序号」列，问题编号已经能定位。用户要「第几条」时再加，从 1 现编，不拿内部编号当序号。
- 质疑上一轮、重查后有变化时，变化的单列「问题编号」「所属域」「变化」，「变化」写「这次新查到」或「这次没查到」，不替用户猜原因。有「这次没查到」的单时，表格下面写一句：这次没查到的单可能已删除，或这期间改了状态、类型等，已不符合上一轮的条件。
- 按文字找单的表格（关键词搜索、涉及某个话题、类似问题、点名字段、问做法）每域一张，默认列为「问题编号」「问题描述」（摘要）「命中处」「原因与措施」；用户点名了列时按用户说的给，「命中处」照加。「命中处」写命中在哪一栏和前后一段文字，命中的说法用【】标出；类似问题写最相近的那一段。表格分组时在「问题编号」后加「分组」一列：涉及某个话题写「问题本身涉及」「处理中提到」「可能相关」；点名字段、问做法写「直接提到」「可能相关」；问做法又说了现象写「两边都提到」「可能相关」。「可能相关」在各种找法里意思相同：文字里没有直接出现这些说法、按意思找到并经助手看内容判断相关，不保证找全。关键词搜索、类似问题不分组。前两组各给最近 20 张（不分组时按词找到的给最近 20 张），「可能相关」一组最多 10 张全部列出；某域超过 100 张时全量导出，同清单。

- 用户说「不要图」「只要数」时不画。
- 用户点名要某种图时照用户要的画。例外：按机型、加工厂这类一单可多值的维度要饼图时改画柱状，并说明各组之和大于总单数、画成饼图比例会失真（决策 2026-10-27「G4a 设计时补的口径」）。
