# 制程问题查询助手 业务描述（总述）

> 本文件写三域共用的定位、范围、跨域规则、常用场景与数据量。各域口径分别见同目录
> `domestic/business_description.md`（国内）、`brazil/business_description.md`（巴西）、
> `overseas/business_description.md`（海外）；链接生成见 `link_rules.md`；字段以 `db_description/` 为准。
> 所有统计类回答都要附「统计口径」说明，规则见下文「统计口径说明」。

## 业务定位

面向公司内部参与制程质量问题的人员，只读查询国内、巴西、海外三个域的制程问题。回答「有哪些、到哪一步、怎么处理的、停了没有、结案没有」，不代替源系统填单、审批、上传或改状态。

**使用者**：处理生产问题的部门人员（生产工程部、质量管理部等）、质量 / SQE 角色、上级领导。领导多看时段统计、工厂 / 类型 / 等级分布与停线、费用态势；处理人员多看待跟进清单、单号详情、改善措施。

**一行一单**：清单与汇总里一张问题单只占一行，单下面的子表（处理步骤、订单、发货单、费用、物料、现象）先收敛再挂到单上，计数以问题单张数为准。

## 三个域

三域单据各自独立，表结构、枚举与流程互不相同。

| 域 | 单号前缀 | 管什么 | 不管什么 |
|---|---|---|---|
| 国内 | `ZC` | 国内工厂制程问题。整机看关联生产订单；物料标识为「物料」时另看小板订单；其他在线订单不分整机、物料，有就看 | 不把退货、订单版本修订当作专项场景；问到时按单上已有内容回答 |
| 巴西 | `BR` | 巴西工厂产线上的制程问题，含费用、补料、8D | 不含海外工厂单据；没有国内那种结案后的责任归属部门 |
| 海外 | `HW` | 海外工厂制程问题。加工厂是海外工厂名称，另有国内工厂。含已选现象、可能原因、物料、PN、发货单和附件 | 没有费用、8D、CAR；其他在线、库存、退货单号不在查询范围 |

单号格式统一为「前缀 + 年 2 位 + 月 2 位 + 当月 3 位序号」，如 ZC2109001、BR2404001、HW2609001。

## 跨域规则

- **选域**：用户点明某一域（国内 / 巴西 / 海外，或给出某域单号）时只查该域；只说「制程问题」而没有点明域时，三个域分别查询再汇总。
- **按单号定位**：按前缀判断所属域，只查该域。
- **权限**：三域各自授权。某一域没有权限时，该域不出数，有权限的域照常计入。国内 CAR 报告另行授权，无权时不展示报告内容；CAR 报告页面链接对所有用户提供（见 `privileges.md`）。
- **汇总呈现**：三域一起查时，先给各域小计，再给合计。无权限的域明说「无权限，未计入」，不说成「没有数据」。
- **已删除**：默认不查。国内只有用户明确要求才列出已删除单；巴西「已删除」一律排除（草稿「待提交」和「已终止」仍在范围内）；海外只查未删除单。
- **跨域汇总**：三域单据各自查询再合并，不是把三域表合成一张。三域枚举不同，按下文「跨域归并」对齐。

### 跨域归并

**问题类型：同名合并，不按含义归并。** 三域合起来共 10 个类型：

| 问题类型 | 国内 | 巴西 | 海外 |
|---|---|---|---|
| 硬件问题 | ✓ | ✓ | ✓ |
| 物料问题 | ✓ | ✓ | ✓ |
| 结构问题 | ✓ | ✓ | ✓ |
| 制程优化 | ✓ | ✓ | ✓ |
| 软件问题 | ✓ | — | ✓ |
| 工厂制程 | ✓ | — | ✓ |
| 其他 | — | ✓ | ✓ |
| 资料问题 | ✓ | — | — |
| 设计问题 | — | ✓ | — |
| 生产问题 | — | ✓ | — |

- 名称相同才合并（三域的「硬件问题」相加）；名称不同各占一行，不推断彼此等同。
- 汇总表里「该域没有这个类型」显示「—」，「有这个类型但为 0」显示 0。
- 用户点名某个类型跨域筛选时，没有该类型的域不计入，统计口径里写明（如「巴西无『工厂制程』类型，未计入」）。
- 问题等级同理：A+ 只有海外有，国内、巴西显示「—」。问题类型的「未填」（巴西草稿、海外空值）与海外的「其他（未识别）」也各占一行。
- 机型同理：三域一起按机型汇总时，国内的机型与巴西、海外的大机型按名称同名合并，名称不同各占一行。

**状态：跨域只分「已结案 / 未结案」两档。** 三域流程环节不同，不按环节对齐。

| 档 | 国内 | 巴西 | 海外 |
|---|---|---|---|
| 已结案 | 已完成 | 已结案 | 已完成 |
| 未结案 | 除「已完成」外的全部（含结案确认） | 待修改类别、待跟进、待设计更改、待SQE确认、待效果确认、待结案 | 除「已完成」外的全部（含结案确认） |
| 另列 | — | 待提交、已终止 | — |

- 巴西「已结案 + 未结案」少于巴西总单数，差额是另列的待提交、已终止，统计口径里写明另列了几张。
- 用户要看各环节积压时，按域分别给该域自己的环节分布，不合成跨域的环节表。国内按当前状态各行的环节计，一单可落多个环节（见国内业务描述「按处理环节筛选与统计」）。

### 汇总不良率

多张单合起来算不良率（按机型、阶段、月份等）时：

- 不良率 = 合计不良数量 ÷ 合计分母 × 100，保留 2 位小数。国内分母为生产数量，巴西为影响数量。不取各单不良率的平均。
- 分母为 0 或空的单不参与这次计算，统计口径里写明有几张不参与。
- 海外不良率是单上原文，% 与 ‰ 混用，不汇总，只逐单列出原文；三域一起统计时写明海外未汇总。
- 国内、巴西的分母不同，三域一起统计时分域给出不良率，不合成一个跨域不良率。

## 统计口径说明（所有统计类回答必带）

凡回答里给出数字结论的——汇总统计，以及清单附带的总数、分布、Top N——都要在结尾附一段「统计口径」，让用户知道这个数是怎么算出来的。只写与本次统计相关的项，用业务语言，不出现表名、字段名。

| 项 | 什么时候写 | 写什么 | 示例 |
|---|---|---|---|
| 时间范围 | 总是 | 起止日期，以及按哪个时间筛 | 2026-01-01 至 2026-03-31，按建单时间 |
| 统计范围 | 总是 | 计入了哪些域；无权限未计入的域 | 国内、巴西；海外无权限，未计入 |
| 计数单位 | 总是 | 按问题单张数计。统计订单、发货单、费用等明细时另说单位 | 按问题单张数计，一张单计一次 |
| 排除 | 总是 | 已删除的单不计入 | 已删除的单未计入 |
| 筛选条件 | 用户给了条件时 | 回显本次用到的条件 | 问题类型：硬件问题；加工厂：惠州百富 |
| 结案 / 未结案 | 涉及结案状态时 | 各域「结案」的含义 | 国内、海外以「已完成」为结案，「结案确认」仍算未结案；巴西以「已结案」为结案，未结案不含待提交、已终止（待提交 3 张、已终止 2 张另列） |
| 停线 | 涉及停线时 | 「停线中」「曾经停线」各指什么 | 国内「停线中」含停线中、重启审核、审核通过、填写重启方案 |
| 部门 / 人员 | 按部门或人员统计时 | 按哪个角色算；哪些单因没有该角色而未计入 | 按问题跟进部门统计；国内物料问题、工厂制程、资料问题不指定跟进部门，未计入；巴西尚无处理过程的单跟进部门为「未指定」，未计入；海外问题跟进部门为空的单未计入。按当前责任人统计时：国内按当前状态各行的人，国内、海外「已完成」的单不计入；巴西不提供，未计入 |
| 多值归属 | 按机型、加工厂、大机型、PN、责任归属部门、海外问题跟进人、当前责任人、国内处理环节等一单可多值的维度统计时 | 一单在它所属的每个分组下各计一次，各组之和可能大于问题单总数 | 一张单涉及 CA、TT 两个工厂时，在 CA、TT 下各计 1；各工厂合计 52 张，去重后问题单 50 张 |
| 跨域归并 | 三域一起按问题类型、问题等级、机型或状态汇总时 | 问题类型、等级、机型同名合并，「—」表示该域没有此项；点名的类型某域没有时写明未计入；状态只分已结案 / 未结案，巴西另列待提交、已终止 | 各域问题类型不完全相同，同名类型合并统计；巴西无「工厂制程」类型，未计入 |
| 文字查找 | 按现象或关键词找单时 | 关键词搜索：按哪些词、「和」还是「或」、在哪些文字里找，结果为全部命中；类似问题：结果是最相近的若干张，不保证完整，不能当作精确计数 | 按现象「音频（喇叭、蜂鸣器）」找到最相近的 10 张单，不保证完整 |
| 样本量 | 巴西、海外按年 / 按月统计、单数很少时 | 提示样本少，占比与趋势仅供参考 | 海外 2025 年仅 3 张单 |
| 费用（巴西） | 统计涉及费用的单数或费用金额时 | 涉及费用按费用明细合计大于 0 认定；美元、雷亚尔分别合计；扣款单独列出、未计入费用 | 涉及费用的单 172 张（按费用明细认定）；只有雷亚尔费用的 1 张单另列；扣款单独列出，未计入 |
| 不良率 | 给出多张单合计的不良率时 | 计算方式；有几张单因分母为 0 或空不参与；海外未汇总 | 不良率 = 合计不良数量 ÷ 合计生产数量；生产数量为空的 3 张单不参与；海外不良率为单上原文，未汇总 |

示例里的数字只示意格式；实际回答中的每个数都来自本次查询结果。

## 三域共用的说法

| 用户说法 | 口径 |
|---|---|
| 制程问题、制程相关问题、制程单 | 该次查询范围内的全部问题单，不按「问题类型」再筛 |
| 工厂制程、制程优化、硬件问题、物料问题等 | 点名了具体类型时，才按问题类型筛选 |
| 制程、制程类 | 不是问题类型，不能当成某一类问题 |
| 单号（`ZC` / `BR` / `HW` 开头） | 定位这一张单 |
| 某机型（「L1400 的问题」） | 国内按机型；巴西、海外按大机型，不按 PN |
| 某 PN | 国内按生产订单上的 PN；巴西、海外按 PN：PN 编码按段精确匹配，PN 名称包含匹配，任一命中即算 |
| 某料号（「物料编号」「物料编码」同义） | 国内、巴西按主表料号；海外按物料清单里任一条的料号。国内不匹配小板订单上的料号。「物料编号」只指料号，不指 PN |
| 某物料名称（「喇叭」「电池」） | 国内、巴西按存货档案的物料名称包含匹配；海外按物料清单里的描述包含匹配 |
| 某加工厂 | 各域按自己的加工厂查：国内按国内工厂名称包含或相近匹配，命中多个工厂时列出请用户选；巴西按段匹配巴西工厂名称；海外按海外工厂名称包含或相近匹配。只说「工厂」「加工厂」时，海外单上的「国内工厂」不参与 |
| 明说「国内工厂为 X」的海外单 | 按海外单上的国内工厂列筛，名称匹配方式同国内加工厂 |
| 列清单时只说「处理人」（「列出单号、处理人……」） | 问题跟进人；说「当前处理人」时才是当前责任人 |
| 某部门跟进的、某人跟进的 | 问题跟进部门、问题跟进人 |
| 只说人名（「张三的问题」） | 问题跟进人 |
| 只说部门（「品质部的问题」） | 问题跟进部门。国内说「责任部门 / 定责」时才查责任归属部门 |
| 给出时间、没说现场发现 | 按建单时间筛；说到「现场发现 / 发现日期」才按现场发现日期 |
| 当前谁在处理、当前责任人、当前处理人 | 当前责任人。国内按当前状态逐行给出环节 + 人（含 IQC、退货 / 退库、并行阶段的人）；海外为主表上的当前责任人；巴西没有，说明后给出问题跟进人 |
| 某人手上的、待处理的、卡在某人那的 | 按当前责任人查，不按问题跟进人。巴西不提供当前责任人，巴西的单不计入，回答里写明 |
| 只说「责任人」 | 同时给出当前责任人与问题跟进人，各自写明角色 |
| 未结案、进行中、没完成 | 还没有到达该域的结案完成状态：国内、海外为「已完成」，巴西为「已结案」（巴西另不含待提交、已终止） |

按人员查时，先把用户给的姓名对应到员工，再按员工 ID 匹配各人员列；姓名对应多名员工时追问部门（见「必要澄清项」）。姓名列只用于展示，不用来匹配。

## 常用查询场景

| 场景 | 能回答什么 | 示例问题 |
|---|---|---|
| 问题单清单 | 按时间、加工厂、机型、物料、问题类型、状态、跟进部门 / 跟进人筛出问题单 | 上个月国内的工厂制程问题有哪些？ / 巴西 CA 工厂今年的物料问题 / 海外还没结案的硬件问题 |
| 单张单详情 | 一张单的现状、处理步骤、原因分析、改善措施、预防对策、停线与结案情况 | ZC2509012 现在到哪一步了？ / BR2601009 的原因和改善措施是什么 |
| 停线查询 | 目前停线中的单、曾经停过线的单、停线与重启时间（巴西只有停线日期，没有重启时间） | 现在有哪些单还在停线？ / 今年国内发生过停线的问题 |
| 跟进人与当前责任人 | 某部门 / 某人跟进的单，当前谁在处理，某人手上有哪些单 | 品质部跟进的未结案问题 / HW2609001 现在谁在处理 / 张三手上还有哪些国内单（巴西不提供当前责任人） |
| 汇总统计 | 按机型、加工厂、问题类型、问题等级、状态、跟进部门或时间段计数与对比 | 6 月总共发生多少制程问题？ / 工程部人员 2026 年第一季度处理的制程问题统计 |
| 类似问题 | 按缺陷现象描述找历史上最相近的问题单及其处理方式；可与时间、机型、工厂组合 | 最近一年有没有涉及音频（喇叭、蜂鸣器）的问题？ / L1400 的制程问题中是否有与音频相关的？ |
| 关键词搜索 | 找出文字里出现指定词的全部问题单 | 搜索描述中有「打印」和「USB」的问题 |
| 域专项 | 国内 CAR、责任归属部门；巴西费用、补料、8D 报告；海外发货单、可能问题原因、附件 | 这张单的 CAR 写了什么根本原因？ / 巴西今年涉及费用的单子共花了多少美元 / 这张海外单涉及哪些发货单 |

## 关键词搜索与类似问题

按文字找单有两种问法，结果预期不同：

| 问法 | 典型说法 | 返回什么 |
|---|---|---|
| 关键词搜索 | 「搜索描述中有『打印』和『USB』的问题」「含 USB 或打印的问题」 | 文字里确实出现这些词的**全部**单。「和」= 都出现，「或」= 出现任一。结果上百条时表格给前若干条，全量导出 |
| 类似问题 | 「有没有涉及音频（喇叭、蜂鸣器）的问题」「有没有出现过开机花屏，当时怎么处理的」 | 按意思最相近的单，默认最多 10 张，按相近程度排序。回答说明这是「按现象描述找到的相近问题，不保证完整」，不当作精确计数 |

两种问法比对的文字范围相同，见下。

### 比对范围

用户没点名字段时，三域各比对下列文字（比对前按 `dirty_data.md`「富文本」剥净图片与 HTML，只留文字）：

| 域 | 比对哪些文字 |
|---|---|
| 国内 | 问题描述、原因分析、改善措施 |
| 巴西 | 问题现象（展平后）、问题描述、最新一条处理过程的原因分析与改善措施 |
| 海外 | 已选问题现象（展平后）、问题描述、问题原因 |

用户点名了某个叙述字段时（如「预防对策里提到换料的单」「处理步骤意见里写了返工的单」），只在该字段里找，不受上表限制；各域有哪些叙述字段，见各域业务描述「叙述文字」。

命中后每张单带回：问题编号（可跳转）、所属域、问题现象或问题描述摘要，以及原因、改善措施、预防对策，让用户看到「当时怎么处理的」。没点明域时三域都找；用户同时给了时间、机型、加工厂等条件时，先按条件缩小范围再找。

## 必要澄清项

| 缺什么 | 追问什么 | 示例回答 |
|---|---|---|
| 时间范围（仅汇总统计类） | 汇总类问题没给时间时，追问要统计哪个时间段 | 今年、近 30 天、2026 年上半年 |
| 类似问题的现象描述过短 | 只说「有问题」「不良」这类泛词时，追问具体现象 | 开机花屏、按键失灵、外壳刮伤 |

### 业务含义

- 三个主表合计 2,974 张单，国内约占 92%。国内每年约 400–800 张；巴西 2024 年起每年 50–80 张；海外 2024 年起只有零星十几张。
- 跨域汇总时，国内的数基本决定合计；巴西、海外按年统计时样本很小，占比、趋势类结论要谨慎表述。
- 国内主表 2,758 行中未删除 2,447 张、已删除 311 张；上表行数含已删除的单。未删除的单中整机单 2,435 张、「物料」单 12 张。巴西主表 199 行中未删除 191 张，其中 190 张填了大机型。海外主表 17 行中未删除 13 张。
- 子表与主表的比例：国内每张单平均约 5 条处理步骤、约 1.5 条生产订单、约 1 个机型；生产订单只挂在整机单上，小板订单只有 21 条、只挂在「物料」单上。其他在线订单 18,179 条，约 1,271 张单有，几乎全部挂在整机单上（「物料」单只有 2 张、20 条）。风险订单流程（退货 / 退库）只有 7 条，进行中的只涉及 3 张单；IQC 状态有值的只有 2 张单。当前状态里的 IQC 段与退货 / 退库段都极少出现。未删除的物料问题 1,408 张，其中 1,331 张关联了 CAR；另有 17 张其他类型的单库里带 CAR，不展示、不计入。巴西每张单约 5 条费用明细（按费用类型的占位行）、约 1.5 条关联申请单；处理过程只有 193 条，少于主表 199 张，说明有单尚无处理过程。海外每张单约 5 条处理步骤、约 2.5 条发货单。
- 大表是流程待办任务（约 420 万行，全公司待办）、文档清单（约 193 万行，全公司附件）、存货档案与 PN 主数据（各约 9.3 万行）、人员（约 1.5 万行）、CAR 报告（约 2.5 万行）。本模块只按问题单关联到其中很少一部分行：待办任务只取国内问题单在并行阶段（状态 30、36、37）的已接受任务。

各域单独用到的表数：国内 15 张，巴西 14 张，海外 11 张；人员、部门、文档清单等基础表多域共用。ERP 实例只用到国内工厂这一张表。
