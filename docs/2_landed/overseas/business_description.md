# 海外制程问题 业务描述

> 字段定义见 `db_description/`；三域共用口径见上级 `business_description.md`。

## 业务域

围绕海外制程问题主表（CoreINFO.dbo.OverseasProblemDetail），只读查询海外工厂制程问题的发现、分类、现象、跟进、处理过程、停线、发货与结案。单号 `HW` 开头。

一张单在主表占一行。发货单、处理步骤、物料、已选现象都是这张单下面的内容，不把它们的行数当成问题单张数。

**不做**：不改单、改状态、上传附件；不含国内、巴西单据；物料不关联存货档案，供应商名称不另查供应商表；不用标准现象表的描述替换已选现象的文字；不把可能问题原因当成已填写的原因；系列不作查询条件；本域没有费用、8D、CAR；其他在线、库存、退货单号不在查询范围。

## 查询范围

- 只查未删除单（是否删除为 0，与源系统一致）。
- 本域用 11 张表：主表、处理步骤、涉及发货单 3 张业务表，加人员、部门、产品、PN、文档清单、国内工厂、标准现象、现象可能原因 8 张主数据表。

## 口径

| 对象 | 口径 |
|---|---|
| 问题类型 | 硬件问题、软件问题、物料问题、其他、工厂制程、结构问题、制程优化。问题类型为「其他」时另有其他问题说明。原问题类型保留改类前的值。空值显示「未填」，枚举以外的值显示「其他（未识别）」 |
| 状态 | 只看主表：指定责任人、责任人确认、其他问题确认、IQC意见、工厂制程分析、IQC确认、填写退货单号、SQE跟进、设计更改、设计变更后SQE确认、效果确认、结案确认、已完成。各环节留痕在处理步骤表 |
| 结案 | 结案完成只有「已完成」；未结案 = 状态不是「已完成」 |
| 问题等级 | A+、A、B、C；空为「未填」 |
| 加工厂、国内工厂 | 加工厂是海外工厂名称（直接存名称），写法统一，取值是可枚举的闭集。国内工厂是另一列，存国内工厂码，翻成国内工厂名称 |
| 按加工厂筛选 | 不要求精确相等：用户给的工厂名称被加工厂包含、或与加工厂名称相近即命中，容忍用户输入不全或输错。只说「工厂」「加工厂」时只看加工厂列，不去匹配国内工厂列 |
| 按国内工厂筛选 | 用户明说「国内工厂为 X」时，按国内工厂列筛：名称被国内工厂名称包含或与之相近即命中，先对到工厂码；命中多个时列出请用户选 |
| 建单时间、发现日期 | 两列。发现日期也叫现场发现日期。给出时间、没说现场发现时按建单时间筛；说到「现场发现 / 发现日期」才按发现日期筛（文本存日期，先解析） |
| 停线字段 | 是否停线在重启后仍为「是」。停线状态为停线中、已经重启、没有停线 |
| 停线中、目前停线、正在停线 | 停线状态为「停线中」 |
| 停线、曾经停线、发生过停线 | 是否停线为「是」，已经重启的仍算 |
| 问题跟进部门、问题跟进人 | 填单时先选一个部门，再选该部门下一个或多个跟进人。只说人名按问题跟进人，只说部门按问题跟进部门 |
| 当前责任人、当前处理人、当前谁在处理、某人手上的 | 当前责任人：问题单流转到最新节点时的处理人（主表姓名列），不用处理步骤上的成员拼出来。已完成的单没有当前责任人，按人查单、统计不计入，与国内一致。只说「责任人」时同时附上问题跟进人，各自写明角色 |
| 填单人 | 创建这张单的人员；用户说「创建人」时同指填单人 |
| 不良率 | 按单上原文展示，保留 `%` 或 `‰`；不参与多张单的汇总 |
| IQC 意见 | 退回仓库，或继续使用 |
| 物料 | 物料 JSON 里的料号、描述、供应商编号、供应商名称，逐条列出。料号与 PN 编码是同一套 15 位物料编码，但物料清单里的料号与主表 PN 列是单上两个不同的位置。按料号筛：任一条的料号命中即算；按物料名称筛：任一条的描述包含即算 |
| 大机型 | 大机型 ID 各段 → 产品名称，一单多个时去重，用「、」连接。用户说「机型」时按大机型查，不按 PN；跨域按机型汇总时与国内机型、巴西大机型同名合并 |
| PN | 主表 PN 各段是 PN 编码，经 PN 主数据得到 PN 名称；每段展示为「PN 名称 PN 编码」，与国内、巴西一致，多段时去重，用「、」连接。按 PN 筛时 PN 编码按段精确匹配、PN 名称包含匹配，任一命中即算。发货单上的 PN 与主表同一套编码，且都等于本单主表某段 PN |
| 系列 | 只展示单上已有文字 |
| 版本 | 主表上的版本；发货单另有发货版本、生产版本，三者不是同一项 |
| 已选问题现象 | 一单可有多条，标准现象和手填现象混在一起，按展平规则连成一段文字 |
| 可能问题原因 | 每条标准现象各自的候选原因清单；本单已写的原因看「问题原因」 |
| 涉及发货单 | 多行列表（序号、PO、发货单号、发货日期、PN、发货版本、生产版本、订单数量、备注），按发货单号升序；PN 同样展示为「PN 名称 PN 编码」；另给订单数量合计 |
| 按发货单号、PO 查单 | 用户给出发货单号（多为 7 位数字）或 PO（字母、数字与连字符组成的长串），查出挂着它的海外单。去掉首尾空格后精确匹配，PO 不分大小写；一个号挂多张单时全部列出，一单一行，并给出该单上这条发货单的发货日期、PN、订单数量。只查未删除单 |
| 附件 | 填单附件与步骤附件，未删除的以文档名称打开预览 |
| 处理步骤 | 完整处理过程给该单全部记录，按 ID 升序；看某一环节时同一环节名称只留最新一条（ID 最大）。步骤上的预防措施与主表改善措施是两列 |
| 设计变更 | 是否设计变更、设计变更责任人、设计更改预计完成时间、设计变更确认结果 |

叙述文字：问题描述、改善建议、备注、问题原因、预防对策、改善措施、效果确认、其他问题说明，以及处理步骤的意见、结论、预防措施。问题描述、改善建议可能内嵌图片。按文字找单时，没点名字段按总述「比对范围」找；点名了其中某个字段时，只在该字段里找。

## 关联

结构总览见 `table_relations.md`；本节为关联条件的信源，修改时同步该图。

| 看什么 | 怎么关联 |
|---|---|
| 处理步骤 | `OverseasProblem_StepLog.ProblemId = 主表.Id` |
| 涉及发货单 | `OverseasProblem_DeliveryOrder.ProblemId = 主表.Id` |
| 大机型 | `ProductType` 各段 `= ProductName.ID` → `ProductName` |
| PN | `PNList` 各段 `= NewProduct.PartNumber` → `Name`；发货单 `PN = NewProduct.PartNumber` → `Name` |
| 国内工厂 | `Factory2 = PaxFactory.FactoryID` → `FactoryName`（国内工厂表在 ERP 实例，与问题单不在同一实例） |
| 已选现象 → 可能原因 | `hasCheckedPhenomenon[].Key`（大于 0）`= AfterSaleIssueClassPhenomenon.ID`；`AfterSaleIssueClassPhenomenonReason.PhenomenonID = 现象 ID` |
| 人员 | `AddUser`、`ConfirmUser`、`DesignUser` `= Employee.ID`；`RUser` 各段 `= Employee.ID`；步骤 `AddUser`、`MemberList` 各段 `= Employee.ID` |
| 部门 | `RDepartment = Department.ID` |
| 填单附件 | `DocId` 各段 `= DocumentList.ID` |
| 步骤附件 | 步骤 `DocID` 各段 `= DocumentList.ID` |
| 附件有效性 | `DocumentList.frecid = 主表.Id` 且 `EffectFlag = 0`，不加 `BusinessType` 条件。附件只能从单上登记的 ID 出发取，不能只按 `frecid` 反查（会撞上其他业务的文档） |
| 制程单链接 | 见 `link_rules.md` |

## 常见查询示例

1. 问题等级为 A+ 的海外制程问题有哪些？
2. 单号 HW2609001 的已选问题现象、可能问题原因和当前责任人是什么？
3. HW2609001 涉及哪些发货单，订单数量合计是多少？
3a. 发货单号 XXXXXXX 对应哪张海外制程问题单？（按发货单号查单）
4. 问题跟进部门为某部门的海外制程问题，跟进人是谁？
5. 状态为已完成，并且 IQC 意见为退回仓库的海外物料问题有哪些？
6. 料号为某编码的海外制程问题有哪些？
7. PN 为某机型名称的海外制程问题，问题描述里有哪些说法？
8. 2026 年 9 月建单的海外制程问题有哪些？
