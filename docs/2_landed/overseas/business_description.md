# 海外制程问题 业务描述

> 字段定义见 `db_description/`；三域共用口径见上级 `business_description.md`。

## 业务域

围绕海外制程问题主表（CoreINFO.dbo.OverseasProblemDetail），只读查询海外工厂制程问题的发现、分类、现象、跟进、处理过程、停线、发货与结案。单号 `HW` 开头。

一张单在主表占一行。发货单、处理步骤、物料、已选现象都是这张单下面的内容，不把它们的行数当成问题单张数。

**不做**：不改单、改状态、上传附件；不含国内、巴西单据；物料不关联存货档案，供应商名称不另查供应商表；不用标准现象表的描述替换已选现象的文字；不把可能问题原因当成已填写的原因；系列不作查询条件；本域没有费用、8D、CAR；其他在线、库存、退货单号不在查询范围。

## 查询范围

- 只查未删除单（是否删除为 0），与管理页面一致：已删除的单查不到，按单号、发货单号、PO 也查不到。
- 本域用 11 张表：主表、处理步骤、涉及发货单 3 张业务表，加人员、部门、产品、PN、文档清单、国内工厂、标准现象、现象可能原因 8 张主数据表。

## 口径

| 对象 | 口径 |
|---|---|
| 问题类型 | 硬件问题、软件问题、物料问题、其他、工厂制程、结构问题、制程优化。问题类型为「其他」时另有其他问题说明。原问题类型保留改类前的值。空值显示「未填」，枚举以外的值显示「其他（未识别）」 |
| 状态 | 只看主表：指定责任人、责任人确认、其他问题确认、IQC意见、工厂制程分析、IQC确认、填写退货单号、SQE跟进、设计更改、设计变更后SQE确认、效果确认、结案确认、已完成。各环节留痕在处理步骤表 |
| 结案 | 结案完成只有「已完成」；未结案 = 状态不是「已完成」 |
| 问题等级 | A+、A、B、C；空为「未填」 |
| 加工厂、国内工厂 | 加工厂是海外工厂名称（直接存名称），写法统一，取值是可枚举的闭集。国内工厂是另一列，存国内工厂码，翻成国内工厂名称 |
| 按加工厂筛选 | 不要求精确相等：用户给的工厂名称被加工厂包含、或与加工厂名称相近即命中，容忍用户输入不全或输错。只命中一个工厂时直接查；命中多个时列出请用户选，与国内一致。只说「工厂」「加工厂」时只看加工厂列，不去匹配国内工厂列 |
| 按国内工厂筛选 | 用户明说「国内工厂为 X」时，按国内工厂列筛：名称被国内工厂名称包含或与之相近即命中，先对到工厂码；命中多个时列出请用户选 |
| 建单时间、发现日期 | 两列。发现日期也叫现场发现日期。给出时间、没说是哪件事时按建单时间筛；说到「现场发现 / 发现日期」才按发现日期筛（文本存日期，先解析） |
| 按事件的时间筛 | 停线的、停过线的按停线日期（文本存日期，先解析）；重启的按停线重启时间，目前已经重启的单都没填，不计入并写明，也不算停线时长；结案的、关闭的按结案时间，即处理步骤里最后一条「结案确认」的发生时间，只对「已完成」的单定。规则与结案周期见总述「按哪个日期筛」「结案时间与结案周期」 |
| 停线字段 | 是否停线在重启后仍为「是」。停线状态为停线中、已经重启、没有停线 |
| 停线中、目前停线、正在停线 | 停线状态为「停线中」。不看是否结案，与国内一致 |
| 停线、曾经停线、发生过停线 | 是否停线为「是」，已经重启的仍算 |
| 问题跟进部门、问题跟进人 | 填单时先选一个部门，再选该部门下一个或多个跟进人。只说人名按问题跟进人，只说部门按问题跟进部门 |
| 当前责任人、当前处理人、当前谁在处理、某人手上的 | 当前责任人：问题单流转到最新节点时的处理人（主表姓名列），不用处理步骤上的成员拼出来。已完成的单没有当前责任人，按人查单、统计不计入，与国内一致。只说「责任人」时同时附上问题跟进人，各自写明角色 |
| 填单人 | 创建这张单的人员；用户说「创建人」时同指填单人 |
| 不良率 | 按单上原文展示，保留 `%` 或 `‰`；不参与多张单的汇总 |
| IQC 意见 | 退回仓库，或继续使用 |
| 物料 | 物料 JSON 里的料号、描述、供应商编号、供应商名称，逐条列出。料号与 PN 编码是同一套 15 位物料编码，但物料清单里的料号与主表 PN 列是单上两个不同的位置。按料号筛：任一条的料号命中即算；按物料名称筛：任一条的描述包含即算；只说「X 的问题」时物料名称与文字两种都查，见总述「三域共用的说法」 |
| 大机型 | 大机型 ID 各段 → 产品名称，一单多个时去重，用「、」连接；对不上产品主数据的段不显示，全部对不上时显示「未识别机型」，不展示内部编号（同巴西，目前都能对上）。用户说「机型」时按大机型查，不按 PN；按完整名称匹配，任一段命中即算，规则见总述「三域共用的说法」。跨域按机型汇总时与国内机型、巴西大机型同名合并 |
| PN | 主表 PN 各段是 PN 编码，经 PN 主数据得到 PN 名称；每段展示为「PN 名称 PN 编码」，与国内、巴西一致，多段时去重，用「、」连接。按 PN 筛时 PN 编码按段精确匹配、PN 名称包含匹配，任一命中即算。发货单上的 PN 与主表同一套编码，且都等于本单主表某段 PN |
| 系列 | 只展示单上已有文字，不作查询条件：按系列查时海外不计入，统计口径里写明 |
| 版本 | 主表上的版本；发货单另有发货版本、生产版本，三者不是同一项 |
| 已选问题现象 | 一单可有多条，标准现象和手填现象混在一起，按展平规则连成一段文字 |
| 可能问题原因 | 每条标准现象各自的候选原因清单；本单已写的原因看「问题原因」 |
| 涉及发货单 | 多行列表（序号、PO、发货单号、发货日期、PN、发货版本、生产版本、订单数量、备注），按发货单号升序；PN 同样展示为「PN 名称 PN 编码」；另给订单数量合计 |
| 按发货单号、PO 查单 | 用户给出发货单号（多为 7 位数字）或 PO（字母、数字与连字符组成的长串），查出挂着它的海外单。去掉首尾空格后精确匹配，PO 不分大小写；一个号挂多张单时全部列出，一单一行，并给出该单上这条发货单的发货日期、PN、订单数量。只查未删除单；查不到（含只挂在已删除的单上）时答「没有找到挂着这个号的单（已删除的单查不到），请核对」。只给 7 位数字、没说是什么号的带连字符的串怎么查，见总述「按编号查单」 |
| 附件 | 填单附件与步骤附件，未删除的以文档名称打开预览 |
| 处理步骤 | 与国内一致：完整处理过程照管理页面「操作记录」给操作人、操作时间、类型、内容、附件 5 列，内容为空时取意见，结论、意见不单列。完整处理过程与看某一环节，都是同一环节名称只留最新一条（ID 最大），完整处理过程再按 ID 升序排。见处理步骤表「处理过程怎么展示」 |
| 设计变更 | 是否设计变更、设计变更责任人、设计更改预计完成时间 |
| 处理结果 | 改善、保持现状、挂起。管理页面放在「责任人确认」下，与国内一致；物料问题设计变更时也记在这一项 |

叙述文字：问题描述、改善建议、备注、问题原因、预防对策、改善措施、效果确认、其他问题说明，以及处理步骤的意见、结论、内容。问题描述、改善建议可能内嵌图片。按文字找单时，没点名字段按总述「比对范围」找；点名了其中某个字段时，只在该字段里找，按意思找还是按词找见总述「点名字段时怎么找」。问「原因、措施」时给什么，见总述「原因与措施怎么给」。

## 单张单详情

与管理页面详情一致（业务方 2026-10-23 管理页面核对）：先给抬头，再按单上走过的环节逐块给，没走到的环节不显示；每块取该环节最新一条处理步骤，处理人是这一条的操作人与操作时间。

- **抬头**：加工厂、大机型（页面写作「机型」）、PN、填单人、建单时间、当前状态（已完成的单不附当前责任人）、涉及发货单、问题类型、影响数量、不良数量、不良率、已选问题现象、问题等级、发现工位、版本、现场发现日期、是否停线（停过线时另给停线状态、停线日期）、物料（每条给料号与描述、供应商编号与名称）、问题描述、改善建议。系列、国内工厂、其他问题说明、备注、附件有内容时给。
- **各问题类型走过的环节**（现有的单）：

  | 问题类型 | 区块顺序 |
  |---|---|
  | 硬件问题、软件问题 | 指定责任人 → 责任人确认 → 效果确认 → 结案确认 |
  | 物料问题 | 指定责任人 → 责任人确认 → IQC意见 → SQE跟进 → 效果确认 → 结案确认 |
  | 其他 | 指定责任人 → 责任人确认 → …（目前没有走完的单） |
  | 工厂制程 | 工厂制程分析 → 效果确认 |

  结构问题、制程优化目前没有单；需要设计变更、退货等环节的单按状态流程另有对应区块。
- **区块内容**：
  - 指定责任人：处理人、问题跟进人（页面写作「责任人」）。
  - 责任人确认：处理人、跟进人是否确认（页面写作「确认结果」）、处理结果、计划完成时间、问题原因（页面写作「原因分析」）、改善措施、预防对策。主表这几项放在这一块里，与国内相同。页面这一块里另有「5Why分析过程」，本助手暂不提供：海外单少、更新不频繁，5Why 又是新加的功能，目前基本没有数据。问到时请到管理页面查看（业务方 2026-10-23 答复）。
  - 效果确认：处理人、效果确认结果。效果确认结果取主表的效果确认，它与效果确认环节最新一条步骤的意见相同（业务方 2026-10-23 正式镜像计数：11 张单全部相同）。
  - 结案确认：处理人、结案结论。结案结论取结案确认环节最新一条步骤的意见，与国内详情页相同。
  - IQC意见、SQE跟进、工厂制程分析等其余环节：处理人与该环节的结论、意见；工厂制程分析的结论是文字，SQE跟进的结论按处理步骤表翻译。

## 关联

结构总览见 `table_relations.md`；本节为关联条件的信源，修改时同步该图。

| 看什么 | 怎么关联 |
|---|---|

| 人员 | `AddUser`、`ConfirmUser`、`DesignUser` `= Employee.ID`；`RUser` 各段 `= Employee.ID`；步骤 `AddUser`、`MemberList` 各段 `= Employee.ID` |

| 填单附件 | `DocId` 各段 `= DocumentList.ID` |
| 步骤附件 | 步骤 `DocID` 各段 `= DocumentList.ID` |

## 常见查询示例

示例里的单号、时间只示意问法，见总述「常用查询场景」之后的说明。

1. 问题等级为 A+ 的海外制程问题有哪些？
2. 单号 HW2609001 的已选问题现象、可能问题原因和当前责任人是什么？
3. HW2609001 涉及哪些发货单，订单数量合计是多少？
3a. 发货单号 XXXXXXX 对应哪张海外制程问题单？（按发货单号查单）
4. 问题跟进部门为某部门的海外制程问题，跟进人是谁？
5. 状态为已完成，并且 IQC 意见为退回仓库的海外物料问题有哪些？
6. 料号为某编码的海外制程问题有哪些？
7. PN 为某机型名称的海外制程问题，问题描述里有哪些说法？
8. 2026 年 9 月建单的海外制程问题有哪些？
