# 巴西制程问题 业务描述

> 字段定义见 `db_description/`；三域共用口径见上级 `business_description.md`。

## 业务域

围绕巴西制程问题主表（CoreINFO.dbo.BrazilProblemList），只读查询巴西工厂产线制程问题的发现、分类、停线、跟进、改善、费用、补料、8D 与结案。单号 `BR` 开头。只含巴西工厂（巴西工厂主数据上的工厂）的单据，不含海外单据。

**不做**：不改单、结案、上传 8D、发邮件；不做国内那种生产订单明细问法（关联申请单只用来解析 PN）；没有国内的「结案定责部门」，相关说法按问题跟进部门解释；不为巴西本地员工、供应商等外部角色设计场景。

**使用者**：总部侧获权查看巴西制程问题的人员，如产线问题处理部门（生产工程部、质量管理部等）、质量 / SQE 角色、高层领导。

## 查询范围

- 状态为「已删除」的单一律排除。「待提交」（草稿）与「已终止」**默认包含**。
- 默认不限工厂或跟进部门，由用户问句收窄；不存在「我的待办」默认视角。
- 按物料查只看主表料号：给料号时按料号匹配，给物料名称时经存货档案的物料名称包含匹配；问题单涉及的存货明细不在查询范围。
- 本域用 14 张表：主表、处理过程、费用明细、关联申请单 4 张业务表，加申请单、PN、产品、存货档案、供应商、问题分类、巴西工厂、人员、部门、文档清单 10 张主数据表。
- **一行一单**：问题单清单与汇总里每张单只占一行。一对多的子表先按下表收敛再挂到单上，不能把多张子表的明细行直接并列，否则同一单会被重复计数。

| 子表 | 收敛方式 |
|---|---|
| 处理过程 | 取最新一条（`ID` 最大） |
| 费用明细 | 汇总为费用美元合计、费用雷亚尔合计、专项费用明细（见费用表文件） |
| 关联申请单 | 全部解析为 PN 后去重，合并成「PN 列表」 |
| 8D 文档 | 不并入清单行；清单只带「是否需要回复 8D」 |
| 大机型（单内多值） | 解析成大机型名称，去重后用「、」连接 |
| 问题现象（单内 JSON） | 展平成一段文字 |

- 看明细时：处理过程给全部历史（按 `ID` 升序）、费用给全部明细行（含 0 金额行、汇率、备注）、8D 给该单全部有效文档。

## 口径

### 时间

| 用户说法 | 口径 |
|---|---|
| 给出时间、没说现场发现 | 按建单时间筛 |
| 现场发现、发现日期 | 按现场发现日期筛（文本存日期，先解析） |
| 统计日期 | 只有用户明说「统计日期」时才按统计日期筛 |

其他文本存的日期（停线日期、统计日期、计划完成日期、设计更改评估时间）展示用原值，筛选、排序、统计用解析后的日期，解析失败按空。

统计日期约六成单没有填。按统计日期筛选、统计时，没填的单不会命中，回答（统计时为统计口径说明）里写明有几张没填、未计入。

### 问题类型

设计问题、结构问题、生产问题、制程优化、硬件问题、物料问题、其他。`其他|备注` 显示为「其他」，备注进「其他问题备注说明」；按「其他」筛选时两种写法都命中。主表与处理过程表各有一份问题类型，含义相同、彼此独立。筛选、统计、跨域归并只用主表这一份；处理过程那份只在看处理过程明细时展示，显示名「处理过程问题类型」，`其他|备注` 同样拆分。

### 状态与生命周期

- 状态：待提交、待修改类别、待跟进、待设计更改、待SQE确认、待效果确认、待结案、已结案、已终止、已删除。没有正式状态流转图，按枚举原值理解与筛选。
- 结案完成是「已结案」。
- 未结案、进行中、没完成 = 待修改类别、待跟进、待设计更改、待SQE确认、待效果确认、待结案。待提交（草稿）与已终止不算未结案，需要时单独列出它们的单数。回答的统计口径说明里写明这一点。
- 结案结果（最新一条处理过程上的「是 / 否」）是结案人对结果的评定，与状态独立。

### 停线

| 是否停线 | 停线状态 | 含义 |
|---|---|---|
| 否 | 空 | 从未停线 |
| 是 | 空或其他取值（如「停线中」） | 停线后尚未标记重启 |
| 是 | 停线重启 | 停过线，已标记重启（是否停线仍为「是」） |

| 用户说法 | 口径 |
|---|---|
| 停线中、目前停线、停线且未重启 | 是否停线为「是」，且停线状态不是「停线重启」（空或其他取值都算） |
| 停线已重启、停线后已恢复生产 | 是否停线为「是」，且停线状态为「停线重启」 |
| 发生过停线、曾经停线、有停线记录 | 是否停线为「是」，不看停线状态 |
| 从未停线 | 是否停线为「否」 |
| 停线级别 | 用级别名称，不用内部编号 |

巴西没有停线重启时间，只能看是否已标记重启（停线状态为「停线重启」）。

### 人员与部门

| 用户说法 | 口径 |
|---|---|
| 问题跟进人 | 该单最新一条处理过程上的问题跟进人；还没有处理过程的单显示「未指定」，不用初始责任人代替 |
| 只说人名（「张三的问题」） | 问题跟进人 |
| 问题跟进部门、某部门跟进 / 处理 / 负责的；只说部门 | 上述问题跟进人所在部门；没有处理过程的单显示「未指定」，按部门统计时不计入，统计口径说明里写明 |
| 责任部门、定责部门、责任归属 | 巴西没有这个维度，按问题跟进部门解释，并在回答（统计时为统计口径说明）中说明 |
| 当前谁在处理、当前责任人、当前处理人（问单张单） | 巴西不提供当前责任人。回答时说明这一点，并给出问题跟进人（没有处理过程的单为「未指定」） |
| 某人手上的、某人待处理的、卡在某人那的（清单、统计） | 巴西不提供当前责任人，巴西的单不计入；回答（统计时为统计口径说明）里写明「巴西不提供当前责任人，未计入」，不改按问题跟进人列单（决策 2026-10-20） |
| 初始责任人 | 主表上的初始责任人 |

填单人所在部门只作人员展示，不作部门统计的默认依据。其他人员：补料人、退货确认人、设计更改人、SQE 确认人、效果确认人、结案人。

### 加工厂

主表直接存巴西工厂名称，可逗号多值（如 `CA,TT`）。用户指定工厂 X 时，按逗号拆段、去首尾空格后任一段等于 X 即命中：搜 `CA` 要命中 `CA` 和 `CA,TT`，搜 `TT` 也命中 `CA,TT`。工厂名称以巴西工厂主数据为准。

### 大机型与 PN

两条独立链路。用户说「机型」时按大机型查，不按 PN；说「PN」时按 PN 列表查。

- **大机型**（也叫机型名称列表）：主表大机型 ID 各段 → 产品名称，一单多个时去重，用「、」连接。跨域按机型汇总时与国内机型、海外大机型同名合并。
- **系列**：大机型各段 → 产品主数据上的系列，去重后用「、」连接展示。
- **PN 列表**：该单全部关联申请单 → PN 编码 → PN 主数据上的名称，去重合并。各条通常相同，但不能排除不同。按 PN 筛时 PN 编码按段精确匹配、PN 名称包含匹配，任一命中即算；展示用名称，只有一个时直接展示，多个时用「、」连接。

### 数量与不良率

不良率 = 不良数量 × 100 ÷ 影响数量，保留 2 位小数；影响数量为 0 或空时记 0。数值是百分数（46.4 表示 46.4%），「不良率 100%」对应数值 100。巴西没有存储的不良率列，分母是影响数量，不是生产数量。

多张单合起来算时，不良率 = 合计不良数量 × 100 ÷ 合计影响数量，保留 2 位小数；影响数量为 0 或空的单不参与（见总述「汇总不良率」）。

### 费用

- 是否涉及费用：是 / 否（0 为测试脏值，按无效处理）。用户明说「是否涉及费用为是 / 否」时，按单上这个标记筛，只看是、否两种。
- 按单汇总：费用美元合计、费用雷亚尔合计、专项费用明细（规则见费用表文件）。如「费用超过 200 美元」按费用美元合计比较。
- 最新一条处理过程上另有「是否有涉案金额」「扣款费用（美元）」「扣款单号」「未转嫁原因」，与专项费用分开。

| 用户说法 | 口径 |
|---|---|
| 涉及费用的单、有费用的单、产生了费用的单 | 费用美元合计或费用雷亚尔合计大于 0 的单，不看「是否涉及费用」标记 |
| 花了多少钱、费用多少、花了多少美元 | 只合计费用明细：问美元给费用美元合计，问雷亚尔给费用雷亚尔合计；没说币种时两种分别给出，不换算、不相加。问美元时，若有单只产生了雷亚尔费用，另行说明这些单的单数与雷亚尔合计 |
| 扣款、转嫁、扣了供应商多少 | 最新一条处理过程上的扣款费用（美元）。它不是费用，不并入「花了多少」；需要时单列「其中扣款多少」 |

统计口径说明里写明：涉及费用按费用明细合计大于 0 认定；扣款单独列出、未计入费用（决策 2026-10-20「巴西涉及费用按费用明细认定」）。

### 8D

| 概念 | 含义 |
|---|---|
| 是否需要回复 8D | 业务上要不要回 8D |
| 已上传的 8D 报告 | 实际挂接的文档；挂在该单的处理过程记录上，一单可有多份 |

「需要回复 8D」为是，不代表已有文件。8D 文件以文档名称打开预览，已删除文档不展示。

### 补料与库存处理

主表：是否需要补料、补料数量、补料结果、补料备注、补料人、补料日期。处理过程：是否库存处理、库存处理数量、在库退货单号、退货确认结果、是否供应商补料、供应商补料数量、入库单号。

### 投诉单号

自由文本，展示原值；筛选用模糊匹配。

### 叙述文字

主表问题描述、补料备注、备注；处理过程各叙述列；费用备注——都是富文本，处理方式与问题描述相同（见 `dirty_data.md`）。问题现象是 JSON，按展平规则处理，不按富文本处理。按文字找单时，没点名字段按总述「比对范围」找；点名了其中某个字段时，只在该字段里找。

## 关联

| 看什么 | 怎么关联 |
|---|---|
| 处理过程 | `BrazilProblemProcess.ProblemID = 主表.ID` |
| 费用 | `BrazilProblemCost.ProblemID = 主表.ID` |
| PN | `BrazilProblemPO.ProblemID = 主表.ID` → `RequestID = Brazil_RequestList.ID` → `PartNumber = NewProduct.PartNumber` → `Name` |
| 大机型、系列 | `ProductIDAll` 各段 `= ProductName.ID` → `ProductName`、`Series` |
| 物料 | `cInvCode = Inventory.cInvCode` → 物料名称、规格型号 |
| 供应商 | `cVenCode = tbIQCvendor.ferpcode`（空值不关联） |
| 停线级别 | `ProblemClass = AfterSaleIssueClass.ID` → `ClassName`（类型不一致时按实际类型转换） |
| 加工厂 | `BrazilFactory` 各段 `= Brazil_Factory.FactoryName` |
| 人员 / 部门 | 各 `*UserID = Employee.ID`；`Employee.Unit = Department.ID` |
| 8D 文档 | `DocumentList.BusinessType = '巴西制程问题单8D报告'` 且 `frecid` 属于该单处理过程 `ID`，且 `EffectFlag = 0` |
| 制程单链接 | 见 `link_rules.md` |

供应商关联不上，或大机型、发现工位、投诉单号为空时，显示「未填」。大机型有值但某段对不上产品主数据时，该段不显示；全部对不上时显示「未识别机型」，不展示内部编号（目前数据里没有这种情况）。

## 数据规模

主表 199 张单（2024 年 80、2025 年 71、2026 年截至 10 月 48）；处理过程 193 条，有单尚无处理过程。其余见总述「数据量声明」。

## 常见查询示例

1. 2024 年 Q3 TT 工厂 A 类硬件问题有哪些？
2. 单号 BR2404001 的完整处理过程和问题跟进人是谁？
3. 目前停线且未重启的物料问题有哪些？
4. 某机型在 2025 年的不良数量与不良率情况？
5. 质量管理部负责跟进且尚未结案的问题列表？
6. 需要回复 8D 的物料问题及改善措施内容有哪些？
7. 2026 年 1 月由生产工程部负责跟进处理的制程问题有哪些？列出问题编号、处理人、问题类型、机型、不良数量、不良率
8. 生产工程部 2026 年第一季度处理的制程问题统计
9. 巴西工厂 CA 涉及的机型名称有哪些？
10. 请提供 26 年出现的非接相关问题
11. 最近 14 天出现的制程相关问题有哪些？
12. 搜索所有制程问题描述中含 USB 或打印的问题
13. 某机型的制程问题中是否有与通信相关的？
