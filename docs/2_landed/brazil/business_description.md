# 巴西制程问题 业务描述

> 字段定义见 `db_description/`；三域共用口径见上级 `business_description.md`。

## 业务域

围绕巴西制程问题主表（CoreINFO.dbo.BrazilProblemList），只读查询巴西工厂产线制程问题的发现、分类、停线、跟进、改善、费用、补料、8D 与结案。单号 `BR` 开头。只含巴西工厂（巴西工厂主数据上的工厂）的单据，不含海外单据。

**不做**：国内那种生产订单明细问法（关联申请单只用来解析 PN）；没有国内的「责任归属部门」，相关说法按问题跟进部门解释；不为巴西本地员工、供应商等外部角色设计场景。

## 查询范围

- 状态为「已删除」的单一律排除，与管理页面一致，按单号也查不到。「待提交」（草稿）与「已终止」**默认包含**。
- **按号查单**：支持问题编号、投诉单号（不分大小写、去掉空格后精确匹配，见下文「投诉单号」）。最新一条处理过程上的扣款单号、入库单号：用户明说是哪种号时按通用筛选规则精确匹配，只给号、不说是什么时不拿它们去匹配。在库退货单号不用于查单（与国内一致），也暂不展示（见下文「补料与库存处理」）；不支持按订单号查单。各种号怎么认、对不上时怎么答，见总述「按编号查单」。
- 默认不限工厂、跟进部门，也不按提问人限定（没有「我的待办」这种默认视角），由用户问句收窄。
- 按物料查只看主表料号：给料号时按料号匹配，给物料名称时经存货档案的物料名称包含匹配（只说「X 的问题」时物料名称与文字两种都查，见总述「三域共用的说法」）；问题单涉及的存货明细不在查询范围。
- 本域用 13 张表：主表、处理过程、费用明细、关联申请单 4 张业务表，加申请单、PN、产品、存货档案、供应商、巴西工厂、人员、部门、文档清单 9 张主数据表。
- **一行一单**：问题单清单与汇总里每张单只占一行。一对多的子表先按下表收敛再挂到单上，不能把多张子表的明细行直接并列，否则同一单会被重复计数。

| 子表 | 收敛方式 |
|---|---|
| 处理过程 | 取最新一条（`ID` 最大） |
| 费用明细 | 汇总为费用美元合计、费用雷亚尔合计、专项费用明细（见费用表文件） |
| 关联申请单 | 全部解析为 PN 后去重，合并成「PN 列表」；PN 编码为 0 的不算（见下文「大机型与 PN」） |
| 8D 文档 | 不并入清单行；清单只带「是否需要回复 8D」 |
| 大机型（单内多值） | 解析成大机型名称，去重后用「、」连接 |
| 问题现象（单内 JSON） | 展平成一段文字 |

- 看明细时：费用给全部明细行（含 0 金额行、汇率、备注）；8D 给该单全部处理过程上的有效文档。

## 口径

### 时间

| 用户说法 | 口径 |
|---|---|
| 给出时间、没说是哪件事 | 按建单时间筛 |
| 现场发现、发现日期 | 按现场发现日期筛（文本存日期，先解析） |
| 停线的、停过线的 | 按停线日期筛（文本存日期，先解析） |
| 重启的 | 巴西没有停线重启时间，不计入，回答里写明 |
| 结案的、关闭的 | 按结案时间筛：最新一条处理过程上的结案日期，只对「已结案」的单定 |
| 统计日期 | 只有用户明说「统计日期」时才按统计日期筛 |

规则与结案周期见总述「按哪个日期筛」「结案时间与结案周期」。

文本存的日期（现场发现日期、停线日期、统计日期、计划完成日期、设计更改评估时间）展示用原值，筛选、排序、统计用解析后的日期，解析失败按空。

按统计日期筛选、统计时，没填统计日期的单不会命中，回答（统计时为统计口径说明）里写明有几张没填、未计入。

### 问题类型

设计问题、结构问题、生产问题、制程优化、硬件问题、物料问题、其他。`其他|备注` 显示为「其他」，备注进「其他问题说明」；按「其他」筛选时两种写法都命中。主表与处理过程表各有一份问题类型，含义相同、彼此独立。筛选、统计、跨域归并只用主表这一份；处理过程那份不展示，也不参与筛选统计。

### 状态与生命周期

- 状态：待提交、待修改类别、待跟进、待设计更改、待SQE确认、待效果确认、待结案、已结案、已终止、已删除。没有正式状态流转图，按枚举原值理解与筛选。
- 结案完成是「已结案」。
- 未结案、进行中、没完成 = 待修改类别、待跟进、待设计更改、待SQE确认、待效果确认、待结案。待提交（草稿）与已终止不算未结案，需要时单独列出它们的单数。回答的统计口径说明里写明这一点。
- 结案结果（最新一条处理过程上的「是 / 否」）是结案人对结果的评定，与状态独立。

### 停线

| 是否停线 | 停线状态 | 含义 |
|---|---|---|
| 否 | 空 | 从未停线 |
| 是 | 空或其他取值（如「停线中」） | 停线后尚未标记重启 |
| 是 | 停线重启 | 停过线，已标记重启（是否停线仍为「是」） |

| 用户说法 | 口径 |
|---|---|
| 停线中、目前停线、停线且未重启 | 是否停线为「是」，且停线状态不是「停线重启」（空或其他取值都算）。不看是否结案，与国内一致 |
| 停线已重启、停线后已恢复生产 | 是否停线为「是」，且停线状态为「停线重启」 |
| 发生过停线、曾经停线、有停线记录 | 是否停线为「是」，不看停线状态 |
| 从未停线 | 是否停线为「否」 |
| 停线级别 | 巴西没有这一项，管理页面也不显示，回答里说明 |

巴西没有停线重启时间，只能看是否已标记重启（停线状态为「停线重启」）。

清单里的「停线状态」一列与按停线状态统计用同一套写法，按上面第一张表写成三种：是否停线为「否」写「从未停线」；为「是」且停线状态不是「停线重启」写「停线中」；其余写「停线重启」。不照单上原值把空写成「未填」。

### 人员与部门

| 用户说法 | 口径 |
|---|---|
| 问题跟进人 | 该单最新一条处理过程上的问题跟进人；还没有处理过程的单显示「未指定」，不用初始责任人代替 |
| 只说人名（「张三的问题」） | 问题跟进人 |
| 只说「责任人」（「这单的责任人是谁」「这单谁负责」） | 问题跟进人：管理页面「责任人确认」里的「责任人」就是问题跟进人。巴西不提供当前责任人，回答里说明 |
| 问题跟进部门、某部门跟进 / 处理 / 负责的；只说部门 | 上述问题跟进人现在所在的部门（单上不存部门，人员调岗后历史单的跟进部门跟着变），统计口径说明里写明；没有处理过程的单显示「未指定」，按部门统计时不计入，统计口径说明里写明 |
| 责任部门、定责部门、责任归属 | 巴西没有这个维度，按问题跟进部门解释，并在回答（统计时为统计口径说明）中说明 |
| 当前谁在处理、当前责任人、当前处理人（问单张单） | 巴西不提供当前责任人。回答时说明这一点，并给出问题跟进人（没有处理过程的单为「未指定」） |
| 某人手上的、某人待处理的、卡在某人那的（清单、统计） | 巴西不提供当前责任人，巴西的单不计入；回答（统计时为统计口径说明）里写明「巴西不提供当前责任人，未计入」，不改按问题跟进人列单（决策 2026-10-20「G1 全局 review 修订」） |
| 初始责任人 | 主表上的初始责任人 |

填单人所在部门只作人员展示，不作部门统计的默认依据。其他人员：补料人、设计更改人、SQE 确认人、效果确认人、结案人。

### 加工厂

主表直接存巴西工厂名称，可逗号多值（如 `CA,TT`）。用户指定工厂 X 时，按逗号拆段、去首尾空格后任一段等于 X 即命中：搜 `CA` 要命中 `CA` 和 `CA,TT`，搜 `TT` 也命中 `CA,TT`。比较时不分大小写；用户说「TT 工厂」时去掉「工厂」二字再比。工厂名称以巴西工厂主数据为准。

### 大机型与 PN

两条独立链路。用户说「机型」时按大机型查，不按 PN；说「PN」时按 PN 列表查。

- **大机型**（也叫机型名称列表）：主表大机型 ID 各段 → 产品名称，一单多个时去重，用「、」连接。按大机型查时按完整名称匹配，任一段命中即算，规则见总述「机型与系列怎么对」。跨域按机型汇总时与国内机型、海外大机型同名合并。
- **系列**：大机型各段 → 产品主数据上的系列，去重后用「、」连接展示。用户说「X 系列」时按它查，任一大机型的系列命中即算，规则见总述「机型与系列怎么对」。
- **PN 列表**：该单全部关联申请单 → PN 编码 → PN 主数据上的 PN 名称，去重合并。每个 PN 展示为「PN 名称 PN 编码」，与管理页面一致；PN 主数据里找不到名称的只给编码；多个时用「、」连接。按 PN 筛时 PN 编码按段精确匹配、PN 名称包含匹配，任一命中即算。
- **PN 编码为「0」**：没选 PN 时留下的占位值，与管理页面一致，不展示、不参与按 PN 查。单上另有其他 PN 时只展示那些 PN；只有 0 的单，PN 显示「未填」（决策 2026-10-21「落盘计数改取正式镜像」补记）。

### 数量与不良率

不良率 = 不良数量 × 100 ÷ 影响数量，保留 2 位小数；与管理页面一致，影响数量为 0 时显示 0.00%，影响数量为空时算不出，显示「未填」。数值是百分数（46.4 表示 46.4%），「不良率 100%」对应数值 100。巴西没有存储的不良率列，分母是影响数量，不是生产数量。

多张单合起来算时，分母为影响数量，规则见总述「汇总不良率」（不良数量为空、影响数量为 0 或空的单不参与）。

### 费用

- 是否涉及费用：是 / 否（0 为测试脏值，按无效处理）。用户明说「是否涉及费用为是 / 否」时，按单上这个标记筛，只看是、否两种。
- 按单汇总：费用美元合计、费用雷亚尔合计、专项费用明细（规则见费用表文件）。如「费用超过 200 美元」按费用美元合计比较。
- 最新一条处理过程上另有「费用转嫁」「扣款费用（美元）」「扣款单号」「未转嫁原因」，与专项费用分开。
- 管理页面把费用明细那张表叫「涉案金额」。用户说「涉案金额」时按费用明细回答，不是费用转嫁。

| 用户说法 | 口径 |
|---|---|
| 涉及费用的单、有费用的单、产生了费用的单 | 费用美元合计或费用雷亚尔合计大于 0 的单，不看「是否涉及费用」标记 |
| 花了多少钱、费用多少、花了多少美元、涉案金额多少 | 只合计费用明细：问美元给费用美元合计，问雷亚尔给费用雷亚尔合计；没说币种时两种分别给出，不换算、不相加。问美元时，若有单只产生了雷亚尔费用，另行说明这些单的单数与雷亚尔合计 |
| 扣款、转嫁、扣了供应商多少 | 最新一条处理过程上的扣款费用（美元）。它不是费用，不并入「花了多少」；需要时单列「其中扣款多少」 |

统计口径说明里写明：涉及费用按费用明细合计大于 0 认定；扣款单独列出、未计入费用（决策 2026-10-20「巴西涉及费用按费用明细认定」）。

### 8D 与附件

| 概念 | 含义 |
|---|---|
| 是否需要回复 8D | 业务上要不要回 8D |
| 已上传的 8D 报告 | 实际挂接的文档；挂在该单的处理过程记录上，一单可有多份 |

「需要回复 8D」为是，不代表已有文件。8D 文件以文档名称打开预览，已删除文档不展示。

其他附件与管理页面一致只给两种，同样以文档名称打开预览、已删除的不展示、不作筛选条件：投诉单附件挂在单上，放在「填单信息」里；设计更改附件挂在处理过程上，放在「SQE 确认」一块里。取法见文档清单字段说明。

### 补料与库存处理

主表：是否需要补料、补料数量、补料结果、补料备注、补料人、补料日期。处理过程：是否库存处理、库存处理数量、是否供应商补料、供应商补料数量、入库单号。

与管理页面一致：「是否库存处理」为「是」时另给库存处理数量；「是否供应商补料」为「是」时另给供应商补料数量、入库单号（见下文「单张单详情」）。为「否」或空时这几项不给。

库存处理的其余信息暂不提供（决策 2026-10-23「G1 四次复核修订」）：管理页面「库存处理」为「是」时另有一栏「库存」；处理过程上另有在库退货单号、退货确认结果、退货确认备注、退货确认人、退货确认时间。这些都不展示，也不作筛选条件，问到时请到管理页面查看。

### 投诉单号

自由文本，展示原值。按投诉单号查单时，两边都不分大小写、去掉全部空格后精确匹配，不做包含匹配：只给了号的一部分（如只给中间几位数字）查不到。点、斜杠、连字符照原样比，不去掉。

查不到（含只挂在已删除的单上）时回答「没有找到这个投诉单号对应的单（已删除的单查不到），请核对完整的投诉单号」。

### 单张单详情

与管理页面详情一致，分几块给（业务方 2026-10-23 管理页面核对）：

| 区块 | 给什么 |
|---|---|
| 填单信息 | 问题编号、填单人、建单时间、加工厂、投诉单号、系列、大机型、PN 列表、问题类型、料号与物料名称、供应商编号与名称、影响数量、不良数量、不良率、问题现象、问题等级、是否停线（停过线时另给停线状态、停线日期）、现场发现日期、发现工位、统计日期、问题描述、是否需要补料（需要时另给补料数量）、是否需要回复 8D、是否涉及费用、费用明细与合计、备注、投诉单附件 |
| 责任人确认 | 最新一条处理过程上的：责任人确认结果、问题跟进人（页面写作「责任人」）、责任人确认日期、计划完成日期、SQE 跟进结果、是否设计更改、是否库存处理（为是时另给库存处理数量）、原因分析、改善措施、改善批次、预防对策、费用转嫁（为是时另给扣款费用、扣款单号；为否时给未转嫁原因）、是否供应商补料（为是时另给供应商补料数量、入库单号）、8D 报告 |
| SQE 确认 | 做过 SQE 确认的单另有这一块：设计更改与 SQE 确认的各项（见处理过程字段说明），以及设计更改附件 |
| 效果确认 | 效果确认结果、效果确认备注、效果确认人、效果确认日期 |
| 结案确认 | 结案结果（页面写作「是否结案」）、结案备注、结案人、结案日期 |

- 处理过程只给最新一条。一单有多条处理过程时，管理页面每条显示一个「责任人确认」，后一条是在前一条的基础上修改、补充的，只看最新一条即可（业务方 2026-10-23 答复）。问「完整处理过程」时同样只给最新一条；8D 报告与设计更改附件仍给该单全部处理过程上的有效文档。
- 原因分析、改善措施、预防对策、未转嫁原因等叙述栏有内容才显示，没有就不显示，不写「未填」。需要回复 8D 的清单同样如此。
- 页面上的「涉及的PO」本助手只取其中的 PN（见上文「大机型与 PN」），「费用涉及物料」不在查询范围，问到时请到管理页面查看。
- 页面「库存处理」为「是」时另有一栏「库存」，本助手暂不提供，问到时请到管理页面查看（见上文「补料与库存处理」）。
- 页面「责任人确认」里另有「5Why分析过程」，本助手暂不提供，问到时请到管理页面查看（决策 2026-10-23「G1 三次复核修订」）。

### 叙述文字

以下叙述文字都是富文本，处理方式与问题描述相同（见 `dirty_data.md`）：

- 主表：问题描述、补料备注、备注。
- 最新一条处理过程：SQE 跟进结果、原因分析、改善措施、改善批次、预防对策、未转嫁原因，以及责任人确认、设计更改、SQE 确认、效果确认、结案各备注。
- 费用明细：费用备注。

问题现象是 JSON，按展平规则处理，不按富文本处理；其中选的标准现象只按词找，手填的现象也按意思找（总述「比对范围」）。按文字找单时，没点名字段按总述「比对范围」找；点名了其中某个字段时，只在该字段里找，按意思找还是按词找见总述「点名字段时怎么找」。问「原因、措施」时给什么，见总述「原因与措施怎么给」。

结构总览见 `table_relations.md`；本节为关联条件的信源，修改时同步该图。

| 看什么 | 怎么关联 |
|---|---|
| 处理过程 | `BrazilProblemProcess.ProblemID = 主表.ID` |
| 费用 | `BrazilProblemCost.ProblemID = 主表.ID` |
| PN | `BrazilProblemPO.ProblemID = 主表.ID` → `RequestID = Brazil_RequestList.ID` → `PartNumber = NewProduct.PartNumber` → `Name` |
| 大机型、系列 | `ProductIDAll` 各段 `= ProductName.ID` → `ProductName`、`Series` |
| 物料 | `cInvCode = Inventory.cInvCode` → 物料名称、规格型号 |
| 供应商 | `cVenCode = tbIQCvendor.ferpcode`（空值不关联） |
| 加工厂 | `BrazilFactory` 各段 `= Brazil_Factory.FactoryName` |
| 人员 / 部门 | 各 `*UserID = Employee.ID`；`Employee.Unit = Department.ID` |
| 8D 文档 | `DocumentList.BusinessType = '巴西制程问题单8D报告'` 且 `frecid` 属于该单处理过程 `ID`，且 `EffectFlag = 0` |
| 投诉单附件 | `DocumentList.BusinessType = '巴西制程问题单附件'` 且 `frecid = 主表.ID`，且 `EffectFlag = 0` |
| 设计更改附件 | `DocumentList.BusinessType = '巴西制程问题单设计更改'` 且 `frecid` 属于该单处理过程 `ID`，且 `EffectFlag = 0` |
| 制程单链接 | 见 `link_rules.md` |

供应商关联不上，或大机型、发现工位、投诉单号为空时，显示「未填」。大机型有值但某段对不上产品主数据时，该段不显示；全部对不上时显示「未识别机型」，不展示内部编号（目前数据里没有这种情况）。
