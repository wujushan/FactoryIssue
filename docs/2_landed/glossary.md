# 业务术语表

> `manifest.glossary` 的唯一信源；改本文件须同步 `src/factory_issue_module/module.py` 的 `glossary`。

| 规范词 | 别称 | 口径定义 |
|---|---|---|
| 制程问题 | 制程单、制程问题单、制程相关问题 | 生产制程中发现并登记的质量问题单。不指某一种问题类型 |
| 问题类型 | 问题分类（管理页面写法）、类别 | 问题单的分类，如硬件问题、物料问题、工厂制程。三域取值不同，跨域同名合并（见总述「跨域归并」） |
| 国内制程问题 | 国内、ZC 单 | 国内工厂的制程问题，单号 `ZC` 开头 |
| 巴西制程问题 | 巴西、BR 单 | 巴西工厂产线上的制程问题，单号 `BR` 开头 |
| 海外制程问题 | 海外、HW 单 | 海外工厂的制程问题，单号 `HW` 开头 |
| 问题编号 | 单号、制程单号 | 「前缀 + 年月 + 3 位序号」，如 ZC2109001。不分大小写，忽略中间的空格、连字符；已删除的单按问题编号也查不到。各种号怎么认见总述「按编号查单」 |
| 加工厂 | 工厂、巴西工厂（巴西管理页面写法） | 问题发生的工厂：国内为国内工厂，巴西为巴西工厂名称，海外为海外工厂名称。只说「巴西工厂的问题」时指巴西域，不是某个工厂。国内按地区说（「惠州的工厂」）时按地区说法对照对到工厂，见国内业务描述「加工厂」 |
| 国内工厂 | — | 国内工厂主数据里的工厂，工厂码翻成工厂名称。国内单的加工厂就是国内工厂；海外单上另记一列国内工厂，只说「工厂」「加工厂」时不参与海外筛选，用户明说「国内工厂」时才按它筛 |
| 大机型 | 机型名称列表 | 产品主数据中的产品名称（巴西、海外），一单可多个。匹配方式同机型 |
| PN | PN 列表、PN 编码、PN 名称 | 三域同一套 PN。PN 编码是 15 位数字，PN 名称是带连字符的型号码，如 `A35-000-RD6-00E0`，展示为「PN 名称 PN 编码」。国内看生产订单，巴西看关联申请单，海外看主表。与料号是同一套 15 位物料编码，区别只在单上登记的位置（见「料号」）。查法见总述「三域共用的说法」 |
| 机型 | 机型名称、机器型号 | 具体终端产品型号，常为「字母 + 数字」简写，如 A920、Q92、IM30。国内来自机型子表，巴西、海外来自大机型（不按 PN）；跨域按机型汇总时同名合并。按完整名称匹配，不做包含匹配：A920MAX、A920PRO 是与 A920 不同的机型。规则见总述「机型与系列怎么对」 |
| 系列 | 产品系列 | 机型所属的产品系列，如 A920 属于 A 系列（没有「A920 系列」）。用户说「X 系列」时按系列查，国内看机型的系列，巴西看大机型的系列；海外系列不作查询条件。「底座」也是一个系列（L920、T3510、B910 等）。规则见总述「机型与系列怎么对」 |
| 料号 | 物料编码、物料编号 | 物料的编码。国内、巴西经存货档案翻成物料名称与规格型号；海外取物料 JSON 里的料号与描述，不经存货档案。按料号查：国内、巴西看主表料号（国内不看小板订单料号），海外看物料清单任一条。与 PN 编码是同一套 15 位物料编码，区别只在单上登记的位置 |
| 停线 | 曾经停线、发生过停线、有停线记录、是否需要停产（国内、海外管理页面写法） | 曾经停过线，已重启的仍算 |
| 停线日期 | 停产日期（国内、海外管理页面写法） | 停线发生的日期。问「停过线的单」按它筛 |
| 停线中 | 目前停线、正在停线、停线且未重启 | 停线状态显示仍在停线、尚未重启。国内含重启审核中、重启审核通过、责任人填写重启方案。只看停线状态、不看是否结案，与管理页面一致 |
| 停线重启 | 已重启、已恢复生产 | 停线后已经重启 |
| 重启日期 | 重启时间、恢复生产日期 | 国内为最新一条停线重启步骤登记的日期，管理页面详情显示为「重启日期」，另有「重启备注」。问「某段时间重启的单」按它筛；停线时长 = 重启日期 − 停线日期。巴西没有，不计入；海外看停线重启时间，没填的不计入 |
| 结案 | 已结案、已完成、关闭 | 国内、海外为「已完成」，巴西为「已结案」 |
| 结案时间 | 结案日期、关闭时间 | 已结案的单结案的时间。国内、海外为处理步骤里最新一条「结案确认」的发生时间，巴西为最新一条处理过程上的结案日期。问「某段时间结案的单」时按它筛 |
| 结案周期 | 结案天数、多久结案、处理周期 | 结案时间的日期减建单时间的日期，按天计，只算已结案的单；汇总时给平均、中位数与分档 |
| 逾期 | 超期、超时 | 本助手不判定逾期。用户明确按计划完成时间筛时按条件查 |
| 未结案 | 进行中、没完成、未关闭 | 尚未到达该域的结案完成状态。国内、海外为状态不是「已完成」，国内含「生产角色驳回」（流程已结束，单独点出张数）；巴西为待修改类别、待跟进、待设计更改、待SQE确认、待效果确认、待结案，不含待提交、已终止（两者另列） |
| 问题跟进部门 | 跟进部门 | 被指定跟进处理问题的部门 |
| 部门简称 | — | 日常对部门的叫法，按简称表对到正式部门，如「工程部」即生产工程部。简称表由管理员维护，对法见总述「部门名称怎么对」 |
| 问题跟进人 | 跟进人 | 被指定跟进处理问题的人员。列清单时只说「处理人」也指问题跟进人；「当前处理人」指当前责任人 |
| 当前责任人 | 当前处理人、当前谁在处理、手上的单、待处理的单 | 问题单当前环节上的人。国内为当前状态各行出现的全部人员（含 IQC 成员、进行中的退货 / 退库责任人，并行阶段另含预防对策确认的待办人员，见国内业务描述「当前责任人」）；海外为主表上流转到最新节点的处理人；「已完成」的单没有。巴西不提供：问单张单时说明并给出问题跟进人，按人查单、统计时巴西不计入 |
| 责任人 | 问题责任人、这单谁负责 | 国内与管理页面导出一致：按问题类型取对应环节最新一步的操作人（见国内业务描述「责任人怎么取」）。海外只说「责任人」时同时给当前责任人与问题跟进人；巴西给问题跟进人（巴西管理页面写作「责任人」），并说明不提供当前责任人。国内「指定责任人」「责任人确认」环节与「责任人处理结果」里的责任人指问题跟进人；定责只到部门（责任归属部门） |
| 当前状态 | 进行到哪了、到哪一步了、现状 | 问题单当前所处的环节。国内为环节 + 当前责任人，可多行，如「预防对策确认 张三」「效果确认 李四」；巴西、海外为主表状态，海外可附当前责任人，巴西不提供当前责任人 |
| 责任归属部门 | 责任部门、定责部门、定责、责任归属于某部门、责任在某部门 | 国内结案后人为定责的部门；问到时只给这一个口径，另给「看该部门跟进的单」的选项。为空时已完成的单写「无需定责」、未完成的单写「未定责」。物料问题不展示、不按它统计。巴西、海外没有，按问题跟进部门理解，并在回答里写明 |
| 原因分类 | — | 国内结案时人为归类的原因，从固定列表选取，如「人为工作疏忽」 |
| 产品在制属性 | 订单类型、生产阶段 | 国内单关联的那次生产所处阶段：首次量产、首次量产爬坡、正常量产、量产爬坡、未释放PN生产、物料试产、小批量试产、工程样机（与管理页面一致）。「物料」单没有这一项 |
| 投诉单号 | Claim、CLAIM 单号 | 巴西单上的投诉单号，自由文本，多数以 CLAIM 开头。按号查单时不分大小写、去掉空格后精确匹配，不做包含匹配 |
| 费用 | 专项费用、涉案金额（巴西管理页面写法） | 巴西单产生的费用明细，按美元、雷亚尔分别合计；与扣款费用分开。「涉及费用的单」按费用明细合计大于 0 认定，不看「是否涉及费用」标记 |
| 扣款费用 | 扣款、转嫁 | 巴西处理过程上的扣款金额（美元），不是专项费用合计。是否转嫁看处理过程上的「费用转嫁」（是 / 否） |
| 补料 | — | 巴西单是否需要补料、补料数量与结果 |
| 雷亚尔 | BRL、巴西币 | 巴西货币 |
| 现场发现日期 | 发现日期 | 现场发现问题的日期，区别于建单时间 |
| 建单时间 | 填单时间、提交时间、填单日期（国内管理页面写法） | 制程单填写建单的时间，按时间筛选时默认用它。巴西草稿（待提交）尚未提交，同样按建单时间计 |
| 统计日期 | — | 巴西单上的统计日期。只有用户明说「统计日期」时才按它筛选，否则按建单时间 |
| 不良率 | — | 单张单的不良比例，数值是百分数（46.4 即 46.4%）。国内取单上已存的值（不良数量 ÷ 生产数量）；巴西现算（不良数量 × 100 ÷ 影响数量，保留 2 位小数）；海外按单上原文展示，保留 % 或 ‰。多张单合起来算见总述「汇总不良率」，海外不汇总 |
| 问题等级 | 等级、问题级别、A 类、A 级 | 产品质量问题的严重程度，三域相同，由高到低 A+、A、B、C，以单上登记的为准，不按定义重新定级。A+：安全问题；A：涉及安全的事故、关键电子器件或关键装配物料功能不良、高比例开箱不良或严重客诉；B：A 类以外的功能性问题，或已影响交付的问题；C：其余问题。说「A 级」只指 A，「A 级及以上」含 A+、A；空为「未填」（国内 2024-04-17 之前的单都没有等级）。完整定义见总述「问题等级」 |
| 停线级别 | — | 本助手不提供：三域管理页面都没有这一项，问到时说明 |
| CAR | 纠正预防措施单、纠正预防措施报告 | 国内物料问题关联的 IQC 纠正预防措施报告，含根本原因、永久纠正措施、预防措施、有效性确认；其他类型的单不展示 CAR |
| CAR 编号 | CAR 报告编号、CAR 单号 | 国内物料问题单上登记的 CAR 编号，形如 `CAR` + 9 位数字，一单一个；可用来查单 |
| 8D | 8D 报告 | 巴西问题单需回复的 8D 报告。「是否需要回复 8D」与已上传的 8D 文件是两件事 |
| IQC | 来料检验 | 来料质量检验；IQC 意见为退回仓库或继续使用 |
| SQE | 供应商质量工程师 | 供应商质量跟进与确认环节，如国内状态「SQE跟进」「SQE确认」 |
| 设计变更 | 设计更改（管理页面写法） | SQE 跟进判定需要改设计后走的环节。三域都有；国内、海外的字段叫设计变更，巴西的字段与各域管理页面多写作设计更改，指同一件事 |
| PMC | 生产物料控制 | 国内状态「PMC确认」环节 |
| 小板订单 | 小板生产任务订单 | 国内中间产物（物料标识为「物料」）的生产任务订单 |
| 其他在线订单 | — | 国内问题单关联、受影响的其他在线生产订单；整机单与「物料」单都可能有。单张单详情里只给条数，用户追问时再列出明细 |
| 物料标识 | 中间产物、物料单 | 国内单标「物料」表示问题出在磁头、面壳组件等中间产物而非整机。标了「物料」的单叫「物料单」，与问题类型「物料问题」是两回事 |
| 问题现象 | 缺陷现象、不良现象 | 巴西单上的现象（展平成一段文字）；海外为「已选问题现象」；国内为建单时选的现象，一单可多条（2024 年以前的单没有，现象多写在问题描述里）。三域的问题现象都进按文字找单的比对范围；从现象清单里选的只按词找，巴西、海外手填的也按意思找（见总述「比对范围」）；国内的不作筛选条件、不统计 |
| 已选问题现象 | — | 海外单勾选或手填的现象，一单可多条。巴西管理页面也把问题现象写作「已选问题现象」，指的是巴西的问题现象 |
| 可能问题原因 | — | 现象下系统预设的候选原因，不是单上写下的原因分析。海外按标准现象给出；国内给建单时登记的那几条 |
| 可能的问题物料 | 可能问题物料 | 国内建单时系统按问题类别和现象推荐的候选物料，不是单上的涉及物料，按物料查单不看它 |
| 5Why | 5Why 分析、五问法、5Why分析过程 | 国内单上逐条的「为什么」与答复的原因，带提问人、答复人与时间；放在本类型的分析环节里，随该环节显示或隐藏。巴西、海外管理页面也有，本助手暂不提供，问到时请到管理页面查看 |
| 原因分析 | 问题原因 | 单上已经写下的原因，三域管理页面都写作「原因分析」。不是「可能问题原因」 |
| 类似问题 | 相近问题、类似案例、以前怎么处理的 | 描述一个具体现象想找先例时，按意思找最相近的问题单，默认最多 10 张，不保证完整。问某个话题有哪些单见「涉及某个话题」 |
| 涉及某个话题 | X 相关问题、有没有涉及 X、出现过 X 吗 | 按说法清单找全：问题本身涉及 X 的、处理中提到 X 的两组全部列出，另附说法不同、可能相关的单（最多 10 张，不保证找全）。X 是话题本身时用这个话题的全部说法；X 比话题小（「eSIM」「电池卡扣」）时只用意思相同的几个说法，组合说法按词组找。详见总述「涉及某个话题怎么找」 |
| 关键词搜索 | 搜索、描述中有 | 找出文字里出现指定词的全部问题单；「和」都出现，「或」出现任一；只按用户给的词找。说「描述里」「描述中」时只在问题描述里找；用户点名其他字段时只在该字段里找，怎么找见总述「点名字段时怎么找」 |
| 非接 | 非接触、NFC | 非接触式读卡（挥卡、NFC）相关问题，按「涉及某个话题」找 |
| 其他 | 其它、剩下的、别的 | 看语境：明说问题类型「其他」时指该类型（巴西、海外有，国内没有）；上文点过具体的类型、工厂、机型等再问「其他的呢」时，指同一维里除已点到之外的其余取值；都不是时追问。系列里的「其它」只在明说「其它系列」时才按系列查。详见总述「『其他』『剩下的』指什么」 |
| 安全问题 | 涉及安全的问题、安全事故 | 起火、冒烟、爆炸、触电等涉及安全的问题。不是问题类型；按问题等级 A+ 与文字两路查、分开列。说「A+ 的单」时只按等级查 |
| 涉及发货单 | 发货单 | 海外单涉及的发货单，含 PO、发货单号、日期、PN、版本、数量 |
| 入库数量 | 已入库数量（国内管理页面写法） | 国内生产订单、小板订单、其他在线订单上已入库的数量 |
| 仓库收货数量 | 已收货数量（国内管理页面写法） | 国内其他在线订单上仓库已收到的退货数量 |
| 发料日期 | 物料发料日期（国内管理页面写法） | 国内生产订单、其他在线订单的发料日期 |
| 效果确认内容 | 效果确认结果（国内、海外管理页面写法） | 效果确认环节填写的结果，叙述文字。只说「效果确认」时指这个环节。巴西的「效果确认结果」是有效 / 无效的评定，不是本项 |
| 处理过程 | 处理步骤、完整处理过程、流转记录、操作记录 | 问题单的处理留痕。国内、海外为各环节的流转记录，照管理页面「操作记录」列出全部记录，给操作人、操作时间、类型、内容、附件，国内另列停线重启几步的「重启操作日志」；巴西为处理过程记录，一条记录各步的结果（原因分析、改善措施、SQE、效果确认、结案等），一单可多条，只给最新一条 |
| 责任人处理结果 | 处理结果 | 责任人确认（国内、海外的硬件、软件、结构问题、制程优化）或国内工程确认（资料问题）时选的处理结果：改善、保持现状、挂起。国内物料问题对应设计更改的「确认结果」，工厂制程没有 |
