# 国内制程问题 业务描述

> 字段定义见 `db_description/`；三域共用口径见上级 `business_description.md`。

## 业务域

围绕国内制程问题主表（CoreINFO.dbo.ZCTracking_ProblemList），查询国内工厂制程质量问题的发现、分类、跟进、责任归属、停线、改善与结案。一张单在主表占一行，单号 `ZC` 开头。

**非核心场景**：退货（在线 / 在库退货单号、其他在线订单的处理方式）与版本修订（版本、是否更改订单版本、修订的订单版本）不做专项口径，问到时按单上原值回答。

## 查询范围

- 默认只查未删除单（是否删除为 0 或空）。用户明确要求「已删除的」才列出已删除单。子表没有删除标记，随主表。
- 本域用 15 张表：主表、机型、处理步骤、生产订单、小板订单、其他在线订单、风险订单流程 7 张业务表，加国内工厂、存货档案、供应商、CAR 报告、部门、人员、文档清单、流程待办任务 8 张主数据表。

## 口径

### 时间

| 用户说法 | 口径 |
|---|---|
| 给出时间、没说现场发现 | 按建单时间筛 |
| 现场发现、发现日期 | 按现场发现日期筛 |

### 问题类型

硬件问题、软件问题、物料问题、资料问题、工厂制程、结构问题、制程优化。修改过类型的单，问题类型是当前类型，原问题类型保留修改前的值。

### 状态与生命周期

- 主表状态是当前所处环节的快照（18 个取值见主表文件）；处理步骤表是每次流转的留痕。问「进行到哪了」给当前状态（见下），问「完整处理过程」看处理步骤表全部记录。
- 不同问题类型走不同路径，可能被驳回到前序环节后再推进，不能只凭当前状态推断全程。
- 结案完成只有「已完成」。「结案确认」仍算未结案。未结案、进行中、没完成 = 主表状态不是「已完成」，只看主表状态。

### 按处理环节筛选与统计

与源系统管理页面一致：按处理环节筛选、统计时，看当前状态（见下）的**每一行**，不只看主表状态。

- **筛选**：当前状态任一行的环节命中即算。例：一单当前状态为「SQE跟进 彭xx / IQC确认 梁xx」，按「SQE跟进」和按「IQC确认」筛都能查到它。
- **环节统计**：一单在当前状态出现的每个环节下各计一次，各环节之和可能大于单数，统计口径说明里写明。
- **环节名称**即当前状态各行的环节文字：主表状态与 IQC 状态的文案、风险订单步骤（填写退货信息 / 填写退库信息）、并行阶段待办任务截出的环节（效果确认 / 预防对策确认）。状态 30 两项并行时在「效果确认」「预防对策确认」下各计一次；36 只在「效果确认」下，37 只在「预防对策确认」下。
- 「填写退货单号」（主表状态或 IQC 状态为 7）与「填写退货信息」（风险订单步骤）是两个不同环节，不合并。
- 当前状态没有显示的环节不命中：「已完成」的单只有「已完成」一行；并行阶段只有待办任务行与进行中的退货 / 退库行，不含 IQC 段。
- 结案判断不走这条规则，只看主表状态（见上）。

### 当前状态

「当前状态」= 当前所处环节 + 处理人。一张单可以有多行，每行是「环节」或「环节 处理人」：该环节没有处理人时只写环节（如「已完成」），同一环节多人用逗号合并：

| 情形 | 当前状态示例 |
|---|---|
| 已结案 | 已完成 |
| 一个环节、多人 | 结案确认 赵xx,何x |
| 多个环节并行 | SQE跟进 彭xx<br>IQC确认 梁xx<br>填写退货信息 邓xx |
| 并行阶段，另有进行中的退库 | 预防对策确认 刘xx<br>填写退库信息 周xx |

**状态 30、36、37（效果确认与预防对策确认并行）**：环节与处理人从流程待办任务取；有进行中的退货 / 退库时，在后面追加退货 / 退库段（规则同下文「其他状态」的第三段）。不追加 IQC 段（决策 2026-10-20「并行阶段追加进行中的退货退库」）。

- 取本单的已接受任务：业务记录 ID = 本单 ID，业务表名以 `ZCTracking` 开头，任务状态为「已接受」。
- 环节取任务标题中「】待」之后的文字：「国内制程问题单【ZC2609022】待效果确认」→「效果确认」。
- 处理人：每条任务一个人员 ID，翻成姓名；同一环节多条任务合并一行。
- 先列效果确认，后列预防对策确认，退货 / 退库段排在最后，如「效果确认 陈xx」「预防对策确认 吴xx」「填写退库信息 周xx」。
- 查不到已接受的任务时，显示状态文案 + 主状态处理人；退货 / 退库段照常追加。

**其他状态**：主状态为「已完成」时只显示「已完成」，不追加下面两段。其余状态由三段组成，按以下顺序每段一行：

| 段 | 内容 | 什么时候出现 |
|---|---|---|
| 主状态 | 主状态文案 + 主状态处理人（主表主状态处理人姓名列） | 总是 |
| IQC | IQC 状态文案（复用主状态的码值与文案，常见 6 IQC确认、7 填写退货单号）+ IQC 成员 | IQC 状态有值时。IQC 状态与主状态相同（如都是「IQC确认」）时并入主状态那一行，人员按员工 ID 合并去重 |
| 退货 / 退库 | 风险订单步骤文案（填写退货信息 / 填写退库信息）+ 责任人姓名 | 有进度为「进行中」的风险订单记录时。同一步骤多人合并一行，不同步骤各占一行；已完成的记录不显示 |

责任人存的是员工 ID，翻成姓名展示，不显示工号。

### 当前责任人

当前责任人 = 当前状态各行出现的全部人员，回答时按行给出「环节 + 人」，不只给主状态处理人。来源随状态不同：

| 状态 | 当前责任人从哪来 |
|---|---|
| 30、36、37 | 已接受的待办任务人员，查不到任务时为主状态处理人；有进行中的退货 / 退库时加风险订单责任人 |
| 已完成 | 无 |
| 其他 | 主状态处理人；IQC 段出现时加 IQC 成员；有进行中的退货 / 退库时加风险订单责任人 |

按当前责任人查单、统计（「张三手上有哪些单」「各人还压着多少单」）：

- 张三出现在当前状态任一行，即算这张单在他手上；同一单出现在多行只计一次。按员工 ID 匹配：主状态处理人、IQC 成员用各自的 ID 列，风险订单责任人、待办任务人员本身存的就是员工 ID；姓名只用于展示。
- 一单多人时每人各计一次，各人之和可能大于单数，统计口径说明里写明。
- 「已完成」的单没有当前责任人，不计入。
- 同名同姓时追问部门，确认是哪一位后按人员查。

### 停线

| 用户说法 | 口径 |
|---|---|
| 停线中、目前停线、正在停线 | 停线状态为停线中、重启审核、审核通过、填写重启方案四者之一。不含已经重启、没有停线。统计口径说明里写明含这几个子状态 |
| 停线、曾经停线、发生过停线（没带「中 / 目前 / 正在」） | 是否停线为「是」，已经重启的仍算 |

停线相关还有停线日期、停线重启时间、重启方案、重启审核人、重启方案制定人。

### 人员与部门

| 用户说法 | 口径 |
|---|---|
| 某部门跟进的、问题跟进部门；只说部门（「品质部的问题」） | 问题跟进部门 |
| 某人跟进的、问题跟进人；只说人名（「张三的问题」） | 问题跟进人 |
| 某部门处理的、某部门负责的、某部门人员处理的 | 同样按问题跟进部门。物料问题、工厂制程、资料问题不指定跟进部门，统计不到；统计口径说明里写明这三类未计入 |
| 当前谁在处理、当前责任人、当前处理人 | 当前责任人，按当前状态逐行给出环节 + 人（见上文「当前责任人」） |
| 某人手上的、某人待处理的、卡在某人那的、某人正在处理的 | 按当前责任人查，不按问题跟进人 |
| 只说「责任人」（「这单的责任人是谁」）、问题责任人 | 给出当前责任人，同时附上问题跟进人，各自写明角色。「指定责任人」「责任人确认」环节、「责任人处理结果」「计划完成时间」里的责任人都指问题跟进人。制程问题不定责到个人 |
| 责任部门、定责、责任归属 | 结案后的责任归属部门（可多个），不是问题跟进部门；为空表示无需定责。两者可能相同也可能不同 |

**问题跟进人按问题类型分两种**：

- 硬件、软件、结构问题、制程优化：提交后由固定负责人指定**一名**跟进人，问题跟进人、问题跟进部门有值。
- 物料问题、工厂制程、资料问题：提交后按类型流转到固定处理角色，**不指定**问题跟进人，两列为空；工厂制程默认流转到工厂的三个接口人。

其他人员：填单人、效果确认人、生产确认人、设计变更责任人、IQC 成员、重启审核人、重启方案制定人。

### 加工厂

主表存国内工厂码，展示时翻成工厂名称。用户给工厂名称时，被国内工厂名称包含或与之相近即命中（容忍输入不全或输错），先对到工厂码再筛；命中多个工厂时列出，请用户选。

### 物料

- 按料号筛：只看主表料号，不匹配小板订单上的料号。
- 按物料名称筛（如「喇叭」）：主表料号经存货档案得到物料名称，包含匹配。

### 物料标识与关联订单

| 物料标识 | 含义 | 看哪些订单 |
|---|---|---|
| 空（NULL 或空串） | 整机问题 | 关联生产订单 |
| 物料 | 磁头、面壳组件等有独立 BOM 的中间产物出的问题 | 小板订单 |

生产订单只出现在整机单上，小板订单只出现在「物料」单上，两者互斥；个别单两种订单都没有，属正常情况（决策 2026-10-18）。

其他在线订单不分物料标识，整机单与「物料」单都可能有，有就展示。

产品在制属性表示该单关联的那次生产处于哪个阶段（首次量产、量产爬坡、物料试产、工程样机等）。

### 数量与不良率

| 字段 | 口径 |
|---|---|
| 不良率 | 不良数量 ÷ 生产数量，单上已存百分数，展示加「%」（46.4 → 46.4%） |
| 多张单的不良率 | 合计不良数量 ÷ 合计生产数量 × 100，保留 2 位小数；生产数量为 0 或空的单不参与（见总述「汇总不良率」） |
| 影响数量 | 整机问题中，受影响的关联生产订单的订单数量之和 |

### 物料问题专属

- **CAR**：只有物料问题展示 CAR（纠正预防措施报告），与源系统管理页面一致；其他类型的单即使库里有 CAR 编号与报告 ID，也不展示 CAR 编号、链接与报告内容，不计入关联 CAR 的单数（决策 2026-10-20「CAR 只在物料问题上展示」）。取问题点、围堵对策、根本原因、永久纠正措施、预防措施、有效性确认。是否关联了 CAR：问题类型为物料问题，且单上 CAR 报告 ID 有值；展示 CAR 编号、生成链接、统计关联数用同一判据。CAR 报告单独授权：没有 CAR 报告权限的用户不展示报告内容，见 `privileges.md`。CAR 报告页面链接对所有用户提供，见 `link_rules.md`。
- **设计变更**：只对物料问题有意义；是否设计变更为「是」时才有设计变更责任人、确认结果、预计完成时间。
- **IQC**：IQC 意见（退回仓库 / 继续使用）、IQC 状态、IQC 成员。

资料问题另有资料问题确认结果。

### 原因

- 原因分析：问题发生原因的叙述。
- 原因分类：结案时人为归类，从自维护的原因列表中选取，是有限集合（如「人为工作疏忽」），可做分类统计；原因分类说明是补充。

### 叙述文字

问题描述、原因分析、改善建议、改善措施、预防对策、效果确认、生产确认备注、备注、原因分类说明、重启方案，以及处理步骤的意见、措施、结论，都是人填写的自由文字，是理解「发生了什么、怎么处理的」的主要依据。用户按现象或做法找单（「外壳开裂」「磁头有异响」）时，没点名字段按总述「比对范围」找；点名了上述某个字段（「改善措施里提到换料」「处理步骤意见里写了返工」）时，只在该字段里找。它们用于理解案情、核对细节，不按固定档位计数或分组。格式见 `dirty_data.md`「富文本」。

发现工位也是自由文本（约 425 种写法），不能当枚举精确筛选。

### 处理步骤

- 完整处理过程：该单全部步骤，按先后顺序给出环节名称、处理人、意见、措施、结论、发生时间。
- 某环节最新一次：同一环节名称只取最新一条（`ID` 最大）。
- 责任人处理结果：取工程确认环节最新一条措施中「处理结果：」之后的文字。
- 步骤附件：附件 ID 可能逗号多值，逐段对应文档；以文档名称打开预览；已删除文档不展示。

## 关联

结构总览见 `table_relations.md`；本节为关联条件的信源，修改时同步该图。

| 看什么 | 怎么关联 |
|---|---|
| 机型、系列 | `ZCTracking_ProductNames.ProblemId = 主表.ID`，一张单可多机型 |
| 整机生产订单 | 主表物料标识为空时，`ZCTracking_ProblemOrders.ProblemId = 主表.ID` |
| 小板订单 | 主表物料标识为「物料」时，`ZCTracking_XBOrders.ProblemId = 主表.ID`；小板订单工厂按名称对 `PaxFactory.FactoryName`，料号对 `Inventory.cInvCode` |
| 其他在线订单 | 不分物料标识，`ZCTracking_OtherOrder.ProblemId = 主表.ID`；工厂按工厂码对 `PaxFactory.FactoryID` |
| 处理步骤 | `ZCTracking_ProblemSteplog.ProblemId = 主表.ID` |
| 风险订单流程（退货 / 退库） | `ZCTracking_RiskStream.ProblemId = 主表.ID`；责任人 `UserID = Employee.ID` |
| 并行阶段待办任务 | `tbTask.frecID = 主表.ID`（文本），`ftable` 以 `ZCTracking` 开头，`fstat = '已接受'`；处理人 `fuserID` 转整数 `= Employee.ID` |
| 加工厂 | `Factory = PaxFactory.FactoryID` → `FactoryName`；按名称筛时先按上文「加工厂」把名称对到工厂码。国内工厂表在 ERP 实例，与问题单不在同一实例 |
| 物料 | `CInvCode = Inventory.cInvCode` → 物料名称、规格型号 |
| 供应商 | `VenCode = tbIQCvendor.ferpcode` → 供应商名称 |
| CAR | 问题类型为物料问题且 `CARID` 有值时，`CARID = tbIQCreportOut.fid` |
| 人员 | 各人员 ID 列 `= Employee.ID` → 姓名；文本型的问题跟进人、重启审核人、重启方案制定人需转整数；主状态处理人、IQC 成员直接用姓名列；风险订单责任人、待办任务人员经人员表翻成姓名 |
| 部门 | `RDepartment = Department.ID`；`AllReDepartment` 各段 `= Department.ID`；人员所在部门 `Employee.Unit = Department.ID`（同名同姓时据此追问部门） |
| 步骤附件 | `ZCTracking_ProblemSteplog.FileUrl` 各段 `= DocumentList.ID`，且 `EffectFlag = 0` |
| 制程单链接 | 见 `link_rules.md` |

可空关联（供应商、责任归属部门、CAR 等）关联不上时显示「未填」，不报错。

## 常见查询示例

1. 2024 年 Q3 某加工厂 A 类硬件问题有哪些？
2. 单号 ZC2109001 的完整处理过程和当前责任人是谁？
3. 目前停线中的物料问题，涉及哪些订单？
4. 某机型系列在首次量产阶段的不良率趋势？
5. 责任部门为某部门且尚未结案的问题列表？
6. 含 CAR 报告的物料问题及纠正措施内容？
7. 2026 年 1 月由生产工程部负责跟进处理的制程问题单有哪些，列出单号、处理人、问题类型、机型、不良数量、不良率
8. 工程部人员 2026 年第一季度处理的制程问题统计
9. 加工厂为惠州百富的机型名称有哪些？
10. 最近一年的制程问题中，是否有涉及音频（包括喇叭和蜂鸣器）的内容？
11. 最近 14 天出现的制程相关问题有哪些？
12. 搜索所有制程问题中有「打印」和「USB」描述的问题
13. L1400 机器的制程问题中是否有与音频相关的？
