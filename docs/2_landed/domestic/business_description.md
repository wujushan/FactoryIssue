# 国内制程问题 业务描述

> 字段定义见 `db_description/`；三域共用口径见上级 `business_description.md`。

## 业务域

围绕国内制程问题主表（CoreINFO.dbo.ZCTracking_ProblemList），查询国内工厂制程质量问题的发现、分类、跟进、责任归属、停线、改善与结案。一张单在主表占一行，单号 `ZC` 开头。

**非核心场景**：退货（在线 / 在库退货单号、其他在线订单的处理方式）与版本修订（版本、是否更改订单版本、修订的订单版本）不做专项口径，问到时按单上原值回答。

## 查询范围

- 只查未删除单（是否删除为 0 或空），与管理页面一致：已删除的单查不到，用户要看已删除的单时说明查不到（见总述「跨域规则」）。子表没有删除标记，随主表。
- 清单与汇总里一张单只占一行，按单计数；一单多个机型时去重后用「、」连接，「物料」单写「物料」（见总述「清单默认列」）。按机型、处理环节、当前责任人等一单可多值的维度分组时，一单在每组各计一次（见总述「统计口径说明」多值归属）。
- 本域用 21 张表：
  - 10 张业务表：主表、机型、处理步骤、生产订单、小板订单、其他在线订单、风险订单流程、已选现象与可能原因、可能的问题物料、5Why。
  - 11 张主数据表：国内工厂、存货档案、供应商、CAR 报告、部门、人员、文档清单、流程待办任务、现象分类、现象主数据、现象可能原因。
- 详情页上的风险订单信息（含「操作记录」里的风险订单操作日志），以及 IQC 区块里库存、在线、CKD 机型三栏的处理方式与退货数量，不在查询范围，用户问到时说明请到管理页面查看（决策 2026-10-22「国内管理页面代码对齐」）。同一区块里的其他在线订单另按下文「物料标识与关联订单」给条数。

## 口径

### 时间

| 用户说法 | 口径 |
|---|---|
| 给出时间、没说是哪件事 | 按建单时间筛 |
| 现场发现、发现日期 | 按现场发现日期筛 |
| 停线的、停过线的 | 按停线日期筛 |
| 重启的 | 按重启日期筛，见下文「停线」 |
| 结案的、关闭的 | 按结案时间筛：处理步骤里最新一条结案确认（环节编码 31）的发生时间，只对「已完成」的单定 |

规则与结案周期见总述「按哪个日期筛」「结案时间与结案周期」；某日期没填的单不计入并写明张数。

### 问题类型

硬件问题、软件问题、物料问题、资料问题、工厂制程、结构问题、制程优化。修改过类型的单，问题类型是当前类型，原问题类型保留修改前的值。

### 状态与生命周期

- 主表状态是当前所处环节的快照（18 个取值见主表文件）；处理步骤表是每次流转的留痕。问「进行到哪了」给当前状态（见下），问「完整处理过程」照管理页面「操作记录」列出全部处理步骤（见下文「处理步骤」）。
- 不同问题类型走不同路径，可能被驳回到前序环节后再推进，不能只凭当前状态推断全程。
- 结案完成只有「已完成」。「结案确认」仍算未结案。未结案、进行中、没完成 = 主表状态不是「已完成」，只看主表状态。
- 「生产角色驳回」：制程优化的单被生产角色驳回后停在这个状态，当前责任人清空，流程就此结束，不会再到「已完成」。与管理页面一致，仍算未结案。列未结案的单或统计未结案数时，这类单单独点出张数，说明「生产角色驳回，流程已结束」，不当作还在处理。

### 当前状态

「当前状态」= 当前所处环节 + 处理人。一张单可以有多行，每行是「环节」或「环节 处理人」：该环节没有处理人时只写环节（如「已完成」），同一环节多人用逗号合并：

| 情形 | 当前状态示例 |
|---|---|
| 已结案 | 已完成 |
| 一个环节、多人 | 结案确认 张三,李四 |
| 多个环节并行 | SQE跟进 张三<br>IQC确认 李四<br>填写退货信息 王五 |
| 并行阶段，另有进行中的退库 | 预防对策确认 张三<br>效果确认 李四<br>填写退库信息 王五 |

**状态 30、36、37（效果确认与预防对策确认并行）**：与管理页面一致（决策 2026-10-22「国内管理页面代码对齐」），分两步。

**第一步：先按两类待办现算状态，不直接用库里的状态码。** 库里的状态码要等有人打开过这张单才会更新，可能是旧的。
- 两类待办都取本单任务状态为「已接受」的：
  - 效果确认待办：业务表名 `ZCTracking_ProblemSoftware3`。
  - 预防对策确认待办：业务表名 `ZCTracking_PreventionConfirm`。
- 硬件、软件、物料、资料、结构问题要做预防对策确认，按下表算：

  | 效果确认待办 | 预防对策确认待办 | 状态 |
  |---|---|---|
  | 有 | 有 | 30 |
  | 有 | 无 | 36 |
  | 无 | 有 | 37 |
  | 无 | 无 | 库里原状态 |

- 工厂制程、制程优化不做预防对策确认，保持库里原状态。

**第二步：按现算的状态逐行给出当前状态。**

| 状态 | 第一行 | 第二行 |
|---|---|---|
| 30，要做预防对策确认的类型 | 预防对策确认 + 预防对策确认待办人员 | 效果确认 + 主状态处理人 |
| 30，工厂制程、制程优化 | 效果确认 + 主状态处理人 | — |
| 36 | 效果确认 + 主状态处理人 | — |
| 37 | 预防对策确认 + 预防对策确认待办人员 | — |

- 预防对策确认待办人员：每条任务一个人员 ID，翻成姓名，多人合并一行。查不到时这一行只写「预防对策确认」。
- 之后照「其他状态」追加两段：IQC 状态有值时追加 IQC 段，有进行中的退货 / 退库时追加退货 / 退库段。
- 只看上面两类待办，其他待办（如「待填写停线重启方案」）不算一行环节。

**其他状态**：主状态为「已完成」时只显示「已完成」，不追加下面两段。其余状态由三段组成，按以下顺序每段一行：

| 段 | 内容 | 什么时候出现 |
|---|---|---|
| 主状态 | 主状态文案 + 主状态处理人（主表主状态处理人姓名列） | 总是 |
| IQC | IQC 状态文案（复用主状态的码值与文案，常见 6 IQC确认、7 填写退货单号）+ IQC 成员 | IQC 状态有值时 |
| 退货 / 退库 | 风险订单步骤文案（填写退货信息 / 填写退库信息）+ 责任人姓名 | 有进度为「进行中」的风险订单记录时 |

- IQC 段出现时总是单独一行。与主状态同名（如都是「IQC确认」）时也不合并，与管理页面一致。
- 退货 / 退库段只占一行，与管理页面详情一致：步骤取进行中记录里最早的一条（按记录先后），人员列全部进行中记录的责任人，按员工 ID 去重；已完成的记录不显示。
- 风险订单责任人存的是员工 ID，翻成姓名展示，不显示工号。

### 当前责任人

当前责任人 = 当前状态各行出现的全部人员：主状态那一行的处理人（状态 30、36、37 时，效果确认一行为主状态处理人，预防对策确认一行为预防对策确认待办人员），加上 IQC 段出现时的 IQC 成员、有进行中的退货 / 退库时的风险订单责任人；「已完成」的单没有当前责任人。回答时按行给出「环节 + 人」，不只给主状态处理人。

按当前责任人查单、统计（「张三手上有哪些单」「各人还压着多少单」）：

- 张三出现在当前状态任一行，即算这张单在他手上；同一单出现在多行只计一次。按员工 ID 匹配：主状态处理人、IQC 成员用各自的 ID 列，风险订单责任人、待办任务人员本身存的就是员工 ID；姓名只用于展示。
- 一单多人时每人各计一次，各人之和可能大于单数，统计口径说明里写明。
- 「已完成」的单没有当前责任人，不计入。
- 同名同姓时追问部门，确认是哪一位后按人员查。

### 按处理环节筛选与统计

与源系统管理页面一致：按处理环节筛选、统计时，看当前状态（见上文「当前状态」）的**每一行**，不只看主表状态。

- **筛选**：当前状态任一行的环节命中即算。例：一单当前状态为「SQE跟进 张三 / IQC确认 李四」，按「SQE跟进」和按「IQC确认」筛都能查到它。
- **环节统计**：一单在当前状态出现的每个环节下各计一次，各环节之和可能大于单数，统计口径说明里写明。主状态与 IQC 段同名、各占一行时，这个环节下仍只计一次。
- **环节名称**即当前状态各行的环节文字：主表状态与 IQC 状态的文案、风险订单步骤（填写退货信息 / 填写退库信息）、并行阶段的环节（效果确认 / 预防对策确认）。并行阶段按现算的状态计（见上文「当前状态」）：要做预防对策确认的类型状态为 30 时，在「效果确认」「预防对策确认」下各计一次；36 只在「效果确认」下，37 只在「预防对策确认」下；工厂制程、制程优化只在「效果确认」下。
- 「填写退货单号」（主表状态或 IQC 状态为 7）与「填写退货信息」（风险订单步骤）是两个不同环节，不合并。
- 当前状态没有显示的环节不命中：「已完成」的单只有「已完成」一行；退货、退库两个步骤都在进行时，只按显示出来的那一个步骤计。并行阶段的 IQC 段、退货 / 退库段与其他状态一样，出现时也命中。
- 结案判断不走这条规则，只看主表状态（见上文「状态与生命周期」）。

### 停线

| 用户说法 | 口径 |
|---|---|
| 停线中、目前停线、正在停线 | 停线状态为停线中、重启审核中、重启审核通过、责任人填写重启方案四者之一。不含已经重启、没有停线 |
| 停线、曾经停线、发生过停线（没带「中 / 目前 / 正在」） | 是否停线为「是」，已经重启的仍算 |
| 重启的、某段时间重启的（「6 月重启的单」） | 按重启日期筛（定义见下文停线部分），只看有重启日期的单 |
| 停了多久、停线多久才重启 | 停线时长 = 重启日期 − 停线日期，按天计，只算两个日期都有的单；没有重启日期的单不计入，写明张数 |
| 已经重启、还没重启、重启审核通过 | 按停线状态：已经重启 = 停线状态为「已经重启」；还没重启 = 同上面「停线中」的四种状态；重启审核通过 = 停线状态为「重启审核通过」 |

- 「停线中」不看是否结案，与管理页面一致：已完成的单停线状态仍是这四种之一时照常算，当前状态照实显示「已完成」。清单里有已完成的单时，回答点出张数。
- 统计口径说明里写明「停线中」含上表这四种停线状态。

**单张单详情的停线部分**：与管理页面详情一致，停线、重启的信息集中放在单张单详情的停线部分（决策 2026-10-22「国内管理页面代码对齐」）。完整处理过程不把停线重启、停线重启审核、责任人填写重启方案三步混在其他环节里，另列一段「重启操作日志」（见下文「处理步骤」）。停线部分每项都取对应环节编码最新的一条：

| 项 | 取什么 | 什么时候展示 |
|---|---|---|
| 是否停线 | 是否停线 | 总是 |
| 停线状态 | 停线状态；重启审核中附重启审核人，责任人填写重启方案附重启方案制定人 | 停过线时 |
| 停线日期 | 停线日期 | 停过线时 |
| 重启日期 | 最新一条停线重启（环节编码 29）登记的日期：操作人点「停线重启」时选的日期，存在这一步的结论里，取日期部分 | 有这一步，且结论或意见有值 |
| 重启备注 | 同一条停线重启的意见 | 同上，且意见有值 |
| 重启方案 | 最新一条「责任人填写重启方案」（环节编码 34）的意见（与主表重启方案同值），附制定人与填写时间 | 有这一步，且停线状态不是「责任人填写重启方案」「重启审核中」 |
| 重启审核意见 | 最新一条「停线重启审核」（环节编码 32）：1 = 同意，0 = 不同意，其他值不写；附意见、审核人、审核时间 | 有这一步，且停线状态不是「重启审核中」「责任人填写重启方案」 |

- 停线状态为「重启审核中」时，管理页面只让审核人、方案制定人和管理员看重启方案。本助手对所有人都不展示重启方案、重启审核意见，完整处理过程里的「重启操作日志」也不给，问到时回答「重启方案审核中，暂不展示」，不按人区分。目前没有这个状态的单。
- 停线状态为「责任人填写重启方案」时，新方案还没填，不展示上一轮的方案与审核意见。
- 用户问「重启过程」「重启情况」时，给这一部分；要看每一次重启的记录时，给完整处理过程里的「重启操作日志」。
- 主表上的停线重启时间，管理页面不写也不展示，本助手同样不用。

### 人员与部门

| 用户说法 | 口径 |
|---|---|
| 某部门跟进的、问题跟进部门；只说部门（「工程部的问题」） | 问题跟进部门。部门名称按总述「部门名称怎么对」对到部门（「工程部」即生产工程部） |
| 某人跟进的、问题跟进人；只说人名（「张三的问题」） | 问题跟进人 |
| 某部门处理的、某部门负责的、某部门人员处理的 | 同样按问题跟进部门。物料问题、工厂制程、资料问题不指定跟进部门，统计不到；统计口径说明里写明这三类未计入 |
| 当前谁在处理、当前责任人、当前处理人 | 当前责任人，按当前状态逐行给出环节 + 人（见上文「当前责任人」） |
| 某人手上的、某人待处理的、卡在某人那的、某人正在处理的 | 按当前责任人查，不按问题跟进人 |
| 只说「责任人」（「这单的责任人是谁」「这单谁负责」）、问题责任人；按责任人查单、统计（「张三负责的单」「各责任人各有多少单」） | 按管理页面导出的「责任人」，见下文「责任人怎么取」。单张单详情里另附当前责任人（未结案时），各自写明角色。定责只到部门（见下一行责任归属部门），这里的责任人是管理页面导出的操作人 |
| 责任部门、定责、责任归属 | 结案后的责任归属部门（可多个），不是问题跟进部门；为空表示无需定责。两者可能相同也可能不同。物料问题不展示责任归属部门，按责任部门查单、统计时不计入，统计口径里写明，与管理页面一致 |

- 「指定责任人」「责任人确认」环节、「责任人处理结果」「计划完成时间」里的责任人指问题跟进人。

**问题跟进人按问题类型分两种**：

- 硬件、软件、结构问题、制程优化：提交后由固定负责人指定**一名**跟进人，问题跟进人、问题跟进部门有值。
- 物料问题、工厂制程、资料问题：提交后按类型流转到固定处理角色，**不指定**问题跟进人，两列为空；工厂制程默认流转到工厂的三个接口人。

**责任人怎么取**（与管理页面导出的「责任人」一致，决策 2026-10-22「国内管理页面代码对齐」）：按问题类型，取对应环节最新一条处理步骤的操作人。

| 问题类型 | 取哪个环节（环节编码） |
|---|---|
| 硬件问题、软件问题、结构问题、制程优化 | 责任人确认（3） |
| 物料问题 | SQE跟进（10） |
| 资料问题 | 工程确认（4，含「确认版本信息」） |
| 工厂制程 | 工厂制程分析（6） |

- 「最新一条」按发生时间取最晚的，同一时间取后录入的。这是照管理页面导出的取法，与别处按记录先后（`ID` 最大）取最新一条不同。
- 结案后改过问题分类的单，按改之前的问题类型取。判断方法：处理步骤里有「修改问题分类」，且在最新一条结案确认之后；改之前的类型看原问题类型。「修改问题分类」这一步在源系统里没有数值编码，按环节名称认。目前没有这样的单。
- 还没走到对应环节的单没有责任人，写「未填」。
- 按责任人查单、统计时，按操作人的员工 ID 匹配，一单只有一位责任人。没有责任人的单不计入，统计口径里写明张数。
- 责任人与问题跟进人、当前责任人是三种角色，同时出现时各自写明。只说人名（「张三的问题」）仍按问题跟进人（见总述「三域共用的说法」）。

其他人员：填单人、效果确认人、生产确认人、设计变更责任人、IQC 成员、重启审核人、重启方案制定人。

### 加工厂

主表存国内工厂码，展示时翻成工厂名称。用户给工厂名称时，被国内工厂名称包含或与之相近即命中（容忍输入不全或输错），先对到工厂码再筛；命中多个工厂时列出，请用户选。

### 物料

- 按料号筛：只看主表料号，不匹配小板订单上的料号。
- 按物料名称筛（如「喇叭」）：主表料号经存货档案得到物料名称，包含匹配。只说「喇叭的问题」时物料名称与文字两种都查，见总述「三域共用的说法」。

### 物料标识与关联订单

| 物料标识 | 含义 | 看哪些订单 |
|---|---|---|
| 空（NULL 或空串） | 整机问题 | 关联生产订单 |
| 物料 | 磁头、面壳组件等有独立 BOM 的中间产物出的问题 | 小板订单 |

生产订单只出现在整机单上，小板订单只出现在「物料」单上，两者互斥；个别单两种订单都没有，属正常情况（决策 2026-10-18「国内生产订单与小板订单按物料标识区分」）。

产品在制属性表示该单关联的那次生产处于哪个阶段（首次量产、量产爬坡、物料试产、工程样机等），显示文字与管理页面一致，见主表字段说明。

「物料」单的单张单详情与管理页面一致：机型一栏显示「物料」，不展示产品在制属性与影响数量；清单里的机型列同样写「物料」（见总述「清单默认列」）。按机型查单、统计不变，仍按机型子表。

其他在线订单不分物料标识、不分问题类型，整机单与「物料」单都可能有。单张单详情里只给条数，如「其他在线订单 12 条，需要可以列出」，没有的不提。用户追问（「其他在线订单有哪些」「列出这些订单」）时再逐条列出，列见其他在线订单字段说明；上百条时表格给前若干条，全量导出。清单、统计不带其他在线订单（决策 2026-10-23「G1 三次复核修订」）。

### 按订单号查单

用户给出订单号（「XXXXXX 有哪些制程问题」「小板订单 XXXXXX 关联了哪张单」），查出挂着这个订单的国内问题单。

- **认哪些号**：用户说「订单号」「订单」「工单」并给出号码，或只给一个 6 位数字，都按订单号查。`ZC` / `BR` / `HW` 开头的问题编号、15 位的料号或 PN 编码、`CAR` 加 9 位数字的 CAR 编号，用户说是订单也不当订单号。其他样子的号怎么认见总述「按编号查单」。
- **查哪几种订单**：只查生产订单与小板订单。只说「订单号」时两种都查，结果里标明在哪种订单里找到；明说「生产订单」「小板订单」时只查那一种。两种订单的号写法相同（多为 6 位数字），只能靠所在订单区分；同一个号不会同时出现在两种订单里。
- **不参与查单的号**：其他在线订单号、在线 / 在库退货单号。退货单号在打开单张单时随单展示，其他在线订单号在追问这张单的其他在线订单时随明细列出。用户明说按其他在线订单号或退货单号查单时，说明本助手只支持按生产订单号、小板订单号查单。
- **怎么匹配**：去掉首尾空格后精确匹配，不做包含匹配。生产订单里有少量手填的带连字符的号（如「6 位数字-序号」）：用户给的号查不到、但有以「该号-」开头的号时，列出这些号请用户选。
- **返回什么**：一单一行。同一张单上这个订单有多行（多个 PN、多次发料）时合并成一行。每行给问题编号（可跳转）、在哪种订单里找到、问题类型、当前状态、机型，以及这张单上该订单的明细：生产订单给 PN（「PN 名称 PN 编码」）与订单数量，小板订单给料号、物料描述与订单数量。一个号常挂多张单，照常全部列出，并按问题类型、是否结案给分布。
- **查不到与已删除的单**：查不到时回答「没有找到挂着这个号的单（已删除的单查不到），请核对；本助手不按其他在线订单号、退货单号查单」。号同时挂在未删除与已删除的单上时只列未删除的，规则见总述「按编号查单」。
- **不按订单号推断时间**：订单号前两位多数接近年份，但不全是（如 01、02 开头的是 2020–2022 年的订单），不当时间条件。用户问「2025 年的订单」仍按建单时间或发料日期。

### 按 CAR 编号查单

用户给出 CAR 编号（「CAR 编号 XXX 对应哪张制程单」），查出对应的国内问题单。

- **「CAR 报告编号」就是单上的 CAR 编号**：管理页面上显示为「CAR编号」，形如 `CAR` + 9 位数字。CAR 报告另有内部 ID，不展示、不用于查找。
- **认哪些号**：用户说「CAR」并给出号码，或给出 `CAR` 加 9 位数字（不分大小写）形态的号，都按 CAR 编号查。
- **怎么匹配**：去掉首尾空格、不分大小写后精确匹配。一个 CAR 编号只对应一张单。
- **查得到哪些单**：只命中物料问题、且未删除的单（判据见下文「物料问题专属」）。查不到（含只登记在已删除的单、其他类型的单上）时回答「没有找到这个 CAR 编号对应的物料问题单（已删除的单查不到），请核对编号」。登记的 CAR 报告在报告表里查不到内容的物料问题单，照常能按 CAR 编号查到。
- **权限**：只用单上的 CAR 编号查找，不读报告内容，有国内域权限就能查，不需要 CAR 报告权限（见 `privileges.md`「CAR 报告」）。返回问题单（可跳转）与 CAR 报告链接；有 CAR 报告权限的用户再附报告内容，没有的按 `privileges.md` 的说法回答。

### 数量与不良率

| 字段 | 口径 |
|---|---|
| 不良率 | 不良数量 ÷ 生产数量，单上已存百分数，展示加「%」（46.4 → 46.4%）。单上为空时写「未填」，不现算，与管理页面一致 |
| 多张单的不良率 | 合计不良数量 ÷ 合计生产数量 × 100，保留 2 位小数；不良数量为空、生产数量为 0 或空的单不参与（见总述「汇总不良率」） |
| 影响数量 | 整机问题中，关联生产订单的在线数量之和，不是订单数量之和；「物料」单不展示 |

### 物料问题专属

- **CAR**：只有物料问题展示 CAR（纠正预防措施报告），与源系统管理页面一致；其他类型的单即使库里有 CAR 编号与报告 ID，也不展示 CAR 编号、链接与报告内容，不计入关联 CAR 的单数（决策 2026-10-20「CAR 只在物料问题上展示」）。只取问题点、围堵对策、根本原因、永久纠正措施、预防措施、有效性确认 6 项叙述内容；报告上的公司名称、检验总数、检查总数、不良数量、不良率不展示。是否关联了 CAR：问题类型为物料问题，且单上 CAR 报告 ID 有值；展示 CAR 编号、生成链接、统计关联数用同一判据。CAR 报告单独授权：没有 CAR 报告权限的用户不展示报告内容，见 `privileges.md`。CAR 报告页面链接对所有用户提供，见 `link_rules.md`。
- **设计变更**：只对物料问题有意义。是否设计变更为「是」时有设计变更责任人；单张单详情的「设计更改」一块给确认结果（即主表处理结果），确认结果为「改善」时另附设计变更预计完成时间，与管理页面一致。
- **IQC**：IQC 意见（退回仓库 / 继续使用）、IQC 状态、IQC 成员。

资料问题另有资料问题确认结果。

### 原因

- 原因分析：问题发生原因的叙述。
- 原因分类：结案时人为归类，从自维护的原因列表中选取，是有限集合（如「人为工作疏忽」），可做分类统计；原因分类说明是补充。
- 问「原因、措施、当时怎么处理的」时：按下文「单张单详情各环节怎么显示」，当前显示的环节里有内容就给，见总述「原因与措施怎么给」。物料问题的原因与处理多写在处理步骤里。

### 问题现象、可能问题原因、可能的问题物料、5Why

与管理页面详情一致，在单张单详情里展示（决策 2026-10-22「国内管理页面代码对齐」）：
- 不作筛选条件、不参与统计。
- 问题现象的文字另进按文字找单的比对范围，归「问题本身涉及」那一组的栏目（见总述「比对范围」「涉及某个话题怎么找」）；可能问题原因、可能的问题物料、5Why 不进。
- 用户问「这单选了什么现象」「5Why 怎么分析的」时照常给出。

- **问题现象**：建单时选的现象，按现象去重，给出现象文字，需要时附所属分类。
- **可能问题原因**：所选现象下系统预设的候选原因，开头写明「根据选择的问题现象，系统分析的可能原因」。不是单上写下的原因分析，问「原因是什么」时不拿它回答。
- **可能的问题物料**：系统按问题类别和现象推荐的候选物料（料号与物料描述），开头写明是系统分析的可能物料。不是单上的涉及物料，按物料查单不看它。
- **5Why**：逐条一问一答，给出问题、提问人、提问时间、原因、答复人、答复时间，待答复的写「待答复」。放在本类型的分析环节里，随该环节一起显示或隐藏（见下文「单张单详情各环节怎么显示」）。
  - 用户问「原因、措施、当时怎么处理的」时，若该环节当前显示，在原因与措施之后附上 5Why。
- 问题现象、可能的问题物料 2024 年起才有，5Why 2026 年起才有，之后的单也不一定有。没有时不显示，不写「未填」。

字段见 `ZCTracking_CheckReason`、`ZCTracking_PossibleInvCode`、`ZCTracking_ProblemFiveWhy` 三张表的字段说明。

### 叙述文字

问题描述、原因分析、改善建议、改善措施、预防对策、效果确认内容、生产确认备注、备注、原因分类说明、重启方案，以及处理步骤的意见、措施、结论，都是人填写的自由文字，是理解「发生了什么、怎么处理的」的主要依据。用户按现象或做法找单（「外壳开裂」「磁头有异响」）时，没点名字段按总述「比对范围」找；点名了上述某个字段（「改善措施里提到换料」「处理步骤意见里写了返工」）时，只在该字段里找，按意思找还是按词找见总述「点名字段时怎么找」。它们用于理解案情、核对细节，不按固定档位计数或分组。格式见 `dirty_data.md`「富文本」。

发现工位也是自由文本（约 410 种写法），按包含匹配筛，不当枚举精确筛选。

### 处理步骤

- 完整处理过程：与管理页面「操作记录」一致，列出全部记录，按先后顺序给出；驳回前的旧记录、每一次驳回与任务转移都列（决策 2026-10-23「操作记录显示全部记录」）。给操作人、操作时间、类型、内容、附件 5 列，内容为空时取意见，结论、意见不单列。
  - 停线重启、停线重启审核、责任人填写重启方案三步不混在其中，另列一段「重启操作日志」，同样列出全部记录；停线状态为「重启审核中」时这一段不给（见上文「停线」）。
  - 页面「操作记录」最下方的「风险订单操作日志」属于风险订单信息，不在查询范围（见上文「查询范围」）。
  - 列法见处理步骤表「处理过程怎么展示」。
- 单张单详情里各环节的结论按管理页面的标签翻译（如工厂制程分析的结论叫「原因分析」），见处理步骤表「单张单详情里的结论」。
- 某环节最新一次：同一环节编码只取最新一条（`ID` 最大）。
- 单张单详情里各环节什么时候显示，见下文「单张单详情各环节怎么显示」。
- 处理结果（改善 / 保持现状 / 挂起）：取主表处理结果，不从处理步骤截取。硬件、软件、结构问题、制程优化放在「责任人确认」下，资料问题放在「工程确认」下，物料问题放在「设计更改」下叫「确认结果」；工厂制程没有。
- 步骤附件：附件 ID 可能逗号多值，逐段对应文档；以文档名称打开预览；已删除文档不展示。

### 单张单详情各环节怎么显示

**抬头**：单张单详情最上方、下表各环节之前的部分，与管理页面详情一致。按页面顺序给下面各栏，括号里是显示条件，没写的总是显示：
- 加工厂、机型（「物料」单显示「物料」）、现场发现日期、问题类型、填单人、建单时间、发现工位、版本、当前状态（见上文「当前状态」）、问题等级、产品在制属性（「物料」单不展示）。
- 责任归属部门（物料问题不展示）、原因分类（与责任归属部门都没有值时，两项都不显示）、原因分类说明（有值时）。
- 生产订单（整机单）、影响数量（「物料」单不展示）、小板订单（「物料」单）。
- 生产数量、不良数量、不良率。
- 停线部分：是否停线、停线状态、停线日期、重启日期、重启备注、重启方案、重启审核意见，各项什么时候展示见上文「停线」。
- 料号、规格型号（有值时）；供应商编号、供应商名称（有值时）。
- 问题现象、可能问题原因、可能的问题物料（有值时，见上文「问题现象、可能问题原因、可能的问题物料、5Why」）。
- 问题描述、改善建议（有值时）、备注（有值时）。
- 附件（填写问题这一步有附件时）。
- CAR 编号（只有物料问题，判据见上文「物料问题专属」）。

与管理页面详情一致：各环节按「问题类型 + 有没有这一步 + 当前状态码」决定显示与否，每个环节取该环节编码最新的一条记录（决策 2026-10-22「国内管理页面代码对齐」补记）。

- 本表只管单张单详情。完整处理过程按上文「处理步骤」给。按文字找单不受本表限制：命中的内容所在环节当前不显示时，命中摘要里注明「该环节已退回重新处理」。

| 小板订单 | 主表物料标识为「物料」时，`ZCTracking_XBOrders.ProblemId = 主表.ID`；小板订单工厂按名称对 `PaxFactory.FactoryName`，料号对 `Inventory.cInvCode` |
| 其他在线订单 | 不分物料标识，`ZCTracking_OtherOrder.ProblemId = 主表.ID`；工厂按工厂码对 `PaxFactory.FactoryID` |
| 处理步骤 | `ZCTracking_ProblemSteplog.ProblemId = 主表.ID` |
| 风险订单流程（退货 / 退库） | `ZCTracking_RiskStream.ProblemId = 主表.ID`；责任人 `UserID = Employee.ID` |
| 并行阶段待办任务 | `tbTask.frecID = 主表.ID`（文本），`ftable` 为 `ZCTracking_ProblemSoftware3`（效果确认）或 `ZCTracking_PreventionConfirm`（预防对策确认），`fstat = '已接受'`；预防对策确认处理人 `fuserID` 转整数 `= Employee.ID` |
| 加工厂 | `Factory = PaxFactory.FactoryID` → `FactoryName`；按名称筛时先按上文「加工厂」把名称对到工厂码。国内工厂表在 ERP 实例，与问题单不在同一实例 |
| 物料 | `CInvCode = Inventory.cInvCode` → 物料名称、规格型号 |
| 供应商 | `VenCode = tbIQCvendor.ferpcode` → 供应商名称 |
| CAR | 问题类型为物料问题且 `CARID` 有值时，`CARID = tbIQCreportOut.fid` |
| 人员 | 各人员 ID 列 `= Employee.ID` → 姓名；文本型的问题跟进人、重启审核人、重启方案制定人需转整数；主状态处理人、IQC 成员直接用姓名列；风险订单责任人、待办任务人员经人员表翻成姓名 |
| 部门 | `RDepartment = Department.ID`；`AllReDepartment` 各段 `= Department.ID`；人员所在部门 `Employee.Unit = Department.ID`（同名同姓时据此追问部门） |
| 步骤附件 | `ZCTracking_ProblemSteplog.FileUrl` 各段 `= DocumentList.ID`，且 `EffectFlag = 0` |
| 问题现象与可能原因 | `ZCTracking_CheckReason.ProblemId = 主表.ID`；`PhenomenonID = AfterSaleIssueClassPhenomenon.ID` → 现象文字；`ReasonID = AfterSaleIssueClassPhenomenonReason.ID` → 可能原因（0 表示没有）；`ClassID = AfterSaleIssueClass.ID` → 分类类型、分类名称 |
| 可能的问题物料 | `ZCTracking_PossibleInvCode.ProblemId = 主表.ID`，直接用表上的料号、物料描述 |
| 5Why | `ZCTracking_ProblemFiveWhy.ProblemId = 主表.ID`；提问人 `AddUser`、答复人 `UpdateUser` `= Employee.ID` |
| 制程单链接 | 见 `link_rules.md` |

可空关联（供应商、责任归属部门、CAR 等）关联不上时显示「未填」，不报错。

## 数据规模

未删除的单（业务方 2026-10-22、2026-10-23 正式镜像计数）：
- 每张单平均约 5.7 条处理步骤、约 1 个机型；「物料」单 13 张里只有 1 张登记了机型，按机型查、按机型统计时「物料」单基本不出现。
- 生产订单只挂在整机单上：3,796 条、2,460 张单，每张整机单约 1.5 条。小板订单只挂在「物料」单上：19 条、10 张单。两种订单都没有的单 4 张。
- 其他在线订单 17,186 条、1,241 张单有，几乎都在整机单上（「物料」单 3 张、22 条）；按问题类型几乎都是物料问题（1,215 张）。
- 问题现象 2024 年起才有：966 张单选了现象（1,569 条，其中 913 条没有可能原因）；295 张单有可能的问题物料（1,653 条）；5Why 2026 年起才有，目前 4 张单、11 条。
- 风险订单流程（退货 / 退库）只有 3 条，都已完成；IQC 状态目前没有单有值。当前状态里的 IQC 段与退货 / 退库段目前都不会出现，规则照旧保留。
- 物料问题 1,438 张，其中 1,364 张关联了 CAR；另有 20 张其他类型的单库里带 CAR，不展示、不计入。

主表行数、按年分布与各表行数见总述「数据量声明」。
