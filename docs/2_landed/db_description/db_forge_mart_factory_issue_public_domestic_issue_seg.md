# domestic_issue_seg（分段表，三域同族）

- **数据源别名（source）**：forge_mart_factory_issue
- **物理表名（table）**：public.domestic_issue_seg
- **表族（family）**：public.<域>_issue_seg（域 = domestic、brazil、overseas，即国内、巴西、海外）
- **所属域**：每域一张，国内为代表成员；三域结构相同
- **用途**：按词找单用（关键词搜索、涉及某个话题的前两组、点名比对范围内的字段按词找），以及清单里问题描述的摘要。收总述「比对范围」里的全部栏目，一单一个栏目一段，不按长度切；包括预设的问题现象、剥净后不超过 10 个字的内容与处理步骤条目。
- **数据产生方**：本助手的治理任务，与文字表同批写入，时效相同（见文字表）。表由治理任务建，首轮跑之前不存在。
- **列类型**：段内序号为 int，其余 text；全部不可空。
- **权限**：表级，随所属域给「允许」；没有权限承载列。
- 另有一张按意思找的段表 `public.<域>_issue_vseg`，是向量表的来源，本助手查询时不读它，不写表文件；它只收参与按意思找的内容，结构见决策 2026-10-27「模块技术设计」。

## 字段

| 字段 | 类型 | 用户可见显示名 | 含义与取值 | 关联 |
|---|---|---|---|---|
| seg_id | text | （内部字段，不返回） | 段编号，主键：`<issue_id>:<字段代号>:<序号>` | — |
| issue_id | text | （内部字段，不返回） | 所属单，同文字表 `issue_id` | 文字表 `issue_id` |
| field | text | （内部字段，不返回） | 字段代号，取值见下表；回答里写栏目名，不写代号 | — |
| seq | int | （内部字段，不返回） | 字段内序号，本表恒为 0 | — |
| seg_text | text | 段落文字 | 剥净的文字（同文字表），开头带栏目名，如「问题描述：…」。清单摘要与命中处的上下文从这里取 | — |
| seg_norm | text | （内部字段，不返回） | 同一段文字的归一化：全角转半角、转小写、连续空白压成一个空格；不带栏目名前缀 | — |
| seg_compact | text | （内部字段，不返回） | `seg_norm` 去掉全部空白，按词找时在数据库里预筛用 | — |

## 字段代号

格里是该域的栏目名，「—」表示该域没有这个栏目。

| 代号 | 国内 | 巴西 | 海外 | 取自 |
|---|---|---|---|---|
| phen | 问题现象 | 问题现象 | 已选问题现象 | 文字表 `f_phen` |
| desc | 问题描述 | 问题描述 | 问题描述 | 文字表 `f_desc` |
| reason | 原因分析 | 原因分析 | 原因分析 | 文字表 `f_reason`（巴西为最新一条处理过程的原因分析） |
| improve | 改善建议 | — | 改善建议 | 文字表 `f_improve` |
| measure | 改善措施 | 改善措施 | 改善措施 | 文字表 `f_measure` |
| prev | 预防对策 | 预防对策 | 预防对策 | 文字表 `f_prev` |
| sqe | — | SQE 跟进结果 | — | 文字表 `f_sqe` |
| step | 处理步骤 | — | 处理步骤 | 分析类环节整理成的一段，见下 |

- **处理步骤**（国内、海外）：只取总述「比对范围」列的分析类环节（环节清单在分段规则配置里，管理员可改），每个环节取最新一条；条目 =「环节名称：」+ 意见（内容里已含意见时不加）+ 去掉操作人姓名的内容 + 工厂制程分析的结论（内容里已含时不加），几部分之间用「；」；同一张单里完全相同的条目只留一条，条目之间换行。去姓名的规则同文字表。
- 栏目分组（哪些代号归「问题本身涉及」，哪些归「处理中提到」）在分段规则配置里，内置默认值是总述「涉及某个话题怎么找」的第一组栏目，其余归第二组。
