# ZCTracking_CheckReason（国内制程问题已选现象与可能原因）

- **数据源别名（source）**：info
- **物理表名（table）**：CoreINFO.dbo.ZCTracking_CheckReason
- **所属域**：国内
- **用途**：建单时选择的问题现象，以及每条现象下系统给出的可能原因。一行是「分类 + 现象 + 一条可能原因」。同一现象下有几条可能原因就有几行；没有可能原因的现象（含手填的现象）只有一行，可能原因存 0。
- **数据产生方**：INFO 系统国内制程问题建单页面。
- **列类型**：按 information_schema（业务方 2026-10-22 内网元数据），各列都不可为空。
- **数据现状**（业务方 2026-10-22 正式镜像计数）：
  - 全表 1,746 行，未删除的单上 1,569 行，涉及 966 张单。
  - 可能原因为 0 的 913 行。
  - 现象、可能原因、分类都能关联上，没有对不上的行。
  - 最早的记录在 2024 年，此前建的单都没有问题现象。

## 怎么展示（与管理页面详情一致）

- **问题现象**：按现象去重，每条现象显示现象文字。需要时可附所属分类（分类类型 → 分类名称），管理页面把它放在悬停提示里。
- **可能问题原因**：取能关联到原因的行，按原因文字排序，逐条编号列出。开头写明「根据选择的问题现象，系统分析的可能原因」。这是现象下预设的候选原因，不是这张单上写下的原因分析，不能当作已确认的原因。
- 2024 年以前建的单没有问题现象，之后的单也不一定有。没有时不显示，不写「未填」。

## 按文字找单

问题现象的文字按现象去重、连成一段，进按文字找单的比对范围，属「问题本身涉及」那一组的栏目（见总述「涉及某个话题怎么找」）。它是选出来的短标签，不受「10 字以内不比对」限制。可能原因不进比对范围。本表不作筛选条件、不统计。
