# ZCTracking_ProblemFiveWhy（国内制程问题 5Why 分析）

- **数据源别名（source）**：info
- **物理表名（table）**：CoreINFO.dbo.ZCTracking_ProblemFiveWhy
- **所属域**：国内
- **用途**：问题单的 5Why 分析。一行是一问一答：有人提出一个「为什么」，对应环节的处理人填写原因。一单可多条。
- **数据产生方**：INFO 系统国内制程问题详情页面。提问后系统给对应环节的处理人发 3 天的待办，填写原因后待办办结。
- **列类型**：按 information_schema（业务方 2026-10-22 内网元数据）。
- **数据现状**（业务方 2026-10-22 正式镜像计数）：
  - 全表 11 行，都在未删除的单上，涉及 4 张单，都是 2026 年提的，都已答复。
  - 问题、原因都是纯文字，没有 HTML 标签；问题最长 84 字，原因最长 148 字。

## 怎么展示（与管理页面详情一致）

- 按提问时间排序（同一时间按录入先后），现生成序号 1..N。逐条给出：问题、提问人、提问时间、原因、答复人、答复时间、答复状态。
- 问题与原因都为空的行不展示。
- 管理页面把 5Why 放在本类型的分析环节里，随该环节一起显示或隐藏。各问题类型放在哪个环节、什么时候显示，见国内业务描述「单张单详情各环节怎么显示」。
- 待答复的只写「待答复」，不给应答人。
