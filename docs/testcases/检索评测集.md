# 检索评测集

G3 产物。用来定文字查找的分段规则（决策 2026-10-20「G2 数据源与治理决策」的「检索评测」；本集落盘见决策 2026-10-28「检索评测集落盘，说法清单维持」）。

模型标签不是应命中。线上回答用的是同一个模型，拿它的标签当标准答案会把看错的单一起放过。

## 标准

| 要评的 | 标准 |
|---|---|
| 前两组（问题本身涉及、处理中提到） | 当天按 `docs/2_landed/topic_terms.md` 做的按词匹配。张数与分组跟参考 SQL 一致。说法改了，标准跟着改 |
| 前两组里人工判过「不是」的单 | 仍留在前两组，不把助手判错。用来决定这个说法要不要改宽 |
| 待判断里人工判「不是」的单 | 不得进入第三组 |
| 待判断里人工判「是」、以及人确认「清单没找到但确实是这个话题」的单 | 第三组与按意思找的正样本。第三组最多 10 张、不保证都出现，只作软断言 |
| 模型标签 | 只用来找分歧、估计准确率。不进本集，不进 golden |

单号以种子工作簿「应命中集」的「话题级」一节为准，这里不另抄一份，避免两处名单不一致。

## 2026-10-27 全量标注

内网跑 `scripts/topic_labeling/`，输出在 `runtime/topic_labeling/20261027-v2/`（不入库）。国内 2474、巴西 203、海外 12，共 2689 张，失败 0 张。模型是 Qwen3-Fast，提示词 v2。6 张文字超长被截断，22 个候选话题没有判断。

与探测 T4 的按词计数有两处不同，都不表示匹配写错了：音频的范围内单数多 1 张，四组命中数相同，是镜像在探测之后多了一张未命中音频的单；非接的「待判断」从 1 变为 0、「带 ＊ 只在第二组」从 2 变为 0，是因为 2026-10-26 已从清单删去「射频」「感应」。

按词结果里，模型判成「问题本身」不到一半、且第一组栏目命中不少于 3 张的说法有：外壳、后壳、壳体、打印、打印机、电池、WiFi。打印的第一组 119 张里，36 张被判为问题本身，48 张顺带提到，35 张无关。外观的第一组 365 张里，295 张被判为问题本身，13 张无关。

清单没找到、模型却判为问题本身的张数：外壳与结构 34，外观 25，通信 5，开机与死机 5，屏幕显示 3，电池与充电 2，触摸 1，其余话题为 0。这些张数是模型说法，没有人判「是」之前不进本集。

开发者 2026-10-28 看过打印和外观的标注，模型判定大部分正确。打印保持出现即算，命中文字交给用户看。外观继续用划伤、掉漆等具体说法匹配。本次不改 `topic_terms.md`。

## 分段对比

还没跑。默认分段仍是 `field_split`。

在平台测试环境做，那里有向量和重排，并且能读库。对比组是 `whole` / `field` / `field_split`，各加一组开或不开扩写。只改配置，然后全量重建、回填。

看这些数：按意思找的前 10、前 50 命中率，以及带机型或工厂时的命中率；按词找时每个话题、每个说法的准确率与召回率；第一组里有多少其实只是处理中提到，第二组里有多少其实是问题本身；第三组判断对不对；重排分阈值几乎不误删相关单。从「第二组」「判断为不相关」「未逐张判断」里抽样核对漏判，是 G5 验收前的事。

`field` 不差于 `field_split` 时改用 `field`。`whole` 明显更好时可以切回。结果记进决策，不改本集的问句。
