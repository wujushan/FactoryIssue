## 规矩（每片都适用）

1. **设计是合同**。每片开工只读该片「范围」列出的几节，加上 `docs/dev/` 里对应的部分，不必通读。每个文件开头用一行注明实现的是设计哪一节。写代码时偏离了设计，在同一次改动里改设计；和业务口径冲突的，先改 `2_landed`（AGENTS.md「落盘文档目录规范」）。
2. **一样东西只有一份**。计划格式只在 `plan/schema.py`，规整与校验只在 `plan/normalize.py`（设计 §5）；显示名、术语、示例问题、说法清单等默认值只从 `2_landed` 解析（设计 §2.3）。S1 起 spike 改为调用 `src` 的实现（设计 §1.3 末条）。
3. **SDK 不臆造**。签名以 `docs/dev/02` 和 `.venv` 里的源码为准；拿不准的写不连库的脚本实测，结论写回设计并注明版本。
4. **不碰真实数据**。编程助手只用假数据写单测（设计 §15 的假 `ctx`，假数据照 `docs/testcases/seed/单测夹具清单.md`）。要在内网验的，写成脚本，或列出 golden 用例 id 用 `scripts/qa_test.py --only` 跑，交开发者执行，只回计数与断言结果。
5. **测试包不带 mart 声明**。S6 之前发到测试环境的预发布包，不声明 mart 别名、`vectorize`、`jobs()`（设计 §2）。
6. **不提交、不打 tag**。开发者说「整理提交」时再提交；发预发布包由开发者做（`docs/dev/08`）。

## 每片的收尾

1. `uv run ruff check src tests`、`uv run pytest` 全过，包括护栏测试（设计 §15；S0 建好，之后每片都跑）。
2. 动了规划层（提示词、计划格式、规整与校验）的，跑 spike 自检，再请开发者在内网跑一次对照集（命令见 S1）。
3. 偏离设计的地方已改回设计，本文件「进度」已更新。
4. 请开发者或 `semantic_reviewer` 对照设计和 `docs/dev/09` 的自检清单评审；过了之后，开发者说「整理提交」。
