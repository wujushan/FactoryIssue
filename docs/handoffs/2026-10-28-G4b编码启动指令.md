## 规矩

- **口径以 `docs/2_landed/` 为准**，代码里不抄第二份：显示名、术语、示例问题、说法清单、部门简称、地区说法都在导入时从 `2_landed` 解析（设计 §2.3）。
- **SDK 不臆造**。签名以 `docs/dev/02-sdk-reference.md` 与 `.venv/Lib/site-packages/forge_*` 的源码为准。拿不准的写不连库的脚本实测，结论写回设计并注明版本。探测脚本放 `runtime/probes/`（已在 `.gitignore`）或 `$env:TEMP`。导入 `forge_platform.bus` 一类模块时用 `uv run --with greenlet python <脚本>`。
- **不连库，不碰真实数据**。单测只用假数据（设计 §15 的假 `ctx`，见 `tests/fakes.py`；假数据照 `docs/testcases/seed/单测夹具清单.md`）。要在内网验的，写成脚本或列出 golden 用例 id，交开发者执行，只回计数与断言结果。
- **红线照 AGENTS.md「硬约束」与「答案呈现规范」**，设计 §15 的护栏测试每片都跑：不露表名字段名、`handle()` 不算数、不用 `ctx.data.query(` / `.raw(`、按钮是对象、只有一条 system。
- **一样东西只有一份**：规划层只在 `src/factory_issue_module/plan/`，spike（`scripts/planner_spike/`）只转接、不留第二份规则（设计 §1.3 末条）。把 spike 里的其他提示或判断迁进 `src` 时照 S1 的做法：先逐字搬、确认 spike 自检与离线重算不变，再改。
- **测试包不带 mart 声明**：S6 之前不声明 `forge_mart_factory_issue` 别名、`vectorize`、`jobs()`（设计 §2）。
- **只读的目录**：`docs/1_user_input/`（可读，不改、不引用其中文件路径）、`docs/dev/`（平台文档快照）、`docs/testcases/`（G3 已冻为 v1.0，要改先问开发者）。`docs/reviews/` 可能有评审者新追加的内容，动之前先 `git diff` 看。
- **不提交、不打 tag**。开发者说「整理提交」时再提交，按文件名逐个 `git add`；`docs/1_user_input/` 下的新文件与 `docs/decisions/2026-10-26-G1初版之后口径变更原文汇编.md` 不提交。
- 发现 SDK 缺能力或文档错误：按 AGENTS.md「平台 SDK 协作原则」写 `docs/platform-feedback/`，不在业务仓静默绕开。

## 已知的坑

- PowerShell 的 `>`、`*>` 会把 spike 的中文输出写乱。用 `cmd /c "set PYTHONIOENCODING=utf-8&& uv run python <脚本> > <文件> 2>&1"`，或让 Python 自己把结果写进 UTF-8 文件再读。
- spike 离线重出汇总：把一次运行的 `raw.jsonl` 与 `run_info.json` 复制到新目录，`spike.py --report --out <目录>`。汇总抬头的提示版本取自 `run_info.json`。
- 其余见任务单「容易踩的坑」。
