## 已知的坑

- PowerShell 的 `>`、`*>` 会把 spike 的中文输出写乱。用 `cmd /c "set PYTHONIOENCODING=utf-8&& uv run python <脚本> > <文件> 2>&1"`，或让 Python 自己把结果写进 UTF-8 文件再读。
- spike 离线重出汇总：把一次运行的 `raw.jsonl` 与 `run_info.json` 复制到新目录，`spike.py --report --out <目录>`。汇总抬头的提示版本取自 `run_info.json`。
- 别用 PowerShell 的 `Set-Content -Encoding utf8` 改源码：它会在文件头加 BOM，`ast.parse` 读到 U+FEFF 报语法错，护栏测试整组失败（S5 踩过）。改文件用编辑工具，或用 `[System.IO.File]::WriteAllText` 配不带 BOM 的 `UTF8Encoding($false)`。
- 本机 Windows 上沙箱子进程偶尔以 `exit=3221227274` 退出、无 stderr，整跑时偶有一条因此失败（多是 `tests/test_s5_multiturn.py::test_m1_cost_flag_survives_verify_and_follow_up`），单跑能过就不算回归（设计 §19「G4b S6b 实现时补定的几处」）。整跑约 10 分钟，用 `cmd /c "uv run pytest -q -p no:cacheprovider > runtime\probes\<文件>.txt 2>&1"` 再看末尾。
- 其余见任务单「容易踩的坑」。

- **调用形状**：大致是三次调用：沙箱 ① 取帧（`return_frames=True`，拿回帧、列名与 3 行样例）；模型写脚本；沙箱 ② 跑脚本，这张帧作为数据集传入。AST 检查、形状检查或运行出错时，把错处交模型修一次，错误原文只给模型看、只进日志。这与 §8.1「每步一次沙箱调用」不同，要写回 §8.1。harness 只认 `run(data)` 一个入口：模型写的 `run` 与外层包装重名，拼接时改名，或在模型代码之后重新绑定。
- **口径函数只有一份**：spike 给模型的 `拆多值`、`合计不良率` 与 `stats/lib/views.py::vw_rate` 是同一条口径。迁进 `src` 时放在 `stats/lib/` 下，复用 `vw_rate` 的写法，不另写一份。这样护栏也查得到：`stats/lib/` 之外不许出现 `.sum` 一类调用。名字可以保留中文，模型提示里照现有写法给。
- **AST 检查**：设计列的那几条，再加上沙箱里本来就没有、跑了才报错的几样（`class` 定义、`hasattr`、`vars`；S2 实测沙箱没有 `__build_class__`、`getattr`、`hasattr`），提前拦下，报一句能照着改的话。import 白名单照 `forge_sandbox/harness.py::_ALLOWED_IMPORTS`（sandbox 0.2.0：pandas、numpy、math、statistics、json、datetime、collections、itertools、functools、re、decimal、time、_strptime、dateutil）。运行时不 import `forge_sandbox`（它只是 dev 依赖，§8.2），所以白名单抄一份进代码，再加一条单测断言它是 `_ALLOWED_IMPORTS` 的子集。
- **形状检查**：§5.5 写的「行数不超过表格条数」默认是 20 行，按月看两年就有 24 行。先拿 spike 的 10 题看会不会误拦，再定上限取 `table_rows` 还是另设。`chart` 的 `x`、`series` 要是 `columns` 里有的列，`series` 要是数字列；配不配图、用什么图仍照总述「什么时候配图」（2 组以上才画；时间点少于 3 个用柱状；饼图超过 8 组改柱状），模型给的图型只作首选。
- **呈现**：照 §4.3 `aggregate`、`custom_stats` 一行：开头注明「以下为临时统计」，接着是表、图（数字只从沙箱结果搬）、分析段（`present/narrative.py`，事实就是结果表）、统计口径（这一步的时间、域、条件，加「按本次临时编写的统计脚本计算」）、答后按钮。表头由模型起，同样过「不露字段名」的护栏。
- **多轮**：质疑重查、换图、递进筛选碰到临时统计怎么办。建议把脚本存进工作区，重放时照同一份脚本跑，不再调模型（质疑重查这一轮只有规划一次调用，§4.3）；改了工作区各键的结构要把 `turn/workspace.py::VERSION` 从 2 加到 3，并加进 `skills/verify_previous.py::_COMPARED`。
- **一轮里有两步临时统计**：§1.2 定的是每轮至多一次，第二步怎么答要写明。

### 口径风险（要单测，也要看 golden 回归）

让模型自己写统计，最容易出的错是口径，不是数字。§1.3 否决「模型直接写 `QuerySpec` 或 SQL」的理由是拦不住口径写错，临时统计同样有这个问题，只是范围小些：取数与派生仍由代码做。下面几条已知的坑，要靠输入帧与列说明挡住；挡不住的（比如只能靠改写计划才答得对），先问开发者：

- 海外不良率是单上原文，百分号与千分号混用，不能当数算（OS-008：不汇总、不算平均，逐单列原文）。
- 不良率的分母，国内是生产数量，巴西是影响数量，不合成一个跨域的不良率（XC-007）。
- 结案时间、停线时长、当前状态都是派生的（§6.3），帧里给派生之后的值；脚本不应该自己从处理步骤里推。
- 费用、扣款只有巴西有。

S7 做完后请开发者回归三域清单与统计那 64 条（含 CN-034、OS-008、XC-007、XC-029、XC-037），看规划器写成临时统计时答得是否仍合口径。
