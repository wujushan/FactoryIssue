## 已知的坑

- PowerShell 的 `>`、`*>` 会把 spike 的中文输出写乱。用 `cmd /c "set PYTHONIOENCODING=utf-8&& uv run python <脚本> > <文件> 2>&1"`，或让 Python 自己把结果写进 UTF-8 文件再读。
- spike 离线重出汇总：把一次运行的 `raw.jsonl` 与 `run_info.json` 复制到新目录，`spike.py --report --out <目录>`。汇总抬头的提示版本取自 `run_info.json`。
- 别用 PowerShell 的 `Set-Content -Encoding utf8` 改源码：它会在文件头加 BOM，`ast.parse` 读到 U+FEFF 报语法错，护栏测试整组失败（S5 踩过）。改文件用编辑工具，或用 `[System.IO.File]::WriteAllText` 配不带 BOM 的 `UTF8Encoding($false)`。
- 本机 Windows 上沙箱子进程偶尔以 `exit=3221227274` 退出、无 stderr，整跑时偶有一条因此失败（多是 `tests/test_s5_multiturn.py::test_m1_cost_flag_survives_verify_and_follow_up`），单跑能过就不算回归（设计 §19「G4b S6b 实现时补定的几处」）。整跑约 10 分钟，用 `cmd /c "uv run pytest -q -p no:cacheprovider > runtime\probes\<文件>.txt 2>&1"` 再看末尾。
- 其余见任务单「容易踩的坑」。
